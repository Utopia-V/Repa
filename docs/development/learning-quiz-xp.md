# 测验、XP 与进度

学习插件在菜单中提供测验和换题重考，并从学习记录里的事实算出奖励、日目标和完课估算。你可以用 `progress.get` 读取进度，用 `progress.setGoal` 修改默认的每日 20 XP 目标；测验通过现有学习契约中的 `quiz.start`、`quiz.finish` 和 `quiz.retake` 操作。

## 设计思路

XP 表示已完成的工作，而 HSRS 表示当前知识状态。因此，两者从同一份判分取证，却分别计算：XP 按任务结算，测验的 HSRS 则按 topic 更新。测验错题另外建立强制直接 review，不能因为模型计算出的到期量为零，就略过补救。复习失败后，继续沿[教学流程](learning-flow.md)转入重教。

XP 只增不减。学习状态会随补判和重判改变，例如答案改正后一节课不再算通过；但学习者已经看到的 XP 不收回，只在判分变好、奖励变高时补发差额。这样测验门槛也不会因重判回退。

MA 官网采用约每 150 XP 测验一次的口径；测验从已学 topics 中抽取多样化集合，禁止参考材料。公开资料还给出约 30 XP 的延后开始窗口，以及错题复习后对同一批 topics 换题重考的做法。依据分别见 [How It Works](https://www.mathacademy.com/how-it-works)、[How Our AI Works](https://www.mathacademy.com/how-our-ai-works)、[The Math Academy Way 第 467 页](https://www.justinmath.com/files/the-math-academy-way.pdf#page=467)和[官方 FAQ](https://www.mathacademy.com/faq)。这里采用官网的 150 XP 口径；采访中另有 120 XP 的描述。

以下精确公式与调度方式属于 Repa 假设，不作为 MA 已公开算法：奖励规则 `repa-xp-v1`；lesson/review 累计 XP 触发测验；最多五个不同 topic、每 topic 一题、固定 15 分钟；测验每个 topic 的 HSRS 更新取 `quality=1`；日目标默认值和 ETA 公式。开始前中止准备会归还这次门槛，开始后中止则按已有作答交卷。

## 实现细节

### 奖励与触发

XP 不另存，由 `replay.ts` 按事实的先后结算：一项任务结束时（课或复习得出结论、测验交卷、到截止时间），按 `progress.ts` 的 `reward` 算出奖励；之后这项任务自己的判分改变（补判、答案改正后的重判、申诉），只在奖励比已结算的最高值高时补发差额，记在使它变高的那条事实的时间。是否通过看任务的实际结论，课的继承进度取重算后的学习状态；奖励的多少只看这项任务自己的作答。更早任务的判分改变使当前的课因继承的进度而通过时，也当场结算；结算都发生在事实的边界，所以打开空间重放得到的 XP 与当时相同，已经结算的 XP 也不因重判收回。

| 任务 | `repa-xp-v1` 奖励 |
| --- | --- |
| lesson | 本次尝试通过后，`max(1, floor(minutes × 独立正确比例))`；失败或中止为 0 |
| review | 通过后，`max(1, floor(5 × 独立正确比例))`；失败为 0 |
| quiz、retake | `floor(15 × 独立正确题数 / 全部交付题数)`，未答也计入分母 |

minutes 取当前课程的 topic；重试的比例只统计本次任务。辅助后正确不进入独立正确分子；没判出结果的作答尚无证据，不进 lesson 和 review 比例的分母。XP 归入使它增加的事实发生的那一天，日汇总因此不会为负。

触发量是 lesson/review 的累计 XP；XP 只增不减，所以不需要另存历史高水位。quiz/retake 奖励不参与触发。没有进行中的任务时，触发量每到一个 150 XP 门槛就出现一场测验；每次选中测验消耗一个门槛，余量保留，同一时刻只保留一场待开始测验。测验出现后，触发量再增加 30 XP 就关闭其他常规候选；已经开始的任务可以完成。强制补救优先于测验，测验在延后窗口内也排在新课前。

### 选题、开始与恢复

测验出现时按当时的学习状态选定 topic，第几场决定打散用的 seed 与候选编号（`quiz-<场次>`），所以重放得到同样的选择。抽样覆盖当前课程全部已学且有 quiz 题的 topics，先比较以往测验次数，再比较最近独立正确的时间；同组由 seed 打散，并优先分散直接依赖或共享先修的项。最多选五项，少于五项就按实际数量开始，没有可用项时菜单说明题量不足。选题不看调用方能否运行 Python；开始时前端缺少所需能力，会报告缺项并留在准备阶段。题目沿原有未见优先策略交付，重复题保留 `repeated` 标记。

开始测验时先写下任务事实，任务停在 `preparing` 并关闭辅导；等辅导中止完成后一次交付全部题目，从这一刻开始计时，截止时间由开始时间加 15 分钟算出。准备失败或题量不足时仍停在 `preparing`，可以沿原任务恢复，或中止准备后重新选择。准备阶段占用原待开始候选，保留它的场次和 topic；第一道题交付后才删除候选。中止准备归还门槛，但不重新赠送延后窗口。

每题沿现有提交入口锁定作答；判分后可以继续答其他题，但反馈与解析到整场结束才释放。`quiz.finish` 不等待判分：交卷时还没判出结果的作答暂无证据，既不算对也不算错。这时只要已有一个 topic 答错或没答，测验就失败（到截止时间结束的为超时）；没有 topic 答错或没答，而还有作答没判出结果，测验照样结束，但结论待定（`unresolved`），菜单照常提供。判出以后测验结论、HSRS 和 XP 随之重算。重复交卷返回已有终态。服务端接受时间必须严格小于截止时间；及时接受的作答即使在截止以后才判出结果，也照样计入。关闭空间不暂停计时，重新打开或下一次查询、命令按截止时刻结束过期场次。超时终态中，没有作答的交付就是未答 timeout；它不伪造一份学习者作答。

交卷或到截止时间后，每个 topic 根据该题的独立正确结果更新一次 HSRS，错误或未答取 fail，并进入强制直接 review；作答还没判出结果的 topic 不更新也不补救，判出以后重算时再更新。补救全部完成后，菜单提供最近一场有 topic 答错或没答的测验的 retake，保留同一批 topic，排除原场题目。库存无法换题时返回 `insufficient_items`，不会静默用原题代替。重考仍然出错时，同样先补救，再提供下一次换题重考。

### 日目标与 ETA

公开状态只包含当前课程；完成率取已完成 topic 比例，复习奖励不增加完成率。日目标是一条 `goal` 事实，默认时区取后端本地时区。日期切换和日汇总都从事实算出，不维护另一份日历数据库。

ETA 是 Repa 的粗略估算：把剩余 lesson（含强制重教）的 minutes 总和乘 1.5，再加当前到期或强制 review 每项 5，除以最近七个完整本地自然日的平均 XP。七天包含零学习日，至少三个正 XP 日且平均值大于零才返回 `etaDays`；否则返回 `null`。前端呈现时应注明“估算”。

## 验证入口

在仓库根目录运行：

```sh
npm run check --workspace=@repa/learning
npm test --workspace=@repa/learning
npm run build --workspace=@repa/learning
```

`learning-quiz-xp.test.ts` 使用真实 HTTP/WebSocket 客户端、临时空间、插件宿主与 JSONL 日志，模型边界只用本地替身。覆盖 149/150 XP、延后窗口、早期 topic 入选、重复交卷、错题强制复习、失败重教、换题重考与库存不足、判分未完成时交卷（待判的题不算对错，全部待判时结论待定）、重判后 XP 不收回、日目标与七日 ETA，以及客户端断线重连、正常重开和完整空间复制恢复。截止前 1 毫秒、截止点和停机过期均用显式 now 检验。`learning-facts.test.ts` 覆盖答案改正后重判的 XP 补发与不收回，以及更早一轮课的补判使当前的课通过时照常结算 XP。完整空间副本和用例终态可用 `REPA_LEARNING_EVIDENCE=/absolute/directory` 保留。
