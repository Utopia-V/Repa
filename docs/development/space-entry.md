# 空间进入与最近空间

编写空间选择界面时，你可以通过这些接口浏览目录、设置父目录，再按学习目标或材料文件名创建空间。后端会建立相应目录，并记住成功打开过的位置，供界面显示最近记录。当前接口已经可用，目录选择和最近空间界面尚待接入。

## 设计思路

`space.open` 已经能够打开空间，不过，调用方需要先给出空间的路径。如果前端要让你从一个学习目标开始创建空间，就还得先确定它放在哪里、使用什么目录名。因此，创建接口应当负责选定新目录，再把这个目录交给已有的打开流程。

要确定存放位置，前端可以先调用 `space.browse`，把后端返回的目录条目显示出来，供你逐级选择。目录列表需要区分文件和目录，也需要支持翻页，所以接口返回的是结构化元信息。Pi 0.87.1 的 `ls` 工具虽然也能列目录，但结果是供模型阅读的文本；这里因此直接使用 Node 文件系统接口取得前端需要的字段。

选定的位置可以保存为应用的空间父目录，以后创建空间时就不必重新选择。为了让这个设置与其他应用设置一样保存和更新，我们把它接入现有的 `settings.get/set/reset`，沿用修订检查与变更通知。前端随后只需把学习目标或材料文件名作为 `hint` 传给 `space.create`，后端就会在这个父目录下生成新目录名。

目录名通过本地文字规则生成，所以尚未配置模型时也能创建空间。不过，生成的名字可能已经被占用。例如，父目录中已有“微积分”时，新空间应当改用“微积分 (2)”，而不是打开原来的目录。后端因此先尝试独占创建目录，名字被占用时再换下一个编号；只有创建成功以后，才会初始化空间。并发请求也使用同一个创建过程，由文件系统分别确定它们取得的目录。

创建成功的空间以后还需要重新打开，所以后端会在每次成功打开时记下路径与时间。原有的 `space.list` 只列出当前后端已经打开的空间，重启后便不能用它找回这些位置；为此，`space.recent` 从应用目录中的持久记录读取最近空间。前端可以先显示这份列表，等你选定其中一项以后，再用 `space.open` 打开。

## 实现细节

### 公开接口与实现入口

接口定义集中在 [spaces/schema.ts](../../packages/repa/src/spaces/schema.ts)，由 `repa/protocol` 导出，前端通过 `RepaClient` 调用。

| 调用 | 参数 | 返回与行为 |
| --- | --- | --- |
| `space.browse` | `path?`、`cursor?`、`limit?`、`includeHidden?` | 目录的真实路径、父目录、当前页条目和可选的下一页游标 |
| `space.create` | `hint` | 在配置的父目录中建立新目录并打开，返回 `Space` |
| `space.recent` | `limit?` | 最近空间的路径、最后打开时间和当前可用性 |
| `space.open` | `path` | 沿用既有行为：目录缺失时递归创建，再打开空间；成功后更新最近记录 |
| `space.list` | 无 | 当前后端已经打开的空间，后端重启后从空列表开始 |

目录浏览和命名创建位于 [entry.ts](../../packages/repa/src/spaces/entry.ts)，最近记录的读取与保存位于 [recent.ts](../../packages/repa/src/spaces/recent.ts)。调用进入 [RepaApplication](../../packages/repa/src/application.ts) 后，应用会读取所需设置，并等待创建、打开和保存操作完成。新建空间也使用 `openSpace`，因此空间身份、内容和 Pi 会话历史都沿用原有的初始化方式。

### 父目录设置与创建

`spaces.parentDirectory` 的默认值为 `null`，只有应用作用域可以修改。值保存在应用目录的 `repa-settings.json` 中，设置机制及应用目录的选择见[模型连接与运行配置](models-configuration.md)。

下面的示例假定 `client` 已连接，并且你已经从目录浏览结果中选定 `/home/user/学习`：

```ts
const scope = { kind: "application" } as const;
const settings = await client.call("settings.get", { scope, namespace: "spaces" });
const parent = settings.entries.find(entry => entry.key === "parentDirectory");
if (!parent) throw new Error("后端未提供空间父目录设置。");

await client.call("settings.set", {
  scope,
  namespace: "spaces",
  key: "parentDirectory",
  value: "/home/user/学习",
  base: parent.revision,
});
const space = await client.call("space.create", { hint: "线性代数期末复习" });
```

示例先保存父目录，再用目标文字创建空间。保存设置时，后端接受非空字符串或 `null`；等到实际创建时，才会检查这个位置。因此，你应当填写已存在目录的绝对路径。如果目录在设置后被移走，创建就会返回 `not_found`，需要重新选择位置。

这个设置只决定新空间放在哪里。修改它以后，已有空间仍保留原位置；如果要打开父目录之外的空间，也可以直接向 `space.open` 提供那个位置。

父目录确定以后，后端还需要把 `hint` 转成目录名。处理时先作 Unicode NFC 规范化，再把路径分隔符、控制字符以及 `<>:"|?*` 替换为空格，随后合并连续空白，保留前 60 个 Unicode 码点，最后去掉首尾的点和空格。这个长度为常见文件系统的文件名字节限制和重名后缀留出空间。如果处理后没有剩下文字，就使用“学习空间”。

取得名字以后，后端尝试创建目录。假如“微积分”已经被占用，就依次尝试“微积分 (2)”“微积分 (3)”。这里已有的文件、目录和符号链接都算占用，原对象会保留下来。

目录创建并打开后，接口会返回 `Space`。到这里完成的是空间准备，刚才的 `hint` 只用于命名。如果还想用这段文字开始交流，就可以拿返回的空间信息继续调用 `session.create` 和 `session.submit`；选好的材料则通过已有内容接口接入。

### 目录条目与分页

首次浏览时，可以省略 `path`，从后端用户的 HOME 开始；进入选中的目录时，再传入它的绝对路径。后端会解析符号链接并返回实际路径，因此，如果你选中一个指向目录的链接，下一次浏览就会进入它所指向的目录。到了文件系统根目录，返回的 `parent` 为 `null`。

每个条目包含 `name`、绝对 `path` 和 `kind`。`kind` 为 `directory`、`file`、`symlink` 或 `other`；普通文件另有按字节计的 `size`。符号链接保留 `symlink` 类型，并在目标可访问时提供 `targetKind`。失效或无法访问目标的链接仍然可以列出，只是不提供目标类型。

浏览接口只读取这些元信息。如果你随后把某个文件选作外部材料，还需要通过 `content.associate` 建立读取授权，具体见[内容说明](content.md)。

默认情况下，以点开头的条目会被隐藏；如果需要显示它们，可以传入 `includeHidden: true`。每页默认返回 100 项，`limit` 可以设为 1～500。条目按 JavaScript 字符串顺序排列，下一页游标使用本页最后选取的名称。因此，继续翻页时，你应当沿用返回的目录路径和相同筛选条件，再把 `nextCursor` 传回。

每次翻页时，后端都会重新读取目录，并且只为当前页取得详细元信息。这样既适合交互式选择位置，也省去了保存目录快照的工作。不过，如果目录恰好在翻页期间发生变化，前后两页看到的就可能是不同时间的内容。这时，如果还需要重新查看完整列表，从第一页开始刷新即可。

### 最近记录与打开生命周期

最近记录保存在应用目录的 `repa-recent-spaces.json`，格式为 `repa.recent-spaces` 版本 1：

```json
{
  "format": "repa.recent-spaces",
  "version": 1,
  "entries": [
    { "path": "/home/user/学习/微积分", "lastOpenedAt": 1791158400000 }
  ]
}
```

`lastOpenedAt` 使用 Unix 毫秒。每次成功打开空间，后端都会把它的真实路径移到列表首位，并更新这个时间。如果你通过符号链接再次打开同一个目录，更新的仍然是原来那条记录。

由于每次打开都要更新这份记录，保存也就属于打开操作的一部分。新空间要等初始化和最近记录保存都完成后才会发布；如果空间已经打开，再次调用时也会等待记录更新。应用退出时同样会等这些操作收尾，避免刚打开的位置还没保存就结束进程。

同一应用目录可能由多个后端使用。如果各自根据旧列表保存，就可能覆盖另一边刚写入的路径。因此，保存过程复用现有的 `SerialQueue`、`proper-lockfile` 和原子 JSON 写入：取得文件锁后，先重读列表，再合并本次路径并保存。普通查询只读取文件，不创建记录文件或持有长期锁；如果原记录损坏，则返回 `invalid_storage`，保留文件供后续处理。

`space.recent` 默认返回前 20 项，`limit` 可以设为 1～100。查询时，后端会检查每条路径是否仍是当前进程可读、可写和可进入的目录，并把结果放在 `available` 中。前端可以据此标记失效位置。

前端可以根据 `available` 决定怎样显示这条记录，但打开空间还需要检查目录里面的状态。例如，目录虽然可读写，空间却可能已经被另一个后端占用。因此，选定记录以后仍应调用 `space.open`，由打开流程完成这些检查。最近记录查询本身只读取路径状态，不会同时打开空间、恢复缺失目录或读取其中的材料。

### 前端可以处理的错误

| 错误码 | 发生位置与含义 |
| --- | --- |
| `parent_directory_required` | `space.create` 尚未取得父目录设置，前端可以引导选择位置 |
| `invalid_path` | 浏览或创建使用的目录路径不是绝对路径，或包含空字符 |
| `not_found` | 浏览目标或创建所用的父目录已经不存在 |
| `not_directory` | 对应路径是普通文件等非目录对象 |
| `permission_denied` | 当前进程没有完成浏览或创建所需的文件系统权限 |
| `invalid_storage` | 最近记录无法读取或格式无效，需要处理原记录中的问题 |

`space.create` 的每次调用都会创建一个新空间。若连接中断而结果不明，前端应先查询最近空间或浏览父目录，确认实际结果，再决定是否发起新的创建。
