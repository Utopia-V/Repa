# 共享后端能力宿主

Repa 的能力既可以由 Agent 使用，也可以由客户端直接调用。本模块把两种调用接到同一个处理函数，并管理调用期间需要的资源。包的安装与加载见[插件说明](plugins.md)。

## 设计思路

以复习为例，Agent 可以记录对话中的练习结果，用户也应该能在复习页面直接作答。无论从哪个入口提交，结果都要更新同一份复习记录，下一次的安排也要由同一套算法计算。

因此，复习的处理逻辑应当先放在应用管理的后端能力中，再分别接到 Pi 工具和公开客户端。Pi 已经提供工具接口，接入时只需要让工具调用这份实现。界面也直接调用它，提交一次作答不必先启动 Agent；以后调整复习算法，修改的也是两边共用的实现。

这些调用还需要使用所在空间的数据。宿主在第一次调用时让复习插件打开这个空间的数据库，后续调用共用这份连接，关闭空间或禁用插件时再通知它结束工作、释放资源。至于表怎样定义、数据怎样迁移、复习时间怎样计算，都由复习插件自己决定。

检查时间安排这样的能力只需要计算，用不到数据库。插件按它们自己的需要使用这些服务，宿主只要求提供能力声明和处理函数。打开空间资源、关闭资源和生成快照都属于可选接口。

## 实现细节

### 定义与实现选择

[`CapabilityHost`](../../packages/repa/src/capabilities/host.ts) 保存已启用的能力定义，按本次选择找到处理函数，检查输入输出，并管理插件在各空间中打开的资源。`Application` 提供调用来源、授权和本次可用的服务。包从哪里来、何时加载，由[插件装配](plugins.md)负责。

[公开描述](../../packages/repa/src/capabilities/schema.ts)说明能力叫什么、接口版本是什么、有哪些实现、接收和返回什么数据，以及适用于应用还是某个空间。[后端定义](../../packages/repa/src/capabilities/types.ts)在这些声明之外保存实际函数：

| 定义 | 用途 |
| --- | --- |
| `BackendPluginRegistration` 的 `id/enabled/factory` | 登记插件及启用状态；启用后才调用工厂取得定义 |
| `BackendPlugin.capabilities` | 声明可调用的能力 |
| 可选的 `settings` | 把插件设置登记到现有 `ConfigStore` |
| 可选的 `openSpace/closeSpace` | 打开和释放本插件在某个空间的运行资源 |
| 可选的 `snapshot` | 参加空间备份与复制 |

同一个接口版本使用相同的输入输出 schema，不同实现用 `implementationId` 区分。调用方可以直接选择实现，也可以使用 `plugins.implementations` 的配置。有多个实现却没有选择时，返回 `capability_selection_required`。

插件设置由现有的 `ConfigStore` 管理，沿用它的继承和修改规则。每项设置需要声明允许在哪些作用域覆盖。禁用插件时保留已保存的值，重新启用后再由插件读取。

### 公开调用与 Agent 工具

`capability.describe({ scope })` 返回该作用域可用的能力、包目录和装配问题。`scope` 为 `{ kind: "application" }` 或 `{ kind: "space", spaceId }`。`capability.invoke({ scope, requestId, contract, implementationId?, input })` 在受理时固定实际实现，返回：

- `execution: "query"`：直接查询当前值，返回 `{ kind: "inline", requestId, result }`，不保存处理记录。
- `execution: "inline"`：保存受理与结果，等待完成后返回 `{ kind: "inline", requestId, result }`。
- `execution: "background"`：返回 `{ kind: "background", request }`，之后查询 `request.get` 或取消 `request.cancel`。

你刷新列表或读取当前参数时，需要的是当前数据，而不是上一次查询的回执。能力可以声明为 `query`，沿同一个调用入口直接返回结果；`requestId` 只关联这次调用，重复调用会重新查询，`request.get` 不保存它的结果。查询复用能力宿主的作用域、运行资源和关闭流程，不另建调度或缓存。

`query` 适用于无业务修改、无需独立资源保留、进度和交互的即时查询。公开查询只取得配置等实际需要的窄服务；需要这些持久责任的能力使用 `inline` 或 `background`。这两种调用由 `BackgroundRequests` 保存请求、受理时的配置和结果，客户端断线后可以用原来的 `requestId` 查询或重传，取得原记录。

应用范围的调用省略 `spaceId`，记录保存在应用目录；空间调用使用所属空间的记录。持久格式和独占访问规则见[请求说明](requests.md#持久格式与资源)。

要让 Agent 使用这项能力，需要在定义中声明 `tool`。Application 会据此向 Pi 会话提供工具，调用时执行同一个 `invoke`。默认情况下，模型填写公共接口的全部输入。不过，有些字段应当由程序提供，例如当前空间和操作标识。这时可以通过 `tool.input: { schema, prepare(input, scope) }` 单独定义工具参数，只让模型填写业务所需的部分。

例如，复习工具的操作标识由程序生成；设置学习语境时，模型给出内容标识，程序补上当前空间。宿主先检查模型参数，再调用 `prepare` 补齐公共输入，最后按原接口检查并执行。`prepare` 只做参数转换。公开客户端仍填写完整输入，公开描述只包含工具 schema，不包含转换函数。

Agent 工具调用已经包含在一次运行中，可以直接使用父运行的身份和取消信号。工具等待处理函数返回后，把结果交给 Pi；即使能力声明为 `background`，也不另建后台请求。前述 `BackgroundRequests` 记录用于公开客户端发起的调用。

### 作用域与服务

处理函数通过 `InvocationContext` 取得本次作用域、来源、取消信号，以及需要的内容服务和插件运行资源。客户端调用记录 `hostId`；Agent 调用记录空间、会话、运行和请求身份。这些信息由应用绑定，模型填写的业务参数不会改变调用身份。

[RepaCapabilityServices](../../packages/repa/src/capabilities/services.ts)由 Application 按本次作用域选入：

| 服务 | 当前责任 |
| --- | --- |
| `progress`、`ask` | 公共后台请求的进度和交互，或父 Agent 运行的通知与交互 |
| `events.publish({ format, data })` | 发布插件状态通知；应用绑定真实的插件、作用域、来源和父请求身份 |
| `settings(namespace)` | 客户端调用读取当前应用／空间层级；Agent 调用读取其实际会话层级的有效配置及来源，复用 `ConfigStore` |
| 空间 `resources.snapshot/retain/create/read` | 在内容授权边界取得实际字节与修订，并按真实父请求持有原件或派生结果；快照取得后退出内容队列，解析不阻塞正常保存 |
| 空间 `models.complete` | 明确输入及模型选择的独立处理，复用现有连接、Pi 调用及重试，归入父请求而不新建会话 |
| 空间 `execution.run` | 在当前能力的实际请求、来源和取消信号下执行命令，复用执行权限与输出保留，不创建平行请求 |
| 空间 `sessions.history/snapshot/submit` | 读取所属空间的指定历史范围或一次冻结消息视图，或向同一空间提交已有的请求／接续形式；新提交仍保留能力来源 |

空间调用取得的是该空间的 `ContentStore`。应用范围的调用没有对应空间，因此当前不提供内容、模型和会话服务。插件使用这些服务时，由应用接入已有的认证、会话和请求实现。

`sessions.submit` 可能需要等待应用处理其他操作。等待期间取消父调用，会同时取消这次等待；一旦新请求已经受理，它就有了独立的请求身份，后续按会话请求规则执行和取消。

### 插件状态通知

插件保存数据后，可以调用 `events.publish({ format, data })` 通知客户端重新查询。应用为通知补上实际的插件、空间、来源和请求身份，发出 `type: "capability"` 的变化事件。通知的内容和含义由插件定义。

同一空间中的其他会话也可能使用这份数据，所以空间变化会通知本空间的所有相关订阅。应用范围的变化则通知所有订阅。状态查询由插件提供，通用 `Snapshot` 中不保存插件数据的副本。客户端首次连接或重新取得快照时，需要另行查询插件状态。

例如[复习插件](review.md)发布 `repa.review.invalidated/1`，表示复习数据需要重新读取。相同操作的回执再次返回时可以重复通知刷新，数据库仍只保存一次实际反馈。

### 资源声明与结果表示

能力可能读取原件、生成图片或返回提取结果。要让这些字节在后续读取时仍然存在，插件需要通过 `inputResources(input, scope)` 和 `outputResources(output)` 声明要保留的 `ResourceRef`。这些函数只指出引用，实际读取和保存由资源服务完成。

标准 `Representation` 已经声明来源和资源，[capabilityRepresentation](../../packages/repa/src/capabilities/resources.ts)会将这些信息连同插件的显式声明交给请求模块。自定义结构仍由插件解释，例如 `{ result: { artifact } }` 需要明确声明 artifact 中有哪些资源，宿主不会遍历所有业务字段猜测。

公开客户端的调用在受理前保留输入资源，在完成前核对输出资源。Agent 工具使用的资源先由当前请求保留，结果进入历史后由会话接手；建立会话分支时，分支也有自己的保留关系。同一能力多次读取或调用模型时，资源逐次追加，后一次调用不会覆盖前一次仍在使用的资源。

会话运行结束后，请求只继续保留原输入，其余结果由会话历史持有。独立后台处理成功后，保留输入和最终结果；失败或取消时，已经取得的资源按原记录保留，之后再由资源回收规则处理。空间资源始终属于明确的空间，应用范围调用需要它们时返回 `space_required`。

能力以 `RepaFault.details` 携带标准 `Representation` 报告失败时，宿主也会核对并追加保留其资源。后台父请求将它保存为失败记录的 `result`；Agent 工具则通过 Pi 的失败工具结果保存在历史 `details` 中。这条路径只识别标准表示，不从任意异常字段推断资源。

`resources.snapshot({ target, revision?, maxBytes? })` 在共同内容队列中读取并保留字节，取得快照后即可退出队列做解析。读取前检查文件大小，读取后再次核对 `maxBytes`。没有请求身份的兼容查询只取得实际需要的服务，不提供需要请求持有资源的模型调用。

复制空间时，共同模块映射标准表示中的来源和资源，包括内嵌的标准表示。插件业务数据中的引用仍由插件处理；[搜索结果分页](search-materials.md#分页读取结果而不再次搜索)展示了一种具体接法。

### 按需打开、取消与快照

提供 `openSpace` 的插件，在第一次空间调用时才取得 `.repa/plugins/<pluginId>` 数据目录。同一空间的并发调用共用一次打开过程；打开失败后，下一次明确调用可以重试。目录沿用 Repa 的受管理路径检查，空间中的符号链接不能把插件写入转到外部。

取消先发出信号，再等待处理函数结束。已经保存的业务修改继续保留，取消不会撤销它们。关闭或禁用插件时，宿主停止接收新调用，取消正在进行的调用和资源初始化，最后等待资源释放；单个调用取消则不影响其他调用共用的初始化。某个资源关闭失败时，其他资源仍继续收尾，再次关闭只处理尚未完成的部分。

禁用和卸载代码都会保留业务数据。备份时仍需要了解这些数据格式的插件参与，因此除了已启用插件的 `snapshot`，还支持随包提供的独立快照入口。插件关闭并重启应用后，也可以只加载这部分完成备份。若缺少必要的快照实现，备份会报告原因，不直接把未知数据库当普通文件复制。接口和具体取舍见[插件装配](plugins.md#禁用后的持久数据快照)。

后台插件在宿主进程中运行，拥有该进程的权限。上述接口管理调用和资源，命令服务的沙箱只约束经它启动的命令。加载第三方插件前需要信任它的代码，具体范围见[插件信任说明](plugins.md#信任的实际范围)。

### 原有学习语境的迁移

原先，内容存储和 Pi 会话接入直接处理学习背景的选择与展开。修改背景的选择或展开方式时，就得改动这些通用模块。

现在，选择哪些学习背景、怎样展开它们，由官方学习能力负责。内容模块保存文件，Pi 使用准备好的背景。学习能力可以替换或关闭，原有的文档、绑定和历史快照会保留。关闭后，用户仍能读写内容、使用普通 Agent 会话。迁移方式见[学习语境说明](learning.md)，应用启动时的接入见[官方后端默认组合](official-learning.md)。
