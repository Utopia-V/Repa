# 学习辅导与即时回顾

学习插件声明 `learning-tutor`，围绕当前任务提供聊天、内容搜索和即时回顾。界面与 Agent 共用 `content.search`、`content.read` 和 `content.open` 的授权与记录入口；复习准备开始时就关闭这些帮助，直到任务结束。

## 设计思路

练习是用来取得证据的：作答如果是在辅导帮助下完成的，答对就说明不了学习者自己会不会。所以作答期间不能提问，也不能查参考内容：课内一道题出来以后到它被收下之前，复习和测验从准备阶段到结束，`beforeMessage` 都拒收消息，内容读取也被拒绝。课内读讲解、看例题和看过反馈以后照常可以问。这样每份作答都是学习者独立完成的，学习记录不必再记谁在什么时候求助过。

复习和测验还要保证第一道题出现之前辅导已经停下。教学流程先写下任务事实，任务停在 `preparing` 并生效限制，再等待 `host.abortAgent("learning-tutor")` 完成；Pi 停稳后才交付第一道题。复习不限时，作答期间一直关闭辅导，做完或中止以后恢复；测验从第一道题出现时开始计时。准备失败时，任务仍是 `preparing`，重新打开以后可以沿 `task.resume` 继续。取消期间到来的消息沿底座原有行为报告 `cancelled`；取消完成后的受限消息由 `beforeMessage` 拒收。

模型不需要在每轮对话里接收整门课。Agent 的命名提示段说明辅导职责和回答方式，视图只写出当前任务与阶段、课内当前知识点的进度，以及最多三个学过的直接先修。需要题目和讲解时，再通过工具读取。工具每次执行都重新检查当前状态，视图也在模型请求前检查限制。因此，旧视图或已放行但尚未启动的消息都不能绕过后来生效的限制。

辅导像 Claude Code 那样，是一段连续的对话，不按任务拆开。换了任务以后，前面的聊天讲的还是旧题，模型靠视图分清学习者现在在做什么：系统提示与工具声明是固定前缀，视图只在内容变化时追加在用户消息之后，任务或阶段一变，下一轮就带上新视图，见底座的[对模型的影响](../../packages/base/README.md#对模型的影响)。对话过长时由 Pi 压缩，压缩以后底座补回最新视图。前端怎样保持、接续和新开会话，见[前端契约](learning-protocol.md#辅导会话)。

学习者卡住时，模型要看清这道题问什么、学习者答了什么、错在哪里。前端用的 JSON 里，这些内容夹在交付编号、提交编号和版本之间，选项只有不透明编号，作答也只记这些编号，模型还得自己对应；按字符切片以后，模型读到的又是从字段中间断开的碎片。所以视图和工具交给模型的都是分行文字：选项按学习者看到的顺序编号，作答和正确答案用同样的编号写出，前端改了字段，模型读到的内容和提示缓存也不随之改变。

## 实现细节

### Agent 与学习产品入口

`plugin.ts` 默认把教学流程的 `beforeRestricted` hook 接到本插件的中止入口，并装配 `tutor.ts`。`learning-tutor` 可直接对话，只列出 `learning_task`、`learning_search`、`learning_read`；读文件、写入、命令、网络和子 Agent 工具均不在声明中。不给 `read`，是因为自制课写在空间的 `course/` 里，草稿里有复习和测验题的答案，辅导读得到就可能在作答期间说出来；长输出由三项工具自己按行分批（见下文），不靠 `read` 续取。

在仓库根目录运行：

```sh
npm run dev:learning -- --home /absolute/repa-home
```

这个入口先构建学习包，再加载学习插件与课件插件启动底座，带通用 Agent（做课由它完成）；通用 Agent 与 `learning-tutor` 都能直接对话。Desktop 与 `npm run dev:web:learning` 的装配相同，Desktop 的页面接线由 [#60](https://github.com/Utopia-V/repa/issues/60) 与 [#62](https://github.com/Utopia-V/repa/issues/62) 接续。

### 内容、版本与原学习位置

`tutor-content.ts` 从已经全量加载的课程建立只读索引，包含 topic 正文、KP 讲解、例题正文与解说、概念卡。正式练习、复习和测验题的私有定义不进入索引；题解只从已经释放的公开 submission 投影取得。可见范围是当前任务的 topic 与学生模型中已经学过的 topic。界面的 `content.*` 请求必须携带完整版本引用；辅导工具按内容编号读取，读到的总是当前课程里的版本。读取只提供当前课程里的内容，课程换版以后旧版本的引用按不存在处理；猜题号、使用不存在的版本或读取尚未学过的 topic 都会失败。下表中界面方法的参数上限见[前端契约](learning-protocol.md#状态与方法)，工具参数的默认值与上限见[工具目录](../generated/tools.md)。

| 入口 | 参数与结果 |
| --- | --- |
| `learning_task` | 只有可选的 `line`；写出学习者正在读的讲解或例题，或者正在做的题，连同学习者的作答、判分结果和已释放的题解 |
| `content.search` | 显式传 `query`、`offset`、`limit`；按内容 id 稳定排序，返回 `ref`、标题、短命中、`origin` 和 `nextOffset` |
| `learning_search` | 同一处理器；省略 `offset`、`limit` 时用工具声明里的默认值；每条结果一行内容编号与名称，下一行是摘录，还有更多时末行写出下一次的 `offset` |
| `content.read` | 按 `refs` 批取，以 `offset`、`limit` 选择内容块 |
| `learning_read` | `ids` 是 `learning_search` 结果里的内容编号；写出每项内容的全文，所在 topic 登记了出处时另写一行“出处：「来源」位置”，编号不存在或还没学到时报错并提示先搜索 |
| `content.open` | 界面打开卡片或参考内容时核对授权，返回服务端 `openedAt`；作答期间拒绝 |

`learning_task` 只从公开状态取值，不读取课程里私有的答案或 rubric。它也逐次检查限制，因而模型可以直接看见正在讨论的题目，而不必要求学习者重新转述。文字由 `tutor-text.ts` 写出，内容块的写法与模型核对共用 `model-text.ts`：代码块用围栏，带 `startLine` 的每行前写行号。开头几行写任务与 topic、知识点及其编号，以及这道题提交到了哪一步（正在判分、判分没有完成，或判分结果）。接着是题面和各小问：选项与排列块按学习者看到的顺序从 1 编号，表格写成 Markdown 表，小问的标签和文本输入框后面的文字（常是单位）照样写出，只有一问时也不省；学习者的作答、各小问的判分、代码题各测试的结果和模型判分的理由写在对应的小问下面，没答对的小问另写正确答案。题解释放以后附在最后。学习者在读讲解或例题时，写出这一页的全文；任务结束以后，写出最后一道题。

界面的搜索与批取有正常响应预算（[`tutor.ts`](../../packages/learning/src/tutor.ts) 的 `TEXT_BYTES`）；搜索可能提前返回 `nextOffset`，批取可能缩短最后一页或只返回前几个引用。每页的 `offset`、实际 `blocks.length` 和 `total` 用于继续读取，尚未返回的引用继续单独请求。分页保持课程原生内容块，不截断 Markdown 或代码块；某个单块已超过预算时报告 `content_block_too_large`，由内容作者拆分该块。预算和分页数量都是 Repa 的工程假设。辅导工具按行分批：`learning_search` 另按条数翻页；三项工具写好的文字超过 40,000 字节或 1,500 行（留在底座 50 KiB、2,000 行的上限之内）时，只交回从 `line` 起的一批，末尾写明这是第几行到第几行、共几行，以及接着读时加上的 `line`。所以底座不再截断辅导工具的输出，题面、代码和作答也都照原来的行写出，不拼成一行。单独一行超过字节上限时整行交回，由底座省略中间。

`ref` 是概念与内容的版本引用，`origin` 定位原任务及可用的原交付。概念卡的例子来自例题时，`origin.content` 指向该例题；来自已经交付的正式题时，`origin.deliveryId` 指向那份交付。界面可以用同一 `content.read` 入口取得原例题，或者回到原交付画面。前端渲染和对话内链接的实际交互由 [#60](https://github.com/Utopia-V/repa/issues/60) 接续。模型看不到 `ref` 和 `origin`：搜索结果只给内容编号（即 `ref.id`）和名称。模型提到学过的知识点时写 `[名称](repa:concept/<知识点编号>)` 链接，与课程正文里概念链接的写法相同；界面可以按知识点编号用 `content.search` 找到概念卡及其 `origin`。

### 作答期间的限制

辅导和内容读取每次都按当时的状态判权：课内有一道题等着作答，或复习、测验还没结束，就拒绝。内容读取与学习记录的写入走同一个串行入口，读到一半时出题，读到的仍是出题之前允许看的内容。课内写下交付以后、返回之前，还会停下出题之前已经放行、仍在生成的辅导回复；停不下来时不拦住学习者，复习和测验则在交付之前等辅导停稳。作答期间关闭提问，与复习、测验结束以前不给反馈是两件事：课内第二题等着作答时，第一题的反馈和题解仍然可见。

参考内容的限制也覆盖历史提交。插件在统一公开响应边界按返回时的当前任务判权；受限期间保留提交身份、原答与处理状态，隐藏反馈（包括期望答案）和题解。这条投影规则覆盖查询、幂等重试、恢复、申诉、状态以及错误携带的状态，不改变日志中的完整判分。内容读取与响应投影共用 `referenceAllowed`，因此历史结果不能绕过 `content.*` 的禁助限制。正式题解只在教学流程释放后可检索、读取。

视图的先修排序使用最后一条事实的时间，不使用每次查询时的相对时间。因此，状态相同时，视图文本保持稳定；下一轮运行通过 Pi 现有命名段和视图更新看到新状态。这个时间与学生模型一样经 `modelDay` 校正：时钟回拨到最近一次更新之前时，按最近一次更新的时刻计算，各先修的强弱不因回拨而颠倒。

复习的完整开始路径位于 `flow.ts` 的 `menu.select` / `task.resume`：先写下任务事实，再等待取消完成，然后交付第一道题，开始时间由它算出，测验的截止时间也由它算出。quiz/retake 走同一条路径，一次交付整场题目；恢复时沿同一步骤继续，见[测验与进度说明](learning-quiz-xp.md)。内容与消息限制已经按所有非 lesson 的未结束任务检查，覆盖 preparing、作答和恢复阶段。

## 未完成项与待验证项

- Desktop 装配、概念链接、卡片和原位置跳转的界面交互由 [#60](https://github.com/Utopia-V/repa/issues/60) 与 [#62](https://github.com/Utopia-V/repa/issues/62) 接续。当前已验证真实客户端读取引用及原例题，界面尚未验收。
- 真实辅导效果及学习外负担的变化，需要真实学习者使用。当前模型边界采用本地假 provider。
- `learning_task` 只写当前这一道题，测验和复习结束以后写的是最后一道。学习者问到同一场测验里的其他题时，模型读不到那道题的题面和作答，只能搜到它已释放的题解。

## 验证入口

在仓库根目录运行：

```sh
npm run check --workspace=@repa/base
npm test --workspace=@repa/base
npm run build --workspace=@repa/base
npm run check --workspace=@repa/learning
npm test --workspace=@repa/learning
npm run build --workspace=@repa/learning
```

`learning-tutor.test.ts` 使用真实 SDK、真实 HTTP/WebSocket 客户端及本地假 provider，组合验证 py01 上课、作答期间拒收提问、答完以后提问、判分、菜单、跨天复习、即时回顾和关闭后复制到新目录恢复。模型收到的文字从 provider 实际收到的请求里取：选择题、代码题和开放题判分以后的当前任务，搜索结果与按编号读取的全文，超过底座上限的当前任务经 `read` 按行续取，以及时钟回拨后视图里先修的顺序。另验证界面的稳定分页、按引用上限批取、长块续取、私有题解释放边界、取消停稳后才交付第一道题，以及准备失败后重开继续。设置 `REPA_LEARNING_EVIDENCE=/absolute/directory` 后，复制恢复用例会把关闭时的完整空间副本保存在新的 `tutor-restored-*` 子目录中。底座 `agent-messages.test.ts` 验证所有权拒绝、取消终态、排队清理与恢复聊天。
