# 学习记录与恢复

学习插件把学习者做过的事情作为事实，逐行追加到空间的 `.repa/plugins/learning/records.jsonl`。任务画面、学生模型、进度和 XP 都从这些事实重放得出，没有另存，删掉也能重算；打开空间时从第一条事实重放一遍。[教学流程](learning-flow.md)在同一入口上完成上课、复习、判分与申诉。

## 设计思路

先看旧做法的一个情形：学习者每答一题，记录就存下整个界面画面和学生模型的投影。这样记录随使用越变越大，答一题要写几十 KB；前端改一个字段，盘上格式就跟着变；学生模型的算法改进以后，也没法用她过去的作答重新推断学习状态，因为记下的是旧算法算出的结果，而不是作答本身。

所以记录只存对推断学习状态有用的事实：选了什么任务、翻到哪一页讲解、出了哪道题、答了什么、当时判成什么，以及主动结束任务和日目标。界面、学生模型、进度和 XP 由程序从事实算出。算法改了，重放同一份事实就得到新算法下的状态；换一组学生模型参数，也能拿同一份历史作答比较两组参数的预测。

作答和判分是两条事实。提交时断开连接，并不能说明作答是否收下，因此先写下作答，再判分。判分途中关掉窗口、判分服务失败、模型表示没有把握时，记录里只有作答、没有判分：这份作答尚无证据，既不算对也不算错，不阻塞任务。条件具备时补判，追加的判分让学习状态随之重算。

题目的答案改正以后，过去的作答按新答案重判。作答事实记下学习者看到的题面版本，判分事实记下判分所依据的题目版本。题面没变而题目版本变了，说明改的是答案或判分方式，就按新定义重判，新判分追加在后面并取代旧判分；旧判分留在记录里。题面变了，过去的作答就不再按新题判。

## 实现细节

### 插件与接入

包根目录的 `repa-plugin.json` 声明 `learning`、代码及底座兼容版本和构建入口 `dist/plugin.js`，可以交给底座现有的插件加载器。`createLearningPlugin({ sources, connect })` 打开时按[课程来源](#课程来源与模型)决定学哪门课，一次加载全部 topic。底座传入的 `host.space.dataDir` 已是本插件的数据目录；时间一律取自底座的 `host.now()`，插件不另设时钟，测试通过宿主的 `now` 拨动时间。

插件自行在其中管理 `format.json`，当前版本是 [`plugin.ts`](../../packages/learning/src/plugin.ts) 的 `LEARNING_FORMAT_VERSION`。目录为空时写入当前版本的标记；非空目录缺少标记，或标记是更早的开发版本（只记投影的版本 1、任务不带课程版本的版本 2），都按无法识别的开发数据停用学习插件，提示删除 `.repa/plugins/learning/` 后重新打开空间，不做转换。版本检查复用[底座辅助函数](../../packages/base/README.md#插件清单与数据版本)，标记损坏、版本过新或记录损坏时只停用学习插件。

打开时先由 `LearningRecords.open` 读入并核对事实，再由 `LearningSession.open` 重放出学习状态、找出要补判的作答。教学方法（`connectLearning`）和辅导（`connectTutor`）共用这个会话：读取当前状态、在串行入口里写入事实、判分。`connect` 选项可以换掉教学方法的装配，测试用它取回会话。

| 入口 | 行为 |
| --- | --- |
| `LearningRecords.open(file, clock)` | 读入以换行结束的完整行，逐条核对格式、序号和引用；末尾的残缺片段只读不写 |
| `records.write(build)` | 在串行入口里调用 `build` 决定要追加的事实，一次写入、一次同步文件和目录，再按顺序通知监听方 |
| `LearningSession.open(records, course, host)` | 重放全部事实；找出没判、要按改正后的答案重判和申诉后待重判的作答，规则题当场判完 |
| `session.view(capabilities)`、`session.state(capabilities)` | 按当前时间和调用方能力算出的状态；菜单按调用方能否运行 Python 当场算 |
| `session.grade(seq)` | 判一份作答并追加判分；同一份作答的并发调用合并为一次，判不了时只在内存里记下原因 |
| `session.autoGrade(capabilities)` | 在后台补判本次会话还没试过的作答，教学方法每次调用时触发；代码题要调用方声明 `python.run`，开放题要有可用模型 |
| `session.idle()` | 等待在途判分和后台补判结束；插件关闭前调用 |

### 事实

每一行是一条事实：`seq` 从 1 起连续，`at` 是写入时的服务端毫秒时间，同一次写入的事实共用一个时间。schema 在 `records-schema.ts` 的 `FactSchema`。任务、交付和提交的公开编号由对应事实的序号得出（`t<seq>`、`d<seq>`、`s<seq>`），不另存。

| type | 字段 | 为什么记 |
| --- | --- | --- |
| `task` | `kind`、`topics`、`course`，换题重考另有 `retakes`，课另有 `practice`、`minutes` | 学习者选了什么任务；测验的 topic 就是这场实际考了什么。`course` 是开始时加载的课程的 `id` 与 `version`（取自 `course.yaml`），课程中途改版以后，仍能知道之前的任务对照的是哪一版。课记下开始时各知识点的必做题和开放题，以及课的分钟数，课程后来加题、加知识点或改分钟数，这节课的结论和 XP 都不变 |
| `viewed` | `task`、`kp`、`page`（`lesson` 或 `example`） | 课内翻到哪个知识点的讲解或例题，也是作答前看过讲解的事实 |
| `delivered` | `task`、`question`、`seed` | 出了哪道题；`seed` 决定选项顺序和不透明编号，重开时按它重建同样的画面 |
| `answered` | `delivery`、`seen`、`answers`，说不会时 `dontKnow` | 作答换回课程里的选项编号；`seen` 是学习者看到的题面版本 |
| `graded` | `delivery`、`version`、`verdict`、`slots` | 当时的判分；`version` 是所依据的题目版本，`slots` 留下各作答位的结论、测试结果和模型理由 |
| `appealed` | `delivery`、`reason` | 学习者要求重判 |
| `ended` | `task` | 学习者主动结束任务：中止，或测验交卷 |
| `goal` | `xp` | 每日 XP 目标 |

一次练习作答通常写三条事实，例如：

```json
{"seq":12,"at":1792454400000,"type":"delivered","task":3,"question":"py01.k1.q1","seed":2854512713}
{"seq":13,"at":1792454405000,"type":"answered","delivery":12,"seen":"sha256:…","answers":{"s1":{"type":"text","text":"2"}}}
{"seq":14,"at":1792454405000,"type":"graded","delivery":12,"version":"sha256:…","verdict":"correct","slots":{"s1":{"verdict":"correct"}}}
```

以下内容不记：界面画面、学生模型、进度、XP 和菜单，它们都从事实算出；题目和课程快照，题目内容取自当前课程，按版本对照，任务只记下课程的标识与版本，课另记开始时的练习题编号和课的分钟数；判分的原始执行结果、规则版本、配置版本和作答前的模型状态，它们没有读取方；题目之外打开卡片或讲解，它不影响作答是否独立。

### 题目版本

题目版本（`questionVersion`）只由学习者看到的内容（题面、作答位和作答后的解析）与判分方式（答案、比较方式、测试和用到的数据）决定。按测试判的题，期望表达式和学习者的程序都在课程清单的运行前导 `runtime.prelude` 之后运行，所以这类题的题目版本还包括前导：例如测试的期望表达式用到前导里的一个答案常量，作者改正这个常量以后，题面不变而判分依据变了，过去的作答就按新的前导重判。其他题判分用不到前导，版本与它无关。知识点归属 `measures`、题型标签和只为检查而写的部分都不进版本：归属改了，题目版本不变，过去的作答照样对得上。

题面版本（`itemVersion`）只覆盖作答前的公开题面，也是公开 `Item.version`。只改答案或解析时它不变，所以进行中的题不必重新交付，过去的作答也能按新答案重判。

### 重放、重算与代价

`replay.ts` 按事实的先后重放。学生模型、课内继承进度、失败的课能否重试和强制补救是已结束任务依次叠加的结果；当前任务在旁边单独计算，结束后叠上去。当前的课也从这份叠加结果继承知识点进度，所以更早任务的重判改变了继承的进度时，当前的课的进度和结论随之改变，与学生模型和菜单一致。各情形的代价如下：

| 情形 | 做什么 | 代价 |
| --- | --- | --- |
| 打开空间 | 每条事实重放一次，再扫描一遍作答找出要补判的 | 随事实条数线性增长 |
| 追加一条事实 | 只更新当前任务；任务结束时叠加一步 | 与当前任务的作答数成正比 |
| 补判、改了对错的重判或申诉更早任务的作答 | 之后的叠加结果过期，下一次用到时从头叠加一遍已结束的任务；对错没变的重判什么也不改变，不过期 | 随任务数线性增长，每次过期重算一次 |
| 同上，而当前的课还可能因此通过、多得 XP | 当场重算一遍，按实际结论结算这节课 | 随任务数线性增长，每条这样的事实一次 |
| 累计 XP 到了测验门槛 | 扫描一遍作答，为这场测验选 topic | 随作答数线性增长，每场测验一次 |

`Replay.applied`、`Replay.recomputations` 和 `Replay.samplings` 记下重放的事实条数、整段重算的次数和选题扫描的次数，测试按它们核对。打开空间时，历史里每段“过期到下一次用到”之间重算一次。

XP 按任务的实际结论结算：是否通过看实际结论，奖励的多少只看这项任务自己的作答；奖励变高时补发差额，变低时不收回。结算发生在这几个时刻：任务自己的事实改变它的结论或作答时，任务结束时，以及更早任务的判分改变使当前的课因继承的进度而通过时。例如上一轮课 KP1 有一题待判就中止了，新一轮先答对 KP1 一题，旧作答这时补判为对，新一轮就继承到已完成的 KP1，这节课随后（只有一个知识点时就在此刻）通过并结算。课结束时记下它当时实际继承的进度，之后它自己的判分改变时按这份进度补发差额。结算都发生在事实的边界，用到的状态只取决于此前的事实，所以打开空间重放与当时现场得到同样的 XP。规则见[测验与进度说明](learning-quiz-xp.md)。

每次作答写入的字节数有上限，也不随历史增长。一道单作答位的题写三条事实，除作答本身和模型理由以外的固定部分，由各字段允许的最长取值决定：题目 id 与作答位 id 的长度上限、按测试判的作答位的测试数上限（判分事实为每个测试记一个结论），以及按最长写法计的序号和时间。`learning-facts.test.ts` 从课程格式与事实格式的 schema 读出这些上限，算出每次作答的字节上限，并断言最长的代码题每次作答正好达到它。作答本身和模型理由另计，它们各有长度上限。

### 写入与时间

写入先在内存里核对引用：判分必须针对已收下的作答，一次交付只收一份作答，申诉必须针对已判的作答，引用必须指向此前正确类型的事实。核对通过后追加 JSONL、同步文件和目录，再交给重放。任一步写入失败都使请求失败，并停止当前实例继续追加；重新打开后以实际日志为准。底座持有空间锁，学习记录只在该宿主生命周期内使用，不额外建立第二套锁。

时间取自底座的 `host.now()`，生产中是服务端时钟，事实的 `at` 也用它。测验从第一道题出现时开始计时，截止时间由开始时间加时限算出；截止时间过后读取状态，就按截止时刻结束测验，时间只会向前，所以读取时就地结算与重放结果一致。课和复习不限时。时钟回拨时，事实的 `at` 可能比前一条早；学生模型按最近一次更新的时刻算，不会因此停住，见[教学流程](learning-flow.md#任务菜单与重算)。到时自然发生的变化（截止、失败的课休息到时、复习到期）不写事实，公开的 `revision` 只随事实条数增加。

### 残缺尾部恢复

打开日志时只读取以换行结束的完整行。末尾存在无换行片段时，完整前缀仍可查询，但继续追加会报 `learning_log_blocked`。完整行的 JSON、schema、序号或引用损坏都会停止重放，恢复命令也不会越过坏行。

先关闭空间，再在仓库根目录运行：

```sh
npm exec --workspace=@repa/learning -- repa-course recover-log /absolute/space /absolute/recovered.jsonl
```

命令通过现有空间锁确认空间已关闭，核对完整前缀，再独占创建目标文件，按原始字节写出前缀并同步。原日志保持原样，目标文件已存在也会拒绝。核对新文件后，在空间保持关闭时，将原日志改名保留，再把新文件移到 `.repa/plugins/learning/records.jsonl`，即可正常打开；没判出结果的作答会自动补判。中部或完整行损坏需要维护者调查，不自动截断。

日志写坏或空间文件夹被误删时，也可以用[空间备份](../../packages/base/README.md#备份与恢复)恢复：备份只收到最后一个换行符，从备份恢复以后学习插件照常打开，可以接着作答。

### 导出学习数据

维护者校准学生模型，要用真实学习者的作答。学习者同意时，界面先调用 `export.prepare` 预览，再调用 `export.create` 生成一个 zip，由学习者自行发送；输入与结果见[前端契约](learning-protocol.md#状态与方法)。zip 只收以下内容，空间中的其他文件一律不收：

| 包内文件 | 内容 |
| --- | --- |
| `records.jsonl` | 学习记录，截取到预览开始时的最后一个完整行 |
| `learning.json` | 插件的代码版本 `pluginVersion`、学习记录的格式版本 `recordsFormat`、导出时加载的课程的标识与版本 `course`；每项任务开始时的课程版本在它的 `task` 事实里 |
| `sessions/*.jsonl` | 学习者选择包含会话时才收入：空间 `.repa/sessions/` 中的全部会话记录，即辅导对话、判分等模型调用，以及通用 Agent 开着时与它的对话 |
| `manifest.json` | 底座写的清单：生成时间、Repa 版本、插件 id、是否收入会话，以及各文件的字节数、记录条数与替换处数 |

会话可能含有私人内容，所以默认不收入；界面在导出前说明这一点，并列出 `export.prepare` 返回的清单，即每个文件的字节数、记录条数和替换掉的凭据与密钥处数。全部内容按反馈包的规则替换凭据与密钥，学习者写进作答的密钥也一样。读取、脱敏与写出由底座的 [`host.prepareExport`](../../packages/base/README.md#导出插件数据) 完成，插件只列出白名单。

预览时，插件把已脱敏的 zip 冻结在内存中，`export.create` 写出的就是这一份，所以清单与 zip 一致，预览以后新增的记录不进入这次导出。插件只保留最近一次预览：写出成功、再次预览或关闭空间以后，旧的 `exportId` 以 `export_expired` 拒绝，需要重新预览；存放目录无效等写出失败时，这份预览仍然有效。zip 默认放在应用配置目录的 `exports/`，桌面端可以把 `directory` 指定为“下载”文件夹。

### 课程来源与模型

一个空间学一门课。插件打开时按顺序决定：换用过空间里的课，就学换用的那一份；空间里有 `course/` 文件夹而还没有换用过，就没有可学的课（`state.get` 的 `course` 为 `null`）；都没有时学 `sources` 给出的课程，缺省是随包的 Python 课。

空间里的课由通用 Agent 写在 `course/`（格式与随包课程相同），经 `course_check` 检查、`course_use` 换用，写法见[写课说明](../../packages/learning/guides/making-courses.md)。插件从不直接读 `course/` 来教学：`course_use` 经 `host.files` 读出 `course.yaml` 与 `topics/*.yaml`，复制进数据目录的临时文件夹，在这份固定的内容上做完整检查（`manual` 作答位的模型核对只报告，不要求记录，因为应用里没有 `course:confirm`）；通过后存成 `courses/<摘要>/`，在 `course.json` 里记为 `pending`。学习者没有做到一半的任务时，插件在没有方法调用进行的时刻换用：按这份副本新建学习会话，从头重放全部学习记录，把 `pending` 改记为 `active`，删掉不再用的副本，再发出 `learning.changed`；有进行中的任务时，等任务结束以后，在某次方法调用结束时再换（结束这项任务的那次调用也算）。所以学习者看到的始终是一份通过了检查的课，写到一半的 `course/` 读不到，重开空间仍学换用后的那一份。换用对学习记录的处理与重开空间时课程改了相同：题目 id 是身份，改答案会重判，课开始时记下的练习清单不变，见[题目版本](#题目版本)。

副本被改坏、读不出来时，插件和空间照常打开，只是没有可学的课；内容相同的一版再次 `course_use` 会换上新复制的副本。`course.json` 先写临时文件再改名，中途断电时要么是旧状态，要么是新状态。

`loadCourseSources` 接收有序来源列表：先列唯一的 `{ kind: "bundled", directory }`，再列 `{ kind: "overlay", file }`。覆盖文件通过 `host.files` 读取，使用 JSON 形状 `{ courseId, basedOn, topic }`；`basedOn` 必须等于上游课程版本，`topic` 按当前 schema 完整替换同 id topic。来源重复、未知 topic 或版本不符都会报错，读取随包课程不会修改其文件。

插件通过 `student-model.ts` 的 `updateStudent` 和 `chooseTasks` 接入 `@repa/learning-model`。图里有课程的先修关系和各 topic 的 `encompassings`（只取正权重），通过与失败沿它按权重隐式传播（FIRe）。时间按 Unix 毫秒除以 `DAY_MS` 转为连续天数；当前时间早于已有的更新锚点（时钟回拨）时，按最近一次更新的时刻算，相当于零间隔，不报错。参数取 `parameters.ts` 的 `STUDENT_MODEL`；`new Replay(course, model)` 按另一组参数重放同一份事实，可以比较两组参数的预测。`memory` 是调度量，不是答对概率。

- 题目从课程删除以后，它的作答不再作为证据，界面显示题目已移除；已经通过的课因此可能不再通过。课开始时记下的练习里，已不在原知识点练习题池的题从中去掉，必做题都不在了就按当前课程。没有 `practice`、`minutes` 的课（加这两项之前的记录）按当前课程计算。
- 辅导和内容读取只提供当前课程里的内容，课程换版以后旧版本的引用按不存在处理。
- 一个空间一门课是测试版的阶段性做法。空间里先学了随包的课、后来出现 `course/` 时，换用以后之前的记录仍在，但它们的 topic 不在新课里，不再显示进度；几门课怎样共用学习状态由知识库提案回答。
- 导出只收学习记录，不收空间里换用过的课程副本；维护者要对照自制课分析记录时，还需要学习者另外提供 `course/`。
- 磁盘满、同步失败等专项注入按共同约定留待实际存储风险出现时补充。

## 验证入口

在仓库根目录运行：

```sh
npm run check --workspace=@repa/learning
(cd packages/learning && node --import tsx --test test/learning-records.test.ts test/learning-facts.test.ts test/replay-properties.test.ts test/backup-export.test.ts)
```

[`learning-records.test.ts`](../../packages/learning/test/learning-records.test.ts) 用三个子进程分别在作答写入后、模型返回而判分未写入时、判分写入后 SIGKILL，再重开核对作答保留、任务不阻塞、补判只调用一次模型；另覆盖同载荷并发提交、写入失败、引用错误、残缺尾部的恢复命令、可忽略的新增字段和经真实宿主重开。[`learning-facts.test.ts`](../../packages/learning/test/learning-facts.test.ts) 覆盖答案或运行前导改正后的重判、判分中断的作答补判以后课按作答先后重新判定（第三题补判为错即失败，XP 不收回）、更早一轮课的重判反映到正在进行的重试、更早一轮课的补判使正在进行的课通过时照常结算 XP、没有证据时不阻塞、中止复习时已有失败证据记为失败、复习判满题数而待判作答判对还能通过时结论待定、每项任务记下开始时的课程版本、只搬事实文件后重算出相同状态、换一组学生模型参数重放得出不同的预测、归属改变不换版本，以及每次作答的字节上限（含最长的代码题）和重算次数（对错没变的重判不重算）。[`replay-properties.test.ts`](../../packages/learning/test/replay-properties.test.ts) 经真实插件方法随机走学习流程（选任务、作答、判分失败、补判、申诉、改答案、等待、重开），每一步核对：现场状态与从事实重放的结果相同；增量叠加与从头叠加的结果相同，当前的课与学生模型用同一份继承进度；每项任务的 XP 等于它到此刻的最高奖励；课和测验的结论不因待判作答的判分而改变，结论待定时待判作答判对和判错的结论确实不同；菜单为空时一定给出最早恢复时间，除非课都学完了，或测验到了门槛却凑不出题。它同时断言序列确实走到了测验、换题重考、结论待定、强制补救，以及补救没通过而在休息、菜单报告恢复时间的情形。合并门禁用固定的种子，只挡常见形状的错误；[`property-exploration.yml`](../../.github/workflows/property-exploration.yml) 每晚换一个种子跑 1000 个序列，失败只报告，不挡合并。本机设置 `REPA_PROPERTY_RUNS`、`REPA_PROPERTY_SEED` 可以换种子多跑。[`backup-export.test.ts`](../../packages/learning/test/backup-export.test.ts) 经真实后端和学习插件核对：导出的 zip 只含白名单中的文件，没有选择包含会话时没有会话记录；作答里写有已保存的密钥时导出内容中的密钥已被替换；清单与 zip 一致，预览以后新增的记录和日志末尾的半行都不进入导出；导出只读取学习记录，选择包含会话时再读会话记录，每个文件只读一次；学习进行中备份，日志末尾有半行，接着学，恢复到原位置以后学习插件照常打开、可以继续作答。
