# 文档规则

文档放置、结构和检查由本文件持有；行文方法见[文档规范 Skill](../.agents/skills/repa-docs-style/SKILL.md)，设立这些规则的理由见[文档纪律提案](../.agents/notes/proposed/process/2026-10-29-docs-discipline.md)。

## 放在哪里

| 内容 | 位置 |
| --- | --- |
| 为什么这样做、放弃了什么 | [设计记录](../.agents/notes/README.md) |
| 包的用法和约定 | 包的 README |
| 当前怎样接入 | `docs/development/` |
| 要做的事 | GitHub Issue |
| 代码目录 | `packages/README.md` 与 `docs/generated/`，脚本生成，不要手改 |
| 常设规则 | 对应层级的 AGENTS.md，每条一到三行，链接到讲理由的地方 |

- 一件事只有一个家，别处链过去；不要抄写同一份状态或约定。
- 只写现状，历史留在提交、PR 和设计记录里；README 不记升级过程、测试数量和运行结果。
- 行为变了，同一个提交里更新受影响的 README 和接口注释。

## 包 README 骨架

包 README 以一个一级标题开头，H2 按下面的顺序组织；检查只覆盖 `packages/*/README.md`。

```markdown
# 包名称

## 概述

## 怎么用

## 对模型的影响

## 已知限制与暂缓
```

- “概述”是第一个 H2，正文不超过 120 个非空白字符，说明包做什么。
- “怎么用”在“对模型的影响”之前；两者之间可以按需要增加“怎么实现”、接口或格式等 H2。
- “对模型的影响”和“已知限制与暂缓”是最后两个 H2，保持这个顺序。
- “对模型的影响”说明模型看到什么、大概多少 token、对提示缓存有什么影响；不往模型面前放东西的包，用一句以“无：”开头的话说明为什么。
- “已知限制与暂缓”至少有一个列表项，或用“目前没有：……”说明为什么没有。

## 检查与例外

根目录运行 `npm run docs:check`；`npm test` 会先运行文档检查及其自身测试，再运行各包测试。检查入口是 `scripts/docs/check.ts`，每个问题输出一行“文件:行号 检查名 说明”，有问题时退出码非零。

| 检查名 | 检查内容 |
| --- | --- |
| 链接 | 相对链接和图片目标存在；锚点是目标标题的 GitHub slug 或 HTML 的 `<a id="...">`；不查外部链接 |
| 路径 | 行内代码以 `packages/`、`apps/`、`docs/`、`.agents/`、`scripts/` 开头的路径存在；去掉末尾行号和锚点，含 `*`、`<`、`{` 的跳过；设计记录不查此项 |
| 不写提交哈希 | 行内代码不使用同时含字母和数字的 7 至 40 位小写十六进制哈希；引用历史用 PR、tag 或文字说明 |
| 一段一行 | 段落不跨行，包括列表项和引用块中的段落；表格、代码块和 HTML 不查 |
| 篇幅上限 | 各层 AGENTS.md 按非空白字符计数，上限和理由写在 `scripts/docs/budgets.json` |
| 停用词 | 按 `scripts/docs/banned-terms.json` 的词、替换词和理由检查，不区分大小写；初始清单为空 |
| 包 README 骨架 | 检查上面的章节顺序、概述长度、模型影响和限制说明 |
| 代码线索 | 目录逐字节核对；原导出须有说明，转导出语句不查；schema 变化须记录版本判断 |
| 设计记录格式 | 按[设计记录格式](../.agents/notes/README.md#格式)检查路径、首行标题、状态和小节，不允许索引文件 |

- 检查范围为 git 跟踪的 Markdown；`scripts/docs/config.json` 记录带理由的排除项，冻结证据、旧 ADR、第三方材料和检查夹具按该清单排除，Repa 自有 Skill 仍检查。
- 路径检查还覆盖 `packages/*/src/**/*.ts` 和 `apps/*/src/**/*.ts` 注释中的 `docs/<名称>.md`、`.agents/<名称>.md`；停用词检查还覆盖这些 src 目录里的 `.ts` 和 `.svelte` 文件。
- 篇幅超限时，先把内容挪到它该在的地方，再压缩，最后才提上限并写明理由；规则的背景和取舍放进设计记录。
- 例外只写在 `scripts/docs/exceptions.json`，结构为 `{ "<检查名>": { "<文件路径>": "<理由>" } }`；只豁免该文件的该项检查，理由不能为空；导出说明注释可按 src 目录豁免。
- 文件已经通过被豁免的检查时，会报“例外已过时，请删掉这条”；文件删除或检查名失效的条目同样要删掉。

## 持久格式与版本

`scripts/docs/persistence.json` 声明持久格式。schema 摘要变了，先在 `docs/persistence/changes/` 记录版本判断及理由，再运行 `npm run docs:gen` 更新认可摘要；首次建立基线。摘要提醒审阅：旧版本会读错才升版本，迁移与标记由所属包负责。
