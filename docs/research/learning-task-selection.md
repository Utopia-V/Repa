# 学习任务选择：怎样利用作答与学习目标

安排下一项学习活动时，我们既要看刚才的作答，也要记得还有哪些内容值得推进。本文从一道简单的题目出发，尝试把这两部分判断接起来，再讨论怎样复用现有的复习算法和时间检查。

这是 2026-10-05 的研究记录，接续 [#38](https://github.com/Utopia-V/repa/issues/38)。学习组织的已接受前提见[全局粗览与局部细化](learning-organization.md)，下面的具体做法仍在试探中。

## 从一道题开始

先看这道题：“一个矩形的周长为 14，面积为 12，求两条边长，并写出推导。”假设学习者独立写出下面这份答案：

> 设一条边为 x，另一条就是 7-x。面积给出 x(7-x)=12，化简为 x²-7x+12=0，也就是 (x-3)(x-4)=0，所以两条边是 3 和 4。

这份答案保留了从题目条件到方程、再从方程到边长的过程，所以我们可以分别查看列式和求解是否成功。在这个例子中，两部分都已经做对；安排下一步时，就可以结合其他学习需要，决定是否还要继续练同一部分。

不过，如果老师在作答前已经给出 `x(7-x)=12`，判断就会有所不同。学生最后写下的答案虽然可以完全相同，但独立列式这一步已经得到了帮助，后面的代数求解却仍然是可观察的表现。因此，下一项活动可以保留一次独立列式的机会，看看没有方程提示时，他能否自己完成这一步。

再回到无帮助的情形。如果前面的推导都正确，最后却把边长写成“3 和 5”，问题就出现在结论与推导的连接处。我们可以先让学习者把这两个数代回周长和面积，再根据他的回答判断怎样处理。这样既能检查错误，也保留了前面已经做对的部分。

这三种情形给后续安排提供了不同依据，而区别来自帮助条件和具体步骤。因此，需要保存的不只是最后的答案，还包括这次怎样作答、哪些判断由此得到。后面再选择活动时，才能接着这些依据往下推进。

## 第一轮模型试探

接下来，我们把上面的三种情形分别交给模型，观察它会怎样保存判断、选择下一项活动。为了让选择有所依据，每次都提供相同的学习背景：

- 五天后有闭卷考试，要求独立列出并解二次方程，也要求读懂二次函数图像。
- 还有一个长期目标：用简单数学模型解释实际问题，对计算速度没有要求。
- 全局粗览中有代数运算、文字建模和函数图像三个范围。目前代数题展开较多，已有三次独立因式分解成功记录，函数图像还没有实际作答。
- 当天剩余 12 分钟。

三个隔离的子 Agent 使用相同的 `gpt-6.1-sol` 模型、`high` 推理档位和任务说明，每个只取得一个案例。A 与 B 的学生文字完全相同，只改变前置帮助；A 与 C 的帮助条件相同，只改变最后写出的边长。调用前已经确定要观察哪些判断和活动会随之变化，模型得到的输入中没有期望答案。

| 案例 | 改变的条件 | 模型保留的判断 | 提出的下一项活动 |
| --- | --- | --- | --- |
| A | 无帮助，完整正确 | 本题的建模、求解与边长解释均有独立作答依据 | 用对应二次函数图像检查交点、对称轴、最低点及方程与图像的联系 |
| B | 老师先给出面积方程，学生随后写出与 A 相同的答案 | 保留代数步骤和本题结果解释，独立列式仍需观察 | 换一组数值，让学习者自行列式，并把周长约束下的面积关系画成图像 |
| C | 无帮助，只有最后的边长写成“3 和 5” | 保留前面正确的列式与分解，定位结论和推导的矛盾 | 用面积函数与水平线的交点复核边长，再用原题条件检查结果 |

三个建议都使用了背景中尚未观察的函数图像，但安排这项活动时要解决的问题不同。A 已经有独立列式和求解的依据，因此直接转向读图；B 还要检查独立列式，所以把列式和画图放进同一道新题；C 则试图借图像复核原来的边长。由此得到的活动既接着当前作答，也包含了整体范围中另一项需要观察的内容。

这些建议还需要结合它们各自要解决的问题调整。C 要先弄清结论为什么不对，直接代回周长和面积会比先引入图像更简单。因此，可以先完成这个短检查，再根据回答决定是否讲解，把剩余时间用于读图。B 的新题只是同型换数，能够继续观察是否会独立列式；如果以后要判断不同情境中的建模表现，还需要换一种数量关系。

这一轮使用的是构造材料，取得了上述三份判断和活动建议。这些活动的教学效果、实际需要的时间，以及后续回答怎样影响路线，还要放进连续的学习过程中观察。

## 当前采用的工作假设

前面的案例首先需要保留下来的，是对实际表现的判断。例如，A 的列式和求解都来自独立作答，B 的列式已有提示，而 C 的错误出现在最后的结论。这些判断可以连同题目、作答和帮助条件写入已有学习文档与语境，后续再根据新的回答修订。

选择下一项活动时，再把这些判断放回整体学习范围中考虑。因式分解已经反复做对，就可以转向尚未观察的图像；独立列式还没有依据，就可以在新题中留出这一环节。活动的形式因此可以随问题变化，采用讲解、讨论、练习或应用，而不是先固定一套教学步骤。

活动选出来以后，接着要考虑它怎样进入实际安排。一项活动可能同时服务多个目标，也可能与已有复习项有关，所以我们需要先理清这些关系，再交给相应的计算能力。下面先讨论多个目标共用活动时怎样计算时间，再讨论哪些作答适合使用 FSRS。

### 一项活动怎样服务多个目标

前面的列式与读图活动既可能帮助准备考试，也可能帮助理解数学模型。如果同一次活动已经能够提供两项目标需要的观察，就可以把它同时关联到这两项目标，实际占用的时间仍只计算一次。

能否共用，要看目标要求的条件是否相符。例如，另一项目标要求限时独立求解，而原活动允许提示、也没有计时，就还需要另一次符合条件的练习。虽然题目都涉及二次方程，但前一次表现没有提供限时独立完成的依据。

因此，原型分别保存目标要求和实际活动。目标说明希望达到什么、有什么期限；活动说明准备做什么、预计花多少时间，以及服务哪些目标。确认可以共用的活动，按其中较早的期限检查；确有不同要求的工作，则分别保留。活动完成以后，再根据实际表现更新各项目标相关的判断。

有了这份不重复的活动安排，就可以调用现有的 [planning 接口](../../packages/planning/src/schema.ts) 检查时间。由于每段 session 只有一个 `goalId`，原型把每项实际活动作为一份工作量传入，并用活动 ID 关联时间段；学习目标及其关系仍保存在研究材料中。这样，检查器计算的是实际安排的工作，不会因为它服务多个学习目标而重复计时。

返回结果也需要按这个对应关系解释。`goal_unallocated` 表示某项活动还有多少时间没有排进去；这些时间是否够用可以继续调整，而是否达到学习目标，还要根据实际作答判断。

### 什么时候使用 FSRS

时间检查回答的是已经选出的活动能否排进去。至于一个具体回忆项什么时候值得再看，则可以使用已有的[复习能力](../development/review.md)。它保存实际反馈和追加更正，再由 FSRS 计算后续安排，也允许人工调整时间。

要使用这份计算，需要先确定本次反馈对应哪个回忆项。综合解题可能涉及多个知识点，但各个步骤实际得到的练习和帮助并不相同。因此，模型应当根据题面、作答和帮助条件解释表现，再给合适的回忆项形成评分，而不是把同一个 rating 填给所有关联项。

保存评分以后，我们可以取得下一次到期时间。如果还想结合考试日期作判断，例如询问“到了考试那天，这个回忆项预计还能记住多少”，锁定的 `ts-fsrs 5.4.2` 也已经提供 `get_retrievability`，能够根据同一张卡的状态查询不同日期的可回忆程度。这个结果可以参与复习安排；建模、迁移和限时完成等要求，则仍使用相应的作答依据判断。

日期查询目前还没有公开为 Repa 能力，所以本轮先在工作层使用锁定库核对接口。后续如果任务选择需要反复使用它，再决定是否加入 `review` 的公开入口。

## 计算接入原型

为检查上面的工作量表示能否直接接用，我们在 `dev 477f2afbe` 基础上的当前构建中启动 Repa，通过 `capability.invoke` 调用了 `repa.planning.check`。这一步先固定活动与目标的关系，以及预计花费的时间，检查传入方式和计算结果。

给定两项目标、18 分钟可用时间，以及一项可共同使用的 12 分钟活动，结果如下：

| 输入变化 | 时间检查结果 |
| --- | --- |
| 为两项目标分别复制同一活动 | 计算为 24 分钟，报告 6 分钟容量不足和活动重叠 |
| 按实际活动计算一次，另外保存目标关系 | 计算为 12 分钟，通过检查 |
| 保持活动与可用时间不变，只把近期目标期限提前到活动开始后 8 分钟 | 总工作量仍为 12 分钟，报告期限前缺少 4 分钟 |
| 在共享活动之外增加一项 4 分钟独立限时观察 | 计算为 16 分钟，通过检查 |

在这组输入下，把工作量按实际活动传入以后，现有检查器就能处理时长、冲突和期限。因此，时间计算可以直接复用；后续要继续试探的是这些输入怎样形成，也就是模型怎样提出活动、估计投入，并判断哪些工作可以共同使用。

FSRS 的接入也作了类似检查：固定一份合成回忆历史和参数，只改变查询日期，取得了两个日期各自的预估值。原型保存了参数、历史和返回值，后续可以沿用这份计算来尝试任务选择。

## 下一步

本轮分别观察了单次作答判断和计算接口，下一轮需要让它们接续处理后续反馈。具体做法是取得新的作答，把观察和当前安排保存到学习文档，再根据接下来的回答修订。期间另开一个会话，读取这些文档，检查保存下来的依据是否足够支持下一次选择。

这段连续过程主要观察两件事：已经有明确依据的局部是否还被反复重查，新反馈是否真的改变了后续路线。先根据少量连续案例调整做法，再判断其中哪些重复工作适合成为能力接口；现阶段仍使用已有文档、语境和计算能力。
