## 从能够持续提供帮助的方法开始

Repa 已经能够读取教材、生成解释和练习、运行程序，并把材料与学习记录保留在空间里。有了这些能力，Agent 就可以先近似承担 Math Academy 的各项学习操作：形成路线、开展局部教学、解释实际作答，再选择新内容或复习。这个起点能够直接服务学习，也提供了改进调度所需的真实活动。

因此，当前先把这些操作组织成可接续的方法。整体路线保留目标、主要范围和关键关系；进入某一部分以后，Agent 再结合教材与已有产物展开教学。遇到需要比较的新情况，可以换例子、画图或制作实验。能够帮助后续学习的产物会保存下来，之后既可继续使用，也可根据新问题修改。

这套方法中的长期状态首先服务于下一次判断。例如，上次为什么停在这里、学习者能独立完成哪一步、哪种提示曾经有效，以及下次需要观察什么，都会影响接下来的帮助。保存这些信息以后，新会话可以从当前重点进入，而不必从头询问目标或重新生成路线。

## 方法、材料和学习记录怎样配合

教学方法说明怎样根据情境选择帮助；具体活动提供问题、来源和参考依据；学习记录保留实际发生的尝试。三者可以共同参与一次教学，却有不同的修改原因。改变解释方法时，原始作答仍然保留；修正一道题时，也需要知道过去的回答针对哪个版本。

现有内容身份、会话历史与局部编辑已经能够承载这些关系。当前官方方法使用普通文档维护路线和安排，把原始材料、实际尝试和可再用的产物关联起来。学习语境展开近期重点，其余内容留下读取入口。由于正文属于同一个空间，用户可以直接修订，Agent 也能够沿当前版本接续。

资料研究支持把具体材料单独维护。[LearnLM 2024 报告](https://arxiv.org/html/2412.16429v1)为场景分别提供教学指令和学习材料，并围绕多轮对话评价教学表现。[Kestin 等的物理教学研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC12179260/)还为题目提供教师题解，并显式指明当前题目部分。对 Repa 而言，可以先在具体活动中保留这些有用结构，而让不同活动采用适合自己的组织方式。

学习记录还需要说明当时得到的帮助。[Bastani 等的研究](https://doi.org/10.1073/pnas.2422633122)分别观察有辅助和无辅助的表现，这也影响我们怎样使用一次作答：独立解出、提示后完成和看解后复述，支持的后续判断不同。官方方法据此保留帮助条件，再用后来的独立尝试修订认识。

## 当前怎样选择新学习与复习

候选活动来自当前路线、未完成的工作和已有记录暴露的困难。Agent 先考虑关键先修和材料是否足够，再结合目标期限、当前差距与可用时间作选择。若当前困难只是一个局部操作，就在当前任务中处理；若缺少的基础会持续阻碍后续内容，就先补这部分。

复习也进入这次选择。上次依靠提示完成的关键步骤，可以换一种情境再独立尝试；已经有较可靠表现的内容，可以继续新学，并为之后的保持或迁移留出观察窗口。每次安排保存所服务的目标、选择理由和下次希望看到的表现。于是，下一次调整面对的是一项有依据的工作，而不是一个孤立的到期日期。

多个目标共享时间，也可能共享知识。一次活动可以同时推进不同目标，但是否已经达到要求，仍需分别看各个目标。例如，为考试快速识别题型与能够解释原理，就可能需要不同的后续活动。时间计算按实际工作处理，具体日期、可用时段和容量检查复用规划能力。

这是一套 Agent 主导的近似方法。它直接使用已有知识和实际材料形成判断，先让学习能够连续开展。调度算法的作用由具体缺口决定：当反复比较同类活动或维护大量复习项成为主要成本时，再把相应判断转成稳定计算。

### FSRS 的接入位置

现有复习插件使用 `ts-fsrs 5.4.2`，根据单个项目的评分、时间和记忆状态计算间隔。项目可以表达不同学习内容；接入时需要确定，每次反馈是否在观察足够一致的对象和完成条件。算法实现与当前接口见[复习能力](../development/review.md)，模型定义见 [FSRS 算法说明](https://github.com/open-spaced-repetition/awesome-fsrs/wiki/The-Algorithm)。

因此，官方方法把 FSRS 用作适用项目的时间估计，再结合先修困难、目标期限和其他活动安排使用。综合任务中的一次成功，需要先解释实际练习了哪些部分；仅凭内容之间存在先修关系，无法确定这次各部分的反馈。[Math Academy 的公开说明](https://www.mathacademy.com/how-our-ai-works)也区分先修关系与实际练习覆盖，其组织方式见[本地摘要](math-academy.md)。

## 首轮试用及修订

2026-10-05，采用 Rust 官方书稿 `1500248d8f230566e4ec9f27fcbb8fe9e2898ab1` 的所有权与借用材料，运行了已有方法、首版持续学习方法及修订版三个条件。每个条件使用相同的四条学习者输入：从 Rust 小工具目标开始，给出带误解的代码与解释，再在新会话加入统计考试，最后报告新的代码对照结果。

真实 Astra 子 Agent 通过本地桥接读取 Pi 的实际输入，自行选择回复和工具调用；内容保存、编译运行、规划与语境由 Repa 执行。切换会话时换用全新子 Agent，所有子 Agent 使用 low effort。首轮观察方法采用与持久结果，实际学习收益由后续真实学习者的表现观察。

已有方法和首版候选都能完成两目标的跨会话接续。候选额外分开保存了活动和参考题解，但两组也共同暴露两项问题：只有分钟预算时，模型补出了 21:30 的占位日程；当前语境保存旧判断后不断追加更正，逐渐变成需要重新解释的记录。

因此，修订版明确按分钟比较预算，已有实际时段时再调用日历检查；同时把当前有效判断与原始尝试分开维护。相同场景的复测中，模型直接使用分钟预算，第二会话后的语境也变成当前目标、有效判断与后续入口。过去的代码、尝试和判断变化保留在活动记录中。

复测还发现，新增目标有时要等学习者说结束后才保存。随后从同一第一会话快照出发，保持工具定义、方法文件和新会话首条输入相同，仅增加本轮保存重要变化的要求。这个条件在首次回答前就完成了目标、安排与语境更新。由此，保存时机也进入默认学习行为的责任，而不是要求用户另行索要总结。

七个独立模型上下文的输入、回复、空间内容和核对结果保留在研究工作层。后端接入和确定性计算已有相应集成回归；模型行为的接续观察继续由 [#43](https://github.com/Utopia-V/repa/issues/43) 持有。

### 接入既有复习项后的选择

后续试用沿用同一空间的路线和实际记录，加入四个复习项，其中一个已经保存此前的 Rust 作答，另有一个邮件分类题的参考答案混淆了条件方向。新的 Astra 上下文自行读取项目与必要历史，按临近的统计考试选择当前活动，而不是要求先清空到期列表。

这轮先暴露了内容维护缺口：原接口只能创建项目，无法修改既有题目、答案或来源。[#44](https://github.com/Utopia-V/repa/issues/44) 因此补入窄更新入口，保留同一项目的身份、反馈与算法状态。模型随后通过这个入口修正参考答案，等学习者给出实际回答后才登记新反馈。重新打开服务核对时，旧 Rust 反馈仍为一条，邮件题新增一条，其余未作答项目保持零条。

这里材料维护、学习活动与反馈登记各自承担清楚的责任。现有模型已经能够利用这些操作完成该场景，当前继续从具体活动判断复习如何与新学习结合，而不是先增加一套统一的任务选择接口。

### 用编程应用更新已有复习项

接下来将同一空间用于一个真实的小程序任务：已有函数统计文本中的关键词，当前要继续接入文件读取。两组拿到相同的代码、材料、路线和复习数据，也同样有 20 分钟推进 Rust；区别是学习者说明自己完成的部分不同。一组独立写出借用参数、调用和后续修改，并解释为何无需复制；另一组拿到这些代码后只换了关键词，运行成功，但仍不理解参数类型。

首轮两个全新模型上下文都据此选择了不同的帮助，并继续推进文件读取。然而，两组都只更新了文档，已有复习项仍停留在上次反馈。因此，问题落在教学方法的状态维护责任：新表现已经进入学习记录，却没有进入已经采用的复习安排。

随后只修改 `learn-with-feedback` 的接续段，要求把实际独立完成、且符合已有项目观察要求的表现登记到相应复习项。复测分别从原共同起点开始，保留各组输入、材料、工具和算法，再各用一个全新 Astra/low 上下文运行。重新打开服务核对，独立完成组的借用项增加一次“良好”反馈，原有一条变为两条；给定代码组保留原来的一条。其余三个项目的反馈数量都保持原值。两组仍继续提供文件读取帮助。

这个结果给当前方法一个具体的组织方式：先围绕目标开展有用的活动，再把活动中实际练到的内容接回已有复习项。一次应用可以同时推进新学习和巩固旧知识，不必在开始前将它归为其中一种。这里采用现有项目、实际记录和 FSRS 接口，变化集中在已有状态怎样得到维护。

## 接下来通过实际使用解决什么

上述试用已经覆盖方法采用、教学产出和跨会话接续。下一步需要继续看实际活动怎样改变后续安排：何时一次应用已经练到有关基础，何时又需要单独巩固，以及多个目标共同占用时间时怎样取舍。真实学习者的延后独立作答与迁移表现作为后续学习效果观察。

持久内容也暴露了一个更具体的问题。后一次 Rust 活动已经更新，但语境中介绍统计目标的旧段落仍可能保留“本轮 Rust 未做”这样的相对说法。把同一项当前状态复制到多个段落后，一次局部更新就容易留下不同步的副本。后续应当结合现有内容引用和语境组成检查状态的归属，让当前安排有清楚的读取位置，历史过程留在记录中。

后续对照从这些实际分歧出发，固定起点与输入，再调整相关方法或内容组织。研究记录保留完整请求、工具结果、产物和空间变化，以便分清改动是否解决了原问题。

早期条件规划与算术作答原型保留在开发工作层。它们的活动成本和行为变化由案例给定，所得结果用于理解程序在这些条件下怎样选择，不再作为当前教学与调度方案的主要依据。其中形成的程序化能力调用入口具有独立用途，见[命令执行说明](../development/execution.md#程序化能力调用)；工作表示与方法改造由 [#39](https://github.com/Utopia-V/repa/issues/39)、[#40](https://github.com/Utopia-V/repa/issues/40) 接续。
