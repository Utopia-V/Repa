# 学习内容与作答证据

2026-10-10。学生状态需要依据实际作答更新，但参考题解也可能出错。同一份回答后来得到不同判断时，系统应当保留原题、当时使用的帮助和原回答，再说明判断为什么改变。本次从一组具体函数题出发，核对内容、判分与记录的区别，并用现有 Repa 入口走通一次合成接入验证。

## 具体步骤比技能标签多说明了什么

本次内容固定在 [OATutor-Content `1925decc`](https://github.com/CAHLR/OATutor-Content/tree/1925decc91567faf6203bdb41b9d52b14891426f)。题族 `a005bd5real2` 给定 `f(x)=x²+2x`、`g(x)=6−x²`，分别询问函数的和、差与乘积。题库注明 OpenStax 来源，仓库将内容按 CC BY 4.0 发布；这里保持原内容，不把本地纠正写回原件。

与只有技能标签的数据不同，这组内容能让我们看见提示实际上要求做什么。加法题的 pathway 包含定义、代入和合并同类项三个可回答的 scaffold；乘积题则只有定义、代入两项可回答 scaffold，后面的展开和化简是提示文本。因而，“有四个提示”与“完成了四个独立步骤”不是一回事。[加法 pathway](https://github.com/CAHLR/OATutor-Content/blob/1925decc91567faf6203bdb41b9d52b14891426f/content-pool/a005bd5real2/steps/a005bd5real2a/tutoring/a005bd5real2aDefaultPathway.json)、[乘积 pathway](https://github.com/CAHLR/OATutor-Content/blob/1925decc91567faf6203bdb41b9d52b14891426f/content-pool/a005bd5real2/steps/a005bd5real2c/tutoring/a005bd5real2cDefaultPathway.json)。

具体内容也暴露了参考依据的问题。[减法 pathway](https://github.com/CAHLR/OATutor-Content/blob/1925decc91567faf6203bdb41b9d52b14891426f/content-pool/a005bd5real2/steps/a005bd5real2b/tutoring/a005bd5real2bDefaultPathway.json)中，定义步骤的提问仍写着加法；代入参考式写成 `x²+2x−6−x²`，但减去整个 `g(x)` 应为 `x²+2x−(6−x²)`。另外，两个不同 scaffold 共用了同一个 `h3` ID。只保存这个 ID，既不能唯一定位原提示，也不能保证引用的是正确参考。

这给出了两个直接要求：内容引用要固定版本，并能区分该版本中的具体对象；原始回答则应与后续评分分开。一个错误参考式导致的拒绝，不应被永久压成学习者“不具备某技能”的事实。

## 判分结果还需要结合呈现方式解释

代码核对固定在 [OATutor `939eb0e3`](https://github.com/CAHLR/OATutor/tree/939eb0e30d8ae2389c8b096c8cd522713a79090e)。它的默认内容子模块不是上述内容提交，因此以下是固定代码对指定小样的路径核对，不是某次部署或历史实验的复现。

该版本的算术判分调用 KAS 做表达式等价比较，默认不要求相同形式或完成化简。离线调用实际函数时，加法题的代入 scaffold、合并 scaffold 和主问题都接受 `2x+6`、`6+2x`，也接受未化简的 `x²+2x+6−x²`；`2x+7` 则被拒绝。因此，某一步被判正确，尚不能证明学习者执行了该步骤标题描述的推导。[判分入口](https://github.com/CAHLR/OATutor/blob/939eb0e30d8ae2389c8b096c8cd522713a79090e/src/platform-logic/checkAnswer.js#L143-L171)、[KAS 比较选项](https://github.com/CAHLR/OATutor/blob/939eb0e30d8ae2389c8b096c8cd522713a79090e/src/kas.js#L5058-L5076)。

标准提示面板还会为 scaffold 添加显示参考答案的子提示，学习者可以主动打开它；`dependencies` 在这里控制 pathway 内的解锁顺序，不是知识先修或练习覆盖图。另一个 Avatar 分支按顺序显示提示正文，不提供相同的 scaffold 作答与门控。因此，解释一次记录时，还要知道实际使用了哪种呈现配置。[提示面板](https://github.com/CAHLR/OATutor/blob/939eb0e30d8ae2389c8b096c8cd522713a79090e/src/components/problem-layout/HintSystem.js)。

日志字段同样需要按调用点核对。顶层提示和 scaffold 提交带有具体 `hintID`，但显示 Answer 子提示的调用传入空 hint，只带子提示状态数组；`hintIsCorrect` 还可能保存判分返回的参考字符串或表达式对象，而不是统一布尔值。归一化数据之前，应保留这些原始类型和定位缺口，不能从字段名补造真实动作。[日志写入](https://github.com/CAHLR/OATutor/blob/939eb0e30d8ae2389c8b096c8cd522713a79090e/src/components/Firebase.js#L276-L365)。

本轮取得的是开放题库、源码及纯判分函数的运行结果。作者公开的人类实验文件只有参与者级前后测等汇总，缺少能与题目、步骤逐项关联的动作日志；该实验内容也不含本次题族。因而，这组核对用于理解内容和观测条件，不能提供真实学生的学习收益结论。[作者研究](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0304013)、[公开数据入口](https://doi.org/10.6084/m9.figshare.23935269)。

## Repa 的合成接入验证

验证使用独立浏览器联调页、真实 Repa 后端与 MCP Apps 桥接。页面明确标注为合成测试，使用固定题面和选定的原参考提示，不是 OATutor 的生产界面，也不是真实学生数据。操作者实际显示错误参考式，再提交 `2x²+2x−6`；页面上报初始化、提示显示和提交三个事件，提示由固定源数组位置定位，避免把重复 ID 当作唯一身份。

浏览器中的可见文本和操作由受控联调核对，页面上报数据则由后端原样保存。这两个证据来源分开解释：后端收到一条 `help-shown`，本身不等于它独立观察到了提示显示。

| 接入环节 | 实际结果 |
| --- | --- |
| 固定内容与初始化 | HTML、原 problem／step／pathway 字节作为资源保留；本次初始化参数包含题目和选定提示条件 |
| 保存作答事实 | `DisplayResult` 保存初始化参数、原回答与页面上报事件；重传取得同一份完成结果 |
| 判断失败 | 本地确定性 provider 返回不合格 JSON，独立模型请求明确失败，已保存的事实字节不变 |
| 参考依据更正 | 对同一回答先使用原错误参考式，再使用另存的纠正式；固定 KAS 等价比较分别为不等价、等价，两份判断及其依据分别保留 |
| 关闭与恢复 | 关闭展示和原服务，重启后仍能读取原事实与判断；修改源文件并回收后，仍能取得原提示资源 |
| 空间复制 | 原事实和判断 JSON 保持原字节，登记资源归属副本，原提示字节仍可读 |

这里的判断特意只比较回答与选定参考式的等价性，不复现上游主问题的实际评分，也不评估模型推理能力。本地 provider 用于验证 `model.complete` 的输入、结构化结果、失败与重传；它不是网络模型，过程中也没有更新 FSRS 状态。

这条路径发现并修复了一处通用数据丢失：原 `DisplayResult` 只保存 HTML 与提交 `input`，没有保留本次实例收到的 `initialData`。现在保存与投递均保留这份可选初始化条件，旧记录保持原样，重开仍以提交 `input` 初始化新实例。接口与回归范围见[展示说明](../development/display.md#关闭历史重开与空间副本)。

## 学习领域还需要承担什么

现有内容、资源和请求机制已经可以分别持久化事实与判断，判断失败也不必丢掉作答。新的学习能力应当复用这些保证，不再建立一套独立资源归档或把所有反馈塞进强制 FSRS 评分。

在上述联调版本中，判断关联由脚本明确填写，尚未形成领域一致性。因此，这次联调提出了学习能力需要统一承担的责任：

- 一次作答针对哪份材料，回答由谁产生、记录由哪个入口上报；测试设施产生的回答明确标记，未知帮助条件保持未知。
- 一份判断使用哪次作答和哪版参考依据，新的判断替代哪份旧判断；两个并发更正不能仅按完成时间争夺“当前有效”状态。
- 内容、事实和判断在空间副本中怎样解释业务引用，哪些原始来源保持历史含义，哪些资源由当前副本持有。
- 重开时怎样恢复具体学习组件的状态。通用展示保留初始化与提交值，但不会替组件推断动态页面的完整状态或操作历史。

这些责任可以在学生算法选定之前接通。此次验证提供的是持久证据与更正路径的工程依据，尚未定义掌握概率、知识传播或任务调度，也没有证明学习效果。
