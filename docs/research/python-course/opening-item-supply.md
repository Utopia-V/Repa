# 开头路径题量核对

Python 课程 `0.2.0` 已按 d 的真实测验与 XP 策略重算四条两周路线。路线触及的并集由 py01–py20 扩到 py01–py21，共 53 个 KP；本轮补入 6 道 py21 练习和 3 道 py01 复习，测验题池保持不变。整个题量任务累计新增 218 道题：107 道练习、51 道复习、60 道测验，课程现有 1,180 道题。原有五道待核对题现已通过 DeepSeek flash 独立核对，题面与判分定义保持原状，`py12.k1.x3` 的解析改为直接引用规则，不再引用会被随机排列的选项序号。

## 设计思路

题量按实际交付的位置计算。练习池要覆盖每 KP 一轮最长五次尝试；中止后重试还会额外消耗题，所以 py01.k1 保留六题。复习池则取四条路线中逐 KP 的最大交付数。这样既能覆盖开头两周的使用，也保留正式流程在库存耗尽时标记重复的兜底。

上一版测验按场次估算，并为每个 topic 独立预留八题。现在直接调用[测验、XP 与进度](../../../../docs/development/learning-quiz-xp.md)的正式入口：由 lesson/review 奖励的历史高水位触发测验，由真实选题策略决定 topic，交卷后先补救错题，再对同一批 topic 换题重考。逐 topic 的实际最大需求降到四题，因此原有测验池的题量足够，不删去已经编写的余量。

测验和重考的奖励也计入每日目标；测验结果还会更新学生模型。因此，真实策略不仅改变测验题数，也会改变两周内的新课、复习和补救。重算发现，40 XP 顺利路线进入了 py21，它的三个 KP 各只有三道练习，仍需各补两题才能覆盖最长五次尝试。40 XP 含失败路线则把 py01.k1、py01.k2 的复习需求推到七题和十三题，比本轮前的库存多一题和两题；这三道复习题也补齐。

## 实现细节

### 固定基线与表现

当前教学基线为合入 c2、c3 和 d 后、按真实测验策略重算题量前的版本；策略版本为 `repa-flow-v2`、`repa-xp-v1`。课程版本固定为 `0.2.0`，逻辑日期仍为 2026-10-21 至 2026-11-03，每天从 `09:00:00+08:00` 开始，时区为 `Asia/Taipei`，topic 抽样与 KP 轮转的 seed 为 `20261021`；作答位的私有排列沿用生产随机源。菜单始终选第一项；每个任务结束后读取真实 `todayXp`，达到日目标才结束当天，因而实际 XP 可以超过目标。

路线使用真实插件宿主、`LearningRecords`、`connectLearning`、提交和菜单推进，测验经 `quiz.start`、`quiz.finish`、`quiz.retake` 完成。规则题正常判分；开放题的语义评分边界使用本地固定正确结果，以控制表现；代码题在课程锁定的 Python 运行时执行。辅导运行不启动，受限准备仍调用真实的宿主中止边界。这里控制的是学习表现与时间，触发、选题、奖励、补救和重考均由正式策略决定。

顺利路线中，lesson 每 KP 两次独立正确，review 三题独立正确，quiz 全对。含失败路线延续原有控制：py01 第一次独立正确后中止，重试时每 KP 按“对、错、错、对、对”完成，首个 review 五题全错；此外，每场原测验的第一题给出结构有效的错误答案，其余题、后续补救和 retake 全部独立正确。lesson/review 的错误原答仍使用“不会”，quiz 则实际填写错答，因为正式测验不接受“不会”。
