# 公开编程提示记录的可用范围

2026-10-10。[函数观测目标核对](learning-observation-contract.md)已经区分回答内容、帮助条件与判断谓词，接下来需要将这些区别落实到真实过程。本轮取得并核对了作者公开的 Kotlin 提示交互数据：具体提示、界面动作报告和后续代码确实同时存在，但接受提示、运行测试和学习成功仍不是同一个结果。当前选择将它用于帮助消费与代码变化的局部取证，完整结构聚合见[核对结果](results/learning-hint-traces-20261010.json)。

## 作者研究与实际发布包

[作者论文 v1](https://arxiv.org/html/2511.06362v1)报告了 34 名本科生的任务过程。他们已有其他语言的编程经历，但没有 Kotlin 经验，使用课程中的三个项目自主求助。论文中的 positive 场景指点击 Accept 采用代码提示，而不是测试通过或能力提升；该队列没有报告随机分配帮助条件或独立后测。论文也没有固定当时的模型 snapshot、课程 commit 和三个具体项目名称，因此旧系统论文中的 GPT-4／14 人配置不被补到这个队列上。

实际原件来自作者的 [Zenodo 17551130 v1](https://zenodo.org/records/17551130)，公开许可为 CC BY 4.0。ZIP 为 54,628,100 字节，官方 MD5 为 `577d7874155222eef307d582dd0a9aca`；本次取得文件的 SHA-256 为 `5527127f0a3c939601b17ef207ef8b34df7cad9159c9617f879efbf4e989d499`。

包中有 1,050 份提示场景 HTML、四份 raw CSV、README 与访谈脚本 PDF。所有成员展开共 1,507,887,364 字节，远大于 ZIP 大小，因此本次按成员读取，没有全量解压到磁盘，也没有执行 HTML、脚本或学生程序。完整读取过的 HTML 和 CSV 完成了各自的 CRC 检查；原 ZIP 摘要在核对前后不变。

raw 表不包含提示，提示保存在预处理场景 HTML 中。这不是文件格式的细枝末节：如果只用 raw CSV，就会把发布者保留的帮助条件漏掉；如果只用场景报告，也不能假设已经看到了完整任务过程。

## 报告内保存了哪些动作

全部 1,050 份 HTML 都能静态解析，合计 1,060,271 个事件：

| 报告类别 | 事件数 | 可直接读取的内容 |
| --- | ---: | --- |
| Log | 5,275 | 提示动作、课程／课节／任务 key、附加上下文 |
| Activity | 943,034 | 鼠标、按键、快捷键、IDE 动作与执行活动 |
| Document Change | 87,361 | 文件名、代码快照及相关标识 |
| File Editor | 12,258 | 文件打开、关闭与切换 |
| Tool Window | 12,343 | 工具窗口动作 |

所有 non-Log 事件都有 `id`、`research_id.value` 与日期。按类别和 ID 核对时，有 15 次重复出现，完整 payload 一致；Log 没有同样的稳定 ID，因此没有仅凭文本相同就把它们合并。报告内的顶层时间都带时区，按瞬时比较非递减。这些结果支持报告内的读取与定位，不保证报告之间没有遗漏或重叠。

每份报告的首个 Log 都是提示入口：960 份由点击开始，90 份由重试开始。其中 737 份有一条生成记录，313 份没有。因而，1,050 份报告不能直接称为 1,050 次成功提示，更不能全部当作完成的教学活动。

还需要区分“保存了代码”与“学习者看到了代码”。包中有 1,028 条请求代码块、734 条生成代码块，另有 453 条主动请求展开代码的记录。生成、banner、展开、接受和点赞的标签分别保留；不能因为分析报告展示了建议代码，就断言当时的学习者已经完整阅读了它。

## 生成之后的记录到哪里结束

本次为每条生成记录统计其后的报告内动作，遇到同报告中的下一条请求就停止，否则止于该报告末尾。实际 737 个窗口全部以报告末尾为界，不能把它们说成已经完整观察到下一次求助之前。

| 报告内生成后记录 | 数量 |
| --- | ---: |
| 包含代码变化的窗口 | 463 |
| 包含 Execution 活动的窗口 | 449 |
| 这些窗口中的代码变化事件 | 57,083 |
| 这些窗口中的 Execution 活动 | 1,175 |

Execution 保存的是执行活动或命令，不是通过测试的结果列。提示请求中确实有测试失败上下文，但它还需要对应具体快照和测试，不能把它当作所有后续代码的即时判分。本次没有取得可直接使用的统一通过标签或 task-complete 事件。

同样，报告中单一的 Log 任务 key 不会自动约束所有编辑。106 份报告包含多个 Document Change 文件名；多个文件也不必然属于不同任务。因此，将后续某份代码解释为本次提示针对的回答时，仍须核对具体文件及内容，不能只传播报告的任务 ID。

## 目录、研究 ID 与人数要分别解释

论文人数、报告目录和 raw 字段有不同口径。实际 HTML 分布在 22 个报告目录中，而四份 raw 表的 `research_id` 集合并集为 156。这个字段值的数量不是学生人数；目录数字后缀与 raw ID 集合也没有字面交集，不能靠名字直接连接两者。

| raw 表 | 数据行数 | 不同非空 `research_id` 值 |
| --- | ---: | ---: |
| activitydata | 1,436,108 | 151 |
| documentdata | 119,214 | 152 |
| fileeditordata | 17,048 | 97 |
| toolwindowdata | 17,802 | 151 |

这些是本次实际文件扫描结果，不替代作者论文使用其他范围或过滤规则的汇总。尚未形成可核验的参与者映射前，不把研究 ID 当作学生进行留出切分或学生等权评价；某个目录或记录缺少提示，也不能被补成“没有求助”。

## 两份报告怎样与原表对应

在完整扫描之前选定的两份报告共含 3,095 个事件。它们属于同一个报告目录、同一个实际研究 ID。其中九个 Log 不在 raw 四表内；其余 3,086 个事件按类别、记录 ID 和实际研究 ID，都在原 CSV 中找到唯一一行。

字段对应需要解释序列化形式，而不是模糊匹配。HTML 把研究 ID 包在 `value` 中，把代码和选中文本包在 `code/lines` 中；有值的 `action_id` 在这些报告中是整数值浮点数。核对使用实际容器字段及精确整数值，两边日期保留原字符串，另按显式时区转换到同一瞬时比较。null 与 raw 空字段也明确对应，不用相近时间或相似代码来猜一条记录。

独立核对确认，这 3,086 个事件的全部原字段与显式字段存在性一致，其中 219 条代码变化还保持了报告代码块与原快照正文的对应。这只证明两个预选报告的连接，不是全部报告、目录或参与者映射的验证。原件、个人标识、代码和定位路径保留在私有工作层；公开结果只有字段和聚合。

## 当前采用范围与下一问题

这个包已能支持一个比总提示数更具体的问题：日志中的接受动作，是否对应后续代码新增了建议所指的改动；主动请求展开但未接受时，是否也出现相同改动？可以先按日志条件选定少量场景，再核对请求时已有的代码、建议内容，以及同一对象的后续快照。建议本来已存在、后来撤销、多文件或无法定位的情况都保留，不以按钮动作补成代码事实。

这一步判断内容对应，不评价改动是否正确，也不证明提示造成改动或学习者已经掌握。因此，可以直接使用真实片段，不必先等完整课程版本。只有继续判断“修复了任务”或“满足客观要求”时，才固定相应题面或局部 criterion 及其依据；后续不受助能力仍需另有证据。

当前课程源码入口已定位到 [Kotlin Onboarding: Introduction](https://github.com/jetbrains-academy/kotlin-onboarding-introduction/tree/ac1603192c7c01134719dc0b00c91a17249f8db7)，但当前仓库版本不是研究时版本。其他来源也按实际可取得范围处理：已查 OATutor 官方入口尚未取得新的真人逐动作包；[FH2T 作者数据论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC12270003/)提供了更接近数学任务的字段说明，完整数据却需要新的协议与联系。它们仍是不同缺口下的来源候选，不用不可取得的字段替当前记录补出真值。

本轮完整 HTML 核对由另一实现独立读取复现；raw 身份聚合与两报告连接也由独立脚本核验。它们证明当前文件的结构和可定位范围，不是学习模型的效果验收。随后完成的[六例内容对应核对](learning-hint-adoption.md)保留了无新建议、无后续快照、文字与代码冲突，以及相符修改后来消失的情况；这些差别继续分别解释，不拟合统一 success 标签。
