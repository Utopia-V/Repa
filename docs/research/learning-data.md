# 学习作答数据的适用范围

2026-10-10。本次核对接续[学习闭环研究](learning-loop.md#一次失败留下的解释可能要等下一题才能区分)：综合题失败后，另一项单独表现能否帮助解释原失败，并改善对后续组成技能表现的预测？要比较这一点，数据需要能对应实际任务、技能关系、帮助和反馈的先后，而不只是提供每题的最终分数。

## 两个发布包分别提供了什么

ASSISTments 的两个公开版本提供了不同信息。2009–10 的修正版把同一次作答的多个技能标签合并到一行；2012–13 则保留了题内动作，可以区分先请求提示还是先回答。因此，本次同时检查文件结构与字段含义，再判断它们能承担哪一部分研究。

| 核验对象 | 2009–10 Skill-builder 修正版 | 2012–13 原始发布包 |
| --- | ---: | ---: |
| CSV 作答记录 | 346,860 | 6,123,270 |
| 学生 | 4,217 | 46,674 |
| 无技能标签的记录 | 63,755 | 3,411,457 |
| 一个技能标签的记录 | 236,068 | 2,711,813 |
| 多个技能标签的记录 | 47,037 | 0 |
| 时间与帮助信息 | 首动作类别、提示和尝试总数；没有作答起止时刻 | 起止时间及 `actions` 动作序列 |

以上数量来自本次对原文件的完整扫描，不是论文中采用其他过滤规则后的样本量。两份文件的事件 ID 都逐行唯一。2009–10 使用 `order_id`；2012–13 的 `problem_log_id` 与别名 `problemlogid` 逐行相同，也没有需要合并或隔离的同 ID 冲突。

### 2009–10：多标签不等于完整过程

[Skill-builder 发布说明](https://sites.google.com/site/assistmentsdata/home/2009-2010-assistment-data/skill-builder-data-2009-2010)明确说明，修正版将多个技能用下划线合并；它也说明请求教学帮助会使该题记为不正确，学生会立即得到正误反馈。因此，`correct = 0` 不能直接当作一次独立回答错误，更不能假设错误后到下一题之间没有发生学习。

这个版本可以提供多标签任务的候选序列，但提示和尝试的总数不能还原它们在题内的全部顺序。`order_id` 可用于官方说明的记录先后，不能替代时间间隔或不重叠的作答时段。多标签本身也只说明注释关系，尚未证明每个标签都是完成题目时必须执行的组成技能。[字段解释](https://sites.google.com/site/assistmentsdata/an-explanation-on-how-to-interpret-our-data-sets)进一步区分了原题、脚手架与题内动作。

### 2012–13：动作可读，但没有双标签事件

[2012–13 发布说明](https://sites.google.com/site/assistmentsdata/datasets/2012-13-school-data-with-affect)介绍了 `actions`、部分得分和技能字段。本次实际文件中，2,711,813 条非空 `skill_id` 都是单个整数，其余记录缺少标签。官方页面虽然保留了“不同技能分行”的说明，但文件中既没有重复事件 ID，也没有同一题目跨学生出现不同非空标签的情况。不能据此拼出一次作答的多个标签。

动作字段按 YAML 安全解析。具体使用 `js-yaml 4.3.2` 的 `CORE_SCHEMA`，只额外接入发布文件中旧式 `!binary` 标量的标准二进制解析；二进制答案保留为字节，不猜测文字编码。首答取动作序列中的第一条 `answer`，只有其结果为布尔值时才视为可用首答；帮助条件按这条回答之前是否出现 `hint` 或 `scaffold` 记录。

| 动作核验结果 | 记录数 |
| --- | ---: |
| 原始事件总数 | 6,123,270 |
| 可以解析的动作日志 | 6,123,228 |
| 其中有布尔首答的日志 | 6,093,645 |
| 其中没有可用首答的日志 | 29,583 |
| 因 YAML 缩进错误而无法解析的日志 | 42 |
| 首答前出现提示或脚手架的日志 | 307,902 |
| 出现某次回答后的提示或脚手架的日志 | 337,165 |

无法解析和没有首答是不同情况，二者都不编码为答错。表中的布尔值也是系统记录的判定，仍需结合题型解释。例如，`open_response` 不作为客观知识测量的结果。没有记录到前置帮助，只表示该日志中未出现这类动作，不能排除日志之外的帮助。

汇总字段也需要与动作分开使用：`correct` 有 5,323 条非二元得分，提示和尝试总数在部分记录中与动作计数不一致。因此，研究题内先后时直接使用动作序列，不把汇总值补造成缺失动作。首答后的提示、重答及反馈可能带来学习，应保留为后续预测的历史条件。

跨题时间还需要单独处理。起止日期没有时区标记，727 条记录的结束早于开始。在 13,453 个日志中，按动作序列读取的 `answer`、`hint` 或 `scaffold` 时间数值出现下降；这些数值的完整时钟语义仍待核对。可以读取首答，不等于已经证明全部日志能够组成严格、无重叠的时间序列。

## 原定相邻序列的结果

扫描前确定的第一版核对只寻找字面相邻的三次日志：先是一道恰有两个技能标签的主问题 M，首答错误；然后是单标签 A 与单标签 B，两者不同且恰好对应 M 的两个标签。A、B 的方向由实际先后确定，两种首答结果都保留。它还要求核对跨题时间，保留帮助和首答后动作，不跳过中间题目或脚手架去补成序列。

2012–13 在“双标签 M”这一前置条件上得到 **0 条候选**。后续相邻关系、时间与回答条件因没有候选而未作评价，不能把它们报告成零异常或零失败。这一结果说明当前导出文件无法承载该版比较，尚未回答关联表示是否改善真实预测。

进一步检查 `assistment_id` 也没有补足这层关系。[官方字段解释](https://sites.google.com/site/assistmentsdata/an-explanation-on-how-to-interpret-our-data-sets)允许一个容器包含多个主问题；实际 138,555 个容器中，6,870 个确实出现多个主问题。按学生与容器分组，127,179 个组同时出现主问题和脚手架，其中 6,671 个组有多次主问题日志。因此，同容器成员既不能直接当作一次练习实例，也不能直接认作技能覆盖关系。完整题目内容另有作者申请条件；公开日志的可读性不包含这份内容的访问与分发授权。

2009–10 另作了不看成绩的结构核对：双标签主问题有 38,794 条，涉及 34 个标签对，其中 13 对在文件中同时具有两个单标签主问题池。按同学生全部日志的 `order_id` 排序，保留中间所有记录，字面相邻的 M→A→B 只有 11 个机会，涉及 11 名学生、4 个标签对。这还没有筛选 M 是否失败，已经不足以承担原定比较。

后续对更长前缀作了单独的[关系组合预测核对](learning-relation-probe.md)，保留全部中间练习，并按学生划分训练与留出记录。增加一个全局 M×A 组合项后，观察到的改善很小，对学生权重和预定重拟合条件敏感，尚未形成采用依据。这项局部比较与本页的原定相邻序列分开保存；题内帮助次序、真实组成关系和学习收益仍由相应证据检验。

同一份 2012–13 日志后来用于另一项[帮助次序的局部预测比较](learning-help-sequence.md)。这次只要求来源题与目标题的单标签相同，并保留完整日志邻接和信息释放边界，因此“双标签候选为零”不再是该问题的前置限制。测试结果显示，来源帮助记录有预测增量，而更细的位置项在预定学生等权口径下尚未形成稳定采用依据；原定综合题归因问题与其零候选结果保持不变。

CSV 按逻辑记录流式读取，保留带引号的多行动作字段。2009–10 文件不是有效 UTF-8，本次用 Latin-1 的逐字节映射核对 ASCII 字段与结构，不解释原答案的文字编码。2012–13 完整通过严格 UTF-8 与 ZIP CRC 检查，成员文件为 3,009,494,391 字节，6,123,270 条数据记录均为 35 列。

本页记录文件适用性、字段含义与候选序列存在性的核验。原始文件、版本化解析结果和冻结的核对计划保存在研究工作层；公开说明只保留聚合结果。后续预测试探的样本、方法与效果另见上述记录。四列 affect 预测值未用于状态、关系构建或模型评价。

## 具体提示与后续代码的公开来源

后续取得并核对了作者发布的 Kotlin 提示过程包，实际保存具体提示、交互报告与代码快照，范围见[公开编程提示记录](learning-hint-traces.md)。它补足了帮助内容与后续编辑的入口，但接受提示、执行测试、客观通过和学习改变仍需分别解释；报告目录、研究 ID 与论文人数也不能混作同一抽样单位。下一步先用真实片段核对建议与代码变化的对应，不把这个近邻来源改写成上述数学组成关系比较已经成立。
