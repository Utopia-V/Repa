# 通过公开应用协议连接可替换前端

本记录约定目标设计；当前实现范围与运行方式见 [README](../../README.md#运行现有-tui)。

## 公开能力与请求输入

Repa 通过公开应用协议向官方与独立前端提供当前状态查询、操作和按范围订阅。协议传递可序列化的产品数据、内容引用与结构化结果，媒体通过资源读取入口取得；Pi 的对象与存储细节留在内部适配层。仅暴露持续对话的事件流，会让每个前端承担历史重建与恢复判断，因此应用接口同时提供当前状态的查询结果。官方提供不依赖 UI 框架的客户端，维护后端状态副本、订阅与重连；第三方也可直接实现协议。具体方法名由后续接口定义确定。

这里的应用协议即 Repa 前后端协议，沿用 v1 名称。首次公开发布前，内部原型的字段调整不要求另起大版本；开发联调依据明确的源码或构建提交。发布后的兼容性演进继续通过协议版本协商表达。

应用协议面向程序调用，模型工具按适合模型使用的形式接入同一组后端能力，不要求与协议方法一一对应。工具适配、内容操作标识与保存粒度的取舍见[共同内容操作](0003-share-file-based-content-operations.md)。

共享能力在应用或空间层提供调用入口，前端操作、展示宿主动作与模型工具按各自形式调用。能力按实际需要取得模型调用、读取会话历史或推进指定会话的能力：处理明确输入可以直接使用所选模型连接与配置；参考过去交流时读取明确范围的历史；让学习 Agent 继续工作时提交会话请求。模型调用本身不要求新建学习会话，本地内容能力仍可在没有模型连接或 Agent 运行实例时使用。

需要跨前端实例存活的材料提取、转写等处理可以关联空间与能力，独立于 Agent 会话提交，复用应用协调层的受理、进度、结果查询、取消与关闭语义。处理能力拥有输入转换与结果含义，共同内容模块拥有保存的内容及资源；关闭视图不自动取消已受理处理，完整退出和异常中断沿用相应收尾与恢复规则。

恢复诊断或语境整理可以通过已有的独立处理能力，使用明确选定的输入、文件引用与问题记录，不以成功展开常规学习语境为前提。相应操作继续遵循本次授权和内容操作约定。

请求可以组合文本、草稿选区、内容引用和图片等资源，保留实际提交的内容与来源。文本、草稿片段和作为输入提交的资源由请求记录保留，受理前确认所需输入资源可用并能保留；尚未受理的准备状态不显示为已提交。内容引用本身不复制原件，引用解析和工具读取所用内容保留实际来源与修订，不把后续变化改写为过去输入。

适配层根据内容能力和当前模型条件提供相应的模型可读表示；进入学习会话的输入由会话保存实际表示与来源，独立处理所需的输入和来源由相应请求及结果保留。不能处理的输入返回具体原因，不静默忽略。提交本次输入、关联来源材料和加入学习语境分别表达，附件不自动成为长期背景。输入及产物的资源保留复用[共同内容操作的资源约定](0003-share-file-based-content-operations.md#材料与资源生命周期)。

公开配置接口提供连接与认证管理、可选模型和连接状态、设置覆盖及其有效值与来源、按项修改与恢复继承，以及某次运行的实际配置。后端统一解释作用域与设置含义，前端无需直接解释 Pi 配置文件；凭据提交与登录秘密不作为普通配置查询或学习会话记录。连接身份、继承与运行配置的责任见 [Pi 嵌入决策](0001-embed-pi-through-node-sdk.md)。

提示内容和自动注入的控制复用上述设置与能力接口，提供各来源的启用状态、覆盖内容和可确定的装配预览，并可查明实际运行使用的内容。默认学习提示可以替换或关闭，独立前端具有相同控制能力；动态贡献与历史结果按[提示内容与自动注入](0001-embed-pi-through-node-sdk.md#提示内容与自动注入)的约定解释。

公开调用采用 [JSON-RPC 2.0](https://www.jsonrpc.org/specification)，默认通过 WebSocket 传输，使动态订阅、操作应答、交互回复与事件共享连接；资源读取使用 HTTP。组件通过客户端共享连接，快照、游标和恢复语义由 Repa 应用协议持有。需要受理结果的操作使用有应答的调用，状态变化使用通知；JSON-RPC 的调用标识只匹配应答，业务请求标识用于查询与去重。后端默认在本机提供接入，连接授权与协议版本协商先于业务调用，HTTP 资源读取同样执行访问控制。Pi 继续通过进程内 SDK 嵌入后端。

## 前端状态与会话

后端拥有已保存的空间内容、会话历史、运行状态与待回答的交互。客户端维护这些数据在当前前端中的副本；前端宿主持有输入草稿、未保存的编辑、导航及跨组件选区，组件持有自身的显示细节。需要跨组件保留的状态通过宿主服务共享，组件按公开约定注册、挂载、更新和卸载，并通过内容引用与具有明确含义的动作协作。官方组件采用相同约定。组件兼容性由宿主契约与渲染环境决定。

同一工作台内，同一份可编辑内容共用宿主的草稿模型，关闭或更换编辑器实例不删除草稿。不同工作台保留各自草稿，通过后端修订检查协调保存。保存回执只确认当时提交的版本，等待期间的新输入继续保留为草稿；收到其他来源的修改时保留本地编辑及其基准。组件可以使用自己的内部编辑模型，交给宿主保留的草稿须能按内容格式恢复。

从未保存的草稿提问时，请求携带实际选中文本，并保留草稿来源与保存基准；这些文字不作为后端正式内容修订。是否提问与是否保存分别由实际操作决定。实例动作明确绑定实际空间、会话或内容目标，界面焦点切换不重定向已经发出的操作。

前端的会话选择只改变查看与订阅的对象，后端按所属空间与会话标识管理运行实例，多个界面实例可以观察同一个运行实例。单纯读取历史不启动 Agent。Pi 的运行时切换会中止并替换当前实例，因此前端切换不直接调用该替换路径。新建、恢复和分支改变交流历史的接续方式，空间内容仍取当前状态；两套内容需要独立演变时通过显式复制处理。

## 会话输入与接续

同一会话由一个活动运行推进历史，多个会话可以并行。官方前端在空闲时普通发送开始新运行，运行中普通发送作为 steer 补充或调整当前工作；明确选择“做完后处理”的输入由应用协调层接收并排队，作为独立后续运行开始。普通对话仍可用自然语言安排任务内的先后顺序，显式排队表达独立后续工作的归属。

steer 指向明确的当前运行，沿用其模型、配置和入口背景，不另建小运行。目标已经结束或不匹配时返回未接入结果并保留输入，不将其悄悄交给其他运行。每条已接收输入可查询其归属和接收状态；接收不表示问题已经处理完成，取消时仍保留尚未进入处理的输入及其状态。

排队请求在受理时保留当时的模型与运行选项，后续默认设置变更不改写已提交的选择；实际开始时才取得当前学习语境。输入进入当前运行与启动独立运行的区分，参考 [Codex 的 steer 契约](https://learn.chatgpt.com/docs/app-server#steer-an-active-turn)及其[后续输入队列](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/app-server/src/request_processors/thread_queue_processor.rs)。Pi 的 steering 与 follow-up 能力由适配层按 Repa 的业务边界接入，底层入队或调用返回不等于独立请求已经完成。

应用受理记录承担请求身份、来源、配置和重启恢复，Pi 承担当前 Agent 的输入投递、工具循环与重试。显式后续请求在获得相应运行归属、准备本次背景后投递；不把整条持久队列预塞入 Pi 并据此宣称独立运行语义已成立。基础 steer 接入可以沿用现有模型选择推进，持久请求与具名连接的完整组合按各自接口接通。

失败任务的“继续”形成明确指向旧任务的新请求，在该任务所属会话的当前历史上接续；忙时排队，开始时使用当前内容和学习语境。原输入尚未进入历史时从受理记录补入一次，已经进入时不重复追加。后端不自动回放已完成工具，Agent 根据实际结果判断后续操作。从旧节点分支属于独立的显式操作，普通继续不另建会话。

## 任务生命周期

当前运行正常结束后，自动开始该会话可自动执行队列中的下一条已提交请求。运行被取消或以失败终态结束后，所属会话的未执行队列暂停并保留供明确继续；取消单条排队请求不影响当前运行，其他会话按自身状态继续。

官方前端正常关闭最后一个窗口时，默认让已启动的 Agent 任务、独立后台处理及可自动执行的已提交队列完成后退出。输入框中未发送的草稿不进入队列。等待回答或授权时后端保持运行，持有原任务及交互，重新打开窗口可以接回；若队列因取消或失败暂停，则保留未执行项供之后明确继续。当没有运行中的工作、可自动开始的已提交请求、未决交互及其他使用后端的前端时，持久保存后退出；仍有其他前端连接时继续为其服务。关闭前提交能正常保存的编辑，其余草稿由前端宿主保留为本地恢复状态。

待处理状态通过后端的状态查询与订阅提供，官方前端宿主接入相应的本机通知能力。通知不可用或未送达不改变待处理事实，重新连接仍可查询；窗口关闭期间的后台通知接入由前端宿主的实际运行环境验证。

完整退出作为独立操作，停止当前运行与后台处理，让内容操作按恢复规则收尾，并保留已完成的修改及未执行队列。重新打开后由明确操作继续未执行项。异常中断后恢复内容操作、会话历史和实际运行状态，结果不明的操作先核对再决定如何继续。定时复习、定期整理等主动后台能力由单独启用的扩展提供，完成已明确提交的工作不自动启用新的后台任务。运行结束由后端结合 Pi 的实际收尾状态与内容操作结果判断，其他前端可通过公开生命周期接口定义自己的关闭交互。

## 组件宿主

组件角色通过公开登记约定扩展，不以核心内置枚举限定。官方提供内容导航、会话消息区、输入区、编辑器、内容展示器和辅助面板等默认角色。提供者以命名空间标识角色，并说明数据绑定与动作约定；新角色可以通过通用视图或面板入口及命令贡献接入。按钮、菜单与快捷键使用命令入口贡献。组件可以通过宿主嵌入其他已登记组件，例如会话消息区使用对应格式的内容展示器。

宿主为组件提供所需的数据绑定、编辑服务、宿主动作及焦点、主题、命令和视图状态等界面服务，复用连接与后端状态副本。数据绑定先提供当前状态，再提供后续变化，普通更新使用同一条订阅通道。面向 Web 渲染环境，参考接入形状为 `mount(container, context)` 返回 `dispose()`，不另设一套 `update` 数据通道；组件自行选择内部框架。关闭实例时清理订阅、监听与显示资源，视图关闭信号用于结束本地加载与显示工作，已提交的后端操作仍按自己的生命周期处理。

展示宿主在实例使用期间统一持有所需的受管理版本和资源，关闭时释放。短暂断线沿用已有重连机制，不立即视为实例关闭；宿主退出或被确认失效后释放临时持有。若异常结束后原版本已不可恢复，重新打开时明确说明，不以新版本冒充原输入。后台请求及长期文档的独立保留关系见[资源生命周期](0003-share-file-based-content-operations.md#材料与资源生命周期)。

官方前端在宿主启动时确定可用的组件实现集合及其代码版本。实例按明确选择、配置中的默认实现和基础回退方式装配，避免依赖扫描顺序接管界面；在本次可用集合中打开不同展示方式属于普通使用。安装、升级或更换组件代码后，通过重启前端宿主生效，不要求跨代码版本接管旧实例的内存状态。正常打开和关闭组件、接收新数据及组件内部交互继续按组件生命周期处理，草稿、导航与选区通过普通保存和恢复约定衔接。已选代码在启动时或首次使用时装载，由宿主实现决定；开发工具自带的热更新不属于 Repa 的产品契约。原生前端与 TUI 使用相同应用协议，可以定义各自的组件实现。

文档、代码与数据等生成产物的内容更新支持普通预览刷新，前端可以自动刷新或保留必要交互状态后重新打开。正在执行的运行仍记录实际使用的输入与内容修订；内容刷新不要求重启前端宿主。

完整前端通过认证连接承担用户的操作界面，包括设置与授权答复；生成内容的展示实例只取得宿主明确提供的数据、资源和动作，不持有后端主连接令牌。权限请求由后端绑定具体操作及范围，多个前端观察同一待回答项，迟到答复不重新启动已取消的操作。插件组件与生成内容的实际执行边界、授权和产物生命周期见[权限与执行环境的决策](0005-execute-display-content-with-host-permissions.md)。

## 订阅与运行结果

订阅首先提供当前快照，再提供与其衔接的变化；重连时从有效游标继续，无法继续时明确要求重新取得快照。订阅范围按实际需要选择会话、文档或空间目录等对象，短期事件缓存服务于连接衔接，长期历史仍由 Session 和内容记录持有。内容查询返回实际内容与修订，修改共用既有内容操作及其局部编辑、修改基准和冲突语义。

请求受理结果与运行结果分别返回。请求标识用于查询受理状态和识别重复提交；无法确认原请求状态时返回未知状态，不自动重启可能已执行的操作。运行事件关联实际会话、运行、消息、内容块或工具调用，保留文本、资源和扩展数据的结构。取消指令收到后，仍须等实际停止才能报告取消完成；重试、工具执行和压缩属于过程，最终状态由后端在运行结束后给出。没有专用渲染组件时，前端仍可显示基本说明或打开相关内容。

启动独立运行的请求在受理时绑定确定的配置，steer 沿用所指运行的配置；同一提交的重传返回原接收状态、归属与选择。失败后继续是新的接续请求，与查询或重传原请求分别表达，具体行为见[会话输入与接续](#会话输入与接续)。结果不明的操作仍先核对。

## 扩展与兼容

扩展在自己的命名空间中公开数据格式、操作与变更通知，并声明兼容版本。前端组件据此使用能力，核心协议提供接入方式；学习方法及其数据含义由相应能力持有。替换显示组件不要求替换后端能力，替换后端能力时按其自身契约解释数据。

共享后台能力按需要取得数据位置，并在实际持有资源时接入启用、关闭与快照等生命周期。数据库、实体、算法和迁移由能力或其可复用依赖实现；宿主协调调用和数据所属关系。其持久性与空间迁移责任见[能力数据与数据库](0003-share-file-based-content-operations.md#能力数据与数据库)。

简单插件可以只提供工具或提示，存储、后台任务、展示和快照都是按实际需要使用的接入。基座接口按确有通用运行或协作需求的能力扩展；新增复习算法或业务数据类型通常只修改对应插件，核心不增加相应实体、表结构和业务分支。关闭学习组合后，通用 Agent 与内容能力仍可用；官方默认组合通过相同入口保留完整学习体验。

包来源、安装与定位优先复用 Pi 的机制。一个包可以选择提供 Pi Agent 资源、Repa 共享后台入口与前端组件，或组合其中多种部分；原有 `pi` 资源声明继续使用，各宿主只装配适合自己的入口。Repa 需要处理资源选择，避免将只有后台或前端入口的本地包误交给 Pi 的 Extension 回退发现；已有包过滤能力的核验见 [Pi 调查记录](../research/pi-ecosystem-compatibility.md#9-pi-0843-的包入口边界补充)。前端入口、组件注册与实现选择由相应宿主约定。纯前端组件可以独立分发，完整 Web 前端可以作为静态资源与入口交付，独立桌面程序按公开协议连接。

共享后台能力取得本次调用的输入、所属空间、取消信号与所需服务接口；模型工具按适合模型的参数形式调用，前端直接通过应用接口调用。处理逻辑与调用形式分别组织，不依赖某个全局的当前 Agent 或当前空间。能力通过稳定命名空间及契约版本说明自己的动作、输入和输出；同一公共契约有多个实现时，由配置明确选择，避免依赖扫描顺序覆盖。

实际装配由相应宿主根据启用状态、应用侧信任与兼容性决定。明确的安装或启用操作允许在相应生命周期装配入口，单纯发现包文件不构成执行授权。代码类入口在相关宿主重启时切换版本，先完成或明确取消已有工作，释放相应资源后再应用包文件的替换。这个选择复用普通关闭与恢复过程，避免要求包迁移正在运行的函数、监听器和内存状态；代价是代码更新需要重启宿主。生成产物的内容仍按普通更新与预览刷新处理。

禁用或卸载能力不删除已有文档、数据和结果；内容保留所需的格式契约与资源，兼容能力可以继续使用它们。Repa 应用协议、组件宿主接口和扩展能力接口分别声明兼容范围，包发布版本不替代接口兼容性。公开数据结构以可分发的 schema 为准，客户端类型与运行时校验从同一来源生成。
