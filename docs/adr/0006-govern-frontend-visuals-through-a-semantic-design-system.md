# 以语义设计系统统一官方前端视觉

## 背景

官方前端会逐步接入学习内容、会话、导航和扩展组件。同一视觉含义若由各页面选择颜色、尺寸与交互样式，主题调整和状态修正就需要逐处修改，也容易让完成、错误、选中与焦点混用同一视觉信号。只集中保存一组色值仍不能明确这些信号的责任，基础控件的行为与业务状态也会继续在调用处重复实现。

Web 首先建立设计规范、主题映射和基础组件，Desktop 随后迁入主应用和侧栏。需要明确这套结构中哪些是后续官方界面应遵循的决定，哪些只是当前宿主的实现。

## 决定

官方前端以语义设计系统组织视觉与交互：[设计系统规范](../design-system.md) 定义语义和稳定约束；主题把语义映射为视觉值；基础组件统一实现尺寸、variant、状态和通用交互；业务组件把业务状态映射到基础组件；页面负责布局、响应式和组合。调用方不能通过局部样式覆盖基础组件的视觉与交互契约。确有新语义时，先确定其用途及调用范围，再扩充规范和 token；当前数值相同的不同语义仍分别命名。

选中、焦点、完成、错误等状态保留独立含义。状态须有适当的可见提示和可访问语义；颜色、背景、边框或 ARIA 属性不能单独替代完整的状态表达。组件的尺寸由 size 决定，variant 表达层级，状态不改变控件几何。具体 token、尺寸、对比度和组件规则由 docs/design-system.md 维护，不复制到本记录。

当前 Web 与 Desktop 分别以各自的 CSS variables 作为主题值来源，由 Tailwind 映射为工具类。基础组件采用引入并经本地适配的 shadcn 源码，复用 Radix 的焦点管理与复合控件行为；Repa 持有引入后的组件契约和升级审查。业务代码不直接消费主题私有变量，也不建立平行的色板或主题运行时。当前文件责任、上游来源和验证入口见[设计系统实现说明](../design-system-implementation.md)及[Web 通用组件说明](../../apps/web/src/components/ui/README.md)。

这项决定约束官方界面的语义和责任边界，不要求不同前端立即共享同一份组件源码。Desktop 按相同设计语义迁移，并保留自身的宿主连接与路由；是否提取共享前端包须由真实调用方和稳定契约决定。独立前端和扩展组件的接入边界继续遵循[应用协议与组件宿主决定](0004-connect-replaceable-frontends-through-application-protocol.md)。

## 取舍与结果

页面各自定制样式初期更直接，但会让相同状态出现多套规则，也让主题和可访问性修正散落于调用处。只统一色值而不统一组件责任，仍需各页面重做控件状态。直接使用上游组件的全部默认样式和 token 则会把未使用的视觉语义带入产品，且不能保证满足 Repa 的状态区分与交互约定。因此选择语义契约、本地适配的基础组件和按实际需求扩充。

这使通用视觉变化需要先修改规范或基础组件，并验证受影响的调用方；本地持有上游源码也意味着升级不能无审查覆盖。换来的约束是：主题映射可以改变视觉值而不改业务含义，业务组件可以复用一致的控件行为，页面布局调整不重定义基础视觉。具体主题、组件清单与接入进度可以继续演化，记录在实现说明中。
