# 将 Pi 作为 Repa 的内部 Agent SDK

本记录约定目标架构；现有 TUI 的配置和运行方式见 [README](../../README.md#运行现有-tui)。

## Pi 与应用的职责

Repa 通过 Pi 的公开 Node SDK 调用 `createAgentSession`、`ModelRuntime`、`SessionManager` 和 `DefaultResourceLoader`。Pi 在 Repa 内部提供模型与 provider、Agent loop、Session、streaming、retry、token 估算与用量统计、compaction、通用工具以及 Package、Extension、Skill 和 prompt 的运行能力。

运行中输入投递、follow-up、图片输入、工具启停、模型选择与独立模型调用也优先通过这些现成入口接入。实现任务区分 SDK 能力接通与 Repa 特有行为；具名连接、持久请求或共享能力宿主的完整交付，不自动成为所有基础操作的前置。当前入口和适配差异由[Agent 开发说明](../development/agent-runtime.md#sdk-能力与接入范围)持有。

Repa 拥有用户面对的学习空间、学习语境、Application interface、配置与前端。Pi 的类型和生命周期集中在内部适配层，Pi 保持为实现依赖。会话适配层负责会话文件、历史消息、分支与运行实例的接入，应用层通过会话身份、历史快照和运行操作管理实际工作。Repa 通过公开入口复用符合产品契约的 Pi 通用工具与扩展格式；社区与 Repa 官方能力都可以使用兼容的 Pi Package、Extension 和 Skill 交付。

Repa 的产品责任分别由通用基座和官方能力承担。基座提供运行、内容、资源、权限与能力协作；学习语境的选择和组织规则、默认教学提示及复习等业务由官方学习能力提供。适用的背景快照、来源判定与 Pi 生命周期接入继续共用，运行宿主通过能力接入消费结果。默认安装组合完整可用；关闭学习组合后，通用 Agent、内容操作及其他已启用能力仍可使用。

通用能力的接入优先使用 Pi 已有的工具工厂、可替换操作接口和服务查询。会话工作视图复用 `SessionManager.buildContextEntries()`、`buildSessionProjection()` 等公开入口，Repa 补充自身语境消息的来源、快照判定和必要回填。工具的读取、输出处理及符合内容契约的编辑逻辑接入共同内容模块，命令工具通过执行接口接入相应环境；匹配与提交的协调仍由内容模块持有。Pi 行为存在差异时，参考 Codex 等成熟实现处理具体缺口，保留其他适用能力。固定版本的公开入口与编辑差异见 [Pi 当前版本核验](../research/pi-ecosystem-compatibility.md#12-pi-0871-的接入与升级)。

## 模型连接与凭据

模型连接直接在 Repa 中配置，支持 API key、本地模型服务及 provider 实际提供的登录方式。连接拥有独立身份，保存端点、provider 类型与认证关联，并可命名以区分服务或账号；改显示名称不改变身份。一次模型选择同时指定连接与该连接中的模型，作为一项完整设置保存与覆盖。模型列表及可用选项由相应适配器提供。空间与会话通过身份引用连接；空间搬移后找不到原连接时保留引用并提示重新绑定，也可显式恢复继承本机默认，不仅凭同名自动接入其他服务。

Repa 管理凭据的保存位置与连接关联，默认通过 `ModelRuntime.create` 的 `authPath` 选项使用 Pi 的凭据存取实现；需要适配其他存储时，通过 `credentials` 接入 `CredentialStore`。模型枚举、登录与认证状态管理继续复用 Pi。前端可提交凭据、发起或取消登录及注销，普通查询返回相应状态；公开配置、学习会话历史与学习语境不承载凭据明文或登录秘密。正常 token 续期继续服务同一认证身份，换账号或端点不在运行中途改写实际连接，主动注销按授权生命周期处理。适配层保留各调用绑定的连接配置与认证关联，多会话不通过交替改写同一个全局 provider 的 key 或端点选择连接。

## 设置与运行配置

可继承的运行设置由后端按应用默认、空间设置与会话选择解析，只允许适合相应作用域的项目参与覆盖。查询同时提供当前覆盖、有效值和来源；恢复继承删除当前作用域的覆盖，与空字符串、空列表等实际值分别表达。覆盖以设置定义的完整值为单位，列表整体替换，需要一起成立的值定义为同一项设置。显式设置无效时指出原因，不悄悄忽略并采用上层值。后端按项处理修改，避免多个前端整份覆写旧配置。

Pi 所属的运行设置通过 `SettingsManager` 的存储适配与覆盖入口接入，复用其加载、读写和重载能力。Repa 的作用域、有效值来源、完整值覆盖及具名连接语义仍由应用解释，不将 Pi 的默认全局与项目设置层级直接作为产品契约。

应用持有连接、默认运行设置、已安装能力及本机信任与授权；空间持有材料、语境、能力约定及可覆盖的设置；会话持有当前选择的运行选项，前端持有布局、主题、快捷键和草稿。启动独立运行的请求，包括明确排队的后续请求，在受理时绑定已经确定的连接、模型与运行选项；steer 只关联目标运行并沿用其配置。重复提交保留原归属与选择，后续常规设置变更不改写已经受理的请求。排队请求的学习语境在实际开始处理时取得。

运行中的模型调用、重试与压缩沿用该运行配置，事先配置的回退策略也包含在其中。运行记录保存解释实际工作所需的配置，不复制整个应用配置或凭据。包代码版本和入口实现的切换在相关宿主重启后用于新运行，已有实例保留实际代码；实际授权继续按当前状态检查。

插件在自己的命名空间下声明设置的类型、默认值、允许作用域和校验规则。宿主可提供基础设置界面，复杂交互也可使用插件组件，最终含义和校验由对应能力持有。持续维护的学习计划等属于文档，生成或处理这些内容的默认选项属于设置。需要模型的能力可以引用已有连接并声明自己的模型选择，不强制与当前聊天模型相同。禁用插件保留其设置，重新启用时由对应版本解释或迁移；普通配置只保存必要的凭据引用。

仅需要模型处理明确输入的能力可以直接复用 Pi 的 `ModelRuntime` 等调用接口；需要历史时读取明确范围的会话内容，需要推进学习会话时才提交相应会话请求。从 Agent 工具调用的处理归入本次工作，从前端直接调用的处理归入相应后台请求，复用既有取消与结果语义，不因使用模型而额外建立学习会话。

## 提示内容与自动注入

各提示来源按需配置与组合，覆盖基础提示、项目说明、Skill 清单与工具使用指导、学习语境、环境与文件变化提示，以及压缩、摘要等辅助模型调用的指令。官方提供默认的学习组合，工具说明由相应能力定义。

提示设置复用已有的应用、空间和会话配置及能力启用机制。同一来源的启用和覆盖状态由其原配置或能力持有，统一展示只聚合这些状态。查询提供来源、启用状态、覆盖关系和实际使用的内容；显式空内容与恢复默认分别表达。预览展示可确定的装配结果，动态能力贡献以实际调用时的结果为准，不为预览额外启动模型或运行任意有副作用的扩展。运行记录通过已有配置、消息和来源关联说明本次真正使用了哪些内容，不另建一套提示词历史数据库。

独立模型处理使用相应能力明确选择的提示与输入。

提示设置沿用运行配置的确定时机，已受理的选择不因之后修改默认值而改变；动态背景继续按各自的入口规则准备。同一运行及其 steer 沿用已经确定的基础配置，不在每轮工具执行后重复添加固定背景。关闭输入源后不再由适配层主动注入或补回该来源，已有对话记录与摘要保留其历史含义。

优先通过 Pi 的资源加载、系统提示覆盖和上下文、压缩等生命周期钩子接入。需要核对最终模型输入，避免只替换基础文本而保留未受控的 SDK 追加内容；固定版本的入口与限制见[提示与会话投影核验](../research/pi-ecosystem-compatibility.md#12-pi-0871-的接入与升级)。默认入口不能完整替换指令时，在相应适配点补齐，继续复用 Pi 的运行、计量和恢复机制。

## 连接失败与接续

临时模型连接错误沿用当前运行的重试策略；需要重新登录、修改连接或处理不兼容选项时，返回可处理原因，保留请求、交流历史与已完成工作。失败后选择继续，形成明确指向旧任务的新请求，在该任务所属会话的当前历史上接续；会话正在工作时将其排队。新请求绑定本次选择的配置，开始时使用当前文件与学习语境。原输入尚未进入会话历史时从受理记录补入一次，已经进入时不重复追加；后端不自动回放已完成工具，Agent 根据实际结果和当前内容决定后续操作。原失败记录保留，从旧节点建立分支仍是独立的显式操作。

自动更换模型须有已配置的回退策略，在模型调用边界接续并记录实际连接与模型；候选无法处理现有输入或所需工具时返回原因，不通过静默丢弃输入继续。

## 默认能力与扩展

官方安装包附带可以直接开展学习的默认组合，包含空间与会话入口、文档编辑、材料阅读、学习语境、基础工具，以及讲解、练习实验、整理、规划和交互展示能力。官方能力采用相同公开接口接入并支持替换或关闭，默认范围见 [README](../../README.md#默认学习能力)。未配置模型时本地内容能力仍可用，空语境允许开始交流。

默认启用的学习协作约定说明空间、语境、材料与长期内容的使用方式，具体方法说明按需取用；这些约定可以通过提示配置修改或关闭。默认学习组合中，模型结合实际目标与反馈决定解释、练习及安排，稳定计算和确定性检查由工具承担。Agent 在实际工作中维护值得跨会话保留的信息，文档与语境可持续修正，不要求固定课程结构或每次关闭时全量总结。

实际完成的产物、学习者的作答与掌握判断保留各自含义。Agent 提供完整帮助或生成通过测试的代码后，后续判断仍依据实际解释、尝试与反馈；既有会话和文档保存所需依据，不另设强制的逐次能力评分流程。

第三方能力通过明确的安装或启用操作进入，展示来源、版本、能力与执行环境，已启用能力沿用已有授权。空间中的扩展声明作为建议使用的能力展示，阅读资料与运行附带代码分别处理；本机信任和授权保存在应用侧，空间文件不能自行授予权限。

运行配置与代码版本的保留不固定后续操作的权限，实际操作按当前授权检查。授权请求、权限收回与相应执行环境的责任见[权限与执行环境的决策](0005-execute-display-content-with-host-permissions.md)。

Pi 承担 Agent 扩展的运行，前端宿主承担界面组件的加载；可替换前端、客户端与组件之间的责任由[公开应用协议的决策](0004-connect-replaceable-frontends-through-application-protocol.md)持有。

相关复用边界与一手来源见 [Pi 生态对 Repa 的可复用性调查](../research/pi-ecosystem-compatibility.md)。
