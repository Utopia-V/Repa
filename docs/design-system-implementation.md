# 设计系统实现说明

稳定规则由 [设计系统规范](design-system.md) 持有；本文记录当前实现与接入方式，不作为新增视觉规则的入口。

前端开发执行约束见 [apps/web/AGENTS.md](../apps/web/AGENTS.md)。

## 责任与文件位置

`docs/design-system.md` 定义语义 → `globals.css` 映射主题 → `components/ui` 实现通用组件 → 业务组件组合使用 → 页面布局。

- `globals.css` 内 `--theme-*` 是主题私有色值，仅用于定义语义变量；业务代码禁止引用。
- 公共 CSS variables 按规范中的色彩语义分层。Tailwind 的 `@theme inline` 将其映射为 `bg-primary`、`text-foreground` 等工具类，普通 CSS 可直接使用同名变量。
- 字体、行高、圆角、间距同样由此文件持有，不通过 JavaScript 注入 token，不维护第二份 JSON 色板。
- 字体文件来自 `@fontsource-variable` 的 Inter（带 `opsz` 轴）、Noto Sans SC 和 JetBrains Mono，随应用打包：页面 CSP 不放行外站样式表，桌面端离线时也要能显示。可变字体的 family 名带 `Variable` 后缀。CSP 也不放行 `data:` 字体，`apps/web/vite.config.ts` 因此让构建不内联字体文件。
- `components/ui` 使用 Fluid Functionalism 的 Base UI 版组件；涉及焦点管理、复合控件与键盘操作的行为复用 Base UI。输入法选字、Esc 逐层退出、失败保留草稿、减少动效和焦点恢复在基础层实现，测试在 `apps/web/test/base-behaviors.test.tsx`。
- 业务组件持有数据与业务状态，只组合语义组件。当前 `components/domain/conversation-message.tsx` 把发送方映射到 `MessageBubble` 的 variant，不另写气泡颜色。
- 页面负责布局，不持有通用组件样式。Web 与 Desktop 主应用的启动、失败重试、断线提示和工作台侧栏已接入；其他 Desktop 组件尚未迁移。

## 当前主题与适配

当前主题是组件库的中性色，强调色为 Sky（`--fluid-accent`）。`surface-inset` 映射到 `muted`；`border-selected`、`border-error` 分别映射到 `primary`、`destructive`；`ring` 映射到 `focus-ring`。Tailwind 打开了 preflight，根字号为 14 px，圆角在 `@theme` 里写成 px。修改主题时保持语义调用不变，并重新验证背景与前景配对。

语义名沿用 shadcn CSS variables，并加上组件库的 `surface-*`、`hover`、`active`、`selected`、`tint`、`z-*` 和 `fs-*`、`lh-*`。`--muted-foreground`、`--destructive` 与组件库的默认值不同，是为了满足文字对比度；`--input` 不同，是为了让输入框边界达到 3:1。

没有深色主题：`:root` 固定 `color-scheme: light`，`dark:` 只在 `.dark` 下生效。

## 主应用接入范围

Web 仅保留主应用入口 `apps/web/index.html`，主题由 `apps/web/src/globals.css` 唯一持有。Select 使用 Base UI 弹层，当前选中标记为勾选。Button 提供规范中的五种 variant。

运行 `npm run dev:web` 并访问主应用。Tailwind 构建集成在 Web Vite 宿主；主题由主应用入口引入；主应用 styles.css 仅保留基于 token 的宿主基础样式。

`npm run check --workspace=@repa/web`、`npm run test --workspace=@repa/web`、`npm run build --workspace=@repa/web` 验证类型、组件与构建。`apps/web/test/design-system.test.tsx` 覆盖主题对比度、选择/焦点独立性、按钮提交语义和进度可访问值。浏览器验收还需检查移动端、键盘 ring 和更换完成色后主要行动保持原色。

实现来源见 [通用组件说明](../apps/web/src/components/ui/README.md)。

```text
  → apps/web/src/globals.css
  → apps/web/src/components/ui
  → apps/web/src/components/domain
  → layouts / pages / features
```

| 修改内容 | 所属位置 |
| --- | --- |
| 语义和可判定约束 | docs/design-system.md |
| 色值、字体尺度、圆角、留白和尺寸 token | globals.css；不新增 tokens.ts |
| 通用 variant / size / hover / active / focus | ui 组件及其 CVA；跨控件的 CSS 由 ui/styles.css 持有，通过 globals.css 加载 |
| 业务状态与基础组件组合 | domain/app-sidebar.tsx、connection-state.tsx、conversation-message.tsx、error-notice.tsx |

`SelectionButton` 统一持续选择的背景、可见标记与键盘焦点，用于目录、筛选和拓扑节点；`SearchInput` 组合 Input 和 Button，页面不再通过子元素选择器改写输入框圆角。`ConversationMessage` 将 sender 映射到 `MessageBubble` 的 variant；通用气泡视觉由 ui 持有。没有真实调用方的业务组件不预建。

Desktop 没有自己的界面：renderer 就是 `apps/web`，由 `apps/desktop/electron.vite.config.ts` 按 Web 自己的 Vite 配置以 desktop 模式构建和开发，所以组件、主题和路由只有 Web 一份。页面运行在桌面端时，preload 在 `window.repaHost` 上提供连接和“在文件夹中显示”，见 `apps/web/src/lib/host.ts`；窗口保留原生标题栏。

Desktop 验证入口为 `npm run check --workspace=@repa/desktop`、`npm run test --workspace=@repa/desktop` 和 `npm run build --workspace=@repa/desktop`；界面本身的测试在 Web。

## 组件调用边界的落实

- `SelectionButton` 持有持续选择外观。调用方只传递 selected、标签和布局位置，不通过 className 拼接 accent 或边框状态。
- Card 的 16 px 内距由 Card 根节点统一提供；Header、Content、Footer 不再追加水平 padding，页面不得覆盖 Card 内距。
- `SearchInput` 要求 label，并使用关联的可见标签；消息输入框按规范的例外不显示标签，以 `aria-label` 提供名称。placeholder 仅作为示例。
- `components/ui/styles.css` 在减少动态效果偏好下关闭所有元素的 animation 和 transition，Motion 的动画由 `lib/fluid-provider.tsx` 跳过。

## 主应用入口

`src/app.tsx` 继续管理连接获取、启动重试、连接监听和卸载清理；不在 UI 迁移中改变协议或客户端生命周期。`components/domain/connection-state.tsx` 组合 Card、Button 与 ErrorNotice 呈现启动及连接状态，`workspace-layout.tsx` 组合应用侧栏与路由出口。`src/routes.tsx` 持有工作台路由。

调用失败统一经 `src/lib/errors.ts` 的 `describeError` 转成标题与说明，再由 `components/domain/error-notice.tsx` 组合 `StatusNotice` 显示。后端业务错误（`RpcError.data.code`）直接使用后端返回的中文说明；协议层错误只显示通用说明，不展示英文原文；`ConnectionError` 提示操作结果未确定，重连后重新读取状态。开发模式下另以等宽小字显示错误码和 `details`。新底座不再提供业务请求编号，排查以错误码为准。

主应用 `src/main.tsx` 加载 globals.css；旧 styles.css 的硬编码配色、渐变、卡片阴影和按钮外观已移除。断线提示位于文档流中，保留路由内容并避免遮挡页面。工作台默认进入“学习空间”；Web 显示最近空间列表，Desktop 仍为材料选择页。

## 应用状态

页面要读后端数据，而连接会在断线后换成新的 `RepaClient`，读取结果也需要在多个页面之间共用，因此 Web 用一个 Zustand store 持有这些状态。`src/lib/store.ts` 的 `createAppStore()` 创建 vanilla store，`src/main.tsx` 创建实例并传给 `App`；`hooks/use-app-store.tsx` 的 `StoreProvider` 把它交给路由内的页面，页面通过 `useAppStore(selector)` 选取需要的字段。测试每次新建 store，不共享模块级单例。

从后端读取的数据统一用 `Resource` 表示：`status` 为 idle、loading、ready 或 error，重新读取期间保留上一次的 `data`，界面不会回到空白。同一份数据只保留一个进行中的读取，并以序号丢弃先发后到的旧结果。`App` 连接成功后调用 `setClient`，store 换用新连接并重新读取已经读过的数据；标签页切回可见时 `StoreProvider` 也会重新读取，因为后端不推送设置和空间列表的变化。修改类操作（目前是 `openSpace` 和 `closeSpace`）把失败抛给调用页面，由页面在本地状态里显示进行中与失败。

目前 store 持有最近空间（`space.list`，最新的在前）、模型提供方（`model.providers`）、模型列表（`model.list`）、默认模型（`model.getDefault`）、当前空间的会话列表（`session.list`，换空间时清空）、当前空间最近的修改历史（`history.list` 与 `history.changes`，换空间时清空）、当前空间的提示各段与应用级提示覆盖（`prompt.list` 与 `settings.get` 的 `prompts`，换空间时清空）、本页面打开的空间、当前会话、待回答的命令授权、自写插件的批准与 MCP 调用的确认、MCP 服务器列表（`mcp.list`，随 `mcp.updated` 更新）、进行中的模型登录和侧栏偏好；侧栏偏好、打开的空间和当前会话的 id 保存在浏览器里，刷新或重启后读回。后端没有查询当前空间的方法，`setClient` 每次连上（包括启动后第一次连接）都对保存的空间调一次 `space.open`：同一个空间后端直接返回，后端重启过则重新打开；打开期间 `session.*`、`history.*` 和 `prompt.*` 请求等它结束再发。打不开时清空空间并记下原因，选空间页显示“无法打开上次的空间”；连接中断导致的失败保留空间，重连后再打开。关闭空间会清掉保存的空间，下次启动回到选空间页。会话列表、修改历史和提示依赖打开的空间，不随其他数据在换连接时直接重读，而是在空间重新打开之后再读。`setClient` 同时在新连接上订阅 `session.event` 和 `confirm.request`，旧连接上的授权请求随断线由后端取消，store 一并清空。


## 工作台侧栏

- `components/ui/sidebar.tsx` 的结构来自 shadcn 官方 `new-york-v4/sidebar.json`，底层是 Base UI，颜色和字号用组件库的 token，包含本次使用的 Provider、Sidebar、Trigger、Rail、Header、Content、Footer、Group、Menu 与 Submenu 组合；未引入没有调用方的 Input、Skeleton、Tooltip 和菜单附件。
- `SidebarRail` 是侧栏边缘的 16 px 手势条，点击切换展开/收起，悬停显示 2 px 中性 `border` 竖线；支持拖动调整宽度、双击重置，键盘方向键调整、Home 重置、Enter/空格切换；上游的 offcanvas 类保留但当前未被使用。
- `layouts/workspace-layout.tsx` 通过 SidebarProvider 组合应用侧栏、打开入口和空白路由出口。桌面展开宽度 280 px，收起为 56 px 常驻图标栏（`collapsible="icon"`）；移动端由官方 `useIsMobile` 与 Sheet 切换为侧边面板。桌面折叠栏自带展开入口，工作区只在移动端渲染浮动打开按钮。桌面可拖动至 200 px—480 px，最大不超过视口的 40%；拖至最小宽度以下收起，折叠时向外拖至 200 px 展开阈值才展开，小幅拖动保持折叠；展开使用完整过渡并结束本次拖动。桌面的展开状态和宽度由 Zustand store 的 `persist` 写入 `localStorage`（键 `repa.web.preferences`，和打开的空间、当前会话 id 存在一起），刷新后保留；存储不可用时退回默认展开、默认宽度，格式不对的项逐项回到默认值；移动端抽屉每次从关闭开始，不保存。拖动期间用 80 ms 短过渡平滑调整宽度，跨过收起阈值时恢复完整折叠动画，取消、失去指针捕获或卸载时清理拖动状态。
- 折叠栏沿用 SidebarMenuButton 的 token 与交互状态，通过 `sr-only` 保留标签的可访问名称，并用 `title` 提供图标提示。侧栏支持拖动调宽、收起与展开；移动端复用 Sheet 的关闭、Escape 和焦点恢复行为。
- Web 的 `components/domain/app-sidebar.tsx` 顶部列出当前空间里的课与最近的空间，底部的 `SidebarFooter` 固定放“修改历史”和“设置”；内容区随会话增多滚动，底部两项不动。没有打开空间而且没有最近空间时只有“学习空间”一项，进选空间页（第一屏）。否则先列当前空间里的课（`courses.list`），名称取课的标题，还没做好的课取文件夹名；点一门是选中它，学习页的课程制作面板与课程全貌换成这门课，菜单仍是几门课合起来的一份，选中哪门是界面自己的状态。其下按 `space.list` 列出最近的五个空间，名称用文件夹名，悬停显示完整路径：当前打开的空间用打开的文件夹图标，下面挂着它的会话，点它进选空间页（在那里看全部、关闭空间）；别的空间用合上的文件夹图标，点了就经 `space.open` 换过去并进入它的首页。运行中换空间会中止运行，所以别的空间不能点，悬停提示原因。更早的空间不列，经当前空间进选空间页。列表下面是“新建课程”，进 `/new-space`：打开着空间时是在这个空间里建 `courses/<名>/` 的表单，建好后选中新课并进学习页；没有打开空间时与第一屏是同一个组件，只换标题，“选择文件夹”仍是次要动作。刷新或重启后 store 读回保存的空间。空间下面的二级列表由 `components/domain/session-list.tsx` 渲染，只列学习者自己用“新会话”开的通用对话：辅导 Agent 的会话和学习插件记下的做课对话在学习页右侧已经能看到和继续，后台任务的会话（`background`）不是对话，都不列。第一项“新会话”从任意页面开始一个还没建立的空会话并进入对话页；其后是这些会话，最近有消息的在前，名称取会话名，没有时取第一条消息的开头，悬停显示全文，点击打开该会话并进入对话页。在对话页时，当前项标在二级列表上：正在查看的会话，或还没建立的新会话时的“新会话”；在选空间页时，当前空间是当前项；在学习页时，选中的课是当前项。运行中其他会话和“新会话”不能点，因为运行状态只属于当前会话，切走后无法再查询。会话还没有分页。收起为图标栏时只剩各项图标，名称和二级列表隐藏。窄屏的抽屉导航是同一个组件。“修改历史”只在打开空间后出现，进入这个空间的修改历史页，见下方“修改历史页”。“设置”目前有模型设置、命令授权和提示，见下方“设置页”。侧栏不再显示 Chat、示例会话、Goals、Wiki、Sources 或本地空间提示卡，布局不再保存会话展开状态。
- `/` 重定向到 `/learning-space`，未知地址显示未找到页面，两者共用工作台布局。Desktop 另有内容为空的 `/settings`。

## 学习空间页面

Web 的 `pages/learning-space.tsx` 按有没有最近空间分成两种布局。第一次使用时没有可以继续的空间，页面问这门课叫什么；还没有可用的模型时，标题下先提示“还没有可用的模型”并给出“去设置模型”，与学习页做课起点的提示相同，建课本身不受影响：一个输入框，下面写出空间会建在哪里（“我的 Repa 文件夹”下的 `<名称>`，没起名时只写 Repa 文件夹），旁边的“更改位置”（文字待写）打开同一个文件夹浏览框，选定的文件夹叫 Repa 就用它，否则用它下面的 `Repa`，与 Windows 安装程序选安装位置的做法一致；已有的学习空间不能选。Repa 文件夹缺省是用户主目录下的 `Repa`（三个系统相同，主目录取自不带路径的 `space.browse`），选过以后记在浏览器里，下次新建仍放在那里；C 盘小的学习者靠它把课放到别的盘。启动时上次的空间打不开（例如课程文件夹被移走）而没有别的最近空间时，这一屏标题下同样说明原因，学习者用“选择文件夹”从新位置打开它。主按钮调用 `space.create` 并带 `fresh: true`，建好后打开并进入学习页的起点。名称里有三个系统中任一个不能作文件名的字符、是保留名或以点、空格结尾时，输入框标为错误并说明，按钮不可用；那个文件夹已有别的内容时后端以 `directory_not_empty` 拒绝，原因显示出来，输入保留，不替学习者改名。“选择文件夹”退为次要动作，行为不变。这一块在工作区里水平、垂直居中，底部留白略多，视觉重心稍高于几何中心；有最近空间的布局保持靠上，列表长短变化时标题不跟着移动；有最近空间时，继续学习是主要任务，页头右侧的“选择其他文件夹”退为 Outline，下面是“最近打开”区块。最近列表读完之前只显示读取提示，不先显示首次引导；读取失败时在区块内显示原因和重试，此时“选择文件夹”回到 Primary，仍可通过选择器进入。列表每一项用整行 `SelectionButton` 显示文件夹名和完整路径，本页面打开的空间处于选中状态，右侧有“关闭”：调用 `space.close`，成功后 store 清空这个空间的会话、会话列表、修改历史和待回答的授权，页面停在选空间页；后端关闭空间会中止正在进行的运行，所以运行中不能关；关闭失败时原因显示在区块标题下方，空间仍按打开处理，后端报错时其实已经放下了这个空间，再关一次就能完成。点击打开的空间同样进入对话页。点击后该项显示“正在打开…”，其他项暂时禁用，失败原因显示在区块标题下方。窄屏下页头按钮移到描述下方并撑满宽度。选择框挂在两种布局之外，读取完成引起布局切换时不会被卸载。打开空间后进入对话页。后端只记录最近空间的路径，没有打开时间；`space.list` 只返回文件夹仍在的那些，课程文件夹被移走或删除以后不再列出，从新位置打开一次就排到最前。原材料选择组件只把文件暂存在页面内存，新底座也没有上传入口，已从 Web 移除。`test/learning-space.test.tsx` 覆盖两种布局、按钮主次、列表、打开后进入对话、打开失败和读取失败重试。

浏览器拿不到本地文件夹的绝对路径，所以页面上的“选择文件夹”由后端浏览文件夹：`features/folder-picker.tsx` 在 Dialog 中调用 `space.browse` 从用户目录开始，一层层点进子文件夹。含 `.repa/` 的文件夹标“已有空间”，当前文件夹底部只有一个“打开”，调用 `space.open`；当前文件夹还不是空间时提示会在里面保存 Repa 的数据，第一次打开时由后端建立 `.repa/`。走到盘的根目录后，“上一级”改为显示 `space.roots` 返回的磁盘列表，Windows 用户由此换到其他盘；mac/Linux 只有 `/`，到根目录后“上一级”禁用。浏览结果只属于当次选择，不进入 store 的共享数据；每次导航后焦点移到当前位置标题，读取失败时停留在原位置并显示原因。`test/folder-picker.test.tsx` 用模拟的 Windows 盘符布局覆盖浏览、已有空间标记、打开、换盘、无权限和打开失败。Desktop 计划改用系统文件夹选择框，随 Desktop 跟进 Web 时接入。

Desktop 仍由 `pages/learning-space.tsx` 居中显示 `components/domain/learning-upload.tsx`：它负责材料拖拽、多文件选择、去重和移除，相邻 CSS 只使用语义 token；“开始学习”不触发上传，保持禁用。Web 定型后 Desktop 再随之调整。

## 对话页

Web 的 `pages/conversation.tsx` 挂在 `/conversation`，没有打开空间时重定向回 `/learning-space`；首页 `/` 有保存的空间时进入对话页，没有时进入选空间页。会话 id 不放进 URL，而是和空间一起由 store 保存在浏览器里：后端一次只持有一个活动空间，URL 里的会话离开它所在的空间就没有意义。进入页面时读取 `session.list`，打开上次查看的会话；它不在列表里，或上次停在还没建立的新会话时，打开最近有消息（`updatedAt`）的会话，再读它的 `session.history`。子 Agent 的会话也在 `session.list` 里，带 `parent`，用户不能直接对话，store 读取时就滤掉，侧栏不列出，也不会被自动打开；在侧栏的会话列表里可以切换到其他会话；空间里还没有会话，或点了“新会话”，都等第一次发送才调用 `session.create`，不留下空会话。

输入框下方的 Ghost 按钮显示当前会话的模型。Pi 把模型保存在会话里，已建立的会话一直沿用自己的模型，默认模型只决定新会话用哪个；所以这里显示 `session.list` 给出的会话模型，还没建立的会话显示选中的或默认模型。点击打开 `features/model-picker.tsx` 的会话版本，只列已连接提供方的模型：已建立的会话调用 `session.setModel`，还没建立的记下来，在 `session.create` 时传入；两种都不改默认模型。模型的提供方没有连接时（例如之前的提供方已断开），按钮旁提示发送会失败。运行中不能换。

显示内容由 `lib/conversation.ts` 转换：`historyItems` 把会话记录转成用户消息、助手消息、工具调用、错误、“已停止”和压缩标记，提示、视图、用量等运行细节不显示；`applyEvent` 按 `session.event` 实时更新，`textDelta` 拼到正在生成的助手消息上，完整的 `message` 覆盖拼接结果，工具调用按 `callId` 更新状态。模型请求失败的那一项带后端给出的原因 `failure`，按原因说一句话：连不上、key 无效（另给去设置模型的入口）、余额不足、请求过于频繁、服务端出错、其他，提供方的原文折叠在下面。Pi 自动重试过的几次失败在记录里标为 `retried`，不显示，一次失败只说一次；实时显示的是运行一级的 `model_error`，出错的助手消息本身不带错误项。运行结束（`runEnd` 或 `session.send` 返回）后重新读取会话记录，以记录替换实时内容。store 只处理当前会话的事件。

想从某条回答换个方向接着问，可以点这条回答下方的“从这里分叉”。`session.fork` 由 Pi 复制整个会话文件，再把新会话的位置停在选中的条目上，所以新会话包含这条回答和它之前的全部内容，用分叉点那时记录的模型，原会话不变。store 的 `forkSession` 分叉后打开新会话并重新读取侧栏列表，页面把焦点移到输入框。新会话的 `updatedAt` 是分叉的时间，排在列表最前；`preview` 仍取第一条用户消息，会话名也一起复制过来，所以侧栏里它和原会话同名，只能靠当前项区分。只有结束一轮的回答可以分叉：带工具调用的消息后面还缺工具结果，出错或停止的回答不完整；实时拼出的消息还没有记录里的 id，`historyItems` 读回记录后才标出 `forkable`。按钮是 Ghost 图标按钮，能悬停的设备上悬停或键盘聚焦到这条消息时才显示，触屏上一直显示；隐藏时只是透明，仍在 Tab 顺序里。运行中不能分叉，失败原因显示在输入框上方。

没有做成 Pi `/fork` 那样的“编辑并重发”：Pi 从用户消息之前分叉，并把原文放回输入框，而 `session.fork` 保留到选中的条目为止，从用户消息分叉会留下一条没有回答的提问。在用户消息之前分叉需要它的上一个条目，会话记录不公开 `parentId`，也不包含模型切换等条目，页面推断出的位置可能丢掉这些条目，所以等后端支持后再接。

`session.send` 要等整次运行结束才返回。运行中发送按钮旁多出“停止”，调用 `session.abort`；发送仍然可用，消息经 `session.steer` 交给 Pi 的队列，Agent 做完当前这一步（这次回复及其工具调用）后、下一次请求模型前读到。这里只用 steer、不提供 follow-up：学习者在运行中补充的通常是“没看懂”“换个例子”这类纠正，应当尽早影响回复；只有一个发送入口，也不需要先弄清两种排队的区别。Pi 在终端里同样以 Enter 为 steer。排队的消息先以用户消息加“排队中”的说明显示在对话记录末尾；后端不转发队列变化，送达时 Pi 发出的用户消息事件按文字对应到排队的那条（Pi 自己移出队列也按文字匹配），再换成记录里的用户消息。停止时后端清空队列，和 Pi 一样把没送到的消息放回输入框，排在正在写的内容前面。运行刚发起、还没收到 `runStart` 时和停止中不能发送：前者没有可以排队的运行，后者再发的消息会被一起取消。模型出错和取消已写进会话记录，由记录显示；没写进记录的失败（例如连接中断）显示在输入框上方，消息内容退回输入框。进入对话页时读取 `model.getDefault`、`model.list` 和 `model.providers`；当前会话还没有模型且默认模型为 `null`（没有可用模型），或发送时后端报 `model_required`，输入框上方改为显示“还没有可用的模型”和去设置页的链接，不再重复显示错误。连接中断时运行状态无法查询，从空闲开始，收到事件再更新。

页面占满一屏，只有对话记录区滚动，输入框留在底部。顶栏只占一行，铺满工作区宽度：左侧只显示空间名称，过长时截断，悬停显示完整路径；“新会话”是工具栏里的轻量操作，用 Ghost 按钮靠右；对话记录滚动离开顶部后才出现分隔线；移动端左侧让出浮动的导航按钮。对话记录停在底部附近时跟随新内容，往上翻看时不打断。`components/domain/message-composer.tsx` 用 `InputGroup` 把文本框和发送／停止按钮合成一个框（两个按钮都是带可访问名称的图标按钮，发送用 Primary，停止用 Outline），聚焦时边框加深为 `input-focus` 色并加阴影，不加粗，文本框随内容增高，最高 240px 且不超过视口高度的 35%，超出后在框内滚动，长行在框内折行、不撑宽页面；Enter 发送、Shift+Enter 换行，输入法确认候选词的 Enter（`isComposing` 或 Safari 的 `keyCode` 229）不发送；`components/domain/tool-activity.tsx` 用图标加文字显示工具状态，内置工具显示动作名称。用户消息按原文显示并保留换行；助手消息由 `components/ui/markdown.tsx` 渲染成 Markdown，正在生成的那条传 `streaming`。

`Markdown` 用 react-markdown 解析，插件分工如下：`remark-gfm` 负责表格、删除线和任务列表；`remark-cjk-friendly` 及其删除线插件让中文标点旁的 `**`、`~~` 生效；`remark-math-extended` 识别 `$…$`、`$$…$$`、`\(…\)`、`\[…\]`，由 `rehype-katex` 渲染，写错的公式显示原文。单个 `$` 也按公式解析，“$5 和 $10” 这类金额会被误认，学习场景下接受这个代价。单个 `~` 不算删除线，`20~25` 保持原样。生成中先经 `remend` 补全没写完的加粗、行内代码、链接和 `$`/`$$` 公式；`\[…\]` 不在它的补全范围内，结束符到达前显示 TeX 原文。组件用 `memo` 包住，文字没变的消息不重新解析；只有正在生成的那条随增量重新解析，长回复的开销尚未单独测量。

元素样式由组件内的 `components` 映射到 token，不使用 typography 插件：Markdown 标题整体下移两级（`#` 渲染为 h3），字号不超过 Body Large；代码使用 Code token 和 `font-mono`（`globals.css` 把它映射到 `--font-code`），代码块和表格、公式块在各自区域内横向滚动。原始 HTML 按文本显示。只有 http(s)、mailto 渲染成新标签页链接，相对路径只显示文字；图片不加载，显示为指向原地址的“[图片：说明]”链接，避免向第三方暴露访问并避免显示模型编造的地址。代码块用 Shiki 按标注的语言高亮，目前只带 Python（py）、JavaScript（js）、TypeScript（ts）、Bash（sh）和 JSON，其他语言和没标语言的代码块按纯文本显示；代码块统一是深色底，语法颜色来自 Shiki 内置的 Catppuccin Mocha 主题，底色、正文和语言标签走 Code token；行内代码保持浅色样式；高亮出错时保留原样的代码块。复制按钮尚未接入。

Pi 在上下文快放不下时会自动压缩：把较早的对话写成摘要，之后 Agent 读摘要和最近的对话。界面上的对话记录不删除，压缩条目的位置显示“已压缩上下文”标记，摘要本身不显示。学习者一般不需要关心上下文长度，所以对话页不提供手动压缩。

Agent 调用 `bash` 或开着调用前询问的 MCP 工具时后端发出 `confirm.request`。`features/command-confirmation.tsx` 挂在工作区布局上，离开对话页也能看到，显示命令和“拒绝／允许”，关闭对话框按拒绝回复；登录用的 input、select、display 请求由设置页的登录流程处理，没有进行中的登录时 store 直接回复取消，避免后端停在等待上。后端取消运行时不撤回已发出的授权请求，`sendMessage` 结束时清空。

Agent 写好的自写插件要学习者批准才加载，后端同样发出 `confirm.request`，`kind` 为 `plugin`。`features/plugin-approval.tsx` 与命令确认并列挂在工作区布局上，显示插件的名称、id、版本、页面和文件清单（每个文件标新增、修改或删除）；批准回复 `true`，拒绝回复 `false`，关掉对话框回复 `null`，后端记为没有作出决定。批准时插件的代码还没有运行，它带来哪些工具要加载以后才知道，所以不列工具。

Agent 或插件在对话里提问时，后端发出 `ask.request`。Web 在 `RepaClient.connect` 的 `capabilities.interaction` 里声明能显示的作答位和内容块，定义在 `lib/ask.ts`：选择、填写两种作答位，Markdown、代码块和公式；排序、表格、代码作答位和图片块还没有做，后端不会把需要它们的题发来，前端宽松读取后仍有不认识的必需特性时回复 `unsupported`。store 按到达顺序保存当前会话的询问，换会话、换空间或关空间时清空。`components/domain/ask-card.tsx` 显示在发起它的工具调用（`origin.callId`）下面，找不到那次调用时放在记录末尾。

卡片按题面、每一问的题面和作答控件排列：单选用单选组，多选用复选框，带“其他”时旁边是自填输入框，开始填写就选中“其他”，单选时同时放下已选的项；填写按 `lines` 用单行或多行输入框，`format` 为数字时给数字键盘，`quick` 是一键填入的按钮。多选题的题面后面加“（可多选）”，可以不答的小问加“（可不答）”；模型调用 `ask_user` 时常在题面里自己写“可多选”，题面文字里已经有“多选”时就不再加，免得显示两遍。Markdown 块只在 `math` 为真时排公式，而 `ask_user` 生成的内容块目前不带 `math`，所以它出的题里公式显示原文，要等后端给这些块标上 `math`。

提交调用 `ask.reply` 的 `submit`，只交动过的小问；没答的必答题等由后端检查并退回，问题标在对应的小问下面并关联到控件，卡片不关，可以改好再交。右上角的“关闭提问”回复 `cancel`。后端接受作答（`accepted`）后卡片收起成问题和回答，结果附了内容块时显示在回答下面；关闭、运行停止、空间关闭和断线时只留一行说明。判对错和作答记录归学习插件，询问卡片不显示判分。等待作答时不再显示“Agent 正在处理”。

卡片开着时 Agent 停在这次询问上，排队的消息要等它结束才读到，所以输入框发出的话代替作答：用 `decline` 把这句话交回 Agent，卡片收起成这句话；输入框的占位文字和卡片底部都说明这一点，和 Claude Code 的做法一致。重新读取会话后，`ask_user` 的提问按会话记录里工具结果的 `details`（`{ item, outcome }`）显示成已结束的卡片：答过的显示问题和回答，回了一句话的显示这句话，关闭的和界面显示不了的各留一行说明；同一次调用还有本页面的实时卡片时只显示实时的那张。运行中止或断线结束的提问，以及插件经 `context.ask` 发起的询问，记录里没有这些内容，仍只剩“向你提问”这一行工具记录。要在记录里照原样显示问题和回答，后端需要两处改动：`session.history` 的工具记录目前不带工具结果的 `details`，而 `ask_user` 的 `details` 只记了题目的 id、版本和作答结果，没有题面。


顶栏“新会话”左边是“反馈问题”。点开后可以写一句哪里不对，勾选“让 Agent 描述这次的问题”（默认勾选，会用当前模型多调用一次，不带工具），再点“生成反馈包”。store 的 `createFeedback` 调用 `feedback.create`，把对话里显示过的错误和发送失败的原因作为 `clientErrors` 一起带上；这些项没有时间戳，`time` 记的是收集的时刻。生成后对话框显示 zip 的完整路径，并请宿主在文件管理器里选中它；打不开时留下路径，用户可以复制或重试。运行中、未连接、还没有会话时按钮不可用，生成期间对话框不能关闭。

打开文件夹由宿主负责。开发时是 Vite 开发服务器的 `POST /__repa/reveal`：只接受同源请求、绝对路径和 `repa-feedback-*.zip` 文件名，macOS 用 `open -R`，Windows 用 `explorer.exe /select,`，其他系统打开所在文件夹。Desktop 还没有对话页，没有接这个入口。

`test/conversation.test.ts` 覆盖记录（含压缩标记和 `ask_user` 保存的提问）与事件的转换和可以分叉的回答，`test/conversation-store.test.ts` 覆盖按最后消息打开会话、子 Agent 的会话不列出也不打开、切换会话与运行中不切换、给新会话或已建立的会话换模型、从回答分叉并打开新会话、换空间清空会话列表、关闭空间清空会话状态与运行中不关闭、延迟建立会话、实时显示与运行结束后替换、失败分类、停止、运行中排队与送达、排队失败、授权排队和重连后重新打开空间，`test/conversation-page.test.tsx` 覆盖页面的发送、输入法回车、停止、运行中继续发送与排队显示、停止后排队消息回到输入框、失败退回输入框、授权对话框、两种发送者的显示方式、会话模型的显示与更换，以及分叉后打开新会话并聚焦输入框、运行中禁用和分叉失败，`test/markdown.test.tsx` 覆盖 Markdown 元素、两种公式写法、链接与图片限制和生成中的语法补全。`test/ask-card.test.tsx` 覆盖询问卡片的位置、单选与自填、退回问题关联到控件、交后收起、多选与接受时附的说明、关闭、运行中止与断线、显示不了的题回复 `unsupported`、输入框代替作答、题面已写“可多选”时不重复提示，以及重新读取会话后按记录显示的三种结局和实时卡片优先。

## 学习页的做课

`pages/learn.tsx` 除了任务和菜单，还按学习插件的 `building.get` 显示做课。store 的 `learning` 随学习状态一起读做课的状态和设置，收到 `building.changed` 时重读。

- **起点**：一个空间只学一门课，起点只属于还没有选定课的空间：`building.get` 里既没有自制课也没有做课的对话，手上没有进行中的任务，而且学习记录里还没有任何事实（`state.get` 的 `revision` 为 0）或者根本没有可学的课。这时整页只有 `features/making-start.tsx`：`materials/` 里的课件（文件名与页数、张数或段数，读不出文字的照课件插件给的原因标出）、添加课件、可不填的要求和“开始”；标题栏不显示随包课的课名和今日 XP。有随包的课时，“开始”旁有一个次要动作改学它，页面随即回到原来的菜单；开始一节以后有了学习记录，起点不再出现。已经有学习记录的随包课空间与以前一样。没有可用模型或没有课件时“开始”不可用。
- **添加课件**：`features/file-picker.tsx` 与选文件夹的做法相同，从用户目录开始，由后端列目录（`space.browse` 带 `files: true`），文件夹点进去，选中的行整行换底色（`OptionRow`）。文件只列课件插件读得了的格式，扩展名取自 `@repa/materials/protocol` 的 `MATERIAL_EXTENSIONS`，作为 `extensions` 交给后端：从用户目录开始时，课件不能淹没在系统文件里。复制进来以后课件插件按内容判断，读不出文字的卡片上写明原因。学习者在几个文件夹里勾选文件，课件插件的 `add` 按路径复制进 `materials/`；失败时对话框留着，显示原因，勾选不丢。
- **开始**：store 的 `startMaking` 新建通用 Agent 的会话，调用 `building.begin` 记下它、取回第一条消息，再像普通消息一样发出，复用 `sendMessage` 的发送流程。
- **做课没有成功**：做课的对话已经接上、运行已经结束（出错、被停止，或者做完了也没有课）而还没有课时，主区域不再显示“正在……”，改为如实说上一次没有成功；在右侧的对话里再说一句就能接着做，输入框在运行结束后照常可用。
- **辅导栏与参考内容**：不能问辅导（`tutorAllowed` 为假）而且不允许看参考内容（`referenceContentAllowed` 为假）时，例如复习和测验，辅导栏不显示以前的记录，只留提示；任务结束后记录照常出现。新课作答阶段按后端给的这两个值处理，不另立规则。
- **标题栏**：起点出现时，以及做课进行中、还没有换用过自制课时，只写页名，不显示随包课的课名和今日 XP。
- **做课的对话**：没有学习任务而有做课的对话时，右侧（窄屏是抽屉）是 `features/making-panel.tsx`，有学习任务时仍是辅导。会话记录、提问卡片和排队的消息由 `features/conversation-transcript.tsx` 显示，对话页共用它；连续的同名、已完成的工具调用合成一行并标出个数，进行中、失败的和向学习者提问的调用照常单独一行。接上这段会话由学习页调用的 `useMakingSession` 负责，不随抽屉开关，提问不会因为换会话被清掉；窄屏时 Agent 提问，抽屉自己打开；新到的提问卡片让开头落在可见范围的上沿，而不是滚到底只露出最后一问。做课和辅导用到的插件工具（`materials_list`、`materials_read`、`course_check`、`course_use`、`course_brief`、`learning_task`、`learning_search`、`learning_read`）在工具活动里有自己的名称。插件在后台发起的会话（`session.list` 里带 `background`）不进侧栏，也不会被自动打开。辅导栏不能问时分两种提示：复习、测验期间一种，新课里题目在等作答（`restrictions.kind` 为 `none`）另一种。
- **整门课**：`features/course-outline.tsx` 在菜单之后。标题下是花费（两位有效数字的美元，`unpriced` 不为零时加一句），同一行右边是自动展开的开关；下面是正在展开的部分与取消、最近一次没有成功的原因与再试（`failed` 的 `message` 照 `ErrorNotice` 显示）；各部分的清单按课程顺序列出标题、范围、出处和状态，状态用图标加文字，还是轮廓的部分可以“先做”。还没有能学的部分时清单展开，有了以后收起（只有轮廓时展开过也一样）。有学习任务时整门课这一节不出现，任务结束回到菜单时再出现。做课的 Agent 正在运行时，“先做”和“重试”不可用：它和后台展开会同时改 `course/`。还没有能学的部分时不显示菜单：这时菜单那句“现在没有可以开始的内容”不贴切，学习者正在和 Agent 商量轮廓。

`test/making.test.tsx` 覆盖起点与开始、新空间整页是起点与改学随包课、有学习记录的随包课空间不变、没有模型、添加课件、整门课的各项操作、后端拒绝展开、只有轮廓时不显示菜单与工具活动的合并、窄屏抽屉、做课的会话在对话页打开，以及插件批准。

## 学习页的测验

测验和重考与课、复习共用 `features/learning-task.tsx`，按[测验与 XP](development/learning-quiz-xp.md) 的契约接入；还没做完的部分见 `npm run verify` 的 `quiz` 步骤里的预期失败。

- **头部**：标题只写“测验”或“重考”，旁边是第几题（当前作答或判分中的那份作答所属的交付，在 `deliveries` 里的位置）和剩余时间；不列全部 topic 的名称，也不显示知识点进度。结束以后不再写题号和剩余时间。
- **剩余时间**：`components/domain/quiz-clock.tsx`，显示到秒，秒向上取整。截止时间是服务端时间，按读到状态时 `serverNow` 与本机时间之差换算（`lib/countdown.ts`，菜单的恢复时间用同一个换算）；同一场测验里只减不增，重新读取时网络延迟或本机时钟回拨不会让它往回跳。Badge 始终是灰色；最后 1 分钟秒表换成闹钟，最后 10 秒闹钟图标以 `animate-breathe` 每秒明暗一次，数字不动，减少动态效果时不动。计时区域是 `role="timer"`，读屏软件只在跨过 5 分钟和 1 分钟时由礼貌播报区各说一次；打开时已经不到 5 分钟不补报。
- **推进与交卷**：测验没有可推进的下一题，判不出结果时不显示“先做下一题”。按契约测验开始后中止就是交卷，所以作答、判分中和判不出结果时，原来“中止”的位置换成“交卷”（样式不变），准备阶段仍是中止。确认框写明还有几题没答；确认后 store 的 `finishQuiz` 带任务守卫调用 `quiz.finish`，画面过时时换成后端交回的状态。题都答完、都判完时，后端还没有对应的阶段，交回的是指向最后一题的“等作答”；前端按作答记录认出这个情形（`quizReady`），不再显示那道题，只用一张卡片说明等交卷；交卷按钮仍在原处、样式不变。后端补上这一阶段以后改用它。
- **留给学习线**：测验现在套在按“当前一步”推进的任务画面里，题目只能按后端给的顺序一道道答；结果页逐题列出对错、交卷后焦点落在哪，随学习线（#117）按答卷来设计，不在这个画面上补。
- **截止时间**：`hooks/use-deadline-refresh.ts` 到了截止时间重新读取一次状态，后端按截止时刻结束这一场，画面换成结果。电脑睡眠时计时器不走、后台页面里计时器会被推迟，所以页面重新可见或窗口重新得到焦点时也检查：过了截止时间就读，没过不读。截止后才交的作答被后端拒绝、交回的状态里这一场已经结束时，结果上方说明这一题没有计入（`learn.quiz.unrecorded.title`），而不是通用的“画面已经更新”。

## 修改历史页

Agent、插件和编辑器都会改动空间里的文件，用户需要知道改了什么，改错时还要能撤回。后端的[空间历史](../packages/space-history/README.md)把每次 Agent 运行、插件写入和外部改动各记成一个提交；Web 的 `pages/history.tsx` 挂在 `/history`，列出这些提交并提供撤回。没有打开空间时重定向回 `/learning-space`，侧栏的“修改历史”栏目也只在打开空间后出现。

`history.list` 只返回提交的来源和时间，`history.changes` 才带每个提交改动的文件，但它从游标一直读到最新。因此 store 的 `history` 读取先用 `history.list` 取最近 200 条提交，再从其中最早一条的父提交开始调用 `history.changes`，两次请求合起来就是同一段带文件的记录；两次之间若有新提交，也一并列出。记录超过 200 条时页面注明更早的没有显示，还没有分页；读到最早的初始状态时，改为注明从什么时候开始记录。每次 Agent 运行即使没改文件也有一个提交，全部冲突的撤回也留下空提交，它们占用 200 条的名额，但不列出。初始状态是第一次打开空间时已有的文件，后端不允许撤回，所以也不作为记录列出。

每条记录显示来源、时间和改动的文件。来源按 `source.kind` 显示为 Agent、`插件 <pluginId>`、外部程序或撤回；外部程序指编辑器等不经过 Repa 的改动，由监听或运行前的快照记下。被撤回的提交也在列表里时，撤回记录注明撤回的是哪一次。文件按新增、修改、删除、重命名列出，超过 8 个时先折叠。后端只给出路径和变化类型，不给差异内容，所以页面不显示 diff。

撤回调用 `history.undo`。它只撤销选中的这一个提交，不回滚之后的提交：这个提交改动的文件逐个恢复到修改之前，新增的被删除，重命名两端一起处理；之后又被改过的文件，以及现在被忽略、超出大小上限或位于嵌套仓库等历史范围之外的文件，算作冲突并保持现状。撤回本身也记成一个提交，之后可以再撤回它。因为撤回会删除或覆盖文件，点“撤回”先打开确认对话框说明这些后果，进行中不能关闭。完成后对话框关闭，页面顶部显示结果：全部恢复时是完成提示和文件数，有冲突时用错误提示列出没有撤回的文件。调用失败时对话框保留并显示原因，可以重试。无论成功还是失败，store 都重新读取历史，因为失败前可能已经恢复了一部分并记成撤回。

后端不推送历史变化，页面每次进入时重新读取，顶部另有“刷新”；重连并重新打开空间后，读过的历史也重新读取。

`test/history-page.test.tsx` 用模拟后端覆盖列表的顺序、来源、文件与折叠，空运行和初始状态不列出，记录超过一次读取数量时的说明，确认与取消撤回，部分冲突的结果，撤回进行中不能关闭及失败后重试，读取失败重试，侧栏入口和未打开空间时的重定向，以及换空间时清空历史。窄屏、键盘操作和对真实后端的撤回尚未在浏览器中核对。

## 设置页

Web 的 `pages/settings.tsx` 挂在 `/settings`，目前有模型设置、学习导出、备份、命令授权、MCP 服务器和提示。模型设置的数据全部来自 Pi：提供方目录、凭据和默认模型都由底座转发，前端不维护提供方表。

- “默认模型”显示 `model.getDefault` 的结果，即新会话不指定模型时使用的模型：Pi 设置里的默认模型，没设置时是第一个可用模型。它的提供方没有连接时在名称下提示发送会失败。“更换”打开 `features/model-picker.tsx`，只列已连接提供方的模型；一个提供方可能有几百个模型，所以用搜索加列表，选中后调用 `model.setDefault`。
- “模型提供方”列出 `configured` 的提供方及凭据类型。`stored` 的可以“断开”（`auth.logout`）；环境变量或 `models.json` 提供的凭据标“由环境变量或配置文件提供”，不显示断开。还没有连接时“添加提供方”是主按钮。
- `features/provider-connect.tsx` 是连接对话框：先搜索选择提供方（不搜索时，国内学生最常有的几家单列在最前面一组，DeepSeek 在第一个，下面仍是 Pi 目录里的全部），有多种方式时再选“用账号登录”或“填写 API key”，只能在 Repa 之外配置的方式只给说明。key 用密码输入框，经 `auth.setKey` 保存，后端保存前先用它试发一次请求：提供方拒绝时不保存，对话框留着说明原因、可以重填；连不上或余额不足时照样保存，对话框说明没能验证的原因，由用户点“完成”关掉；后端返回 `requires_interactive_login`（例如 Amazon Bedrock 还要选认证方式）时自动改走 `auth.login`。账号登录和这类 key 登录过程中，后端发来的 `display` 显示为说明和“打开链接”（新标签页），收到即回复，后端不用等用户点；`input`（`secret` 时为密码框）和 `select` 在对话框里排队回答。底座把选项写成 message 里的“id：名称 — 说明”，每项都能对上时按钮直接显示这一行。关闭对话框即取消：未回答的请求回复 `null`，之后的失败不再提示；只在浏览器里等待回调、没有可回答请求的步骤要等后端自己结束。登录失败显示原因，可以重试。
- “命令授权”读写应用设置里的 `commandPolicy`（`settings.get`／`settings.set`），store 只取这一项，最近空间和提示覆盖由各自入口读取。“每次询问”（`ask`）时 Agent 调用 `bash` 都弹出对话页的授权对话框，只由少数只读命令组成的命令除外（见 [`@repa/base` 说明](../packages/base/README.md)）；“完全访问”（`fullAccess`）时直接运行，没有发起连接的后台命令也会运行，而询问模式下它们会被阻止。命令不在沙箱里，可能改动学习空间之外的文件，这些改动不在空间历史的撤回范围内，所以选完全访问时先用对话框说明后果，确认后才保存；改回询问没有风险，选中即保存。后端在每次命令执行前读取设置，保存后从下一条命令起生效，正在运行的会话也一样；已经弹出的授权对话框不会因此自动允许。设置对所有空间生效，保存失败时显示原因并保留原来的选项。
- “MCP 服务器”由 `features/mcp-settings.tsx` 渲染，数据是 store 的 `mcpServers`（`mcp.list`），随 `mcp.updated` 整份替换。每个服务器一张卡片：名称、状态（已连接及工具数、连接中、停用、失败，状态同时用文字表达）、命令名或地址；失败时下方用错误提示显示原因，并有“重新连接”（`mcp.reconnect`）。两个开关分别是启用（`mcp.set` 的 `enabled`）和调用前询问（`ask`）；删除先用对话框确认，因为这一项里的令牌随之删除。“添加”打开对话框，粘贴服务器说明里给的一段配置（整段或其中“名字: {…}”的部分），交给 `mcp.add`，格式不对时显示后端的原因并保留输入。没有通用 Agent 的装配里后端以 `mcp_unavailable` 拒绝，这一节不显示。调用工具前的确认（确认种类 `mcp`）与命令共用 `features/command-confirmation.tsx` 的对话框：标题写服务器与工具，下面是参数的 JSON。对话页的工具活动把 `mcp__<服务器>__<工具>` 分开显示。这一节的界面文字目前是占位。
- “提示”由 `features/prompt-settings.tsx` 渲染，显示后端每次运行开始时装配系统提示用的各段（`prompt.list`），顺序就是装配顺序。各段由打开的空间和其中的插件决定，没有打开空间时只说明这一点并给出去选空间页的链接。后端只给出段落 id，名称和来源说明由 `lib/prompts.ts` 按已知 id 对照，未知的直接显示 id；插件段落显示为“插件 <id>”。每段可以启停和编辑，修改从下一条消息起生效：
  - 后端按默认、应用（所有空间）、空间三级合成，`prompt.set` 整体替换一级的覆盖，`prompt.reset` 清除一级。应用级覆盖从 `settings.get` 的 `prompts` 读取；空间级覆盖协议读不到，由有效内容和上一级的差异推出，和上一级相同的部分当作没有覆盖，对装配结果没有区别。
  - 列表里的开关只写本空间这一级，保留这一级已有的文字覆盖；和上一级一致时清除这一级的启停覆盖，一级里什么都不剩时改用 `prompt.reset`。
  - 编辑对话框选择保存到“只在本空间”或“所有空间”，两级各有草稿，切换时显示那一级当前的内容。保存和上一级相同的文字时不留文字覆盖。本空间这一级在所有空间有文字覆盖时，恢复按钮写作“改回所有空间的内容”，否则写作“恢复默认”；选所有空间而本空间另有修改时，提示本空间仍用自己的内容。空间说明、Skill 目录和工具说明由文件或运行状态生成，编辑时说明覆盖后会盖住之后的变化。
  - “预览”调用 `prompt.preview`，按发送顺序给启用的段落编号，停用的段落标明不发送，空段落标明为空，另列插件提供的运行时视图。预览是按当前配置算出的，不是某次调用的记录；运行时 Pi 还会加上工作目录和工具声明，这些不在预览里。
