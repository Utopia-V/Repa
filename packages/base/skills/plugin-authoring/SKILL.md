# 给 Repa 写插件

## 插件是什么，什么时候写

插件是空间里 `.agents/plugins/<id>/` 下的一个文件夹，里面有清单 `repa-plugin.json` 和一个入口模块。你用 `plugin` 工具的 `load` 加载它，使用者批准以后，它在 Repa 的后端里运行，声明的工具从你的下一次回复起就能调用。此后每次打开这个空间，它都按批准的版本自动运行，通用 Agent 的各个会话都能用；它自己的数据放在数据目录里，跨会话保留。

值得写成插件的，是以后还会反复出现的需求：同一件事要做第二次、第三次，或者要记住上一次做到哪里，例如“取论坛板块上次以来的新帖”。只做一次的事，直接用文件工具或一段临时命令做完即可。

插件的代码以使用者本人的权限运行，能读写任何文件、联网、运行程序，所以只写使用者要的功能。

## 文件夹

本 Skill 目录下的 `template/` 是一个能直接加载的最小插件，含 `repa-plugin.json` 和 `index.ts`，要改的地方标着“改：”。先读这两个文件，复制到 `.agents/plugins/<id>/` 再改，比从头写更不容易出错。

- 插件 id 以小写字母开头，只含小写字母、数字和连字符，例如 `forum-digest`。文件夹名、清单的 `id`、入口导出的 `id` 三者相同。id 不能与随产品附带的插件相同，`plugin list` 里这类插件标着“随产品附带”。
- 清单只有这些字段：`id`；`version`，SemVer 版本号，例如 `0.1.0`；`baseVersion`，照模板写；`entry`，入口文件相对文件夹的路径，用 `/` 分隔；可选的 `title`。多写字段会被拒绝。不要写 `pages`，插件页面还没有提供。
- 入口可以是 `.ts`、`.js` 或 `.mjs`。用 `.ts` 不需要构建，也不需要 `package.json`，Node 加载时只去掉类型标注。
- 文件夹里只放代码：只能有普通文件，不能有符号链接，文件和目录合计不超过 2000 个、共不超过 16 MiB。数据放数据目录，不放这里。

## 入口模块

入口以 `export default` 导出插件定义 `{ id, async open(host) { ... } }`，`open` 返回实例。实例可以有以下几项：

| 成员 | 作用 |
| --- | --- |
| `tools()` | 返回工具列表 |
| `instructions()` | 一两句话，告诉模型什么时候用这些工具。加载结果里会带上它，下一次运行起进入系统提示 |
| `view()` | 返回通用 Agent 每次运行都要看到的简短状态文字，没有时返回 `undefined` |
| `close()` | 收回 `open` 里启动的东西 |

每个工具是 `{ name, description, parameters, execute(input, context) }`：

- `name` 以字母开头，只含字母、数字和下划线，不能用连字符。它不能与内置工具（`read`、`bash`、`edit`、`write`、`grep`、`find`、`ls`、`powershell`、`subagent`、`ask_user`、`plugin`）或别的插件的工具重名，所以加上插件名作前缀，例如 `forum_fetch`。
- `parameters` 用 `Type.Object({...})` 声明，每个字段带 `description`，模型照着它填参数。宿主调用 `execute` 之前已按它校验过 `input`。
- `execute` 返回 `{ text }`，`text` 是给模型看的分行文字。超过 50 KiB 或 2000 行时，模型只看到首尾，全文另存，所以大结果要分页。出错时抛出 `new Error("说明")`，模型读到的就是这句说明。
- `context.signal` 是这次运行的中止信号，耗时的请求把它传给 `fetch`。

`open` 收到的 `host` 提供下面这些能力：

| 成员 | 用途 |
| --- | --- |
| `host.space.dataDir` | 本插件独占的数据目录，用 `node:fs` 读写，跨会话保留。状态、缓存和“看到哪里”的记录都放这里 |
| `host.space.root` | 空间根目录 |
| `host.files.read`、`write`、`list` | 读写空间里给使用者看的文本文件，路径相对空间根目录；写入记进空间历史，可以撤回 |
| `host.models.complete({ prompt, system })` | 调一次模型，返回文字；摘要、挑选这类要判断的步骤用它 |
| `host.now()` | 当前时间，Unix 毫秒 |

能导入的只有三类：Node 内置模块（`node:fs/promises`、`node:path` 等）、本文件夹里的文件、`@repa/base/plugin`。最后一个提供声明参数用的 `Type`、错误类 `RepaFault`，以及 `Plugin`、`Tool`、`Host` 等类型。联网用 Node 自带的全局 `fetch`，不必导入；第三方 npm 包不能用。

## 要守的几条

- **模块顶层只定义代码。** 读文件、联网、启动定时器都放进 `open`，状态也在 `open` 里建立。宿主要先导入新版本才知道它能不能用，顶层有副作用的模块导入失败时会留下收不回的东西；同一版本再次打开时复用已导入的模块，顶层代码不再执行，放在顶层的状态会被前后两次打开共用。
- **`close` 收回 `open` 启动的东西。** 用 `clearInterval` 停掉定时器，等后台工作结束。替换插件时，新版本要等旧版本的 `close` 返回才打开；卸载时 `host` 立即作废，`close` 里只能写自己的数据目录。
- **`open` 里只碰自己的数据目录。** 加载常常发生在你这次运行的中途，运行这时占着空间的写锁，`open` 里写空间文件或读空间历史会直接失败，加载随之失败。写空间文件放进工具的 `execute`。
- **只用类型剥离能处理的 TypeScript。** 不能用 `enum`、`namespace` 和构造函数的参数属性；只是类型的名字用 `import type` 导入；导入本文件夹的文件要写出真实扩展名，例如 `./feed.ts`，不能写 `./feed` 或 `./feed.js`。

Repa 还没有定时任务。需要定期做的事，先做成工具，例如“取上次以来的新帖”，把看到哪里记在数据目录里，由使用者让你调用。

## 顺序

1. 调用 `plugin list`，看这个空间已有哪些插件、id 是否已被占用、要改的插件现在是什么状态。
2. 读 `template/` 下的两个文件，复制到 `.agents/plugins/<id>/`，按“改：”的注释改 id 和工具。改已有的插件，就直接改它的文件夹。
3. 调用 `plugin load`，`id` 填插件 id。这次调用的返回就是结果；使用者通常要先批准，同一份内容批准过的不再询问。
4. 成功时，结果列出工具名。下一次回复就用真实的输入调用新工具试一次，再把结果和以后怎样使用告诉使用者。失败时，按下一节改好文件再 `load`。改动只有再次 `load` 才生效：运行的是批准时复制下来的那一份，不是文件夹里的文件。
5. 新版本改坏了而旧版本是好的，就在 `plugin load` 里加 `from: "previous"`，让上一次选定的版本重新生效，不必再批准。不再需要的插件用 `plugin unload` 卸载，文件夹和数据都保留。

## 常见报错

| 报错里说的 | 怎样改 |
| --- | --- |
| 插件清单 repa-plugin.json 不合要求：缺少……、多了…… | 按“文件夹”一节补齐或删掉字段 |
| 无法读取插件清单 repa-plugin.json | 清单不是合法的 JSON，按报出的位置改 |
| 插件要求底座版本……，当前底座是…… | `baseVersion` 改成模板里的值 |
| 插件文件夹……里清单的 id 是…… | 文件夹名与清单的 `id` 改成一样 |
| 入口导出的插件定义的 id 是……，清单里是…… | 入口里的 `id` 改成与清单相同 |
| ……是随产品附带的插件 | id 已被随包插件占用，换一个 id 和文件夹名 |
| 插件文件夹……不存在 | 核对路径与 id |
| 是符号链接、目录联接或特殊文件；插件文件夹超过上限 | 删掉链接，把数据和依赖移出文件夹 |
| ……导入了……：插件文件夹里的代码只能导入…… | 改用 Node 内置模块或自己写，别的包不能用 |
| ……找不到…… | 导入要写出文件名和真实的扩展名 |
| 用了需要转换的 TypeScript 写法 | 把 `enum` 等换成普通对象或常量 |
| 导入了模块没有导出的名字 | 类型改用 `import type` 导入 |
| 有语法错误 | 按报出的文件和行号改；正在运行的旧版本不受影响 |
| 工具名……无效、是底座内置工具的名字、已经是插件……的工具 | 按“入口模块”一节改工具名 |
| 工具……要有 description 文字、用 Type.Object 声明的 parameters 和 execute 函数 | 补齐工具的这几项 |
| 在打开期间写空间文件或读、记空间历史 | 把这些操作从 `open` 挪进工具的 `execute` |
| 插件……打开失败 | `open` 里抛了错，按原因改；插件这时显示为失败，可以用 `from: "previous"` 恢复上一次的版本 |
| 使用者拒绝了插件、使用者没有作出决定 | 问使用者原因，不要反复加载 |
| 正在加载或卸载 | 同一个插件的上一次装卸还没结束，等它结束再试 |
