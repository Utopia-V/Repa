# 底座的开发规矩

以下规矩源自 2026 年 10 月对整个仓库的一次问题清点，每条之后附有促成该规矩的教训。它们补充根目录的 [AGENTS.md](../../AGENTS.md)，在底座和其他包中同样适用。

- **新增机制前，先找已有做法。** 先查阅[包地图](../README.md)和[生成目录](../../docs/generated/)。底座中同类事务已有做法时，复用或扩展该做法，不另起一套。确认、提问、前端代做服务三件事曾各写一套"向前端发请求、等回复"，修好一处，其余两处照旧。
- **每个机制须说清防什么、伤及谁，并设在问题产生之处。** 期望值的指纹曾在学习者一端核对，但题目、运行器和答案同在一个安装包内，在该端不会各自变化；这种核对查不出真问题，只会因换行、注释而误报，使代码题下线。
- **有当前的使用方才添加，是否删除视代价而定。** 曾为仅存在一周、没有任何用户的 27 条核对记录编写兼容代码，留下两套规则。反之，独立、不牵连别处且没有代价的部分，即使暂时无人使用也可保留。
- **盘上只记事实，派生内容可删除后重算。** 学习记录曾在每一步存下整个界面画面，体积随使用不断增大；前端一改，盘上格式即随之改变；算法改进后，也无法依据历史重新推断。
- **版本依约定的语义而定，不依实现的字节而定。** 期望值曾绑定 `runner.py` 全文的哈希，Windows 检出时换行一变，代码题即静默下线。
- **按 Pi 的设计使用 Pi。** Pi 承担起来不自然的部分，自行编写一小段直接的代码，编辑工具即按此实现。不给 node_modules 打补丁，也不修改 Pi 传入的内部对象：为缓存保温所打的补丁锁死了 Pi 的版本，而保温在实际使用的组合中从未运行。
- **给模型的输出只含其所需内容，写成分行文字；需要更多时由模型自行获取。** 把前端用的 JSON 按字符切片交给模型，模型读到的是从字段中间断开的碎片；前端一改字段，模型读到的内容和提示缓存均随之改变。
- **测试不依赖机器的繁忙程度。** 只有专门测试超时的步骤使用短时限。平台本身不支持的环境直接跳过；可以准备的环境若缺失，则测试失败并说明准备方法。
- **文档不记录测试数量和运行过程。** 做法的理由与放弃的方案写入[设计记录](../../.agents/notes/README.md)；单次运行的结果写在 PR 中。
