# 底座的开发规矩

这些规矩来自 2026 年 10 月对整个仓库的一次问题清点，每条后面是让它成为规矩的那次教训。它们补充根目录的 [AGENTS.md](../../AGENTS.md)，在底座和其他包里同样适用。

- **加机制之前，先找现成的。** 底座里同一类事已经有做法时，复用或扩展它，不另起一套。确认、提问、前端代做服务三件事，曾经各写了一套"向前端发请求、等回复"，修好一处，另外两处照旧。
- **每个机制说清它防什么、伤到谁，并放在问题产生的地方。** 期望值的指纹曾在学习者那边核对，可题目、运行器和答案装在同一个安装包里，在她那边不会各自变化；这种核对查不出真问题，只会因为换行、注释误报，把代码题下线。
- **有现在的使用方才加，删不删看代价。** 曾为一周大、没有任何用户的 27 条核对记录写兼容代码，留下两套规则。反过来，独立、不牵连别处、也没有代价的东西，暂时没人用也可以留。
- **盘上只记事实，派生的东西可以删掉重算。** 学习记录曾在每一步存下整个界面画面，越用越大，前端一改，盘上的格式就跟着变；算法改进以后，也没法拿历史重新推断。
- **版本跟着约定的语义走，不跟着实现的字节走。** 期望值曾绑定 `runner.py` 全文的哈希，Windows 检出时换行一变，代码题就静默下线。
- **按 Pi 的设计用 Pi。** Pi 承担起来不自然的部分，自己写一小段直接的代码，编辑工具就是这样做的。不给 node_modules 打补丁，也不改 Pi 传进来的内部对象：为缓存保温打的补丁锁死了 Pi 的版本，而保温在实际用的组合里从来没有运行过。
- **给模型的输出只放它需要的，写成分行的文字；它要更多，让它自己取。** 把前端用的 JSON 按字符切片给模型，模型读到的是从字段中间断开的碎片，前端一改字段，模型读到的内容和提示缓存都跟着变。
- **测试不依赖机器忙不忙。** 只有专门测超时的那一步用短时限。平台本来不支持的环境就跳过；能准备的环境缺了，就失败并说明怎样准备。
- **文档不记测试数量和运行过程。** 为什么这样做、放弃了什么，写进[设计记录](../../.agents/notes/README.md)；一次运行的结果写在 PR 里。
