# 学习规划

计划是后续工作要继续读取和修改的文档。先读已有计划、相关材料和当前学习语境，承接用户自己作出的调整，再决定本次需要安排的范围。目标与预期产物可以变化，时间安排服务于实际学习需要。

把目标转成这次可以执行、检查和调整的工作。所需分钟是工作量估计，说明会影响安排的依据或假设；已有作答、困难和复习记录用于修正估计。实际发生的学习与未来安排分别表达，排进日程的任务仍是待办。同时启用了 `guide-learning` 时，可以用它比较新学习与巩固的活动，再把选定工作落实到可用时间。

涉及“明天”“本周”等相对日期时，用 `planning_clock` 取得实际日期和时区。采用用户指定的时区；机器时区只是没有另行指定时的依据。期限落实到具体日期和时刻，可用时段只覆盖本次规划范围。

## 核对时间

先沿用用户提供的时间粒度。只有“每天半小时”或“现在还有 15 分钟”时，把活动工作量与这些分钟数比较，保留每天或本次的分配即可。`check_plan` 接受具体起止时刻，所以只有在已有实际可用时段、需要检查日历安排时才使用它；不要为调用工具补出用户没有给定的钟点。

用 `check_plan` 检查这类候选安排：

- `timeZone` 是统一时区；`availability` 列出实际可用时段。
- `goals` 用局部 `id` 关联工作量 `minutes` 和可选 `deadline`；`sessions` 将具体起止时间关联到 `goalId`。这些标识只用于这次检查，不建立另一份任务数据库。
- `start/end/deadline` 使用明确的 ISO 日期时间。通常填本地日期时间，由 `timeZone` 解释；夏令时重复小时需要用相符的 UTC offset 区分，不能凭一个含糊钟点安排两次。
- 读取每项目标的未安排工作量、期限前容量不足、重叠及超出可用时间等结果，再调整安排。重叠的可用窗口只计算一次；工具按实际经过的分钟计算时长。

约束不成立时，说明具体缺口以及可调整项：减少本次范围、延后期限、增加时间，或修正工作量估计。取舍沿用用户已经给出的优先级；需要用户决定且会改变计划的部分，保留明确待定项。

## 保存与接续

通过现有内容工具保存或局部修改计划，格式按内容选择。正文交代目标、具体安排、必要材料和本次取舍，保留尚未解决的约束；来源可使用已有内容引用。工具检查结果是这份候选在给定假设下的计算，不另存一份需要同步的权威日程。

时间减少、目标变化或实际反馈出现后，重新读取当前文档和相关事实，计算受影响部分。保留人工校订与仍然成立的安排，说明调整原因。按实际需要把当前重点维护到已有学习语境中，不以新建会话或关闭会话触发固定的全量重排。
