# 开头路径题量核对

Python 课程 `0.2.0` 的开头路径新增 209 道候选题：101 道练习、48 道复习、60 道测验。题量来自 14 个自然日的四条固定路线，触及的并集是 py01–py20，共 50 个 KP。lesson 和 review 使用 c2 的真实流程；quiz 使用场次上界估算，待 d 合入后复核。

## 设计思路

一次 KP 练习最多尝试五次，而原题池只有三题，因此即使全课程题量很多，第四次尝试仍会重复。复习也有同样的问题：它先轮转 KP，再优先选择未见题；早期 topic 在两周内被多次调度，只有两题的 KP 会在第三次交付时耗尽。这里按实际使用位置补题，保留原有的重复兜底，不改变教学策略。

练习供给至少覆盖每 KP 一轮最长的五次尝试。中止后重试会额外消耗题，所以 py01.k1 按实际路线补到六题。复习供给取四条路线中逐 KP 的最大交付数，而不是把不同学习者路线的需求相加。测验按 topic 合并题池计算：最多四场，每场一个 topic 最多一题，每场再预留一次换题重考，因此逐 topic 的保守库存是八题。这些逐 topic 的最大值不要求同时发生；全体四场连同重考至多交付 40 题。

## 实现细节

### 固定基线与路线

教学基线是 `d3e3ee33d159bf8747af2a357d762b9a907af175` 中的 c2，策略版本为 `repa-flow-v1`。课程清单固定为 `0.2.0`，题目版本随内容哈希变化。逻辑日期为 2026-10-21 至 2026-11-03，每天从 `09:00:00+08:00` 开始，课内 KP 轮转 seed 固定为 `20261021`。菜单始终选择第一项，没有预先截取前若干课；任务完成后达到日目标才结束当天，因此实际 XP 可以超过日目标。

路线通过真实插件宿主、`LearningRecords`、`connectLearning`、正式提交和菜单推进。规则题正常判分；开放题的语义评分边界给出固定正确结果，以控制学习表现；代码题使用无头的内部 Python 批次适配器，在课程锁定运行时执行。固定的是表现与逻辑时间，不是用模型推测一条课程路线。

顺利路线每 KP 两次独立正确，review 三题独立正确。含失败路线在 py01 第一次独立正确后中止，再开始同课；重试时每 KP 的正确序列为“对、错、错、对、对”，验证第五题通过。首个 review 五题全错，之后继续选择 c2 给出的首项，观察失败后的后续复习。其他 lesson 和 review 按顺利表现完成。错误原答使用“不会”，不把判分服务故障算成学习失败。

触及的 topic 包括赋值与追踪（py01）、表达式与单位（py02）、类型与转换（py03）、函数调用（py04）、字符串（py05）、列表与切片（py06）、拼接与汇总（py07）、比较与边界（py08）、布尔组合（py09）、分支（py10）、报错定位（py11）、需求与验收例子（py12）、导入与文档（py13）、表结构（py14）、CSV（py15）、标签与位置选择（py16）、掩码筛选（py17）、组合条件（py18）、缺失值（py19）及数字转换审计（py20）。

### 缺口与新增题

原题、例题、讲解及既有核对记录保留；新题使用 `q4`、`q5`（py01.k1 另有 `q6`）、`r3` 起的新 id，以及 `x3`、`x4`。归属沿[写课说明](../README.md#资格补救与信用分开写)：`measures` 默认是所在 KP，`uses` 只标实际执行的其他子技能。

下表的需求按题池分别计算。“首次重复”是该 KP 在该题池中的交付序号；`—` 表示四条路线没有观察到重复。练习另列五次尝试的容量要求：原库存只有三题，最长一轮的第四题必然重复，即使顺利路线实际只用了两题。复习未触及的 KP 需求为零，保留原有两题。

题型按每道题的作答位种类组合计数：T 为文字，C 为选择，O 为排列，B 为表格，P 为代码；例如 `CT×1` 表示一道同时含选择与文字位的题。同一种作答位在一道题里出现多次，仍计为一道题。分布列按“补前 → 补后”排列。

补后统计包含五道尚待模型独立核对的候选题。它们的库存位置已经补上，但当前有效供给仍有下列缺口；复跑使用的是完整候选库，不能把这五道题算成已经完成核对的供给。

### 题型与情境变化

- `py01.k1.q5` 把“读代码填结果”改成三张指令卡排序，必须同时满足先定义、再计算、最后显示的依赖；核对程序枚举排列并实际运行，不把标准排列再抄一次。
- `py03.k1.q5` 用逐行求值表对照文字拼接、整数相加和浮点相加，要求保留引号与小数点；区别不只是换一组数字，而是判断同一个加号在不同类型下的行为。
- `py12.k2.r4` 从普通命中例子换成零命中的库存输出，要求明确“零行但保留列名”；它考的是无结果验收约定，不能靠更换阈值或多给一个正常例子代替。
- `py20.k2.x4` 要追踪转换失败的原字符串清单并排除原本缺失，而不只是回答转换后有几个 NaN；它把数字转换放进可审查的清理流程。
