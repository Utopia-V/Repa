# Python 课程关系核对

这份对照记录课程从 `dev f374d34e2` 的 0.1.0 格式迁移到 0.2.0 时，对 107 条原先修边的内容判断。课程仍有 48 个 topic、120 个 KP、962 道题；107 条学习资格边全部保留，补救位置按 KP 分别填写。覆盖图有 111 条声明边，其中 102 条为正权重，9 条为零权重。题目内容与判分定义保持原样，53 道题的 `uses` 收窄或补充。

## 设计思路

原来的每条先修边同时带着 `key`、正 `weight` 和非空 `covers`，会让“要先学过”自动变成“在这节课又练到了”。本次先保留资格，再分别判断补救和信用。这样，对课程路线尚有疑问的地方可以保持原有资格，而不必同时给出尚无依据的信用。

核对以各 KP 的讲解、相关题面、选项、作答位和参考程序为依据。下表保留每条旧边的原值，同时给出当前关键补救位置、独立覆盖权重和可定位的题目。某个题型标签或题面提到了某个概念，本身不足以证明执行了那个子技能。例如，按一份完整需求选代码，不等于又练了一次“把模糊需求写清楚”；计数循环没有收集列表，也不因此获得 `append` 收集技能的信用。

正权重统一采用 0.5，表示确认有子技能复用后的初始量级，是 Repa 的待校准假设。它不是从旧 `covers` 长度折算的比例，也不是 MA 已公开的权重。后续学生模型还要结合本题实际 `measures/uses` 决定哪些 KP 有证据，不能把整条边当成每一道题的信用。零权重边保留待审阅的关系，但不传信用。
