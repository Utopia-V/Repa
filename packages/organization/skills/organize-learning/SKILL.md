# 整理长期内容

先确定这次整理服务的目标，再读取现有内容与相关来源。交流中的结论、仍待解决的问题和可继续使用的解释按实际用途进入文档；临时讨论可以留在会话。需要查旧交流时用 `search_history` 和 `read_history` 取得明确范围，不从会话存储文件猜内容。

文件粒度按阅读、引用和后续修改的需要选择。承接用户已有目录、段落、符号和批注，只改本次确定的部分。拆分、合并、移动会改变哪些引用的含义，由实际内容决定；程序负责执行已确定的变化。

## 身份与共同保存

用 `content_info` 查询相关文件或 `repa:document/<id>`、`repa:material/<id>` 的身份、结构 `revision` 和组成，正文仍通过 `read` 按需读取。稳定引用跟随内容身份，普通路径链接跟随路径；移动前核对本次涉及的路径链接。

一次必须共同成立的重组用 `apply_patch` 保存正文、新身份和已确定的引用变化：

- 保留原文档主体时沿用其身份，新拆出的文档取得新身份。
- `registrations` 登记空间内已有或本补丁产生的文件，可给新对象初始 `members/resources`。同一补丁的正文需要引用新对象时，明确提供尚未使用的内容 `id`；它可以是清楚的局部名称。省略时由保存入口生成，之后用 `content_info` 取得实际引用。
- 普通多文件内容的组成用 `compositions` 更新，`ref` 和结构 `base` 来自当前 `content_info`。正文修改基准与结构基准各自表达含义。
- 已确认需要迁移的文内链接直接写进补丁，保留仍指向原主体的链接。

保存结果及保存期间的错误返回操作标识。用 `content_operation` 的 `get` 核对实际状态；需要撤回已完成的整理时用 `undo`，它作为新操作保留可区分的后续修改。发生正文匹配、结构基准或恢复冲突时，先读取相关现场，调整明确受影响的部分；已有人工修改是后续判断的依据。

## 维护学习语境

用 `get_learning_context` 查看当前绑定及其修改基准。已有绑定仍合适时，直接维护对应文档；采用组成清单时，`items` 是该 JSON 文档的正文，不是内容清单里的普通 `members`。

组成清单的基本形式如下，`ref` 取自实际 `content_info` 结果：

```json
{
  "items": [
    { "ref": { "spaceId": "所属空间", "id": "文档标识" }, "mode": "expand", "title": "当前目标与困难" },
    { "ref": { "spaceId": "所属空间", "id": "材料标识" }, "mode": "reference", "note": "按需查原文" }
  ]
}
```

`expand` 展开当前正文，`reference` 保留标题和稳定引用；成员也可放在 `{ "title": "分组", "items": [...] }` 中。把后续帮助真正需要的目标、实际反馈、困难和当前安排留在语境，较长解释与原材料可以保留为引用。

需要选择新的根文档或组成清单时，调用 `set_learning_context`，传入 `get_learning_context` 的 `revision` 作为 `base`，以及 `{ kind: "document" | "composition", contentId }`。`learning_context` 用于核对最终展开文本和来源，它的视图修订不是绑定修改基准。空间归属和操作标识由工具适配层填写。

整理结果应能在下一次交流继续补充；会话结束本身不要求全量总结或重新安排整个空间。
