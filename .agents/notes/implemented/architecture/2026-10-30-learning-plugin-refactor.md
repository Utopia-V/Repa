# 学习插件重做：只记事实、当场判分，检查与判分采用同一套判断

状态：已落地

## 问题

在 2026 年 10 月的问题清点中，学习插件的问题大致分为四类，结论均经维护者逐条讨论。

第一类是把派生内容当作记录。学习记录在每一步都存下整个界面画面和学生模型的投影，体积随使用不断增大；前端一改，盘上格式即随之改变；算法改进后，也无法用历史作答重新推断学习状态。快照去重从不生效、写入无人读取的戳和字段、同一事实有多种表示，根源均在于此。

第二类是检查设在所防问题不会发生的位置。代码题的期望值预先算好存入 `expected.json`，并绑定了 `runner.py` 全文的哈希。然而题目、运行器和答案装在同一个安装包中，在学习者一端不会各自变化；这种绑定查不出真问题，Windows 检出时换行一变，代码题反而静默下线。课程核对时每段候选程序都重启一次解释器，整门课串行需四十多分钟，时间几乎全部耗在重启上。

第三类是流程会卡死，或在没有证据时强行判定。判分途中关闭窗口、开放题的模型调用失败、模型表示无法准确判分，均会使任务停滞或被记为失败；复习和测验期间合上笔记本，计时仍继续。

第四类是数值和规则没有出处。流程中的数字、学生模型的常数散落在代码中，未标明出自 Math Academy 公开的内容、Repa 的猜测还是研究结论；FIRe 实现后又被关闭；测验触发、选题和完课估算使用了复杂的规则，理由只写着"Repa 假设"。

另有两项与学习插件的结构有关：Python 运行器连同 `runner.py` 装在学习插件中，Web 为使用它而依赖整个学习包；辅导工具把前端用的 JSON 直接交给模型。

## 决定

### 学习记录只记事实

每次作答只记录对推断学习状态有用的事实：所出的题目，学习者的作答（换回题目原来的选项编号）及其所见的题面版本，当时的判分结果及其所依据的题目版本，出题和作答的时间，作答前是否问过辅导或读过参考内容，以及任务类型（课、复习、测验、换题重考）。此外记下学习者的操作：选定任务、课内翻到哪一页、主动结束任务、申诉和日目标；每次交付另记一个 seed，选项顺序和不透明编号由它重建。界面、学生模型、进度和 XP 均由这些事实计算得出，可以删除后重算。任务、交付和提交的编号由事实的序号得出，不另存。各类事实的字段见[学习记录说明](../../../../docs/development/learning-records.md#事实)。

题目的版本只由学习者看到的内容和判分方式决定，按测试判的题还包括课程的运行前导。知识点归属改变时不更换版本，重算学习状态时按新归属计算。公开题面另有一个只覆盖作答前题面的版本，作答事实记它：题面没变而题目版本变了，说明改的是答案或判分方式，过去的作答才按新定义重判。

没有证据则既不算对也不算错：中途离开、判分失败、模型表示无法准确判分，均属尚无证据，不阻塞任务，也不记为失败。条件具备时自动补判，学习状态随之重算。测验结束时若还有判出来可能改变结论的作答，结论先记为待定（`unresolved`），判出以后再定。

题目的答案改正后，过去的作答按新答案自动重判，对错两个方向均生效；新判分以追加方式取代旧判分。XP 只增不减，不因重判收回：XP 按任务的实际结论、在事实发生时结算，奖励变高时补发差额，变低时不收回。

### 判分：答案存于题目，在同一环境中当场计算

题目中存的是答案本身，即期望表达式和参考解。判分时，在运行学习者程序的同一环境中当场算出期望值，再与学习者程序的结果比较。该环境是应用内置的 Pyodide；执行方可以替换，学习者自己安装的 Python 也能按同一约定接入。一次判分请求先求期望表达式，再运行学习者的程序，二者在同一个 Worker 里，程序改不到已经算出的期望值。参考解不发给前端，用来在检查时判对；代码题的试运行（`run.prepare`）只把课程前导、第一个公开测试的数据与 setup 和学习者的代码交给前端运行，不含期望表达式、参考解和隐藏测试的输入，也不写入学习记录。

因此，`expected.json`、指纹、重新生成以及前后端运行器摘要的比对一并去除。前端连接时在 `capabilities.services` 中声明 `python.run`，即表示能运行 Python；执行请求只有协议名和测试，不携带学习插件的编号。

### 检查工具

检查工具用与判分相同的一套判断检查一道题：参考答案须判对，已知的错误作答须判错。它与判分共用同一个入口 `runCodeTests`，入口只认一个运行测试的函数：判分时它经前端的 `python.run` 运行，课程核对时它是 Node 里的 Pyodide 沙箱。

题目在何处产生，检查就应能在何处运行：包括我们自己写的、社区贡献的，以及模型在学习者一端写的。因此它是产品中的工具（`repa-course check`），不只是仓库中的测试。课程核对的沙箱目前只能建在 Linux 上，其他系统只做结构检查；在学习者一端检查模型写的题，属于[范围之外](#范围之外)的下一项功能。

解释器状态的隔离以题目为单位：互不相干的题目彼此不能影响，同一道题的参考答案、等价写法和已知错误写法之间也不能。判分时每次提交换一个预热好的新 Worker。检查工具为了速度整门课共用一个解释器，每个任务后由 `runner.py` 删去新建的文件、恢复常被改动的全局设置，并用系统熵给随机数重新播种；恢复失败或超时才换新的解释器。恢复失败时这个任务的结果已经算出，照样保留，余下的任务在新的解释器里接着运行，判分时也一样。这依赖一个事实：课程代码不改动库的属性。随包课程全部 2,696 个任务结束时留下的改动只有新建的文件、`builtins._` 和库按需导入的模块（2026-10-30 记录）。整门课核对从四十多分钟降到十秒以内，CI 每次都运行，"只在定时任务跑整门课核对"的开关已去除。

程序算不出答案的作答位列入 `manual`，由 `course:confirm` 请模型只看题面独立再解一遍；结果一致时在 topic 文件末尾的 `verified` 段记下核对记录，`course:check` 对缺少当前记录的复习题和测验题报 `manual_unconfirmed`。

一道题最多一个按测试判的作答位，检查工具以 `multiple_code_slots` 拦下有多个的题；有先后关系的多步代码题见[暂缓](#暂缓)。

### 学生模型与流程

- 启用 FIRe，权重取课程 `encompassings` 中的值，标明为假设。
- 删除 `uses`，按 Math Academy 公开的做法以 topic 为单位传递信用；待真实数据证明按题传递信用的预测更准确时再加回，研究需要时从 git 历史找回标注。
- 课、复习、测验三种任务用同一条规则计算质量：通过时取独立答对的比例，失败时取 1 减去这个比例，不低于下限。
- 公式的常数集中在 `@repa/learning-model` 的 `DEFAULT_MODEL_CONFIG`，各有名称和出处，调参即调整这些常数；研究专用的缩放、指数、capped-sum 和速度开关已删除。
- memory 采用差额更新：旧 memory 先衰减到本次，这次的信用再补上它与 1 之间差额的相应比例，从本次起按新间隔衰减。拿到满额信用的通过不论迟到多久都回到 1，同一个复习不会立即再次出现；公开的 memory 式没有标出各项属于哪个时刻，这一取法是 Repa 的假设。
- 测验按课与复习的累计 XP 触发，XP 只增不减，不使用历史高水位。测验从学过、有测验题的 topic 中选题，先选以往测过次数最少的，次数相同时按这一场的 seed 随机（按 Math Academy 降低以往测过者优先级的说法细化），补足的 topic 优先出没见过的题；每个 topic 一题，答错转入复习，与 Math Academy 一致。
- 完课估算为"剩余课时 ÷ 最近几个完整自然日平均每天所得的 XP"，显示为一个日期；Math Academy 公开 1 XP 约合一分钟专注学习，与课的预计用时同一单位。
- 复习判定和菜单规则保留，标明为假设，实际使用后再调整。
- 时间一律取自底座的 `host.now()`。时钟回拨时按零间隔继续，不致停滞。
- 课：同一个知识点答错第 3 题时这节课失败，后续与课失败相同；连续独立答对 2 题通过、练满 5 题仍未通过即失败，沿用原规则（MA 公开答错太多即中止，阈值未公开；按知识点计，因为错误集中在同一个知识点才说明没学会）。判错、部分对和说不会都算答错；没判出结果的作答判出以后，按它原来的位置重新判定。
- 复习不限时，与 MA 公开的一致：中途离开，下次接着做。学习者中止复习时，把没判出结果的作答和还没出的题都当作答对仍不能通过，才记为失败并照常做失败更新；其他情形不更新学生模型。测验结束时，无论交卷还是到了截止时间，没有作答的 topic 都算答错，做失败更新并转入复习（时间到了题还没做完，本身说明掌握有问题；只让交卷时的空题算错，等时间耗尽就能避开失败）；已作答而未判出结果的题判出以后再计；题目已从课程删除的 topic 不是学习者的原因，不算对错。
- 没有可用模型（底座的 `host.models.defaultModel()` 为空）时，不出也不自动补判开放题；可出的题只剩开放题时报 `model_required`。
- 先筛除调用方用不了的题目（显示不了，或缺少 `python.run`、可用模型）再选题；课中有未通过的知识点没有一道能用的题时，这节课不进入菜单。

### 辅导

辅导工具 `learning_task` 向模型提供一份写给模型看的当前任务：题面、学习者的答案、判分结果，写成分行文字。需要更多内容时，由模型自行用工具获取。复习和测验期间不回答，由辅导 Agent 的 `beforeRun` 关卡在每次运行前拒绝。

选项和排列块按学习者看到的顺序编号，作答和正确答案用同样的编号写出，正确答案只写在没答对的小问下面。除 `learning_search` 按条数翻页外，工具不自己分页：文字超过底座的上限时，底座保存全文、只交给模型开头和结尾，模型用 `read` 按行续取，所以辅导 Agent 的工具加上 `read`。搜索结果每条写出内容编号、名称和一段摘录，`learning_read` 按编号读取当前版本；版本引用和原学习位置是界面用的，模型用不到。模型提到学过的知识点时写 `repa:concept/<知识点编号>` 链接，与课程正文里的概念链接相同。视图同样写成分行文字：当前任务与阶段、课内当前知识点的进度，以及学过的直接先修中记忆最弱的几个；先修排序用最后一条事实的时间，时钟回拨时与学生模型一样不倒退。内容块写给模型的写法与模型核对共用 `model-text.ts`。

辅导是一段连续的对话，不按任务拆开：一个学习空间保持一段 `learning-tutor` 会话，重开时接续，学习者可以主动开始新对话；换任务不换会话，模型从视图得知当前任务，对话过长时由 Pi 压缩。前端的做法见[前端契约](../../../../docs/development/learning-protocol.md#辅导会话)。

### 数值命名与假设清单

流程数值集中在学习插件的 `parameters.ts`，学生模型常数集中在 `@repa/learning-model` 的 `DEFAULT_MODEL_CONFIG`，每个均有名称并注明出处（Math Academy 公开、Repa 猜测、研究结论）。学习插件说明中的"[尚待查证的假设](../../../../packages/learning/README.md#尚待查证的假设)"逐条写明它控制什么、出处是什么、何种证据会使其改变。数值只保留在代码中，学习插件的说明只引用名称，不抄写数值。清单收入学生模型常数、memory 的差额更新、Math Academy 未公开的部分（复习判定、衰减形状、质量）、FIRe 权重、测验答错时按 `failSpeedStep` 降速的幅度，以及研究中仍属假设的各项；Math Academy 公开而直接照用的规则不列入，出处写在代码注释中。

### 拆分 Python 运行器

Python 运行器连同 `runner.py` 拆为独立的小包 `@repa/python-runner`，Web、桌面端和学习插件均依赖它；Web 与桌面端不再为运行 Python 而依赖学习包。拆包时修复了运行器的两处时间窗：`runner.py` 在输出收集之内释放 capture 的值（原先那行 `del value` 在收集之外），值的 `__del__` 打印的内容计入这一项的输出上限；页面运行器在领取预热的 Worker 之后、发出任务之前检查取消，此前这段时间里的取消会丢失。

### 范围之外

维护者的主要用法是提供自己的材料（讲义、教材），由模型拆出 topic、知识点和题目，题目经检查工具核对后进入练习和复习的循环。这条路径在产品中尚不存在，包括将知识作为普通文件放在空间中、在对话中新建 topic 和修改题目的工具、把预制课程复制一份作为自己的课程修改。它是下一项功能，另行提案。本记录完成了它所需的检查工具；另一部分出题说明见[暂缓](#暂缓)。

## 考虑过的其他做法

- **预先算好期望值，加指纹防止其过时。** 已放弃。答案本就随课程装在学习者一端，在同一环境中当场计算，期望值与判分天然一致；存储期望值反而需要始终保证计算环境与判分环境相同。
- **检查时每段程序换一个新的解释器。** 已放弃。隔离最彻底，判分也是每次提交换一个新的 Worker，但每次启动约 2.7 秒，整门课串行需四十多分钟。从内存快照启动也省不下多少：Pyodide 314.0.7 的快照接口未公开，只能在加载包之前做快照，加载并导入 NumPy 和 pandas 的约 2 秒仍然要花。
- **每个任务后与基线比较全部模块和类的属性并改回。** 已放弃。它能拦下课程代码改动库属性（如 `math.pi = 3`）的情形，但每个任务要比较约 5.3 万个属性，多花 3 至 8 毫秒，整门课核对从约 7 秒增至约 21 秒，这段代码还要在判分时运行；随包课程没有这类改动，原地修改它也查不出。
- **随机数在任务之间恢复成基线时的状态。** 已放弃。这样每个任务抽到的随机数都相同，算期望值的任务和运行候选程序的任务也抽到同样的数，依赖未设种子的随机数的题因此能通过检查，判分时新的 Worker 却抽到别的数。改为每个任务后用系统熵重新播种，与新的解释器相同。
- **记录中存储界面画面，重放时直接读回，不重新运行教学逻辑。** 已放弃。这相当于把缓存当作记录，新算法无法依据历史重新推断。
- **每次读取都从第一条事实重放。** 已放弃。代价随历史增长、每次调用都付。改为打开时重放一遍，之后增量更新；只有补判或重判更早任务的作答时，才把已结束的任务重新叠加一遍，次数由测试计数。
- **交付时存下打乱后的题面和编号映射。** 已放弃。它们是界面内容；记一个 seed 就能重建同样的画面，记录也小。
- **只用一个题目版本判断能否重判。** 已放弃。一个版本分不清改的是答案还是题面；题面也变了时，按新答案判旧作答会判错。
- **把 XP 也记成事实。** 已放弃。XP 由事实算出；按事实先后结算、只补发不收回，重放就得到同样的 XP。
- **按题传递信用（`uses`）。** 暂不实施。现有研究不支持依靠未经验证的隐式信用压缩复习，待真实数据证明其预测更准确后再加回。
- **memory 按公开式的直接读法更新，即 `max(0, memory + rawDelta) × 0.5^(days / interval)`。** 已放弃。这样本次刚得的信用也乘上了自上次复习以来的衰减：晚一个间隔以上才复习时，即使满额通过，memory 也只回到到期线，同一个复习立即再次出现。
- **把一题最多一个代码作答位定为长期规则。** 已放弃。有先后关系的几步代码放在同一题中继承解释器是合理的；现在的限制只到多步代码题实现为止。
- **辅导工具按行自己分页。** 已放弃。底座已经对超过上限的工具输出保存全文，模型用 `read` 按行续取；工具再分一次页，模型就要学两套续取方法。随包课程中写出来最长的一道题连同题解约 2.5 KB、76 行（2026-10-31 测量），远在上限之内。
- **`learning_read` 仍收完整的版本引用。** 已放弃。模型要逐字抄回课程、topic、种类和 64 位哈希，抄错一位就读不到；版本用来让界面的链接固定指向当时的内容，模型读的总是当前课程。
- **每个任务开一段辅导会话。** 已放弃。换任务以后旧聊天讲的是旧题，但视图在任务或阶段改变后的下一轮写出当前任务，模型据此分清；对话过长时由 Pi 压缩。

## 影响

- 学习记录每次作答写入不到 1 KB，此前为 52 至 100 KB；界面、学生模型、进度和 XP 可以删除后由事实重算。打开空间时每条事实只重放一次，之后增量更新，只有补判或改变对错的重判使更早任务的证据改变时才整段重算；60,000 条事实的全量重放约需 0.1 秒。字节上限与重算次数的断言见[代价关卡](../process/2026-10-30-cost-gates.md)。
- 改正一道题的答案或运行前导后，过去的作答自动重判，学习状态随之变化，XP 不减少；只改知识点归属不换题目版本，过去的作答照样对得上。
- 判分途中关闭应用、判分服务失败或模型表示没有把握时，任务不停滞，作答不记为错误，条件具备时自动补判。复习不限时，关闭应用后下次接着做；测验关闭期间照常计时，重新打开时按截止时刻结束。
- 课程文件换成 CRLF 换行后，题目版本和判分结论不变，代码题不再因换行静默下线。整门课核对只启动一个解释器；对同一道题的同一份作答，检查与判分给出相同的结论。
- 未配置模型时不出开放题。换一组学生模型参数，用 `new Replay(course, model)` 重放同一份学习记录，即可比较两组参数的预测。
- 辅导读到的是分行文字，前端改字段不再改变模型读到的内容和提示缓存。
- 前端契约随之改变：`completed.outcome` 增加 `unresolved`，`etaDays` 改为 `etaDate`，新增错误码 `model_required`；底座的 `Models` 新增 `defaultModel()`，课程不再接受 `uses`。
- 学习插件的数据格式升为版本 2，开发阶段的旧学习记录不转换：插件停用，提示删除 `.repa/plugins/learning/` 后重开空间。删除的 `uses` 与研究专用开关，研究重启时从 git 历史取回。
- 课程核对整门课共用解释器，候选程序改动已导入的模块（例如给 pandas 打补丁）时，影响会延续到之后的候选；随包课程没有这类代码，判分每次提交用新的 Worker，不受影响。

## 暂缓

- 出题说明排入下一阶段：要求题目区分懂与不懂的人、每个错误选项对应一种具体误解、各选项的形式和长短相近，检查工具仍只查对错；它供模型按维护者的材料出题时使用。
- 多步代码题等模型出题需要时再实现：有先后关系的几个代码作答位按顺序在同一个解释器中运行，题目写明每一步交给下一步的变量名，判第 n 步时先运行前面各步的参考解，一步出错不连累后续各步，互不相干的代码出成两道题；随包课程没有这种题。
- 学习者程序的结果超过比较上限时暂按没有证据处理，判分规则排入下一阶段；这类作答只是不计入证据，不阻塞任务。
- XP 与学习状态按当前课程计算，topic 的预计用时改了，过去课的 XP 随之改变；学习记录不存课程快照，题目与课时都取自当前课程。
- 已结束的课若因更早任务的补判改变了继承的进度，只在它自己的判分改变时按结束时的进度补发 XP，学生模型照常按重算后的进度计算；这一情形条件很窄，覆盖它要在每次重判时重新评估之后的全部任务。
- 代码题判分尚未在真实的页面 Worker 与桌面端中验证，现有测试以 Node 沙箱代替页面的 Worker，桌面端也尚未加载学习插件、关闭通用 Agent；组装学习者版本时一并处理。
- 勉强通过的课（例如每个知识点都是"错、错、对、对"）质量为一半，一学完即到期；先保留，实际使用以后再定是否给第一次间隔设下限。
- 时钟回拨跨过已结算的测验截止时间、其间又开始新任务时，重放结果与当时不同；只在这种时钟回拨下出现，情形很窄。
- 已通过的复习被后来的任务取代以后改判为不通过，不记失败，与主动中止不一致；只有新任务开始以后，重判或补判又使已通过的复习不再通过时才会出现，情形很窄。
- 读取菜单时对全部历史测验计算证据，耗时随测验场数线性增长；测验只在累计 XP 到了门槛时出现，场数远少于作答数。
- 测验选题尚未降低被其他可测 topic 覆盖者的优先级；Math Academy 没有公开降低多少，目前先按测过次数排序。
- 题目的 `measures` 只有格式检查读取，去留待定；它不进题目版本，也不影响判分和调度。
- 测验任务的 `kps` 只列第一个 topic 的知识点，复习与测验中的知识点计数恒为 0；只有课按知识点记进度。
- 代码题试运行把第一个公开测试的 setup 原样发到前端，setup 若自行算出并保存答案，答案会随之发出；写课说明已要求 setup 只放准备输入的代码，课程检查暂不识别这种情形。
- 课程作者为选项和文字作答位写的 `feedback` 尚未展示给学习者和辅导；这需要界面配合。
- 代码题判分算出的失败原因没有记录，辅导只看到测试名和对错；辅导仍能读到学习者的代码，可以据此分析。
- 复习、测验结束后，辅导只能看到最后一道题；学习者问到其他题时，模型仍能搜到已释放的题解。
- 开放题判分的提示仍以 JSON 交给模型；它是不进辅导会话的隔离调用，不影响辅导读到的内容和提示缓存。
- 单行超过 50 KiB 时，`read` 无法续取；随包课程最长的一道题连同题解约 2.5 KB。
- 概念链接 `repa:concept/<知识点编号>` 的格式留待下一阶段重新设计；它要与笔记的设计一起确定。
- `docs/research/python-course/` 中两份迁移记录的相对链接已失效，文中仍描述已删除的 `uses`；它们是冻结的核对记录，保持原貌，不在文档检查范围内。
- `packages/learning/courses/README.md` 中的运行时版本与阈值、`packages/python-runner/README.md` 中的时限与大小仍写有数值；它们只影响文档的准确，不影响学习者。
