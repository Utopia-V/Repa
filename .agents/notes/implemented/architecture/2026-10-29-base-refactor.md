# 底座重构：移除防御性机制，按约定与 Pi 的设计重整

状态：已落地

## 问题

2026 年 10 月对仓库进行了一次问题清点，所列问题均经维护者逐条讨论。底座层的问题大致分为三类。

第一类是为不会发生的问题设置的机制：每次调用插件方法都运行一次 git log 并唤醒所有插件；为一个在实际组合中从不运行的缓存保温功能给 Pi 打了补丁；压缩对话前直接修改 Pi 传入的内部对象。

第二类是同一件事写了几套，或写在了不应写的位置：确认、提问、前端代做服务各有一套"向前端发请求、等回复"；渲染视图时抛错被当作"不许运行"的关卡；用户修改提示词的方式是整段替换插件的文字。

第三类是格式和版本只认"相等才打开"：一个插件的数据版本不符，整个空间便无法打开；没有版本标记的 `.repa/` 会被直接当作当前版本；应用配置放在 `~/.repa`，主目录因此被当作空间。

学习者尚未开始使用，没有需要保护的真实数据，因此本轮可直接修改格式，不写迁移。

## 决定

### 空间格式与版本

当前为开发阶段，盘上格式可以直接修改，开发数据可以丢弃，不写迁移。旧数据可读、改写前备份和持久格式变更记录的规则自首个测试版起执行：新版本负责读取旧格式，需要改写时先备份，全部成功后才更新标记；只有旧版本会读错的改动才升版本。

- 底座以 `.repa/format.json` 识别空间，只在尚无 `.repa/` 时初始化。已有目录缺少标记、标记损坏或版本高于当前版本时，给出原因并拒绝打开；检查先于锁和辅助文件的创建，因此拒绝时不写入目标空间。
- 标记读取接受不高于当前版本的正整数，允许未知可选字段；设置及提示覆盖读取时清理未知字段，已知字段仍校验，写入严格按当前格式生成。
- 插件的数据版本由插件自行管理，底座不再维护 `plugin-versions/`，已有目录原样保留。插件打开、能力声明或启动追赶失败时，只停用该插件以及依赖它且无法成立的插件，空间其余部分照常。学习插件只为空数据目录写入版本 1 的标记；非空目录缺少标记时停用，并提示删除开发数据目录后重开空间。
- 空间版本 1 覆盖会话 jsonl、父调用关联文件、工具输出全文、影子 Git、空间提示覆盖，以及插件独占目录的位置；插件目录内部的格式由插件管理，运行锁与搜索忽略文件可重建。具体字段见[持久格式目录](../../../../docs/generated/persistence.md)，格式范围见[底座说明](../../../../packages/base/README.md#格式与版本-1)。
- 应用配置独立于空间，依次由显式指定的 home、`REPA_HOME` 和系统默认目录确定。Linux 使用 `$XDG_CONFIG_HOME/repa`，未设置或不是绝对路径时使用 `~/.config/repa`；Windows 使用 `%APPDATA%\Repa`，缺少 APPDATA 时使用用户目录下的 `AppData\Roaming\Repa`；macOS 使用 `~/Library/Application Support/Repa`。目录浏览只把有有效格式标记的目录标为空间，应用配置与空间数据不再混杂。
- 空间 Skill 位于 `.agents/skills/`，是 Agent 可修改、空间历史照常记录的普通文件；应用 Skill 位于配置目录的 `agent/skills/`。旧 `.repa/skills/` 不加载，也不迁移。
- 前端连接不再上报无人读取的 `capabilities.interaction.vocabulary` 整数，能显示的内容由能力清单决定。插件清单中插件自身的 `version` 保留，作为常规版本标注。

### 移除无收益的机制

- 插件方法调用后不再执行 `history.list(1)`、`wake` 和 `flush`。文件改动经由 `space.onRevision` 通知插件；插件自有数据不进入历史，用最新历史版本号唤醒其他插件并未传递新信息，却多启动一个 Git 子进程，历史队列繁忙时还会阻塞状态读取。插件自有状态变化通过自己的事件通知前端。
- 缓存保温的补丁和整套保温设置均已删除，缓存采用 Pi 默认行为。锁定的 Codex 目录未声明缓存寿命，原保温从不触发；学习者使用的 DeepSeek 缓存可以保留数小时，而补丁会锁定 Pi 版本并增加打包工作。日后若实际遇到需要保温的服务商，先实测，再寻求 Pi 上游解决。
- 压缩前不再原地过滤 Pi 的 `event.preparation.messagesToSummarize`。该做法依赖 Pi 的内部实现；摘要提到之前的状态本属事实。底座在 `session_compact` 中通过公开的追加与刷新入口补回最新视图，自动重试的第一次请求也能读到当前状态。

### 插件与模型之间

- **运行前的关卡。** 插件 Agent 用 `beforeRun` 在每条消息真正开始运行前判断，包括排队后的消息；拒绝时给出原因，消息不写入会话，也不启动模型。视图只负责渲染，出错按原错误报出。关卡不在同一次运行的每次模型请求前重复检查；插件进入受限状态时保存限制并中止已有工作。
- **插件调模型。** 空间插件发起的 `complete` 和 `completeStructured` 各自使用一个 Pi 短会话，输入、回复与用量随 jsonl 保存，运行内调用同时记录父关联。短会话在会话列表中隐藏，仍可按编号读取历史；没有空间归属的 runtime 调用只保存在内存中。结构化结果通过带 schema 的 `submit_result` 工具获取；模型写错工具名或参数不合格时，Pi 把具体错误交回模型，在同一会话中给它一次更正机会。整次结构化调用最多两个请求，仍不正确则返回失败和简短诊断；短会话关闭自动重试与压缩，避免额外请求。
- **超长的工具输出。** 超过 Pi 默认字节数或行数上限时，底座保留开头和结尾，把全文保存到 `.repa/tool-output/<会话 id>/<工具调用 id>.txt`，并告知模型省略量与文件路径，模型可用 read 工具继续读取。即使首行本身超过预算，也能按 UTF-8 字符边界保留内容，避免整行 JSON 被截成空内容。给模型的内容是否只含所需信息、是否分行，仍由各插件负责。

### 提示词画板

当前提示词按来源 id 整段覆盖，应用覆盖与空间覆盖依次生效，不记录覆盖基于哪一版默认文字。插件更新默认文字后，已覆盖该来源的用户收不到更新；来源 id 改变时，原覆盖也会失效。提示词画板及设置页的调整见[暂缓](#暂缓)。

### 前后端之间

- **三套反向请求合成一套。** 确认、提问、前端代做服务共用一套带编号、可取消且绑定接收连接的待答机制。请求内容、错误与关闭通知由各自调用方提供，连接断开时统一结束该连接的待答项；其他连接不能代答，已结束的请求不向重连客户端重放。
- **重连以后的运行状态。** 初始化响应写出前，后端在同一段同步代码中先订阅广播，再读取当前内存状态作为基线，并立即写出响应；后续事件排在响应之后。基线包含活动空间、停用插件，以及正在运行或有消息排队的会话，不加载磁盘旧会话。客户端通过 `handshake.baseline` 取得基线；前端接入由 Aqua 跟进，逐级退避重连与连接状态显示见[暂缓](#暂缓)。

### 会话按 Pi 的方式建立

新会话使用 Pi 1.1.0 的 `SessionManager.create(cwd, sessionDir, { id })`，编号由底座传入，文件名为 `<时间戳>_<id>.jsonl`。Pi 在出现第一条用户或助手消息时创建文件，此前缓冲的条目一并写入；未产生对话的会话关闭后不留 jsonl。

按编号打开会话时，底座只列目录，匹配 `_<id>.jsonl`，再交给 Pi 读取一个文件。找不到时返回 `session_not_found`。当前开发阶段不迁移随机文件名的旧会话，也不逐个读取会话头来查找。

### 时钟

底座通过 `Host.now()` 为插件提供可替换的时钟，测试可以拨动。学习插件的教学流程、记录和辅导另有可注入的时钟参数，默认使用 `Date.now()`，当前尚未统一接到 `Host.now()`。

### 保留的部分

- 精确编辑工具保留，实现旁写明不用 Pi 对应行为的原因：Pi 在精确匹配失败时会做模糊匹配，并规范化被改动的整行文字，包括 NFKC、去除行尾空白、把弯引号和破折号换成 ASCII。中文段落常为一整行，其中全角标点与引号可能因此被改动。
- 文件、改动通知、历史、模型调用、`runAgent`、工具中向用户提问、`createModelScope` 均保留。学习插件通过空间文件保存课程覆盖；`runAgent` 和提问供插件组织任务与交互，`createModelScope` 供父插件管理嵌套插件的模型工作。

### 构建

根目录以 `tsc -b` 和 project references 统一准备库包，各包独立入口使用同一引用关系；根目录的测试与检查先准备依赖，再以 `--ignore-scripts` 运行各包入口。增量判断交给 TypeScript，未变化的项目直接跳过，同一 worktree 的构建命令串行运行。原 `ensure-base.ts` 的时间戳扫描与构建锁已删除，构建命令与配套产物见[开发指南](../../../../docs/development/README.md#增量构建)。

## 考虑过的其他做法

- **提示词：为用户的修改记下所基于的默认文字版本，默认文字变化时提醒用户。** 已放弃。画板做法从根本上分开了用户的文字和插件的文字，既无需记录版本，也无需提醒。
- **插件调模型：只记录用量，不保存对话，因为输入随时可从事实重新拼出。** 已放弃。统一为"所有模型调用均在 jsonl 中"更简单，也更一致。
- **压缩：向 Pi 上游请求一个正式的过滤钩子。** 暂不实施。待实际使用中确认模型确实被摘要中的旧状态带偏后，再作考虑。
- **保温：保留补丁，补做在真实服务上的核实。** 已放弃。学习者使用的服务不需要保温，而补丁的代价是确定的。
- **结构化结果一律不重试，首次不合格即失败。** 已放弃。这把"不盲目重发"用过了头：Pi 的更正带有具体错误，几乎都能一次改对；直接失败则判分没有证据，日后补判还须再发一次完整的请求。
- **删除暂时无人使用的接口，例如 `createModelScope`。** 已放弃。它独立、不牵连别处，删除不会带来任何好处，而且嵌套插件本就是既定设计。

## 影响

- 插件方法读取状态不再额外启动 Git 或等待历史队列；文件改动通知与插件自有状态事件各自传递实际变化。保温补丁与内部消息对象修改被移除，升级 Pi 时少了相应的补丁和内部实现依赖。
- 空间在创建锁和辅助文件前识别格式，未知或更高版本的数据保持原样；插件失败隔离使其他插件、对话与历史仍可使用。应用配置使用独立目录，Skill 使用通用位置；旧配置、旧 Skill 和随机文件名会话由开发者自行处理，当前不提供迁移。
- 插件 Agent 的运行限制有独立入口，视图错误直接暴露；空间插件的模型调用留下可查的会话和用量，结构化调用的更正次数有明确上限。这些接口变化由仓库内插件随实现一并接入。
- 超长插件工具输出给模型保留首尾和全文路径，全文文件增加盘上占用，当前不自动删除；read 按行读取，超长单行仍需整行读，插件分行输出有利于续读。
- 确认、提问与代做服务在断线时由同一机制结束；后端提供有序基线与后续事件，前端显示仍取决于 Aqua 的接入。
- 新会话沿用 Pi 的延迟落盘，进程在首条消息前退出只会丢失尚未产生对话的空会话；按编号接续只读取匹配的一个文件。根目录全量测试统一准备库包，避免各包脚本重复构建依赖。
- 删除保温后，换用缓存寿命很短的服务商时，空闲后的第一次请求费用可能增加，届时需实测。插件提示当前仍有整段覆盖的限制，由暂缓的画板调整接续。

## 暂缓

提示词画板排入下一阶段，设置页的要求见 [#41](https://github.com/Utopia-V/repa/issues/41)。画板把插件文字与用户文字分开：提示块统一注册，插件声明固定位置，用户不调整顺序，以保持提示前缀稳定；插件板对用户只读、可以关闭，用户写在独立的板上，空间根目录 AGENTS.md 是其中一块，也可按需为各 Agent 增加用户板。插件更新只改自己的板，用户文字得以保留。

设置页的范围是查看每块板的来源、位置、启用状态与最终拼接结果，开关插件板，以及编辑用户板；现有整段覆盖随该项调整移除。原提案参考 dsh 的 `ctx.systemPrompt`：片段按序号拼接，部署方用独立的前后提示块定制，不修改插件片段。

第六步的前端部分由 Aqua 接续，包括基线接入、逐级退避重连与连接状态显示。
