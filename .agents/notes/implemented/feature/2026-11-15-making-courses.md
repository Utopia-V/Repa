# 学习者把自己的课件做成课

状态：已落地

## 问题

[里程碑一](https://github.com/Utopia-V/Repa/issues/54)的终点是试用者在应用里把自己的课件做成课并跨天学习。在本记录的决定落地之前，这一点做不到，缺的是一整条路，而不是某一处：

- 学习插件只认随包的 Python 课：课程的来源写死在插件里，一个空间里没有放自制课程的位置。
- 课程格式和课程检查绑着 Python：`runtime` 必填，检查无条件启动 Python 沙箱，一门不含代码题的课也过不了。
- 没有“把材料做成课”的流程。当时只有一份写课说明和一个检查器，没有谁来读材料、出骨架、出题、检查、改正，也没有做完以后让学习插件用上这门课的入口。
- Agent 读不了课件。PDF 和幻灯片交给读文件工具，得到的是乱码。
- 学习者版本关着通用 Agent，没有能做这件事的 Agent。
- 界面上没有放材料、看进度、看花费的地方。

此前用一门操作系统课的课件手工试过一次，得到几条必须顾及的事实：约四成知识点是要记住的内容，不是要会做的题；模型手算的数值答案不可靠，自写的数值题五处手算全错，靠程序复算才发现；现成的习题质量参差，缺答案、缺选项，卷面答案本身也有错。

## 决定

第一个测试版只求这条路走通、走得省心，不求课程结构的最终形态。[题目结构](../../proposed/architecture/2026-11-02-item-structure.md)与[知识库](../../proposed/architecture/2026-11-11-knowledge-base.md)两份提案在测试版之后实施，本记录不动它们要改的东西。这些决定由 PR [#143](https://github.com/Utopia-V/Repa/pull/143)、[#144](https://github.com/Utopia-V/Repa/pull/144)、[#146](https://github.com/Utopia-V/Repa/pull/146) 至 [#149](https://github.com/Utopia-V/Repa/pull/149)、[#155](https://github.com/Utopia-V/Repa/pull/155) 至 [#158](https://github.com/Utopia-V/Repa/pull/158) 与 [#160](https://github.com/Utopia-V/Repa/pull/160) 落地，当前的用法见学习插件说明的[在应用里做课](../../../../packages/learning/README.md#在应用里做课)。

### 一个空间一门课

自制的课放在空间里的 `course/`，格式与随包课程相同，即 `course.yaml` 加 `topics/`；材料放在空间里的 `materials/`。学习插件学的是最近一次经 `course_use` 换用的 `course/`。空间里有 `course/` 而还没有换用过时，没有可学的课，学习页给出做课的起点；空间里没有 `course/` 时，才学随包的 Python 课。

一个空间里不装几门课，也不在课程之间切换。几门课怎样共用一份学习状态，是知识库提案要回答的问题；在那之前，想学另一门课就另开一个空间。这样学习记录、学生模型和菜单都不必改，一门课做坏了也只影响这个空间。

课程文件是空间里的普通文件，经文件工具写入，改动进入空间历史，可以撤回。

### 课程格式与检查不再假定 Python

- `runtime` 只在课里有代码题或带测试的排列题（学习者的代码要运行）时才需要，缺了报 `runtime_missing`。Python 核对程序 `verify` 只在检查时运行，用的是 Repa 自己的 Python 环境，课程不必声明。检查器只在课里有 `verify`、代码题或带测试的排列题时运行 Python。
- 题型 `kind` 不再限于六个编程题取值，改为任意的小写标签。它本来就不参与选题和判分。
- 四个题池、每个知识点的题量下限、复习与测验题要有程序能判的作答位，这些维持原样。它们保护的是学习闭环：复习和测验不等模型判分，学过的内容有足够的题可练。要记住的内容用选择、填空、排序这类程序能判的作答位来考，现有格式已经支持。

### 做课由通用 Agent 完成，学习插件提供说明、工具和检查

做课要读材料、定范围、写文件、反复检查和改正，是通用 Agent 的工作。学习插件不另设一个出题的 Agent，而是提供以下几样东西：

- 一份写课说明 [`guides/making-courses.md`](../../../../packages/learning/guides/making-courses.md)，随学习插件附带，学习插件在它的提示说明 `plugin:learning` 里把绝对路径指给通用 Agent。内容是课程格式、要守的规矩和做课的顺序。同一目录的 `example-course/` 是一门不含代码题、能通过检查的完整例子。
- 工具 `course_check`：检查 `course/`，返回哪一个文件、哪一处、错在哪里、怎样改，一页 40 处，分页给出。它不调用模型。
- 工具 `course_use`：检查通过以后，让学习插件换用 `course/` 现在的内容。检查没有通过就不换，所以学习者学的始终是一门通过了检查的课。
- 工具 `course_confirm` 与 `course_brief`，在提案之后加入。前者让另一次模型调用不看答案重做每道由程序判分的题，`course_use` 只换用核对过的课，见[做课时的模型核对](2026-11-16-model-confirm-in-app.md)；后者写出要展开的部分的轮廓和学习者在它之前学到的概念，供学习者在对话里要求先做后面某一节时使用。

学习者对这门课的要求和与 Agent 商定的事，写在空间根目录的 `AGENTS.md` 里。每次运行都带着这个文件，后台展开时没有人可问，Agent 靠它知道该做成什么样。

### 课随着学习长出来

一门课不是先整本做完再学。做课像懒加载：先有一个大体的轮廓，学到哪里，哪里才展开成讲解和题目；轮廓本身也随着展开而修正。

- **轮廓**先出来，而且要快：从课件的目录、标题和章节划分得出有哪些部分、各讲什么、先后怎样，每个部分只有名字、一句话的范围、它在材料里的出处和估计的知识点。这一步不细读全部材料，几分钟内让学习者看到整门课的样子，他可以删掉不学的、标出要紧的。
- **展开**只做学习者快要学到的那一小段：细读对应的材料，按出处实际讲的内容增删估计的知识点，写讲解和题目，再检查、核对、换用。学习者学着前面的，后面的接着展开；学完了已经展开的部分而后面还没有做好时，学习页如实显示正在展开的部分。
- **轮廓会变。** 细读一段材料以后，常会发现原先的划分不对：两个部分其实是一回事，某一节该拆开，先后次序要调。还没学到的部分可以随时改。已经学过的部分不因此推倒：它的题目和学习记录照现有的规矩保留，要改正也只按“题目 id 是身份、改答案会重判”的办法改。

这样第一节课很快就能开始，没学到的部分不花钱；轮廓里的错也便宜，因为发现时它后面还什么都没做。

轮廓记在 `course/` 的课程文件里：还没展开的 topic 写成 `status: outline`，展开的写成 `status: complete`。换用以后，学习页据此显示整门课的样子和哪些部分已经可以学。第一段由对话里的 Agent 在学习者认可轮廓以后展开，后台不抢先做。此后的展开按以下规则进行：

- 学习者学到已展开的部分只剩一节没学时，学习插件经 `host.models.runAgent` 在后台让通用 Agent 展开接下来的两部分（`EXPANSION_SIZE`，Repa 的假设）。同一时刻只有一次展开；每个“学过的 topic 数”只自动试一次，失败如实记下原因，不自动重试，学习者再学完一节或明确要求时再做。
- 学习者可以随时要求先做某一部分（前端经 `building.expand`），也可以用 `settings.set` 关掉自动展开，设置存在插件数据目录的 `settings.json`。
- 后台任务列出程序按换用的那一版现算的内容（`expansion-brief.ts`）：要展开的各部分的范围、出处、直接先修和估计的知识点，学习者在它们之前学到的概念，以及还没讲到的部分。模型因此不必为这些去翻课程文件。
- 学习者有做到一半的任务时，`course_use` 只换用只增不改的新版本，即展开过的 topic 除核对记录外一字不差，只展开轮廓或增加部分；进行中的任务照常继续。新版本改了展开过的部分时，`course_use` 不换用并写明原因。提案设想的是等学习者做完手头的任务再自动换用，这一步没有实现：后台展开的说明要求不动展开过的部分，万一改动了而没能换用，这一次展开记为没有成功，按上一条规则在之后重做。

规矩里有两条来自那次手工试做，写在说明里，第一条另由检查器强制：

- 数值答案由程序算出。凡是要计算的答案，写一段核对程序独立算出来，不用模型心算的结果。检查器运行这些程序；答案是数的作答位只列进 `manual` 时，以 `numeric_manual` 报错。
- 现成的习题只在题面完整、答案能核对时才用，否则改写或另出。

### 课件转成文字

随产品附带的插件 [`@repa/materials`](../../../../packages/materials/README.md) 提供工具 `materials_list` 与 `materials_read`，把 `materials/` 里的文件读成文字，按页、按张或按段返回。它支持带文字层的 PDF、PPTX、DOCX，以及提案之外的旧版 PPT 与 DOC。插件以 npm 包的形式随包，带着解析这些格式的库，装上应用就能用，不依赖使用者机器上的其他程序。扫描件没有文字层，读不了；插件不交回空白或乱码，而是给出一句能转述给学习者的原因，例如“可能是扫描件或图片”。

### 没有课件时

很多学习者手里没有课件，或者资料在网上某处。所以学习页的起点在没有课件时，写了想学什么也能开始；`building.begin` 随之给出另一条第一条消息，写明没有课件，并附上学习者想学的内容。写课说明里有这时的做法：先用 `ask_user` 问清想学什么、为了什么、现在的起点、有没有指定的资料，一次问完，至多追问一次；学习者指定了地方就先读那里，没有就搜索，优先教材、课程主页和官方文档；轮廓先按学科通行的结构排出，再用读到的资料核对，用到的网页登记为课程清单里带 `url` 的来源，许可不明时只作取材参照。其余与有课件时相同。

搜索和读网页用模型提供方现成的服务，底座只把它包成通用 Agent 的 `web_search`、`web_fetch` 两个工具（见[底座说明](../../../../packages/base/README.md#搜索与读网页)）。试用者大多用 DeepSeek，而 DeepSeek 在 2026 年 11 月公布了 Search API 与 Fetch API，认证用的就是学习者已经接上的那把密钥。密钥在底座手里，插件拿不到，所以工具放在底座，只给通用 Agent，凭据里有提供这项服务的提供方时才出现。接的不是 DeepSeek 时，Agent 如实告诉学习者只能凭自己的知识做，这样写出的部分不登记来源。

### 学习者版本打开通用 Agent

做课和自写插件都以通用 Agent 为前提，所以学习者版本打开它。命令确认保持询问模式；只由少数只读命令组成的 bash 命令不问，名单与判断方法见[底座说明](../../../../packages/base/README.md#定义-agent关卡与视图)，PowerShell 命令一律询问。

### 界面

做课不另设页面，而是放在学习页上。还没有课的空间里，学习页是做课的起点：列出 `materials/` 里的课件，可以添加课件、写要求，然后开始。开始以后，右侧是做课的对话；课有了轮廓以后，学习页显示整门课的全貌，即各部分的状态、正在展开的部分和最近一次没有成功的原因，标题一行有到现在的花费和自动展开的开关。吩咐经对话进行，状态显示在页面上：前端用 `building.get` 读取，状态变化时插件发 `building.changed`。花费由底座的 `host.models.usage` 按会话汇总各次模型请求的用量，按模型目录的单价折算；做课的对话、调用过做课工具的会话，以及它们起的子 Agent 和模型核对的调用，都算在内。

## 考虑过的其他做法

**先实施题目结构提案，再做课。** 那样做出的课一开始就是知识点、考法、变式的结构。但它要改学习记录的格式和学生模型的取证方式，测试版会因此推迟，而它要回答的问题只有真人学过自制的课以后才看得清。

**一个空间里装几门课。** 学习者不必为每门课另开空间。但它要先回答同一个知识点在两门课里算不算一个，这正是知识库提案的内容。

**学习插件自带一个出题的 Agent。** 可以给它更窄的工具。但做课需要的读写文件、运行核对程序、向学习者提问，通用 Agent 都已具备；另设一个，只会多出一套权限和入口要维护。

**课件转文字做成不带依赖的插件文件夹。** 自写插件就是这种形式。但不带解析库就读不了 PDF，只能依赖使用者机器上恰好装着的程序。

**先把整门课做完再学。** 课程一次成型，结构前后一致。但一门课几十节、几百道题，学习者要等很久、先付全部的花费，而其中相当一部分他未必会学到；骨架里的错也要等全部做完才显出来。

**自己写一个搜索插件，或者接一个搜索服务。** 几乎所有 Agent 都能搜索，提供方的接口已经有了，再造一套搜索、抓取的机制是重复发明，还要学习者另申请一个服务的密钥。打开 Pi 的 MCP 接入是更大的一件事，排在测试版之后，见[通用 Agent 接上 MCP 服务器](2026-11-16-mcp-servers.md)的提案。

**用 DeepSeek 给模型的服务器端工具（`deepseek_web_search`、`deepseek_read_url`）。** 不必写工具。但它只支持 flash，网页正文不交回客户端，不能分段和缓存，锁定的 Pi 也没有接它。

**由我们替试用者把课做好。** 最省事，也最可控。但那样检验不到这个产品要回答的问题：学习者能不能自己把手头的材料变成一门课。

## 影响

- 学习者在一个新空间里放进课件，几分钟内就能看到整门课的轮廓，随后第一节展开并通过检查和核对，学习页出现可学的第一节，后面的部分仍只是轮廓；没有展开的部分不产生花费。2026-11-16 在 Windows 笔记本上验收候选版本时，四份操作系统课件（三份 PPT、一份 DOC）做成 38 部分的轮廓约用 2 分钟，前两节展开、核对并换用约用 5.5 分钟，之后后台自动展开第 3、4 部分约用 6 分钟；这门课到此的花费约 0.2 美元，共 204 次请求。上完一节、关闭再打开，学习页回到同一门课，进度不变。
- 一门不含代码题的课能通过检查并上完一节，学习插件的代码不必为它修改。
- 检查没有通过，或有题缺少当前的核对记录时，学习者学的仍是上一次换用的课。
- 放进扫描件时，Agent 得到“读不出文字”的原因，而不是凭空编出一门课。
- 不放课件、只写想学什么时，Agent 先问清需求；接上 DeepSeek 时到网上找资料，轮廓里的各部分登记网页出处；用别的提供方时如实说明只能凭模型自己的知识做。
- **课的质量**仍是最大的未知数。检查器保证格式正确、数值答案经程序算过，模型核对挡住一部分题面的毛病，但保证不了讲解清楚、题目考到点上。要用真实课件多做几门，并由学习者真正学过，才能知道。
- **花费。** 一门课几十节、几百道题，全部做完的模型用量不小。只展开快要学到的部分、在页面上显示花费，学习者不学的部分就不花钱。后台自动展开会在学习者没有明确要求时产生花费，所以花费显示在学习页上，自动展开也可以关掉。
- **轮廓改动与学过的内容。** 已经学过的部分不随轮廓重排，轮廓改得多了，学过的那几节可能与后来的划分不完全对齐。彻底的办法是知识点以名字为身份，属于知识库提案。
- **Python 核对的运行环境。** 核对程序和代码题的检查先用 Linux 沙箱；Windows、macOS 和缺少 Landlock 的 Linux 上建不了沙箱，改经开着的应用页面的 Worker 运行，学习者做代码题时判分本来就在那里运行。应用窗口都关着时两处都没有，检查报 `python_unavailable`，后台展开过不了检查，记为没做成。经页面核对时每批测试启动一个新的 Worker，一次检查要多花些时间。
- **一个空间一门课是阶段性做法。** 知识库实施以后会改，届时已有的自制课怎样并入要有交代。
- **学习者版本有了通用 Agent**，也就有了执行命令和写文件的能力，命令确认是唯一的关卡。做课时弹出的确认展示的是原样的命令，不懂技术的学习者难以判断该不该允许。

## 未做与暂缓

- **扫描件读不了。** 试用者的材料若主要是扫描件，这条路走不通，要补本机识别或交给能看图的模型，由里程碑一之后的工作接续。
- **改了展开过的部分以后的自动换用**没有实现，理由与现在的做法见上文“课随着学习长出来”的最后一条规则。
- **学过一节以后，学习页回不到做课的对话。** 学习页右侧只要状态里有一项学习任务就是辅导，这项任务已经结束或中止时也是如此，没有任务时才是做课的对话（`apps/web/src/pages/learn.tsx`）。所以学过一节以后，学习者想改课只能从侧栏新开一个会话吩咐通用 Agent。候选版本验收时也观察到了这一点。
- **`course/` 里没有换用的改动，会在下一次换用时一起带上。** 被核对挡下、留在 `course/` 里的改动没有“放弃”的入口，下一次 `course_use` 会把它与新的改动一起检查和换用。
