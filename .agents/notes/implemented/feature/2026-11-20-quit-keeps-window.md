# 退出时窗口留到后端收尾完成

状态：已落地

## 问题

学习者关掉桌面端时，后端还要收尾：停下正在进行的模型请求，最后备份一次，提交空间历史，再释放空间锁。平时这一步不到 1 秒；会话记录较大、杀毒软件逐个扫描新文件，或插件的 `close` 卡住时，可能慢得多，甚至不结束。

原先的做法是窗口立即消失，后端在后台收尾，超过 60 秒就结束后端进程。窗口一关，Windows 和 Linux 上应用就没有界面了，学习者无法再退出一次；再次打开应用时，单实例锁把这次启动交给仍在收尾的进程，什么也不会发生。60 秒的期限正是为此而设。然而，同类软件没有这样做的：VS Code 在关闭变慢时保留窗口，过一会儿显示“Closing the window is taking a bit longer…”，只给一个“Close Anyway”，主窗口的等待不设期限；Joplin 退出时若有待同步的改动，显示说明和“Quit anyway”；Anki 保留窗口并显示备份进度，等备份完成再退出。这些产品都把等待留在学习者看得见的地方，由用户决定是否不再等，而不是让进程在没有界面时自行到期。

## 决定

退出时窗口保留，后端开始收尾；收尾完成，窗口关闭，应用退出。平时不到 1 秒，学习者看不出变化。

收尾开始的同时，主进程经 preload 通知页面（`onQuitting`）。页面停下与后端的连接，此后不显示“后端连接已中断，正在自动重连”，也不再重连，因为后端是应用自己关的。收尾超过 2 秒仍未完成，页面盖上一层说明：“正在保存并退出”，以及“立即退出”按钮。2 秒是 Repa 的假设，写在 `QUIT_NOTICE_DELAY_MS` 旁：平时不到 1 秒，超过它才值得打扰学习者。

点“立即退出”（经 preload 的 `quitNow`），或在收尾期间再关一次窗口、再按一次退出快捷键，都结束后端进程，应用随即退出；空间锁留到过期后回收，尚未提交的文件改动在下次打开空间时记为外部改动。除此之外不结束后端进程，不再有到期自动结束：窗口还在，学习者自己能决定。

macOS 上关窗口不退出应用，保持原样。真正退出时走同一过程；此时若已没有窗口，就不显示任何东西，收尾慢时再退出一次即结束后端进程。

实现在 `apps/desktop/src/main/quit.ts`：窗口的 `close` 事件（macOS 以外）在有后端要收尾时被拦下，改为退出应用；`before-quit` 第一次到来时开始收尾，收尾期间再到来就结束后端进程。页面一侧在 `apps/web/src/app.tsx` 与 `apps/web/src/components/domain/connection-state.tsx`。

## 考虑过的其他做法

- **窗口先消失，后台收尾，到期结束后端进程。** 即原先的做法。窗口消失后学习者既看不到应用还在保存，也无法决定不再等，只能靠一个期限替他决定；期限长了，重新打开应用时什么也不会发生，期限短了，又会截断正常但较慢的收尾。
- **保留窗口，同时保留一个较长的自动期限。** 窗口在时学习者已有“立即退出”可用，自动期限只会在他选择继续等的时候替他放弃，不防范任何学习者自己处理不了的情形。

## 影响

- Windows 关机或注销时，Electron 不发退出事件，这一情形不在此处理，结果与原先相同，后端随宿主一起被结束，见[接入客户端与进程宿主](../../../../packages/base/README.md#接入客户端与进程宿主)。
- 在浏览器里直接打开页面（没有桌面端）时没有这一层；Web 开发服务器关闭后端时，页面照常显示断线并重连。
