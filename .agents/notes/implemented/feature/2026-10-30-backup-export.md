# 空间备份与学习数据导出

状态：已落地

## 问题

学习插件改为只记事实以后，学习者的进度、XP、复习安排和学生模型都由 `.repa/plugins/learning/records.jsonl` 中的事实算出。空间历史不记录 `.repa/`，这份日志没有任何副本：测试版的缺陷若把它写坏，或学习者误删了空间文件夹，几周的学习进度随之丢失，维护者用于评价的数据也一并丢失。#54 列出的停止条件中，第一条就是学习数据损坏或丢失。

另一方面，维护者需要在学习者同意时取得学习数据，用于校准学生模型，这是里程碑一的评价依据之一。此前只能请学习者手动压缩整个空间文件夹再发送，其中可能夹带与学习无关的私人内容，学习者也无从确认发送了什么。

要求：定期自动备份，间隔可以调整，只保留最近几份；学习数据可以一键导出，其中必含作答记录与版本信息，会话记录由学习者选择是否包含。备份只存在本机，这与同类产品一致：Anki 默认每 30 分钟自动备份一次卡片与复习数据，间隔可调，存于本机，[文档](https://docs.ankiweb.net/backups.html)也说明本机备份不能防范设备损坏或丢失；Obsidian 的[文件恢复](https://help.obsidian.md/plugins/file-recovery)按不短于 5 分钟的间隔为笔记存快照，默认保留 7 天，存于笔记库之外。

## 决定

### 备份的内容与位置

底座定期把空间的 `.repa/` 复制一份，作为一份备份，存到应用配置目录的 `backups/` 下，不放在空间之内。`.repa/` 中有学习记录、会话、工具输出全文、提示覆盖，以及记录空间文件历次修订的历史库 `history.git`，所以一份备份同时保存了学习数据和空间文件的历史。空间锁 `.repa/lock`、恢复留下的标记与暂存内容，以及写到一半的临时文件不收入；复制不跟随符号链接与目录联接，空间外的文件不会被带进备份。

各空间的备份按空间根目录真实路径的 SHA-256 前 16 位分组存放。每份备份是一个普通目录：`data/` 是 `.repa/` 的副本，`manifest.json` 记下空间路径、备份时间、种类（定期备份或“恢复前”的备份），以及所收各文件的路径、大小和修改时间。

### 何时备份

打开空间以后、使用期间每隔一个间隔、关闭空间之前，各检查一次；设置页的“立即备份”走同一条检查，各次检查依次进行。间隔由学习者设定，默认 30 分钟，可在 5 至 1440 分钟之间调整；改了间隔，从这时起按新的间隔等下一次检查。

检查时，把 `.repa/` 中各文件的路径、大小和修改时间与最近一份备份的清单比较，没有变化就不复制。这样，应用空闲时不会产生内容相同的备份，较早的备份也不会因此被挤掉。空间文件的改动记入历史以后，历史库随之变化，下一次检查即会备份。

关闭空间时的检查在 Agent 与插件都停下以后、释放空间锁之前完成，桌面端退出时等后端收尾，也就等它结束；关闭因此稍慢，但上一次使用的改动不必等到下次打开才进入备份。

### 一致性

备份不暂停学习与对话；只有复制历史库期间，空间文件的写入排队等待。每个文件按它的写法，取进程在复制时意外退出也会留下的状态：

| 文件 | 写法 | 备份的取法 |
| --- | --- | --- |
| 学习记录（`.jsonl`） | 学习插件按行追加 | 复制到最后一个换行符为止，不收半行 |
| 会话（`.jsonl`） | Pi 在主线程上同步写入：平时按行追加；新建会话、读取需要迁移的旧版本会话、分支到新文件时整体重写 | 每个文件用一次同步复制完成，整体重写不会与之交错；同样只复制到最后一个换行符 |
| 提示覆盖、会话的父关联、`.ignore` | 先写临时文件，再改名 | 读到的总是某一个完整版本；临时文件不收 |
| 版本标记、工具输出全文 | 只写一次；工具输出写完以后才在会话中引用，父关联在会话文件出现之前写下 | 先复制会话、后复制其余文件，备份中的会话所引用的文件都已写完 |
| 历史库 | 提交与维护都经过历史队列 | 在历史队列中复制 |

各文件取自不同的时刻。会话所引用的工具输出全文和父关联，按上表的顺序复制即可保证齐全；学习记录与历史库不引用 `.repa/` 中的其他文件。学习记录中的每条事实只引用在它之前的事实，以完整行结尾的任何前缀都能重放。所以从备份恢复以后，已收下的作答都在；没有判出结果的作答，题目仍在且题面未变时自动补判，否则保留作答，不算对错。

插件数据目录中的文件须属于上表中的写法。以后的插件若需要其他写法（例如数据库文件），须先提供自己的备份方法，其数据才能纳入备份。

### 保留与失败

每份备份先写到所属分组中以 `.tmp-` 开头的临时目录，全部复制并同步以后改为正式名称，才算成功；进程中途结束留下的临时目录，在这一组下次备份时清理。成功以后，删除这个空间超出保留份数的最旧的定期备份；保留份数由学习者设定，默认 5 份，可在 1 至 100 份之间调整。最近一次成功的时间取这一组最新一份备份的时间。

失败时（例如磁盘已满、目录不可写），删除临时目录，已有的备份全部保留。失败原因记在活动空间的备份状态里，设置页显示它与最近一次成功的时间；下一次检查时再试，之后成功或确认没有变化时清除。

### 恢复

恢复在空间列表中进行，不需要先打开空间，所以空间因数据损坏而打不开时也能恢复。每个空间列出它的备份（时间、大小与种类）；文件夹已不存在的空间，其备份同样列出。学习者选定一份后，有两种恢复方式。

**恢复到原位置**，用于空间的数据损坏或想回到较早的状态：

1. 取得空间锁，恢复全程持有；空间在本后端或别处打开时以 `space_locked` 拒绝，文件夹已不存在时以 `space_not_found` 拒绝。`.repa/lock` 留在原处；学习者只删了 `.repa/` 时，先把这个目录建出来。
2. 把当前的 `.repa/` 复制为一份“恢复前”备份，空间锁以及上次中断留下的暂存目录、换出的内容和恢复标记不收入。此时空间已关闭，没有写入者，这一步不打开空间，也不提交历史，数据已经损坏时同样可以做；所有文件按原始字节复制，日志不截，当前状态原样保留，以便撤回或排查。“恢复前”的备份不参与轮换，保留到学习者删除为止，用它可以撤回这次恢复。这一步失败时停止恢复，空间保持原样。
3. 先清理上次中断留下的暂存与换出的内容，再把选中的备份复制到暂存目录 `.repa/restore-staging/`，写下恢复标记 `.repa/restore.json`；把 `.repa/` 中除锁、暂存目录和标记以外的内容全部换出到 `.repa/restore-replaced/`，再把暂存的内容换入；换入换出都落盘以后，删除换出的内容和暂存目录，最后删除标记。

学习记录、会话和文件历史由此回到备份时的状态；空间文件保持原样，下次打开时作为外部改动记入历史。中途中断以后，打开空间时见到恢复标记即以 `restore_incomplete` 停止，提示重新恢复。重新恢复从头做起：中断前的状态已在上一次的“恢复前”备份中完整保存，选中的备份也没有改动，所以从头再做不会丢失数据。

**恢复到新文件夹**，用于空间文件夹被误删的情形：学习者为新空间选定位置与名称，该处已有同名的文件或文件夹时以 `restore_target_exists` 拒绝。底座在同一位置的临时文件夹 `.<名称>.restoring` 中准备全部内容，即备份中的 `.repa/`，加上按其中历史的最近一次修订写出的空间文件；这些文件与新建的目录自底向上同步落盘以后，再改为选定的名称。中断时只留下临时文件夹，再次恢复到同一名称时先清理它。空间历史不收入的文件（忽略项、嵌套仓库和大文件）不在其中。

两种恢复从备份复制时，来源中的目录或文件中途消失即报错，不发布：这说明所选的备份正被删除，例如原空间仍在使用、定期备份恰好把它轮换掉了，复制出的内容会缺少学习记录。Windows 上杀毒软件扫描新文件时，目录改名可能暂时失败，发布备份和换入换出都会稍候重试。

### 导出学习数据

学习插件提供“导出学习数据”，生成一个 zip，由学习者自行发送给维护者。导出按固定的白名单收入：学习记录 `records.jsonl`，截取到预览开始时的最后一个完整行；`learning.json`，记下插件的代码版本、学习记录的格式版本、课程标识与版本；学习者选择包含会话时，再收入空间 `.repa/sessions/` 中的全部会话记录，即辅导对话、判分等模型调用，以及通用 Agent 开着时与它的对话。底座另加 `manifest.json`，记下生成时间、Repa 版本、插件 id、是否收入会话，以及各文件的字节数、记录条数与替换处数。导出不跟随链接，空间中的其他文件一律不收，会话的父关联与工具输出全文也不收。

应用设置与登录凭据不在空间内，不会被收入；但学习者可能把密钥写进作答，会话正文中也可能有工具读出的文件内容。所以导出的全部内容都按反馈包的规则替换凭据与密钥：保存的凭据、Pi 解析出的密钥和名称像凭据的环境变量值逐字替换，再处理私钥与常见令牌格式，`.jsonl` 逐行解析后替换；读不到保存的凭据时不生成导出。会话可能含有私人内容，默认不包含；界面在导出前说明这一点，并展示清单，列出所含文件、记录条数与替换处数。

导出分两步：`export.prepare` 读取、脱敏并在内存中打成 zip，冻结这一份，返回清单；`export.create` 把同一份 zip 写出。预览与最终的 zip 因此一致，预览以后新增的记录不会使清单与内容不符。学习插件只保留最近一次预览：写出成功、再次预览或关闭空间以后，旧的预览失效，需要重新预览；写出失败时，这份预览仍然有效。

读取、脱敏与写出由底座的插件接口 `Host.prepareExport` 提供，学习插件只列出白名单。底座只收插件数据目录下的顶层文件，按读取开始时的大小读，`.jsonl` 只取到最后一个换行符；多级路径与符号链接都拒绝，因为中间一级目录若是指向别处的链接，只查最后一级挡不住它，而学习插件只导出顶层文件。会话与备份时一样，每个文件在一段同步代码里读完。zip 沿用反馈包的写法：在内存中生成，先写同一目录中的临时文件再发布，不覆盖已有文件；默认放在应用配置目录的 `exports/`，桌面端可以指定为“下载”文件夹。

### 前端

界面由 Aqua 实现，后端提供以下方法与事件。设置页用 `settings.get`、`settings.set` 调整备份间隔与保留份数，用 `backup.create` 立即备份，用 `backup.status` 和通知 `backup.updated` 显示最近一次成功的时间与失败原因。空间列表用 `backup.list` 列出各空间的备份，`backup.restore` 和 `backup.restoreTo` 是两种恢复方式，`backup.delete` 删除“恢复前”的备份；`space.open` 报 `restore_incomplete` 时，引导学习者从这个空间的备份重新恢复。学习界面用学习插件的 `export.prepare` 与 `export.create` 导出学习数据。用法见[底座的备份与恢复](../../../../packages/base/README.md#备份与恢复)和[导出学习数据](../../../../docs/development/learning-records.md#导出学习数据)。

## 考虑过的其他做法

- **由学习者选择备份文件夹，备份整个空间文件夹的 zip。** 本提案的上一版，已放弃。它须处理同步盘锁住文件等问题，学习者还要多做一次选择；而空间文件已由 `.repa/` 中的历史记录，备份 `.repa/` 即可。
- **备份存为 zip。** 暂不采用。底座现有的 zip 代码在内存中生成整个文件，`.repa/` 较大时占用内存；恢复还须新增读取 zip 的代码。目录可以逐个文件复制，恢复时直接复制回去。
- **备份时暂停全部写入。** 已放弃。学习记录由学习插件直接追加，会话由 Pi 写入，都不经过底座的队列，要暂停它们须为插件增加新的协调接口；按写法取意外退出时的状态，不需要暂停。
- **中断后从断点续做恢复。** 已放弃。续做须为每一项记下进度并据此判断；从头重做同样不丢数据，因为“恢复前”的备份与选中的备份都保持不变。
- **存放在各平台的数据目录**（例如 Linux 的 `~/.local/share`、Windows 的 `%LOCALAPPDATA%`）。暂不采用。应用的设置、凭据与反馈包都在应用配置目录，`REPA_HOME` 一处即可改变全部位置，测试也依靠它与真实目录隔离。备份占用的空间成为问题时再迁移。
- **云端备份与跨设备同步。** 不在本记录的范围内。
- **导出时附带学生模型的计算结果。** 已放弃。学生模型由事实重算，导出事实即可，不把派生内容当作记录。
- **导出作为底座的协议方法，插件只声明要收入的文件。** 暂不采用。学习界面经学习插件的方法工作，导出与其余学习操作走同一条路，课程与记录格式的版本也由插件给出；底座只提供插件自己做不到的部分，即保存的凭据、会话记录、应用配置目录，以及与反馈包共用的脱敏和写法。以后的插件需要导出时，同样调用 `Host.prepareExport`。
- **预览只返回清单，写出时重新读取。** 已放弃。两次读取之间新增的记录会使清单与内容不符，学习者确认的就不是实际发出的内容。
- **会话只收学习插件自己的会话，即辅导对话与判分调用。** 暂不采用。会话的归属记在会话文件之中，挑出它们须读遍空间的全部会话；学习者版本不开放通用 Agent，空间中的会话本来都与学习有关。会话默认不收入，收入前学习者能看到清单。

## 影响

- 学习者正常学习时，使用期间每隔设定的间隔、关闭空间之前各出现一份新的备份，应用空闲时不新增；每个空间只保留设定份数的定期备份。
- 学习进行中备份，用它恢复到原位置后，空间可以打开，学习记录没有半行，学习插件照常打开，可以继续作答。删除空间文件夹以后，用最近一份备份恢复到新文件夹，学习进度与备份时一致，空间文件恢复为备份时历史中的最近一次修订。
- 恢复到原位置以后，可以用“恢复前”的备份撤回这次恢复，保留份数为 1 时也是如此。恢复的任一步中断，重新恢复以后空间可以打开、可以继续学习；恢复到新文件夹中断时，选定的名称处不出现不完整的空间。备份失败时已有的备份全部保留，设置页显示失败原因与最近一次成功的时间；备份中途结束进程，不留下不完整的备份。
- 一键导出的 zip 只含白名单中的文件；未选择包含会话时，其中没有会话记录；作答中写有已保存的密钥时，导出内容中的密钥已被替换。脱敏只替换凭据与密钥，会话中的其他私人内容由学习者决定是否包含。
- 代价关卡：没有变化时不复制任何文件；一次备份对每个文件只复制一次，复制的字节数等于所收文件大小之和，按块读写，内存占用不随文件大小增长，不启动 Git。导出只读取白名单中的文件，每个文件只读一次。
- 备份占用的磁盘空间约为 `.repa/` 的大小乘以保留份数，再加上“恢复前”的备份。会话和工具输出全文随使用增长；空间中放入大量资料时，历史库也随之增大。备份列表显示每份的大小，学习者可以减少保留份数。
- 复制历史库期间，空间文件的写入排队等待，等待时间随历史库的大小增长。历史库很大时，再考虑只复制变化的部分。
- 导出在内存中生成整个 zip，冻结的预览在写出、再次预览或关闭空间之前一直占用相应的内存，收入的会话越多占用越大。
- 备份与导出对会话的取法都依赖 Pi 在主线程上同步写会话文件。升级 Pi 时须核对这一点；写法改变时，取法随之调整。
- 本机备份不能防范硬盘损坏或设备丢失，这与 Anki、Obsidian 的本机备份相同。数据损坏若长时间未被发现，较早的完好备份会被轮换删除；保留份数决定了能回退多远。
- 空间文件夹改名或移动以后，旧备份仍按原路径列出，新备份另起一组。
- 恢复依赖持久格式的版本规则：开发阶段的旧格式按既有规则可以丢弃，不保证跨开发版本恢复；首个测试版之后，盘上格式的改动须提供转换。

## 暂缓

- **两个请求同时恢复到同一个新文件夹会互相干扰。** 后开始的请求会清理前一个请求正在准备的临时文件夹。只有界面同时发出两个恢复请求时才会发生，所以界面应在恢复进行中禁用恢复按钮，后端不为此另加互斥。
- **代价关卡中复制的字节数取自清单中的长度，尚未在实际读写处计数。** 复制循环一直读到计划的长度为止，读不满即报错，读到的字节全部写出，所以计数与实际写出的字节数一致，现有结论不受影响；在读写处另行计数只多一层核对，留待复制的方式改变时再做。
- **关闭空间前的备份只收入已记入历史的改动。** 关闭前一刻的外部编辑，要到下次打开空间时才记入历史，再进入下一次备份。这些改动仍在空间文件中，不会丢失；只有学习者关闭以后随即误删空间文件夹，备份中才会缺少这一刻的编辑，影响很小，排到以后。
