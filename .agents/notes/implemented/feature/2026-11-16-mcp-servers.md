# 通用 Agent 接上 MCP 服务器

状态：已落地

## 问题

Repa 的通用 Agent 缺一项能力时，原先只有两条路：等底座或某个插件补上，或者用命令行。做课时已经撞上过：DeepSeek 的读网页服务读不回 PDF 讲义和一部分网站；接的不是 DeepSeek 时，Agent 没有搜索。这类能力别人大多写好了，以 MCP 服务器的形式提供（搜索、读网页与 PDF、笔记、日历、文献库），接上就能用，Repa 不必各写一个插件。

内嵌的 Pi 带着两样与 MCP 有关的东西：

- `@earendil-works/pi-mcp`：独立的 MCP 客户端库，支持 stdio 和 Streamable HTTP，负责握手、请求的对应、超时和取消，另有 OAuth 的积木。它不依赖 Pi 的其余部分。
- `pi-coding-agent` 里的 MCP 扩展：在上面那个库之上做了配置文件、工具命名、状态提示和登录命令。它只在 Pi 自己的命令行里加载，Repa 经 SDK 建的会话没有。

把后者接进 Repa 的会话，在一个草稿分支上实际试过（真实协议后端、离线模型、本机写的测试服务器）。能通，但它是为 Pi 的命令行设计的，放进 Repa 处处要绕：

| 事实 | 后果 |
| --- | --- |
| 服务器进程跟着每个 Pi 会话起：每个对话、每个子 Agent、每次后台运行各起一份，只是打开旧会话看历史也会起 | 有状态的服务器会有好几份，互不相通 |
| Pi 的会话关闭时不通知扩展，服务器不会被关掉 | 不另补一处，后端收到退出信号 8 秒后仍在运行 |
| 配置、凭据、日志默认读写 `~/.pi/agent`；改到 Repa 的目录所需的函数和类没有导出 | 要自己读配置，再把一个形状相同的对象强行当作它的凭据类传进去 |
| 连接失败、需要登录、仍在连接这些提示都发给 Pi 的界面 | 在 Repa 里全部落空，学习者什么也看不到 |
| 一个不回答的服务器让每个新会话的第一条消息等满 10 秒 | 期间没有任何提示 |
| 登录远程服务器的流程挂在 Pi 的 `/mcp` 命令上 | Repa 用不了 |
| Repa 每轮重设启用的工具，会把扩展启用的工具关掉 | 要在 Repa 一侧为它开例外 |
| 超长的结果写进 `/tmp`，不清理；Repa 自己对工具结果的截断不生效 | |

## 决定

Repa 自己管 MCP 服务器的连接，把它们的工具当作 Repa 的工具交给通用 Agent。连接用 `pi-mcp` 这个客户端库，不用 Pi 的 MCP 扩展。MCP 因此是底座的一项能力，立在 Repa 自己的接口上：配置的位置与格式、连接的归属、确认、状态都由 Repa 定。客户端库只在 `packages/base/src/mcp/client.ts` 一个文件里用到，换成别的 MCP 客户端只改这个文件。

实现前先用本机的测试服务器核对了这个库：列工具、调用、结果转成给模型的内容、调用中取消（服务器收到 `notifications/cancelled`）、超时、`tools/list_changed` 通知、进程自己退出时的通知，以及关闭时连同子进程一起结束，都够用，不需要另补。

### 服务器配置在哪里

配置属于这个人，不属于某个空间，放在应用配置目录的 `mcp.json`。格式用各家通行的 `mcpServers` 写法，因为每个服务器的说明给出的都是这一段，粘贴过来就能用：

```json
{
  "mcpServers": {
    "fetch": { "command": "uvx", "args": ["mcp-server-fetch"] },
    "notes": { "url": "https://example.org/mcp", "headers": { "Authorization": "Bearer …" }, "askBeforeCall": false }
  }
}
```

Repa 自己的两个开关也写在这一项里：`disabled`（与 Cline 等客户端的同名字段含义相同）和 `askBeforeCall`（省略时询问）。放在同一项里，粘贴来的一段不带它们时就是默认值，改名、删除时也不会留下另一个文件里对不上的记录。别的客户端写的字段（`type`、`alwaysAllow` 等）原样保留，Repa 不读。

设置页有一节“MCP 服务器”：列出配置的服务器和各自的状态，可以添加（粘贴一段）、停用、删除、切换调用前询问、重新连接失败的服务器。经协议改动时配置随即生效；手改的文件在下一次读取列表时生效。

空间里的文件不能配置服务器。空间可能是别人给的，stdio 服务器是一条在本机运行的命令；自写插件要经批准才运行，是同一个理由。

### 连接归谁

连接归后端，一个服务器一份，所有空间与会话共用。后端启动后在后台连接，不等它；连上以后它的工具才出现，连不上的在设置页显示原因。一个不回答的服务器因此不拖住任何消息，打开旧会话看历史也不起进程。连接断了标为失败并写明原因，不自动重连：断开多半有原因（缺依赖、缺令牌），自动重试只会反复起进程，使用者在设置页点一次重新连接即可。后端正常退出时关闭全部连接，等进程连同子进程结束。

stdio 服务器在使用者的主目录运行（配置里写了 `cwd` 时用它），继承后端的环境变量，加上配置里的 `env`；后端的连接令牌 `REPA_TOKEN` 不交给它。

### 工具怎样交给 Agent

每个工具登记成 Repa 的一项工具，名称按通行的 `mcp__<服务器>__<工具>`，说明和参数取自服务器。它与插件的工具走同一条路，所以结果按 Repa 的上限截断、进会话记录、前端的工具活动里看得到。运行被停止时，进行中的调用随之取消。插件工具不能用 `mcp__` 开头的名字。

只给通用 Agent 和它的子 Agent，包括插件经 `runAgent` 交给它的后台任务。插件声明的 Agent（例如学习辅导）的工具是它定义里列出的那几个，不会多出来。

### 调用之前问不问

MCP 工具可能有副作用（发邮件、改日历），而课件和网页里可能带着诱导模型的文字。沿用命令授权的做法，按服务器设定：

- 每个服务器有一个“调用前询问”的开关，默认打开：每次调用经确认种类 `mcp` 问发起这次运行的连接，写明服务器、工具和参数。
- 关掉以后这个服务器的调用不再询问。
- 命令授权设为“完全访问”时都不问。

服务器在工具上声明的“只读”不作为依据：它是服务器自己说的。后台运行没有人可问，开着询问的服务器在后台调用时被拒绝，原因作为工具错误交回模型。

### 上限

- 同时连接的服务器至多 16 个，也就是 stdio 进程至多 16 个；超出的按文件次序标为失败。常见的用法是三五个。
- 一个服务器至多声明 64 个工具，超出时整个服务器标为失败，而不是截掉一部分让模型看不到。有的提供方一次请求至多接受 128 个工具。
- 一个工具的说明至多 1024 个字符，更长的截断并标出；OpenAI 的函数说明超过这个长度时整个请求被拒。
- 请求（握手、列工具、一次调用）各自的时限默认 60 秒，配置里写了 `timeout`（秒）时用它。

### 令牌

请求头和环境变量的值、地址查询串里的值可能是令牌。它们只交给服务器，不进会话记录和给模型的内容；设置页的列表只给命令名或去掉查询串的地址；状态说明里出现这些值时换成 `***`；反馈包与插件导出的脱敏名单加上这些值。

### 第一版没有做的

- 需要 OAuth 登录的远程服务器：状态写明“需要登录，暂不支持”。用请求头带令牌的可以。
- 工具很多时的按需加载。服务器的工具全部声明给模型，嫌多就停用这个服务器。
- MCP 的资源和提示；工具结果里的图片换成一行说明，不交给模型。
- 按空间配置服务器。

## 考虑过的其他做法

- **把 Pi 的 MCP 扩展加进 Repa 的会话。** 试过，能通，约二十行加一个小文件。放弃的理由是上表：每个会话一份进程、状态对学习者不可见、登录用不了，补齐这些要在 Repa 一侧为一个扩展写一圈例外，而且它的行为取决于 Pi 没有导出的内部。
- **让 Agent 用命令行调用 MCP 服务器。** 每次调用都起一个进程，握手一次；Windows 上还要有可用的命令行。
- **按空间配置服务器。** 见“服务器配置在哪里”。
- **按服务器声明的只读标记决定问不问。** 标记是服务器自己写的，不同服务器的宽严不一；让使用者按服务器决定，规则只有一条。
- **把两个开关放进 Repa 的 `settings.json`。** 按服务器名对应两个文件，改名、删除时要两处一起改；放在同一项里更直接，别的客户端也会忽略它们。
- **连接断了自动重连。** 见“连接归谁”。
- **做成一个插件。** 密钥、连接和确认都在底座，插件拿不到，也不应该拿到；别的领域同样需要它。

## 影响

- 新的持久文件 `<应用配置目录>/mcp.json`，登记为 `mcp-config`。
- 协议多了 `mcp.list`、`mcp.add`、`mcp.remove`、`mcp.set`、`mcp.reconnect`、通知 `mcp.updated` 和确认种类 `mcp`。
- 没有配置服务器时行为与此前相同：不起进程，不多工具，提示不变。
- stdio 服务器以学习者的身份在本机运行，Repa 不隔离它；工具说明是服务器写的文字，会进模型的上下文。
- 服务器写空间里的文件不经 Repa 的写入路径，空间历史把这些改动记为外部程序的改动，可以撤回，但不归到发起它的那次运行名下。
- 后端被强行结束而服务器不理会输入流关闭时，进程可能留下。Windows 上起 `.cmd` 包装的命令（`npx`、`uvx`）与结束进程树按客户端库的写法（cross-spawn 与 `taskkill /T`），须在真机上核对。
