# 做课时的模型核对：每道题由另一次模型调用不看答案重做

状态：已落地

题目的核对由 PR [#162](https://github.com/Utopia-V/Repa/pull/162) 落地，做法与取值以学习插件说明的[模型核对](../../../../packages/learning/README.md#模型核对)为准。讲解的独立阅读量过以后，决定不作为做课的一步，名词链接尚未实现，见下文“讲解由另一个读者读一遍”。

## 问题

学习者在应用里把课件做成课，题目由模型写出。答案对不对，在本记录落地之前有两道关：答案是数的作答位必须带 `verify` 核对程序，由程序算出；其余作答位（选择、填空、排序）列进 `manual`，只在检查结果里报出个数，由写题的模型自己对照材料。

程序核对解决了算错。清点七门用真实模型做出的课，127 个由程序核对的数值作答位里，没有一处是算术错误。但把这些题交给另一次模型调用，让它只看讲解和题面、不看答案重做一遍，有 4 处与标准答案不一致，占 3.1%，逐条看都是题面的毛病：

| 情况 | 处数 |
| --- | --- |
| 题面写着“接上题”“仍是上面两个作业”，单独抽出来没有条件 | 2 |
| 条件自相矛盾：“依次提交、单道顺序执行（均在提交后立即开始）”，程序按同时提交算出 18，按题面字面是 6 | 1 |
| 记号的约定有歧义，两种读法各得一个答案 | 1 |

同样的办法用在 146 个没有程序核对的作答位上，得到 2 处真毛病（1.4%）：一道单选题有两个选项都成立，一道填空题的题面与答案的字数对不上。

这类毛病写题的模型自己看不出，因为它知道自己想说什么；核对程序也看不出，因为程序算的正是写题者的读法。学习者遇到时，按题面读对了却被判错。练习里它拖住一节课的通过，复习和测验里它压低学生模型对这个知识点的估计，而学习者分不清是自己错了还是题错了。

这道关仓库里原先就有。随包课程的复习和测验题由 `npm run course:confirm` 核对：[`check/confirm.ts`](../../../../packages/learning/src/check/confirm.ts) 把学习者看得到的题面交给一次隔离的模型调用独立再解，按作答位自己的判分规则与标准答案比对，一致的在 topic 文件的 `verified` 段记一条记录，课程检查对缺记录的题报 `manual_unconfirmed`。应用里做课当时没有接它：空间里的课按 `confirmations: "reported"` 检查，只报个数，原因是那时应用里没有能发这次调用的入口。插件可以经 `host.models` 发隔离的模型调用以后，这个原因就不在了。

## 决定

把模型核对接进应用里的做课，并把范围从 `manual` 作答位扩大到所有由程序判分的作答位。

### 谁来做，什么时候做

学习插件给做课的通用 Agent 加一项工具 `course_confirm`，参数 `topicIds` 是要核对的 topic，一次至多 8 个。它对这些 topic 里还没有当前记录的题各发一次隔离的模型调用，经 `host.models.complete`，用学习者的默认模型，花费计入这门课的花费。请求之间互不相干，可以并发：同时至多 `CONFIRM_CONCURRENCY`（8）个，一次调用至多 `CONFIRM_REQUESTS`（100）个（含重试），都是 Repa 的假设，超出的题列为没有核对，再调用一次接着核对。工具交回的是没有通过的题：题目编号、模型的作答、标准答案，以及模型认为题目有问题时的那句说明；没有核对成的题（请求失败、输出不合格式）单独列出。一致的题在 topic 文件的 `verified` 段记下，格式沿用原有的核对记录。

做课的次序变成：写题，`course_check` 改到通过，`course_confirm` 改到没有不一致，`course_use` 换用。后台展开同样如此，因为它没有连接也能发模型调用。

`course_check` 仍然不调用模型，因为它要能离线运行，同一份内容每次结果相同。它只多报一项：由程序判分的题有多少还没有当前的核对记录。

### 交给模型看什么

随包课程的请求只含题面，不含讲解。随包 Python 课的题靠通用的 Python 知识就能做；自制的课不行，课件里的定义可能与通行说法不同，题目考的是课件的说法。所以对空间里的课，请求里加上这道题所属知识点的讲解，与学习者做题时读过的一样。上面的数字就是在这个条件下量出来的。答案、解析、核对程序和别的题仍然不给；选项、排列块和表格选择格的编号照旧换成不透明的 a、b、c……，模型的回答再换回课程里的编号去判。

系统说明另请模型在题目缺条件、有歧义或不止一个答案成立时附一句说明（`note`），并按学习者的界面说明填空怎样写：文字只写答案本身、不写成句子；数值写成小数或整数、不写分数，因为学习者的输入框是小数键盘；输入框的提示文字和后面的单位照样写出。这几条来自真实模型的重放：没有它们时，独立作答的一方把填空写成整句、把非整数写成分数或不舍入的长小数，而学习者照着界面不会这样写。

### 核对哪些题

四个题池里所有由程序判分的作答位都核对：有 `verify` 的数值作答位，以及选择、填空、排序和表格。代码题与按测试判的排列题由测试判分，不在其内；按评分要点由模型判分的开放题没有唯一答案，也不在其内。例题一并核对，因为例题的答案是学习者照着学的。

`course_use` 对缺少当前记录的题怎样处理，取与随包课程相同的规则，并扩大到全部题池，例题、练习、复习、测验同样强制，这是我的决定：有题缺记录时不换用，回复列出前 40 道和总数。理由是这一关挡的是学习者会直接撞上的错，而它不通过时，Agent 手里有具体的分歧可改。给学过的 topic 补写记录不算改动了它，补上记录以后照样能换用。

### 核对记录的范围

核对记录新增范围标记 `question-lesson-v1`。它的哈希绑定题面、作答位与判分规则、数据和所属知识点的讲解，不含解析和 `runtime`：请求里没有这两项，这几种作答位判分也不运行 Python。所以改解析不必重新核对，改题面、答案、选项或讲解就要。随包课程的 `question-runtime-v1` 记录与请求不受影响。命令行可以用 `npm run course:confirm -- <课程目录> --scope question-lesson-v1` 按同样的范围重放，`--dry-run` 只打印请求、不调用模型。

### 不一致以后

工具把分歧交回 Agent，由它判断是题面、答案还是选项的问题并改写，改完再核对。没有“标记为已知并放行”的办法：模型核对错了的情形也有（量到过一次，盲做漏选了课件原话里的一项），这时把题面改得更明确，对学习者没有坏处。一道题改了两三次仍不一致时，Agent 把它删掉；知识点下的题数因此不够时如实留着，与“做不完就停下”的原有规矩一致。

模型的作答与标准答案一致、却附了说明指出题目有问题时，同样不记录，工具单独列出。这一条是在重放以后加上的：第一版照样把它们记为通过，而重放里这样的说明指出的都是真毛病，例如单选题两个选项都成立、题面要求的字数与答案不符，作答一致只是碰巧。

### 先由机械检查挡住的一类

“接上题”一类不需要模型。写课说明加了一条：每道题自成一体，题面里有解题所需的全部条件，因为题目会被单独抽出来练习、复习和测验。课程检查对题面里的“接上题”“上题”“同上题”“前一题”等写法报错误 `question_not_self_contained`（[`check/rules.ts`](../../../../packages/learning/src/check/rules.ts)）。提案原想只报提醒；实际做成错误，检查因此不通过，Agent 必须改写题面。这一条没有等模型核对，先行落地。

### 讲解由另一个读者读一遍

同一个办法用在讲解上量过，结论是不作为做课的一步，这是我的决定。

设想是：一次隔离的模型调用只看到学习者此前学过的概念和这一节的讲解，列出读不懂就卡住的术语，同时指出讲解里哪个词指的是哪个学过的知识点，后者就是名词链接。在五门真实做出的课、47 个知识点的讲解上试过，结果如下：

- **贵。** 读一篇四百字的讲解，默认的 flash 模型要输出一万多 token，几乎全是推理，约 0.013 美元；一节三个知识点约 0.04 美元，与写这一节本身相当。核对一道题只要约 0.0003 美元。
- **约三分之一是误报。** 抽 22 个它标为“读不懂就卡住”的术语逐个读过，三分之一是课预设的基础，而不是讲解没讲清，例如特征值一课里的“行列式”。读的一方不知道学习者的底子。其余属实。
- **链接约四分之三是对的。** 抽 34 处逐个读过，25 处指得对，其中有按字面匹配找不到的（讲解写“互不重叠”，指的是“互斥”那张卡片）。错的 9 处是同一种：讲解里的词没有自己的卡片，被连到一张只是提到它的卡片上。

所以讲解不逐节读一遍。写的一方已经拿到“此前学过的概念”和“后面才讲的部分”，这是[状态范围提案](../../proposed/architecture/2026-11-15-state-scope.md)的第一步，已由 PR [#160](https://github.com/Utopia-V/Repa/pull/160) 落地；学习者自述的基础在空间的 `AGENTS.md` 里，每次运行都带着。

名词链接仍然按意思来认，但不为它单独读一遍：并进做课时本来就要发的调用，或者等学习者打开这一节时再算、算过存下。提示里要写明“卡片讲的就是这个词本身才算”。名词链接尚未实现，具体接在哪一次调用上、结果存在哪里，等实现时再定。

## 考虑过的其他做法

- **答案不手写，只由核对程序给出。** 设想是模型先手写答案、再写程序去对，两者对不上会反复修改。清点真实做课的 21 次课程检查，12 次没有通过，没有一次是答案与程序不一致，全是格式错误。这个做法也不触及题面的毛病。
- **数值题写成带参数的模板，由程序生成变式。** 这解决的是复习时变式不够，属于[题目结构提案](../../proposed/architecture/2026-11-02-item-structure.md#题目的供给)的题目供给，与答案对不对是两件事。试用者学上几周、复习题真的用尽之前，没有数据说明需要它。
- **换一个更贵的模型核对。** 127 个数值作答位上，同一家的另一个模型（单价约为默认的 flash 的七倍）与 flash 各报 4 处不一致，三处真毛病两者都抓到；这几处是不是毛病，是逐条读过定的，没有把哪个模型当作标准。花七倍的钱没有多抓到东西。
- **让 Agent 起一个子 Agent 去重做，不加工具。** 子 Agent 有读文件的工具，读得到 `course/` 里的答案和解析，隔离只能靠它自觉。
- **只靠学习者申诉。** 申诉要保留，但学习者在复习里答错时分不清是谁的问题，多数不会申诉，而错判已经记进学生模型。

## 影响

- 一门自制的课换用以后，每道由程序判分的题在 topic 文件里都有当前的核对记录；改了题面、答案、选项或讲解，记录失效，要重新核对。核对的请求里没有答案、解析和核对程序，选项的编号是不透明的。学习页上这门课的花费包含核对的调用。
- PR #162 在六门真实做出的课上用默认的 flash 模型重放了两次，每次 331 道题。第一版的结果是 309 道一致，15 道不一致，7 道因网络失败而如实报为没有核对成；不一致里除已知的题面毛病外，还有非整数答案没说保留几位、填空只收了一种说法，以及模型把填空写成整句的误报。按这些结果修正以后，在同样六门课的新副本上再次重放：321 道一致并记下，5 道不一致，4 道答对但指出题目有问题，1 道因网络失败。没通过的 9 道逐条读过，都是题面的毛病，这一次没有误报：

  | 情况 | 道数 |
  | --- | --- |
  | 题面写着“接上题”“仍是上面两个作业” | 2 |
  | 条件自相矛盾 | 1 |
  | 非整数答案没说保留几位，判分只认一种写法 | 3 |
  | 单选题两个选项都成立 | 1 |
  | 题面要求的字数与答案对不上 | 2 |

  对照提案所列的 6 处毛病，记号有歧义的那一道两次重放都没有被指出，其余 5 处都被报出。
- **每节多花钱和时间。** 重放中每题约 0.0003 美元，331 道题合计不到 0.1 美元；提案阶段的实验按每题约 0.0005 美元估计，一节二十多道题约 0.01 美元，做这一节本身约 0.03 美元。请求并发，时间以秒计，但每有一处不一致，Agent 就多一轮修改和检查。
- **核对的模型与写题的模型是同一家，可能有同样的误解。** 一致不等于标准答案对；这一关挡的是两次读法不同的题，挡不住两次都读错的。记号有歧义的那一道就是这种情形。
- **讲解本身错了，核对也跟着错。** 请求里带着讲解，模型按讲解作答。讲解的对错靠出处和学习者的反馈，不在这一关。
- **误报让好题被改写。** 见“不一致以后”。改写的方向是更明确，代价是多一轮。
- **核对会阻止与事实不符的改动。** 候选版本验收时，验收者要求只改一道多选题的标准答案，使它与课件相悖；独立作答的一方反复给出原答案，这道题拿不到记录，`course_use` 不换用。另一次只把一种同样正确的写法加进填空的 `key`，重新核对一致，换用以后旧作答被重判为正确。

## 未做与待定

- **名词链接**尚未实现，接在哪一次调用上、存在哪里，见上文。
- **填空题的另一种问题：** 标准答案只列了几种写法，意思相同的别的写法会被判错。核对能看见它；写课说明现在要求 Agent 把这些写法加进 `key` 或改成选择题，判分一侧放宽匹配的改法还要另议。
- **在本记录落地之前做出的课都没有 `question-lesson-v1` 记录**，下一次换用前要整门核对一遍，需调用 `course_confirm` 两三次。
- **`verified` 段是文本。** 写课说明要求不要手改，代码并不阻止。
