# Repa 的设计语言

状态：提案

## 问题

Repa 对学习者的要求是减少一切学习外的心智负担，界面则是长期状态的视图。我运行了现在的前端，对设计语言乃至主入口均不满意。主入口要求打开以后先选文件夹，这是学习以外的一件事。界面文字的问题已在 [#101](https://github.com/Utopia-V/Repa/issues/101) 提出，这里谈其余部分。

更深一层的问题是规则没有写下来。`docs/design-system.md` 规定了 token 和组件怎样用，却没有回答界面为什么长这样、每一刻要对学习者回答什么。规则若只存在于口头，无论人还是 Agent 接手，每一轮都要重讲一遍什么可以、什么不可以。

## 做法

我的决定是先形成一整套语言，再谈落地。字号、控件、状态、动效和流程都在其中，细节要精细到可以称作设计，而这有行业标准可查。

语言分两层。一层换了主体也成立：从第三国际塔风格换到极简主义，同一件事仍应总在同一位置，能点的仍应看着能点，每一刻仍要回答学习者的问题。这一层来自行业的博客和教程，经与我们的要求对照，写成[清单](../../../../prototypes/design-language/CHECKLIST.md)。另一层才是主体，这里取名“复”：Repa 来自 repetition，图形只有一个方格单元，第一天是点阵，学得越久织得越繁复，简洁与繁复成为同一个学习者在时间上的两端。规则写在[语言文档](../../../../prototypes/design-language/LANGUAGE.md)里。

风格可以大胆，狂野也是一种设计。我对探索稿的意见在于粗糙，即实用度不够，未站在用户的位置。所以判断一个元素的标准是从学习者的位置看它有没有用，再把它做完。知识树做好了很有用，地图能回答“这一格是什么”才算地图。

[原型](../../../../prototypes/design-language/README.md)用整门 Python 课的真实内容把这条路线走通，真实内容查出的问题多于占位内容。它暂不考虑程序怎么跑，后端是模拟的。样式规则和踩过的坑写入 [`repa-design`](../../../skills/repa-design/SKILL.md)，可用于其他项目的规范写入 [`interface-craft`](../../../skills/interface-craft/SKILL.md) 和 [`ui-text`](../../../skills/ui-text/SKILL.md)，下次不必再讲。

## 考虑过的其他做法

只换配色和字体。这是最省事的路，但同一框架上的几套配色只算一个选项换了几次衣服；大框架本身可以打破，左中右三栏和先选文件夹都不是前提。

把框架、皮肤、图形都做成可替换的插件。探索时实际做过，8 种框架和 9 种皮肤跑在同一组部件上，可行。但这不是现在要做的事：我要的是产品语言，dsh 那样的插件化不在范围内，工夫花在插件的隔离和检查上，就没有花在画面上。这些探索稿保留，其中的框架和图形都算设计。

删去最张扬的部分，比如地图入口、红色楔形和织纹。不删，理由同上：问题不在狂野。

把全图作为知识库的主入口。读到的用户反馈几乎一致：全局图好看，却很少有人靠它找东西；有人用的是一跳的局部关系和反向链接。所以树、页面和局部关系是主入口，全图退到次要位置。这部分证据多为论坛自述，已在清单中标明。

用连续天数、待复习数字和单项时长促使学习者回来。学习者对积压和惩罚的反感有较多记录，这些也会把组织学习的负担交还学习者，故不用。

## 验收

- 打开应用，不读说明就知道下一步是什么、为什么是它、分量多大；没有任务时知道何时恢复。
- 做到一半离开再回来，未提交的作答和阅读位置都在。
- 答错时，题目不移动，错在哪、正确答案和判定都在眼前，题目再长也如此。
- 讲解里遇到半记得的词，不离开当前页就能看到定义；一个月前学的内容，按名字或按大致位置都能找回，并且看得懂，不必另找它提到的表。
- 有答案未提交时，读不到参考内容，也问不了辅导。
- 换掉主体的颜色、字体和图形，清单的三个部分仍然成立。
- 最终由真实学习者使用以后判断负担是否减少。

## 风险与代价

落到 `apps/web` 要重做页面结构，而不只是替换 token，工作量不小。前端由 Aqua 负责，落地方式需另行商定。

设计走在接口前面。今天页和知识库需要全课 topic 与知识点的只读状态查询，作答历史要跨任务，记忆估计要按 topic 给出，学习契约目前都没有。

正文行高、字号步长、中文标题字距和控件比例没有可靠来源，是工作值。原型只在 Linux 的 Chromium 里看过，宋体还需随应用打包切片。没有真实学习者用过；风格这样强的界面长期使用是否疲劳，地图和全图是否真比列表有用，目前都没有证据。
