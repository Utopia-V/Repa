# 做课时的模型核对：每道题由另一次模型调用不看答案重做

状态：提案

题目部分已实现（“谁来做，什么时候做”“交给模型看什么”“核对哪些题”“不一致以后”），讲解部分（“讲解由另一个读者读一遍”）仍是提案，留在 `proposed/` 待量过再定。已实现部分的做法与取值以学习插件 README 的[模型核对](../../../../packages/learning/README.md#模型核对)为准。

## 问题

学习者在应用里把课件做成课，题目由模型写出。答案对不对，现在有两道关：答案是数的作答位必须带 `verify` 核对程序，由程序算出；其余作答位（选择、填空、排序）列进 `manual`，只在检查结果里报出个数，由写题的模型自己对照材料。

程序核对解决了算错。清点七门用真实模型做出的课，127 个由程序核对的数值作答位里，没有一处是算术错误。但把这些题交给另一次模型调用，让它只看讲解和题面、不看答案重做一遍，有 4 处与标准答案不一致，占 3.1%，逐条看都是题面的毛病：

| 情况 | 处数 |
| --- | --- |
| 题面写着“接上题”“仍是上面两个作业”，单独抽出来没有条件 | 2 |
| 条件自相矛盾：“依次提交、单道顺序执行（均在提交后立即开始）”，程序按同时提交算出 18，按题面字面是 6 | 1 |
| 记号的约定有歧义，两种读法各得一个答案 | 1 |

同样的办法用在 146 个没有程序核对的作答位上，得到 2 处真毛病（1.4%）：一道单选题有两个选项都成立，一道填空题的题面与答案的字数对不上。

这类毛病写题的模型自己看不出，因为它知道自己想说什么；核对程序也看不出，因为程序算的正是写题者的读法。学习者遇到时，按题面读对了却被判错。练习里它拖住一节课的通过，复习和测验里它压低学生模型对这个知识点的估计，而学习者分不清是自己错了还是题错了。

这道关仓库里已经有。随包课程的复习和测验题由 `npm run course:confirm` 核对：[`check/confirm.ts`](../../../../packages/learning/src/check/confirm.ts) 把学习者看得到的题面交给一次隔离的模型调用独立再解，按作答位自己的判分规则与标准答案比对，一致的在 topic 文件的 `verified` 段记一条记录，课程检查对缺记录的题报 `manual_unconfirmed`。应用里做课没有接它：空间里的课按 `confirmations: "reported"` 检查，只报个数，原因是当时应用里没有能发这次调用的入口。现在插件可以经 `host.models` 发隔离的模型调用，这个原因不在了。

## 做法

把模型核对接进应用里的做课，并把范围从 `manual` 作答位扩大到所有由程序判分的作答位。

### 谁来做，什么时候做

学习插件给做课的 Agent 加一项工具 `course_confirm`，参数是要核对的 topic。它对这些 topic 里还没有当前记录的题各发一次隔离的模型调用，经 `host.models.complete`，用学习者的默认模型，花费计入这门课的花费。请求之间互不相干，可以并发。工具交回的是没有通过的题：题目编号、模型的作答、标准答案，以及模型认为题目有歧义时的那句说明。一致的题在 topic 文件的 `verified` 段记下，格式沿用现有的核对记录。

做课的次序变成：写题，`course_check` 改到通过，`course_confirm` 改到没有不一致，`course_use` 换用。后台展开同样，它没有连接也能发模型调用。

`course_check` 仍然不调用模型：它要能离线运行，同一份内容每次结果相同。

### 交给模型看什么

现有的请求只含题面，不含讲解。随包 Python 课的题靠通用的 Python 知识就能做；自制的课不行，课件里的定义可能与通行说法不同，题目考的是课件的说法。所以对空间里的课，请求里加上这道题所属知识点的讲解，与学习者做题时读过的一样。上面的数字就是在这个条件下量出来的。答案、解析、核对程序和别的题仍然不给；选项的编号照旧换成不透明的。

### 核对哪些题

所有由程序判分的作答位都核对：数值的（有 `verify`）、选择、填空、排序。代码题由测试判分，不在其内；按评分要点由模型判分的开放题没有唯一答案，也不在其内。例题一并核对：例题的答案是学习者照着学的。

`course_use` 对缺少当前记录的题怎样处理，取与随包课程相同的规则并扩大到全部题池，例题、练习、复习、测验同样强制，这是我的决定：有题缺记录时不换用，回复写明是哪些题。理由是这一关挡的是学习者会直接撞上的错，而它不通过时 Agent 手里有具体的分歧可改。

### 不一致以后

工具把分歧交回 Agent，由它判断是题面、答案还是选项的问题并改写，改完再核对。没有“标记为已知并放行”的办法：模型核对错了的情形也有（量到过一次，盲做漏选了课件原话里的一项），这时把题面改得更明确对学习者没有坏处。一道题反复改不过时，Agent 把它删掉，知识点下的题数不够就如实留在轮廓里，与“做不完就停下”的现有规矩一致。

### 先由机械检查挡住的一类

“接上题”一类不需要模型。写课说明加一条：每道题自成一体，题面里有解题所需的全部条件，因为题目会被单独抽出来练习、复习和测验。课程检查对题面里的“接上题”“上题”“同上”报提醒。这一条不等本提案，随手先做。

### 讲解由另一个读者读一遍

同一个办法可以用在讲解上，这一部分证据还少，排在题目之后。

[状态范围提案](../architecture/2026-11-15-state-scope.md)的第一步让程序算出“学习者在这一节之前学到的概念”和“后面才讲的部分”，交给写这一节的模型，要求清单之外的术语第一次出现时先说清。用真实模型对照过一次（同一门操作系统课展开同样两节，另一个模型在不知道是哪一边的情况下列出没有先说清就使用的术语）：改动前 18 个，其中 3 个读不懂就卡住；改动后 7 个，没有卡住的。每边只有一次，只能说明方向；而且第一版只给已学概念时，这个数没有下降，写的一方拿到了事实并不总是照做。

所以同一份清单还可以交给读的一方：一次隔离的模型调用，只看到学习者此前学过的概念和这一节的讲解，列出读不懂就卡住的术语，由 `course_confirm` 一并交回。上面的对照里列术语的那个模型就是这样一个读者。写的一方按它改了以后是否真的改好、误报有多少，还没有量过，实现时先量再定是否强制。

这一遍阅读同时解决讲解里的名词链接。读的一方手里有学过的每个概念的名称和定义，它在读讲解时对每个术语要作的判断本来就是两种：这个词学习者没学过，要先说清；这个词指的就是前面学过的某个概念。后一种正是该加链接的地方，而且是按意思认出来的，不会把字面相同、意思无关的词组连上。所以它交回的除了没说清的术语，还有“讲解里的哪个词指哪个知识点”，由程序写进这一节。

状态范围提案把“输出以后让模型再读一遍”列为放弃的做法，理由是费用高、边生成边显示的回答要多等一遍。这个理由只对辅导的即时回答成立。讲解、解析和卡片是做课时写下来的：读一遍只在写成时发生一次，结果存下来，之后每次显示不再花钱也不用等。因此链接分两种来历：写下来的内容由这一遍阅读给出；辅导的即时回答仍按那份提案的办法，由程序在图上相邻的卡片里按名称匹配，样式从淡。

## 考虑过的其他做法

- **答案不手写，只由核对程序给出。** 设想是模型先手写答案、再写程序去对，两者对不上会反复修改。清点真实做课的 21 次课程检查，12 次没有通过，没有一次是答案与程序不一致，全是格式错误。它也不触及题面的毛病。
- **数值题写成带参数的模板，由程序生成变式。** 这解决的是复习时变式不够，属于[题目结构提案](../architecture/2026-11-02-item-structure.md#题目的供给)的题目供给，与答案对不对是两件事。试用者学上几周、复习题真的用尽之前，没有数据说明需要它。
- **换一个更贵的模型核对。** 127 个数值作答位上，同一家的另一个模型（单价约为默认的 flash 的七倍）与 flash 各报 4 处不一致，三处真毛病两者都抓到；这几处是不是毛病是逐条读过定的，没有把哪个模型当作标准。花七倍的钱没有多抓到东西。
- **让 Agent 起一个子 Agent 去重做，不加工具。** 子 Agent 有读文件的工具，读得到 `course/` 里的答案和解析，隔离靠它自觉。
- **只靠学习者申诉。** 申诉要保留，但学习者在复习里答错时分不清是谁的问题，多数不会申诉，错判已经记进学生模型。

## 验收

- 用上面七门课重放：做课时这 6 处毛病都被 `course_confirm` 报出，题没有改好之前换不上。
- 一门自制的课换用以后，每道由程序判分的题在 topic 文件里都有当前的核对记录；改了题面或答案，记录失效，要重新核对。
- 核对的请求里没有答案、解析和核对程序；选项的编号是不透明的。
- 学习页上这门课的花费包含核对的调用。
- 标准答案没有问题的题，绝大多数一次通过；报告里给出七门课上误报的处数。

## 风险与代价

- **每节多花钱和时间。** 用 flash 核对，105 道题共约 0.054 美元，每题约 0.0005 美元；一节二十多道题约 0.01 美元，做这一节本身约 0.03 美元。请求并发，时间以秒计，但每有一处不一致，Agent 就多一轮修改和检查。
- **核对的模型与写题的模型是同一家，可能有同样的误解。** 一致不等于标准答案对；这一关挡的是两次读法不同的题，挡不住两次都读错的。
- **讲解本身错了，核对也跟着错。** 请求里带着讲解，模型按讲解作答。讲解的对错靠出处和学习者的反馈，不在这一关。
- **误报让好题被改写。** 见“不一致以后”。改写的方向是更明确，代价是多一轮。

## 待定

- 核对记录的范围标记（已定）：新增 `question-lesson-v1`。哈希绑定题面、作答位与判分规则、数据和所属知识点的讲解，不含解析和 `runtime`（请求里没有它们，这几种作答位判分也不运行 Python）；随包课程的 `question-runtime-v1` 记录不受影响。
- 讲解的独立阅读是否强制，等量过误报和修改的效果再定；它给出的链接有多少是对的，同样要量。
- 读出的链接存在哪里：直接写进讲解的文字，还是在这一节里另记一份、由应用显示时加上。
- 填空题的另一种问题：标准答案只列了几种写法，意思相同的别的写法被判错。这是判分定义的问题，核对能看见它，但改法（放宽匹配、改成选择题）要另议。
