# 学习者把自己的课件做成课

状态：提案

## 问题

[里程碑一](https://github.com/Utopia-V/Repa/issues/54)的终点是试用者在应用里把自己的课件做成课并跨天学习。现在做不到，缺的是一整条路，而不是某一处。

- 学习插件只认随包的 Python 课：课程的来源写死在插件里，一个空间里没有放自制课程的位置。
- 课程格式和课程检查绑着 Python：`runtime` 必填，检查无条件启动 Python 沙箱，一门不含代码题的课也过不了。
- 没有“把材料做成课”的流程。有的只是一份写课说明和一个检查器，没有谁来读材料、出骨架、出题、检查、改正，也没有做完以后让学习插件用上这门课的入口。
- Agent 读不了课件。PDF 和幻灯片交给读文件工具，得到的是乱码。
- 学习者版本关着通用 Agent，没有能做这件事的 Agent。
- 界面上没有放材料、看进度、看花了多少的地方。

此前用一门操作系统课的课件手工试过一次，得到几条必须顾及的事实：约四成知识点是要记住的内容，不是要会做的题；模型手算的数值答案不可靠，自写的数值题五处手算全错，靠程序复算才发现；现成的习题质量参差，缺答案、缺选项，卷面答案本身也有错。

## 做法

第一个测试版只求这条路走通、走得省心，不求课程结构的最终形态。[题目结构](../architecture/2026-11-02-item-structure.md)与[知识库](../architecture/2026-11-11-knowledge-base.md)两份提案在测试版之后实施，这里不动它们要改的东西。

### 一个空间一门课

自制的课放在空间里的 `course/`，格式与随包课程相同：`course.yaml` 加 `topics/`。材料放在空间里的 `materials/`。空间里有 `course/` 这个文件夹，学习插件就用它，没有才用随包的 Python 课；`course/` 在而课还没做出来时，学习页如实显示“课还没有做好”，并指向做课。

不做一个空间里装几门课、在课程之间切换。几门课怎样共用一份学习状态是知识库提案要回答的问题，在那之前，想学另一门课就另开一个空间。这样学习记录、学生模型和菜单都不必改，一门课做坏了也只影响这个空间。

课程文件是空间里的普通文件，经文件工具写入，改动进空间历史，可以撤回。

### 课程格式与检查不再假定 Python

- `runtime` 只在课里有代码题或 Python 核对程序时才需要；检查器只在这时启动沙箱。
- 题型 `kind` 不再限于六个编程题取值。它本来就不参与选题和判分。
- 四个题池、每个知识点的题量下限、复习与测验题要有程序能判的作答位，这些维持原样。它们保护的是学习闭环：复习和测验不等模型判分，学过的内容有足够的题可练。要记住的内容用选择、填空、排序这类程序能判的作答位来考，现有格式已经支持。

### 做课由通用 Agent 完成，学习插件提供规矩和检查

做课要读材料、定范围、写文件、反复检查和改正，是通用 Agent 的工作。学习插件不另设一个出题的 Agent，它提供三样东西：

- 一份写课的说明，随学习插件附带，学习插件在它的提示说明里指给通用 Agent。内容是课程格式、要守的规矩、做课的顺序。
- 工具 `course_check`：检查 `course/`，返回哪一个文件、哪一处、错在哪里、怎样改，分页给出。
- 工具 `course_use`：检查通过以后让学习插件换用 `course/` 现在的内容。检查没通过就不换，学习者学的始终是一门通过了检查的课。

### 课是随着学习长出来的

一门课不是先整本做完再学。做课像懒加载：先有一个大体的轮廓，学到哪里，哪里才展开成讲解和题目；轮廓本身也会随着展开而修正，越来越清楚。

- **轮廓**先出来，而且要快：从课件的目录、标题和章节划分得出有哪些部分、各讲什么、先后怎样，每个部分只有名字、一句话的范围和它在材料里的出处。这一步不细读全部材料，几分钟内给学习者看到整门课的样子，他可以删掉不学的、标出要紧的。
- **展开**只做学习者快要学到的那一小段：细读对应的材料，定下这一节的知识点，写讲解和题目，检查，换用。学习者学着前面的，后面的接着展开；学完了已经展开的部分而后面还没好，学习页如实显示并说明正在做。
- **轮廓会变。** 细读一段材料以后常会发现原先的划分不对：两个部分其实是一回事，某一节该拆开，先后次序要调。还没学到的部分可以随时改。已经学过的部分不因此推倒：它的题目和学习记录照现有的规矩保留，要改正只按“题目 id 是身份、改答案会重判”的办法改。

这样第一节课很快就能开始，没学到的部分不花钱，轮廓里的错也便宜：发现时它后面还什么都没做。

轮廓记在 `course/` 里，与已经展开的课程文件分开，学习页据此显示整门课的样子和哪些部分已经可以学。谁来触发下一段的展开，先取简单的：学习者学到离已展开部分的尽头只剩一节时，学习插件在后台让 Agent 展开下一段；学习者也可以随时要求先做某一部分。

规矩里有两条来自那次试验，写死在说明里：

- 数值答案由程序算出。凡是要计算的答案，写一段核对程序独立算出来，不用模型心算的结果。检查器会运行这些程序。
- 现成的习题只在题面完整、答案能核对时才用，否则改写或另出。

### 课件转成文字

一个随产品附带的插件，提供工具把 `materials/` 里的文件读成文字，按页或按张返回，支持带文字层的 PDF、PPTX、DOCX。它以 npm 包的形式随包，带解析这些格式的库，装上应用就能用，不依赖使用者机器上的其他程序。扫描件没有文字层，第一版读不了，如实告诉使用者这份材料读不出文字。

### 学习者版本打开通用 Agent

做课和自写插件都以通用 Agent 为前提。学习者版本打开它；命令确认保持询问模式，只读命令不问。

### 界面

一个做课的页面：把材料放进来，看到大纲和每一节做到了哪里，看到到现在花了多少。吩咐经对话进行，状态显示在页面上。花费由后端按会话汇总各次模型请求的用量，按模型的单价折算。

## 考虑过的其他做法

**先实施题目结构提案，再做课。** 那样做出的课一开始就是知识点、考法、变式的结构。但它要改学习记录的格式和学生模型的取证方式，测试版会因此推迟，而它要回答的问题只有真人学过自制的课以后才看得清。

**一个空间里装几门课。** 学习者不必为每门课另开空间。它要先回答同一个知识点在两门课里算不算一个，这正是知识库提案的内容。

**学习插件自带一个出题的 Agent。** 可以给它更窄的工具。但做课需要的读写文件、运行核对程序、向学习者提问，通用 Agent 都已具备；另设一个只会多出一套权限和入口要维护。

**课件转文字做成不带依赖的插件文件夹。** 自写插件就是这种形式。但不带解析库读不了 PDF，只能依赖使用者机器上恰好装着的程序。

**先把整门课做完再学。** 课程一次成型，结构前后一致。但一门课几十节、几百道题，学习者要等很久、先付全部的花费，而其中相当一部分他未必会学到；骨架里的错也要等全部做完才显出来。

**由我们替试用者把课做好。** 最省事，也最可控。但那样检验不到这个产品要回答的问题：学习者能不能自己把手头的材料变成一门课。

## 验收

- 在一个新空间里放进一门课的课件（PDF 与幻灯片），让 Repa 做课：几分钟内看到整门课的轮廓，随后第一节展开并通过检查，学习页出现这门课的第一节。这时后面的部分还只是轮廓。
- 学到已展开部分的尽头之前，下一段已经在后台展开；没有展开的部分没有产生花费。
- 展开某一段时发现轮廓要改（合并、拆分、调整次序）：还没学的部分随之改变，已经学过的部分和它的学习记录不变。
- 上完一节课；关闭应用再打开，接着学；隔天打开，复习里出现前一天学过的内容。
- 一门不含代码题的课通过检查并能学完一节，学习插件的代码不必为它修改。
- 做课过程中写出一道答案算错的数值题：检查器运行核对程序把它查出来，Agent 改正以后才能换用。
- 检查没有通过时，学习者学的仍是上一次通过检查的课。
- 做课的页面上看得到已经花了多少。
- 放进一份扫描件：得到“这份材料读不出文字”，而不是一门凭空编出来的课。

## 风险与代价

- **课的质量。** 这是最大的未知数。检查器保证格式正确、数值答案经程序算过，保证不了讲解清楚、题目考到点上。只在一门课上手工试过一次，要用真实课件多做几门才知道。
- **花费。** 一门课几十节、几百道题，全部做完的模型用量不小。只展开快要学到的部分、页面上显示花费，学习者不学的部分就不花钱。后台自动展开会在学习者没有明确要求时产生花费，页面上要看得见，也要能关掉。
- **轮廓改动与学过的内容。** 已经学过的部分不随轮廓重排，所以轮廓改得多了，学过的那几节可能与后来的划分不完全对齐。彻底的办法是知识点以名字为身份，属于知识库提案。
- **Python 核对只能在 Linux 上运行。** 核对程序和代码题的检查用的沙箱目前只支持 Linux。其他平台上含核对程序的课过不了检查，要另外解决。
- **一个空间一门课是阶段性做法。** 知识库实施以后会改，届时已有的自制课怎样并入要有交代。
- **扫描件读不了。** 试用者的材料若主要是扫描件，这条路走不通，要补本机识别或交给能看图的模型。
- **学习者版本有了通用 Agent**，也就有了执行命令和写文件的能力，命令确认是唯一的关卡。
