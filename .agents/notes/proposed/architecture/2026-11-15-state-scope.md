# 状态的范围：逐层的摘要，按任务给模型看

状态：提案

## 问题

Repa 把状态放在模型之外，每次运行时把需要的部分交给模型。状态会一直增长，模型的上下文不会，所以“交哪一部分”要有规则。现在没有，每一处各自处理，第一个测试版做下来已经撞上三次。

其一，后台展开课程时，模型不知道学习者提过什么要求。要求只存在于做课对话的头几条消息里，而后台展开是另一次运行。眼下的补救是让 Agent 把要求记进空间的 `AGENTS.md`，每次运行都带上，但这只解决了这一种内容。

其二，讲解里用了后面才讲的术语。用操作系统课件做课时，第一节的讲解直接用了“用户态”“特权指令”，它们是第三节的内容。写课说明里有“术语第一次出现时说清”这句话，模型却无从知道哪些术语学习者已经见过：没有人把“前面讲过什么”交给它。

其三，模型把状态复述成文字。出完轮廓以后，Agent 在对话里把整门课的划分又写了一遍，而同一份轮廓就在学习页上。这段文字是模型写的、没有出处也不会更新，课一改它就与实际不符。

再往上看还有一层缺口。[知识库提案](2026-11-11-knowledge-base.md)已经定下一个人只有一个知识库、几门课共用其中的知识点，可是“几门课同时在学，今天学什么”需要一个站在各门课之上的视角，现在没有任何东西能给出它。学习以外的领域（健康记录、写作）接进来以后，同样的问题会在更高一层重现。

## 做法

### 已定的要求

以下各项是我的决定，设计以此为前提。

- **长期状态的范围可以选择。** 能看全局，也能在需要的时候把一个领域隔开。
- **隔离是递归的。** 一个知识点、一门课、整个学习领域，一层层往上，每一层都可以单独拿出来看。
- **默认隔离，全局是特意合成出来的。** 做某一层的事时，模型看到的是这一层的细节；别处的内容只以摘要出现。
- **摘要是线索，不是事实。** 它告诉 Agent 往哪里看；要据此做事，先去取原文。摘要因此带着找回原文所需的元数据。
- **元数据由程序维护。** 模型手写的元数据靠不住，程序盖上去的才稳。
- **树与树之间连成图。** 先修这类关系跨过层次，把不同的树连起来。
- **课程是空间里的子结构。** 不同的课之间有联系，也有共有的部分；只属于一门课的内容放在空间里它自己的文件夹中。
- **可以在一份副本上试着改，满意了再并回来。**

### 层次

学习这个领域里，层次是这样的：知识点的卡片，课程里的一节，一门课，这个人的知识库，再往上是 Repa 里的其他领域。

每一层有一个主人，细节只存一份。按知识库提案，知识点的主人是知识库里的那张卡片，学得怎样记在卡片对应的知识点上；课程不拥有知识点，它是排在知识库之上的一条路，指认它讲授和用到的知识点。所以同一个知识点出现在两门课里时，状态只有一份，两门课看到的是同一份。

这里有两种“包含”：知识库包含卡片，这是归属；课程包含它的各节、各节包含讲授的知识点，这是路线。范围按后一种来划（学习者此刻在某门课的某一节里），状态按前一种来找主人。

### 一门课在空间里的位置

几门课在同一个空间里，各占一个文件夹。划分的依据是内容归谁：

| 归一门课，在它的文件夹里 | 归这个人，在空间一级 |
| --- | --- |
| 路线：分成哪几节、先后次序、各节的出处 | 知识点的卡片 |
| 讲解、例题和题目 | 学习记录，以及由它算出的学习状态 |
| 这门课的课件 | 菜单、XP、日目标 |
| 学习者对这门课的要求（为什么学、何时学完） | 学习者对所有学习的要求 |
| 做课的对话与展开的进度 | |

```text
<空间>/
  AGENTS.md          对所有学习的要求
  <卡片>/            知识库的卡片，几门课共用
  courses/
    操作系统/
      AGENTS.md      对这门课的要求
      course/        清单、各节、题目
      materials/     课件
```

课与课的联系不写在任何一门课的文件夹里。两门课讲到同一个知识点，是因为它们指认了同一张卡片，这层对应按知识库提案记在卡片的文件头；先修是卡片之间的关系。所以删掉或移走一门课的文件夹，不影响另一门课，也不影响已经学会的知识点。课程文件夹里除了那份要求以外没有这个人的状态，去掉它就可以原样交给别人使用。

要求分两级存放，与范围的规则一致：在某门课里的一次运行读到空间的要求和这门课的要求，读不到别的课的。

测试版的空间里，`course/` 和 `materials/` 直接放在空间的根下，与这里一门课的文件夹内部相同。把试用者分开的几个空间并成一个时，每个空间原样成为 `courses/` 下的一个文件夹。

### 摘要

每一层向上一层交出一份摘要。一节课的摘要是它讲什么、出自材料的哪里；一门课的摘要是学到哪里、还有多少、什么时候要学完；知识库的摘要是今天有多少要复习、哪门课最紧。

摘要有两种来历，处理不同。能由程序从事实算出的（进度、到期的复习、题数、期限），每次用到时现算，不存，也就不会过期。需要模型来写的（“他在这个知识点上常把并发说成并行”），写下来时由程序一并记下四样元数据：

| 元数据 | 内容 | 用处 |
| --- | --- | --- |
| 指向 | 细节在哪里：知识点或题目的编号，材料的文件与页码范围 | Agent 拿着它直接取原文 |
| 截至 | 写下时所依据的状态是哪一版 | 程序比对当前版本，过期的自动标出 |
| 来源 | 哪一次运行写的，依据是哪几条记录 | 学习者不认可时追得到源头 |
| 规模 | 底下有多少内容 | Agent 决定取多少 |

这四样够 Agent 找回原文即可，不再增加。来源一项几乎是现成的：空间的每次写入本来就记在发起它的运行名下。

这个形状在 Repa 里已经出现过三次，只是没有名字：辅导先搜索得到带编号的条目，再按编号读全文；课程轮廓里每一部分写着出处，展开时照着去读课件；课件工具先列出每份文件有多少页，再按页码读。以后各层交出的摘要都照这一个形状。

其中有一处现在不合格：轮廓里的出处是模型写的一行文字（“第 9–14 张”），程序读不懂，也没有核对过这个范围是否存在。它要改成程序认得的形式，即哪份文件、从第几页到第几页，课程检查据此核对。这是往格式里加字段，已有的课不受影响。

### 按任务给模型看

一次运行在树上有一个位置。交给模型的是：这个位置的细节，同一层其余部分的摘要，一路向上各层的摘要，以及它声明要用的横向关系那一头的摘要。这份内容由程序在运行开始时算出，经底座已有的视图交给模型；模型需要更多时，用摘要里的指向去取。

最先用在三个地方，都不改存盘的格式：

- **展开一节课。** 程序把这一节的轮廓、出处的地址、它的先修已经讲过哪些概念（名称加一句话定义）直接放进任务。模型据此知道哪些词可以直接用，哪些要先解释，不必自己去翻文件。
- **辅导。** 交给辅导的是当前这道题所属知识点的细节、它的先修的卡片摘要，以及其中按学生模型学习者多半已经记不清的几个。辅导据此决定提到旧知识时要不要顺带讲一句。
- **几门课之间。** 每门在学的课交出摘要，菜单在知识库这一层决定今天先做什么。知识库提案把“几门课同时在学时新课怎样分配”列为待定，这里给出它所需的输入。

对话里也照此办理：模型要提到一门课的轮廓、一个知识点时，写的是指向它的引用，由应用按当前状态画出来，不把状态复述成文字。提问卡片和 `repa:concept/` 链接已经是这种做法。

### 横向的关系

先修、覆盖和卡片之间的链接跨过层次。它们由程序沿着图去取，取到的同样是摘要加指向。

名词链接按这张图来做。讲解、答完以后的解析、卡片和辅导的回答里，出现卡片名称或别名的地方由程序加上链接，鼠标移上去显示卡片的一句话定义。为了不把无关的词组连成链接：

- 只拿图上相邻的卡片去匹配，即同一节的知识点、它们的先修、辅导这一轮实际查过的卡片，而不是整个知识库。
- 能被链接的名称和别名在写卡片时定下，课程检查拦掉太短的、是另一张卡片名称一部分的、在全课到处出现的。
- 自动加上的链接样式很淡，并且选中任何一个词都可以查卡片。这样偶尔配错时，界面并没有声称什么。
- 模型自己写的概念链接照旧，用在它要点明“这就是前面讲过的某某”的地方。

题面和作答位里不出现任何链接，作答之前也不显示，这一条沿用[题目结构提案](2026-11-02-item-structure.md#链接与显示)：认出该用哪项知识本身就是要考的内容。

### 隔离

一次运行默认只看得到它所在位置的细节。插件 Agent 本来只有自己定义里列出的工具，这是现成的隔离。跨领域取用（学习要参考别的领域，或者反过来）只能取对方交出的摘要，并且由取用的一方声明要哪一条；学习者看得到这些声明，可以关掉。眼下只有学习一个领域，这一部分等第二个领域出现时再做。

### 在副本上试改

“写的地方与生效的版本分开”在 Repa 里已经有三处：课程在 `course/` 里写、通过检查后换用的是一份副本；自写插件在文件夹里写、批准后运行的是一份快照；空间文件的每次写入可以按运行撤回。它们已经覆盖“试着改一门课”“试着改一个插件”。

这里不另造一套通用的分支机制，只补学习记录这一处：把假设的事实接在真实记录后面重放一遍，得到“如果这样学，到某一天会怎样”，以及让新的学生模型参数先在这个人的历史上运行、与现行的比较。学习记录只记事实、状态全靠重放，所以这一处几乎不需要新的存储。

### 与提示词画板的关系

[提示词画板](https://github.com/Utopia-V/Repa/issues/41)管的是不随状态变化的文字：谁放哪一块，用户写在自己的那一块上。本提案管的是随状态变化的内容，经视图进入上下文，不进系统提示。两者合起来才是“交给模型什么”的全部。学习者对一门课的要求现在记在空间的 `AGENTS.md`，它是用户的画板，归那一边。

### 测试版留下的阶段性做法

测试版里一个空间只有一门课，侧栏把最近的几个空间列成课程，“新建课程”建的是一个新空间。这是为了不在测试版之前改动学习记录，不是设计：按知识库提案，几门课在同一个空间里。落实知识库时，侧栏列的改为空间里的课，试用者已经分开的几个空间要并成一个，办法见风险与代价。

### 分步

1. 展开课程和辅导两处按任务给内容。只动程序拼任务和视图的地方。
2. 出处改成程序认得的地址，课程检查核对。
3. 随知识库提案落地：课程各占空间里的一个文件夹，课程一级的摘要，几门课之间的菜单；侧栏改为列空间里的课。
4. 名词链接与小窗，对话里按引用画出轮廓和卡片。
5. 假设性重放。
6. 第二个领域出现时，做跨领域的摘要与声明。

## 考虑过的其他做法

- **把全部状态都交给模型，靠上下文窗口变大来解决。** 状态增长没有上限，而且交得越多，模型越容易被无关的旧内容带偏。
- **只给工具，让模型自己去查。** 模型不知道有什么可查，第二个问题里它正是因为不知道前面讲过什么而没有去查。摘要的作用就是告诉它有什么。
- **让模型维护一份“当前状态”的文档。** 这是多数 Agent 记忆的做法。没有出处和日期的陈述会慢慢变成没人敢删也没人敢信的内容，所以这里要求模型写的摘要必须带元数据，能算的一律现算。
- **为“在副本上试改”做通用的状态分支。** 现有的三处已经覆盖课程和插件，学习记录用重放即可；通用分支要回答合并冲突，眼下没有需要它的情形。
- **名词链接由模型逐处标注，或输出以后让模型再读一遍。** 前者每次输出都增加负担，而且会漏；后者费用高，辅导的回答是边生成边显示的，多一遍就要等。

## 验收

- 用同一套课件做课：后台展开写出的讲解里，凡是先修没有讲过的术语，第一次出现时都有一句解释；学习者在起点提的要求在后面每一节里都得到遵守。
- 学习者问辅导一道题：回答里提到的旧知识点，是学生模型里他记忆已经偏低的那些，并且带着能点开的卡片。
- 两门课同时在学：打开应用看到的是一份今天的安排，其中有两门课的内容，而不必先选一门课。
- 模型写下的一条关于学习者的判断，学习者能看到它出自哪几次作答；这些作答被改判以后，这条判断被标为过期。
- 课程里的出处写错了页码范围，课程检查报出来。
- 讲解里的名词能移上去看到定义；任何题在作答之前，题面上没有链接。

## 风险与代价

- **摘要的词汇越加越多。** 四样元数据是上限；一种新的摘要要先说明哪个任务需要它。
- **按任务算出的内容算错了，模型不会知道。** 它只看到被给予的那一部分。所以每次运行实际给了什么要能在运行记录里查到，与提示词画板里“某次调用实际使用了哪些画板”是同一项要求。
- **把试用者分开的几个空间并成一个。** 每个空间的文件原样移进 `courses/` 下的一个文件夹；学习记录是按行追加的事实，可以按时间合并；课程各自带着编号，不会相撞；卡片与课程知识点的对应按知识库提案在开课时重新提议。要做的是一个一次性的合并工具，并且合并之前各空间照常可用。这笔代价是测试版的阶段性做法带来的。
- **名词匹配配错。** 做法里已经把机会和代价都压低，仍可能出现；学习者能在卡片上关掉某个别名。

## 待定

- 模型写的摘要存在哪里：卡片的文件头，还是学习记录里的一种事实。
- “学习者多半已经记不清”的界线取多少，这要用试用者的数据来定。
- 对话里的引用写成什么形式，是沿用 `repa:` 链接还是一种块。
- 合并空间的工具做成什么样，要等试用者实际有几个空间时再看。
- `courses/` 这个文件夹的名称；随包的课程不在空间里，它在空间中是否也占一个文件夹（只放要求和进度）。
