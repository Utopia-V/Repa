# 题目结构与选题：知识点、考法与变式

状态：提案

## 问题

py03.k2“类型转换”有五道练习题：q1 预测五段转换的输出，q2 追踪转换前后的变量，q3 改代码完成转换，q4 判断 `int("7.0")` 在哪里出错，q5 预测转换后前导零是否保留。#93 之前的规则按题池顺序出题，连对两题即算通过，所以一直答对的学习者只做 q1、q2，从没写过转换代码，却被记为通过；全课程 42 道代码练习题，这样的学习者只会遇到 6 道。

原因在课程格式。格式只规定题目放进哪个题池，没有规定同一题池里的题彼此是什么关系，选题规则却假定池里的题可以互相替代。按答对次数通过的规则都以可替代为前提：MA 随机出题而通过率不受影响，前提是题池里的题彼此相似；题目难易混杂时，学习者能靠容易的题显得已经学会（Koedinger 等，EDM 2012）。

测试版改为练习题全做，答对超过所答题数的一半才通过（#93）。全做不再漏练，但会的人也要做完每一道题，复习和测验也只能靠另设的题池才有没见过的题。

测试版的课程格式还有几处是为这一门 Python 课写死的，不宜带进下一阶段：

- 每个知识点固定分例题、练习、复习、测验四个题池，题目的用途在编写时就定死了；
- 题型（`kind`）是格式里全局固定的六个取值（预测、追踪、找错、解释、小改代码、写清需求），只适用于编程课；
- 需要模型核对的作答位只在复习和测验题里核对，同一道题放进不同的题池，核对标准就不同；
- 课程由人逐题编写，题目不够时没有补充的途径。

Repa 要做到的是：学习者说明想学什么，在模型能力允许的范围内逐步搭起学习路线和练习。题目结构因此不能只为这一门课服务。它要告诉编写者（人或 Agent）该写什么题、写多少，让程序能判断题目是否够用，也要让选题规则换一门学科照样成立。

## 做法

### 知识点、考法、变式

**知识点**是学习者会当作一件事来思考、来查阅的概念，例如“类型转换”。它有一张概念卡，是讲解、例题和链接的对象。

**考法**是同一知识点下用同一种方法解的一类题。判断两类题是否属于同一考法，看两件事：解法是否相同，做对一类能否说明会做另一类。会预测 `int("12") + 1` 的结果，写代码时仍可能忘记先转换；两者解法不同，做对前者说明不了后者，所以读和写是两种考法。高中更常见：函数的单调性有求单调区间、判断或证明单调性、利用单调性解不等式三种考法，会求单调区间的学生不一定会用单调性解不等式。考法可以有自己的例题。只有学习者会把它当作一个单独的概念来查阅，需要自己的讲解和概念卡时，它才升为知识点甚至 topic，例如传送带问题。没有声明考法的知识点只有一种考法，大多数知识点属于这种情况。现有课程 120 个知识点中，88 个既有读代码的题，又有改写或编写代码的题，是首先要判断是否分开读与写的对象。

**变式**是属于同一种考法、可以互相替代的题。考法标在题目上；一道题若同时涉及两种考法，就拆成两道题。py03.k2 分为读（q1、q2、q4、q5）与写（q3）两种考法。同一考法的变式按定义可以互换，所以选题不在其中由易到难地挑：难的那道若需要另一种解法，它属于另一种考法；若只是步骤多些，答对哪一道都同样说明问题。

具体的陷阱，例如前导零丢失、小数被截断、`int("2.5")` 报错，既不是知识点，也不是考法。它们写在概念卡的常见混淆里，分布在变式中，答错时由解析点明。若某个陷阱必须人人亲手遇到，就要写进这种考法的每一道变式，否则能否遇到取决于抽到哪道题。

知识点和考法都不能切得过细。切成“`int("2.5")` 会报错”这样的原子，会有四个后果：学习者不会去查这样一张卡；每个原子都要单独取证，题目做不完；一道综合题若关联几十个原子，就看不出它考查什么；每条都单独练熟以后，学习者遇到新问题仍不知道该用哪一条。2017 年版高中课程标准也把“重视以学科大概念为核心，使课程内容结构化”列为修订的主要变化之一。

有作答数据之前，考法的划分靠编写者判断。数据足够以后，学习曲线可以提供复查的线索：一种考法下某道变式练到第几次仍错得明显多，划分可能有误。Additive Factors Model（AFM）比较两种标注对作答的预测，在 11 个数据集中至少 10 个上找到了更好的划分（Koedinger 等，EDM 2012）。但预测改善不能直接说明应当拆分，更难的变式也会持续错得多，所以它只提示复查，不自动改动课程。

### 选题策略

选题策略决定两件事：下一道出哪题，以及一个知识点何时结束、结论是什么。它读取知识点的考法、题目属性、本次任务里的作答和学生模型；学习插件负责记录作答、判分、XP 和更新学生模型。通过条件随策略而定，因为全做与按考法取证的通过条件本来就不同。

已经得出的结论不因课程或策略的改动而改写。为此，每个任务开始时记下所用策略的名称和版本，以及它所依据的课程结构，即每个知识点的考法；每次出题记下题目所属的考法。重放时按这些记录计算，所以课程后来增加题目、改标考法或换了策略，已有任务的通过与失败都不变。答案改正后的重判照常生效，因为它改变的是作答本身对不对。课程里删去的题，已有作答保留最后一次判分。这些字段进入学习记录，按[持久格式的规则](../../../../docs/AGENTS.md#持久格式与版本)记录版本判断。测试版的课是否也在开始时记下必做题，在测试版发出之前另行决定；不记的话，没有这项记录的课按当前课程计算，课程改动仍可能改变它们的结论。

这条边界先作为学习插件内部的接口实现，暂不做成可以从外部加载的插件。外部插件要解决加载、接口兼容和可信度三件事：选题策略决定通过与失败，进而影响学生模型和 XP，有缺陷的策略会把没学会的人记为通过。目前的两种策略都由我们编写，而且是先后两个版本，不是并存的选择；等某门课或社区确实要提供自己的策略，再开放成插件。

### 按考法取证

1. 知识点的各种考法按编写顺序出，例如读在写之前；同一考法在学习者没见过的变式里随机抽取。
2. 对错按整题计：部分答对在通过与失败上按答错计，部分表现只体现在 XP 上，与 MA 一致。
3. 某种考法答错，看过解析以后，换一道这种考法的变式。
4. 一种考法在两个条件同时满足时通过：答对超过所答题数的一半；证据量不少于 2。每答对一题，证据量增加 1 减去这道题的猜中机会。猜中机会由作答位算出：两个选项的选择题为 1/2，四个选项为 1/4，自由作答近似为 0。所以只有自由作答的考法答对两题即可，只有四选一的考法要答对三题，单靠两个选项的选择题答对两题不能通过。
5. 一种考法在一节课里最多出 5 题。在剩下的题数内已不可能满足第 4 条时，这种考法失败，这节课随之失败，之后照常冷却和补救。重试时保留已通过的考法，与测试版保留已通过知识点的做法一致。
6. 全部考法通过，知识点通过。

除了通过和失败，知识点还可能停在两种状态。一种是待判：结论取决于还没判出结果的作答时，等它判出来，与测试版相同。另一种是缺题：这种考法已没有可出的变式，证据却还不足以得出结论。可出的变式指学习者没见过、这个前端能显示、当前有办法判分的题，所以没有可用模型时，只能由模型判分的开放题不算在内。没有证据就既不算对也不算错，缺题因此不记为失败：知识点停在原处，界面说明原因；补上变式以后接着做，已通过的考法保留。菜单只提供每种考法都有足够可出变式的课。

以上数值都是 Repa 的假设：证据量 2，每种考法一节课最多 5 题。MA 公开过的说法是“五题内答对两题”或“连对两题”，确切规则没有公开；答对超过一半是我们自己的要求，因为五道错三道说明没有学会。比例要和证据的多少一起看，一千道错三道，证据很多，结论是会了。有了作答数据以后，改为估计学习者掌握每种考法的概率，证据的多少与猜中机会都包含在这个估计里。

用 py03.k2 检验：会的人做两道“读”的变式、两道“写”的变式即通过；测试版要做五道，其中只有一道写代码。q1 答错的人接着做“读”的其他变式，直到满足条件，或在 5 题之内已不可能满足。

### 题目的供给

题目是否够用要按考法核算，不能看知识点的总题数。py03.k2 一共 12 道题，写代码的只有 2 道：一直答对的人在课上就用掉这两道，之后的复习和测验已没有没见过的写代码题。课程检查对每种考法核算课上最多要用的题数（第 5 条的上限）和之后复习、测验所需的储备，不够时报告缺口；不依赖模型就无法通过的考法也一并报告。

补题由编写者完成，Agent 也可以编写变式。Agent 写的变式与人写的经过同一套课程检查才加入课程，检查设在题目产生之处。代码题除了要求参考解答通过测试，还要用错误的程序检验测试能否把它拒绝，因为一次生成的编程题常有测试代码本身出错的情况（Logacheva 等，ICER 2024）。只改数字的变式由模型编写，报告的出错率与人工编写的相当（Kim 等，EMNLP 2025）；改换情景的变式难度未必一致（Liu 等，arXiv 2602.05114），需要作答数据校准。

### 不分题池

题池现在承担的四件事，都能由题目属性和学习记录得出：

| 题池承担的事 | 不分池以后 |
| --- | --- |
| 给复习和测验留出没见过的题 | 选题优先出学习者没见过的变式。“见过”包括作答过和作为例题看过完整解答，所以展示例题时要记下是哪道题 |
| 复习和测验只出核对过的题 | 所有题按同一标准核对，不再因所在题池不同而不同 |
| 复习和测验考迁移，而不是考能否认出原题 | 同一考法的变式本身要有不同的题型和情境；复习和测验在保证考法的前提下，优先出学习者没做过的题型 |
| 例题有完整解答 | 每道题的解析都写成完整解答，哪道都能作例题 |

于是例题、练习、复习、测验是题目的四种用途，由选题策略在运行时决定。这要以按考法取证为前提：全做会用掉所有的题，复习和测验就只剩做过的题。

### 复习与测验

复习不要求每次覆盖全部考法，那样一次复习会很长；改为轮换，优先出最久没有直接练到的考法，这从学习记录即可算出。选定考法以后再挑变式：先挑没见过的，其中优先学习者没做过的题型。测验照旧每个 topic 一题，作为对整个 topic 的抽查，不要求覆盖全部考法。

### 链接与显示

题目与知识点的关联有两种。一种是题目所属的知识点和考法，由所在位置和考法标注给出，原有的 `measures` 不变。另一种是“这道题用到了哪个旧概念”，不另设字段，直接在解析里写概念链接，例如“这里用到了[类型转换](repa:concept/py03.k2)”，这是已有的写法。反向链接由程序扫描讲解、例题和解析中的概念链接算出，与 Obsidian 的做法相同。

学习者只在学习时看得到链接：

- 任何题在作答之前都不显示链接。考法或知识点的名称可能直接给出答案，例如 q5 考的就是“转换会丢掉前导零”；复习和测验里，认出该用哪项知识本身就是要考的内容。课程检查禁止在题面和作答位里写概念链接。
- 答完以后，解析里的链接可以点开概念卡。学习者对学过的概念常常有印象却想不起来，这正是链接的用处。
- 概念卡上的“出现在哪些题”只列学习者做过或作为例题看过的题，以免提前看到复习和测验要出的题。

整题的对错只记在它所属的考法上，不归咎于用到的旧概念；旧 topic 的复习信用照旧按 topic 之间的覆盖关系传递（FIRe）。

### 题目属性

| 属性 | 用途 |
| --- | --- |
| 所属知识点、考法 | 选题与取证 |
| 题型（`kind`） | 说明要学习者做什么。取值由课程定义：编程课是预测、追踪、找错等，数学课可以是计算、证明。单选、填空这类作答方式由作答位得出，不重复记在这里。题型不用来判断能否互相替代；复习和测验优先出学习者没做过的题型 |
| 难度估计（可选），注明来源 | 界面显示 1 至 5 星。来源可以是编写者的估计或考试统计的难度系数；有了我们自己的作答数据，以数据为准，校准值另存，不改课程文件。同一考法的变式难度相差很大时，课程检查提示复查是否应分成两种考法；选题不按难度排序 |

这些属性不计入题目版本，修改后不触发重判；考法改标对已有任务的影响由上文的记录处理。没有使用方的属性不加：预计用时等 XP 和测验时长确实需要时再加；同类题分组由考法标注即可得出。

### 综合题

需要专门教的综合能力，例如化工流程题要求的流程分析，单独作为一个 topic，证据记在它自己身上。把综合题拆成有铺垫的多步小题，可以作为练习的脚手架，但它替学习者完成了规划，不能作为独立完成综合题的证据。

### 术语

| 概念 | 定名 | 不再使用 |
| --- | --- | --- |
| topic 下可以查阅的概念 | 知识点 | 正文中的 KP |
| 同一知识点下用同一种方法解的一类题 | 考法 | 技能（高中不这样说）、能力（已指前端的交互能力，如“能力缺项”）、考点、要求 |
| 属于同一种考法、可以互相替代的题 | 变式 | 同类题 |
| 题目的用途 | 例题、练习、复习、测验 | 题池（随格式修改停用）、角色、测试题（“测试”指程序测试） |
| 运行时决定下一道题和何时结束 | 选题、选题策略 | 出题规划 |
| 编写题目与变式 | 编写题目 | 出题（曾兼指编写与选题）、写题 |
| 任务、知识点或考法达到要求 | 通过、失败 | 过关、证明 |
| 学生模型对长期记忆的估计 | 掌握 | 知识点刚在课上通过时，界面不写“已掌握” |
| 由概念反查题目 | 反向链接 | 双链 |

英文名称：知识点 knowledge point，代码中为 `kp`；考法 problem type，MA 的知识点、ALEKS 的 item 都是一个 problem type；变式 variant；题型 kind，与代码同名，不译作 format（作答位已有表示数值格式的 `format` 字段），也不译作 question type，以免与 problem type 混淆。落地时，能按字面检查的旧名称列入 `scripts/docs/banned-terms.json`；“KP”会命中代码里的 `kpId`，需要给停用词检查加一个只查正文、区分大小写的选项。

## 考虑过的其他做法

- **按能力拆分知识点（MA 的做法）。** MA 的知识点对应一种题型，各有例题。照搬会让概念卡碎裂，一个概念分成几张卡，也容易切成原子。改为在知识点之下列考法，需要单独讲解和概念卡的考法再升为知识点。
- **一题一个原子考法。** 11 月 1 日的草稿把 py03.k2 的五道题列成五项，等于没有分组，什么也省不了。
- **用三个问题判定拆分。** 草稿曾问：能否举出让人答对甲、答错乙的错误想法；一句解释能否纠正它；是否需要反复练习。一句话能否纠正、要练几次，都因人而异，会把已确认要分开的读和写合并。改为比较解法，以及能否互相提供证据。
- **同一考法内由易到难出题。** 变式按定义可以互换；需要另一种解法的“难题”属于另一种考法。由易到难只会让最容易的一道决定是否通过。
- **要求至少答对一道非选择题。** 按控件类型划线，只有选择题的考法永远不能通过，把选择改成填写选项文字又能绕过。改为按猜中机会折算证据量。
- **变式用完即判失败。** 题不够不说明学习者不会，改为缺题，等补题。
- **结构化的“用到”字段。** 作答位逐个标注“用到”的旧概念，用于反向链接、归因和覆盖检查。显示与反向链接用正文链接即可；归因不需要它，因为整题对错不归咎于旧概念，旧 topic 的信用按覆盖关系传递；课程格式此前已删去按题标注的 `uses`。
- **只记策略版本。** 换策略时旧任务照旧计算，但课程改动仍会改变它们的结论，因为题目归属和必做题取自当前课程。所以还要记下任务所依据的考法和每道题所属的考法。
- **立即做成外部插件。** 理由见“选题策略”。
- **每次复习覆盖全部考法。** 复习太长，改为轮换。
- **测验题只有覆盖整个 topic 才算证据。** 测验本来就是抽查，每个 topic 一题；这样限制只会让测验失去作用。
- **难度不设字段。** 11 月 1 日的草稿以“教学顺序不等于难度、难度要靠数据”为由删去。估计不准也可以先作起点；高中题还有考试统计的难度系数。
- **保留测试版的全做。** 不漏练，但会的人也要做完每一道题，一直答对的路径上练习从约 240 题增加到约 469 题。

## 验收

以下各项都能用随包课程或示例课程走一遍，从学习者看到的结果和学习记录核对：

- 一直答对的学习者学 py03.k2：通过之前答对过两道写转换代码的变式，这个知识点共做四道题。
- 第一题答错的学习者：这种考法通过之前，又答对过两道没见过的同一考法变式。
- 只有两个选项的选择题组成的考法：答对两题仍未通过；答对四题、且答对超过一半才通过。
- 一种考法的可出变式用完而证据不足：这节课不记为失败，界面说明在等新题；课程补上变式后重开空间，学习者接着做，已通过的考法不必重做。没有可用模型时，只剩开放题的考法同样按缺题处理。
- 课上作为例题展示过的题，在还有其他没见过的变式时，不出现在之后的复习和测验里。
- 任何题在作答之前都看不到概念链接；答完以后，点击解析里的链接能打开概念卡；概念卡只列学习者做过或作为例题看过的题。
- 一节课通过以后，给这个知识点增加变式、改标一道题的考法、换用新的选题策略，重开空间后这节课的结论与 XP 都不变。
- 课程检查对 py03.k2 报告写代码的考法缺题，并说出差几道。
- 一门只有数学题的示例课程，使用自己定义的题型（如计算、证明），能通过课程检查并上完一节课，学习插件的代码不必修改。

## 风险与代价

- **编写成本。** 88 个知识点要判断是否分开读与写，并给题目标注考法；所有解析要写成完整解答；所有题按同一标准核对，`course:confirm` 的调用会增加。标注可以由 Agent 先提出、人审阅。
- **会的人可能跳过陷阱。** 考法分得粗，答对两道变式就能通过，没写进这两道题的陷阱就遇不到。必须人人遇到的陷阱要写进每道变式，编写成本随之增加。
- **变式不足。** 现有课程按考法核算以后，写代码的考法普遍缺题：120 个知识点中 60 个没有代码题，41 个只有一道。补题要靠人和 Agent 编写，代码题的变式最贵。
- **旧策略的代码要保留。** 重放测试版的记录需要测试版的规则。
- **学习记录格式变化。** 任务所用的策略与考法、每道题所属的考法、展示过的例题都要进入学习记录，按持久格式的规则记录版本判断。
- **考法划分在有数据之前靠判断。** 划分的对错要等作答数据检验。

## 待定

- 数值：证据量 2、每种考法一节课最多 5 题、复习和测验所需的储备。
- 按考法取证与不分题池同时上线，还是先上按考法取证、保留题池。不分题池离不开按考法取证，反过来则不然。
- 测试版的课是否在开始时记下必做题，在测试版发出之前决定。
- 英文名称：上面四个以外的术语随实现确定，将来国际化时统一。
- “我已经会了”：挑战题要覆盖这个 topic 的全部考法，通过后跳过，之后直接作答失败时转入补学。它另有生命周期，不在本提案之内。
