# 学习插件重做：只记事实，判分当场算，核对和判分用同一套判断

状态：提案

## 问题

2026 年 10 月的问题清点里，学习插件的问题大致有四类，结论都是和维护者逐条讨论过的。

第一类，是把派生的东西当成了记录。学习记录在每一步都存下整个界面画面和学生模型的投影，越用越大；前端一改，盘上的格式就跟着变；算法改进以后，也没法拿历史作答重新推断学习状态。快照去重从不生效，写了没人读的戳和字段，同一个事实有好几种表示，根子都在这里。

第二类，是把检查放在了不会出问题的地方。代码题的期望值预先算好，存在 `expected.json` 里，还绑定了 `runner.py` 全文的哈希。可题目、运行器和答案装在同一个安装包里，在学习者那边不会各自变化，这种绑定查不出真问题，Windows 检出时换行一变，代码题反而静默下线。课程核对每段候选程序都重启一次解释器，整门课串行要四十多分钟；判分却复用解释器，两边跑法不同。

第三类，是流程会卡死，或者没有证据也硬判。判分途中关掉窗口、开放题的模型调不通、模型说判不准，都会让任务卡住或记成失败；复习和测验期间合上笔记本，计时照走。

第四类，是数值和规则没有出处。流程里的数字、学生模型的常数散在代码里，不标是 Math Academy 公开的、Repa 猜的，还是研究得出的；FIRe 实现了又关掉；测验触发、选题和完课估算用了复杂的规则，理由只写着"Repa 假设"。

另外两件和学习插件的结构有关：Python 运行器连同 `runner.py` 装在学习插件里，Web 为了它要依赖整个学习包；辅导工具把前端用的 JSON 直接交给模型。

## 做法

### 学习记录只记事实

每次作答只记对推断学习状态有用的事实：出了哪道题、哪个版本，她答了什么（换回题目原来的选项编号），当时判成什么，出题和作答的时间，答前有没有看讲解或问辅导，这是哪种任务（课、复习、测验）。界面、学生模型、进度和 XP 都从这些事实算出来，可以删掉重算。

题目的版本只由她看到的内容和判分方式决定。知识点归属改了不换版本，重算学习状态时按新归属算。

没有证据就不算对也不算错：中途离开、判分失败、模型说判不准，都只是还没有证据，不卡住任务，也不记成失败。条件具备时自动补判，学习状态随之重算。

题目的答案改正以后，过去的作答按新答案自动重判，对错两个方向都算；新判分追加，取代旧判分。XP 只增不减，不因重判收回。

### 判分：答案存在题目里，当场在同一环境里算

题目里存的是答案本身，也就是期望表达式和参考解。判分时，在跑她程序的同一个环境里当场算出期望值，再和她的结果比。现在这个环境是应用内置的 Pyodide；以后她用自己装的 Python，判分也用它。

于是 `expected.json`、指纹、重新生成和前后端运行器摘要的比对都去掉。"能不能跑 Python"改成前端连上时声明一次。执行请求里不再带学习插件的编号。

### 检查工具

检查工具用判分的同一套判断检查一道题：参考答案要判对，已知的错误作答要判错。它和判分只有一个入口。

题目在哪里产生，检查就在哪里跑：我们自己写的、社区贡献的，还有模型在学习者那边写的。所以它是产品里的工具，不只是仓库里的测试。

检查程序的跑法和判分一样：复用解释器，任务之间按 `runner.py` 恢复状态，恢复失败或超时才换新的解释器。整门课核对应该从四十多分钟降到一分钟左右，CI 里"只在定时任务跑整门课核对"的开关随之去掉。

跑不了代码的题，在写题、改题时让模型只看题面独立再解一遍，结论不存档。

一道题里有多个代码作答位、彼此有先后关系的，是一种正当的题型，叫多步代码题：作答位按顺序在同一个解释器里跑，题目写明每一步交给下一步的变量名；判第 n 步时，先跑前面各步的参考解，所以一步错不连累后面。互不相干的代码，出成两道题。

### 学生模型与流程

- 打开 FIRe。权重先用课程里现有的值（多为 0.5），标明是假设。
- 删掉 `uses`，先按 Math Academy 公开的做法以 topic 为单位传递信用；等真实数据证明按题传信用预测更准时再加回。研究要用时从 git 历史找回标注。
- 课程结束时也按答对比例算质量，课、复习、测验三种任务用同一条规则。
- 保留公式本身的常数，起名并注明出处，以后调参就调它们；研究专用的缩放、指数、capped-sum 和速度开关删掉。
- 测验按累计 XP 触发，XP 只增不减，不要历史高水位。测验从学过、近期没考过的 topic 里随机挑题，每个 topic 一题，答错转复习，和 Math Academy 一致。
- 完课估算改成"剩余课时 ÷ 最近每天的平均学习时长"，显示成一个日期。
- 复习判定和菜单规则保留，标明是假设，真用以后再调。
- 时间一律取底座的 `host.now()`。时钟回拨时按零间隔继续，不卡住。
- 中途离开复习或测验：没答的 topic 不算对也不算错；这次测验就此结束，没测到的 topic 之后重排；已答的照常算。
- 没有可用模型时，不出开放题。
- 先把前端显示不了的题筛掉再选题；一道都显示不了的知识点不进菜单。

### 辅导

辅导工具给模型一份写给模型看的当前任务：题面、她的答案、判分结果，写成分行的文字。要更多，由模型自己用工具去取。复习和测验期间不回答，这条已经在底座重构第 5 步改成用 `beforeRun` 关卡。

### 数值有名字，假设有清单

流程数字和学生模型常数集中到一处，每个都起名、注明出处（Math Academy 公开、Repa 猜测、研究结论）。学习插件的说明里另建一份"还没摸清的假设"，每条写它管什么、出处是什么、什么证据会让它改。数值只留在代码里，文档只引用名字，不抄数值。先收进去的有：流程里的数字、学生模型常数、Math Academy 没公开的部分（复习判定、衰减形状、质量）、FIRe 权重、测验"速度降 0.2"的幅度，以及研究里仍是假设的各项。

### 拆出 Python 运行器

Python 运行器连同 `runner.py` 拆成一个独立的小包，前端和学习插件都依赖它。顺手把 `runner.py` 里那行 `del value` 挪进输出收集的范围，修掉两处小的时间窗和顺序差异。

### 出题说明

从源头改出题说明：题目用来把懂和不懂的人分开；每个错误项都应当是某种具体误解会选的；各选项的形式和长短相近。检查工具仍只查对错。以后模型从维护者的材料出题，也用这份说明。

### 不在这次范围

维护者的主要用法，是拿自己的材料（讲义、教材）来，由模型拆出 topic、知识点和题，题经检查工具核过后进入练习和复习的循环。这条路径在产品里还没有，包括知识放在空间里当普通文件、在对话里新建 topic 和改题的工具、把预制课程复制一份当自己的课来改。它是下一项功能，单独提案；这次先把它要用的两块做好：检查工具和出题说明。

## 分步

1. 拆出 Python 运行器；检查工具改成和判分同一个入口、复用解释器。之后各步跑测试都快很多。
2. 判分当场算，去掉 `expected.json`、指纹和运行器摘要比对。
3. 学习记录只记事实，状态重算；没有证据的规则、答案改正后的重判。
4. 学生模型与流程的各项改动，以及假设清单。
5. 辅导工具改成写给模型看的分行文字。
6. 出题说明。

每一步一个分支、一次审阅、一次合并。第 1 步做完，CI 里整门课核对的开关就可以去掉。

## 考虑过的其他做法

- **预先算好期望值，加指纹防它过时。** 放弃了。答案本来就随课程装在她电脑上，当场在同一环境里算，值和判分天然一致；存值反而要一直保证算值的环境和判分的环境相同。
- **检查时每段程序都重启解释器，隔离得更彻底。** 放弃了。判分不是这样跑的，检查比判分严，两边结论可能不同；时间也几乎全花在重启上。
- **记录里存界面画面，重放时直接读回，不重跑教学逻辑。** 放弃了。这等于把缓存当记录，新算法没法拿历史重新推断。
- **按题传递信用（`uses`）。** 暂不做。现有研究不支持靠未验证的隐式信用压缩复习，等真实数据证明它预测更准再加回。
- **一题最多一个代码作答位。** 放弃了。有先后关系的几步代码放在同一题里继承解释器是合理的。

## 验收

- 在 Windows 上按 CRLF 检出，她能做完一道代码题，第二天复习到它，判分结果和 Linux 上一样。
- 整门课核对在一分钟左右跑完；对同一道题，检查和判分给出同样的结论。
- 改正一道题的答案以后，过去的作答自动重判，学习状态随之变化，XP 不减少。
- 复习或测验中途关掉应用，再打开不会卡住，没答的 topic 不记成错。
- 没配模型时，不出开放题。
- 换一组学生模型参数，能拿历史作答重放，比较两组参数的预测。

## 风险与代价

- 学习记录的盘上格式要换。维护者和 Aqua 本机有旧格式的开发数据。按"旧数据永远能读"，旧格式里的事实都在，读到时转换成新格式，先备份再改标记；转不了的条目原样保留并报告。如果维护者认为开发数据不必保留，可以改成直接丢弃，省掉转换代码。
- 删掉 `uses` 和研究专用的开关以后，研究重启时要从 git 历史拿回。
- 拆包会动到 Web 和桌面端对运行器的引用，前端那一半由 Aqua 跟进。
