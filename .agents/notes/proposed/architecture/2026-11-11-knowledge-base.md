# 一个人一个知识库：知识点以名字为身份，课程排在知识库之上

状态：提案

## 问题

Repa 现在按课程组织知识。知识点由课程定义，编号形如 `py01.k1`；学习状态按这门课计算；一个空间只装一门课。这带来四个后果。

其一，学过的内容会被再教一遍。学习者在一门课里学会了归纳法，另一门课用到它时，Repa 并不知道，只能从头安排。学校教育里常见的毛病正是如此：一门课不确定学生在别的课上学过没有，于是再教一遍。Repa 要替学习者安排学习，就应当先知道他已经会什么。

其二，学习者没有一份属于自己的知识。学过的内容散在各门课里，课程一换就无从查看。根目录的 `AGENTS.md` 要求学过的内容随时可查；一份只存在于系统内部、学习者看不到的记录，对人没有吸引力。

其三，学过的一切都被同等地长期保持。为一次考试学的内容，考完以后仍会不断安排复习。照此下去，学得越多，每天花在复习上的时间越长，而其中相当一部分已经用不上。

其四，先修写在课与课之间。随包的 Python 课有 48 个 topic、107 条先修，[课程关系核对](../../../../docs/research/python-course/relations-review.md)逐条看过，其中 9 条的后一个 topic 并没有用到前一个 topic 的内容，只因路线上排在后面而保留。一节课里只有一个知识点需要的前提，也成了整节课的门槛。先修指向的又是本课程里的某一节课，学习者在别处学会了同样的内容，无从满足它。

## 做法

### 已定的要求

以下各项是我的决定，设计以此为前提。

- **一个人只有一个知识库。** 学习者会的一切都在其中，组织成树或图。学习状态记在知识点上，随人而不随课程。知识库对学习者可见、可改，不是系统内部的账目。
- **知识点是人类知识中有名字的那个东西本身。** 牛顿第三定律、辗转相除法、哲学家进餐问题，各自就是一个知识点；谁来教、怎样表述，它都是同一个。两门课提到同一个名字，指向的就是知识库里的同一个知识点。
- **知识点上挂着三样内容**：它能解哪些题，它包含的思想，它在别处的用处。第三样是知识之间的联系，属于知识本身，不属于某一门课。
- **要长期保存的是学习者在知识点上的记录**，即会不会、会到什么程度、何时学的、错在何处。知识点的文字、例题和题目可以重新生成，更换以后不算损失。
- **有卡片不等于要学。** 往知识库里添一张卡片，不会自动安排学习。安排什么、保持什么，取决于学习者为了什么而学：为了一个有期限的目标，为了长久掌握，或者只为通过一次考试。
- **不再需要的知识不再安排复习。** 它在知识库里保留，记忆的估计照常随时间下降，只是不再因此产生任务。
- **学习者说会，就按会处理。** 此后的作答若表明并非如此，再由程序纠正。入学测验可以加快这一过程，但不是前提。
- **先修关系只写确实离不开的。** 先后次序一部分是知识本身的性质，一部分来自课程的编排；后者不写成先修。
- **课程是排在知识库之上的一条路。** 安排课程时考虑哪些已经学过、哪些需要复习。

Repa 帮助学习者更快进入一个领域，或者准备应试内容。深刻的理解要在真实世界的实践中获得，不在承诺之内，因此“学会”的证据仍然是程序能够核对的作答。

### 知识库与卡片

学习者的知识库就是他的学习空间：一个文件夹，其中每个知识点有一张卡片。卡片是一个 Markdown 文件，文件名通常就是知识点的名字，正文写这个知识点的思想和它在别处的用处，并用 `[[名字]]` 链接到别的卡片；文件开头的元数据（下称文件头）里写着别名，以及它对应哪些课程里的哪些知识点。学习者可以用任何编辑器修改卡片、给它改名、把它移进子文件夹，也可以自己新建一张。Agent 修改卡片用的是空间里普通的文件写入，改动进入空间历史，可以撤回。学习产品默认只为一个人开一个学习空间；另开一个空间，就是另一个知识库。

哪些作答算在一张卡片上，由它的文件头决定。学习记录里的作答只写明考的是哪门课的哪个知识点；卡片的文件头列出它对应的课程知识点，列在同一张卡片上的，作答就算在一起。文件头是学习者的文件，他或他的 Agent 可以直接改：把一行从一张卡片移到另一张，就是把那门课的那个知识点拆出去；把两张卡片的文件头并成一张，就是合并。改错了再改回来即可，因为作答本身不动，归到哪张卡片每次都按当前的文件头重新算。

卡片因此可以随意改名、移动、删除而不丢记录。卡片被删除以后，课程知识点上的作答仍在学习记录里，只是暂时不属于任何卡片，各自单独计算；再有卡片的文件头列出它，就重新归过去。一个文件被复制成两个、文件头列着同一个课程知识点时，程序不自行决定归谁，请学习者指认；指认之前它单独计算。文件头里另有一个不带含义的短编号，供自述等指向卡片本身的记录使用，使它们在卡片改名以后仍找得到这张卡片。

知识点上挂的三样内容来源不同。思想和用处是卡片的正文，由人和 Agent 书写，可以整篇重写。卡片第一次建立时，正文取课程为这个知识点写的初稿，即现有课程格式里概念卡的定义、常见混淆和例子；此后它是学习者的文件，课程换版不覆盖它。能解哪些题，由程序从课程的考法和学习者做过的题算出。别的卡片、讲解和解析在哪里提到它，由程序扫描链接算出，即[题目结构提案](2026-11-02-item-structure.md#链接与显示)所说的反向链接。学得怎样也是算出来的：卡片文件里不写学习状态，状态由学习记录重放得出，显示时与卡片合在一处。

知识库里只有学习者遇到过的知识点：学过的，说自己会的（下文称自述），自己加进来的。一门课里还没有学到的知识点留在课程里，学到时才建立卡片。这样，知识库里有哪些卡片始终由学习者自己的经历决定，不因开始一门课而一次多出上百张。

### 课程怎样接到知识库上

课程不再定义知识点，而是指认知识点。课程里的知识点保留课程内的编号（如 `py03.k2`），题目编号也不变，但这些编号只在这门课里有意义。课程为它涉及的每个知识点写出名字和别名。涉及的知识点分两类：一类由这门课讲授，有讲解、例题和题目；另一类是预备知识，课程要用到却不讲。现有格式里概念卡的 `name` 和 `aliases` 已经是名字和别名，只是此前仅用于显示；预备知识是新增的一项。

学习者开始学一门课时，程序为课程涉及的每个知识点找一张卡片：课程写的名字与某张卡片的名字或别名相同，就提议对应到它，并把这个课程知识点写进那张卡片的文件头。有作答而暂时没有卡片的课程知识点也在查找之列。没有找到的，等学习者第一次遇到它时新建卡片。按名字查找只用于第一次提议，此后以文件头为准，卡片改名、课程换版都不影响已有的对应。查找的规则因此不是长期的约定，以后可以改进，也可以交给 Agent 判断。

按名字提议会有两种错。一种是同一个知识点有两个名字：一门课叫“辗转相除法”，另一门叫“欧几里得算法”，彼此都没有把对方列为别名，知识库里就会有两张卡片。后果是多学一遍，与现状相同；学习者或 Agent 之后把两张卡片的文件头并到一起即可。另一种是两个知识点同名：列表的“索引”和数据库的“索引”会被当成一个。后果是该学的被跳过，所以开课时，凡因对应而被认作已经学过的知识点都列给学习者看；他指出其中某个不是一回事，程序就为它另建卡片，把那一行移过去，这门课在它上面的作答随之归到新卡片。

没有人指出时，程序不会自己发现两个知识点被混为一个：答错只说明没有掌握，照常补救。为学习者生成课程的 Agent 在写课时读得到知识库，已有的知识点沿用卡片上的名字，所以这两种错主要出在别人写好的课上。对应以课程里的一个知识点为单位；需要更细时，可以在学习记录里追加一条，把个别作答改归另一张卡片。这是留给 Agent 和愿意动手的使用者的办法，界面不必提供。

一个空间里可以同时有几门课。菜单、XP、日目标和测验都属于这个人，不按课程分开。课程从哪里来、经过怎样的检查才可使用，属于 [#99](https://github.com/Utopia-V/repa/issues/99)，不在本提案之内。

### 学习记录指向知识点

要长期保存的是学习者在知识点上的记录，所以学习记录加上卡片的文件头就要足以算出每个知识点的状态，不能要求课程文件在场。现在有两处做不到。交付事实只记题目编号，属于哪个知识点要到当前课程里去查，题目从课程里删去以后，这份作答便不再作为证据。一次作答的信用传给哪些旧知识，也取决于当前课程里写的覆盖关系。照此，课程整门重新生成一次，过去的作答全部失效；卸载一门课，在它上面顺带练到的旧知识也不再算数。

[学习记录](../../../../docs/development/learning-records.md)因此作如下改动，新增事实的名称和字段在实现时确定：

| 事实 | 内容 | 用途 |
| --- | --- | --- |
| 用到一门课的一个版本（新增） | 课程、版本和它的结构：各知识点的课程内编号、名字与别名，topic 的组成，先修，覆盖关系。结构没有变化的版本不重复记 | 重放不需要课程文件；过去的作答按当时的关系计入 |
| 开始、调整或结束学一门课（新增） | 课程，以及下文的两个日期 | 决定安排什么、保持什么 |
| 自述，或收回自述（新增） | 卡片的编号 | 见下文“自述” |
| 个别作答改归另一张卡片（新增） | 交付的序号、卡片的编号 | 比课程知识点更细的纠正 |
| 对一份作答的诊断（新增） | 交付的序号、诊断的文字、由谁写下 | 错在何处：这次卡在哪里，是思路、写法还是粗心。由 Agent 在作答之后写，学习者可以改 |
| 选了一项任务（`task`） | 课记下课程、版本和这一次要讲的知识点；复习、测验和核对记下要考的课程知识点 | 任务的结论只取决于它开始时的要求和它自己的作答 |
| 出了一道题（`delivered`） | 增加课程、版本和课程内的知识点；考法和猜中机会按题目结构提案加入 | 一份作答考的是哪门课的哪个知识点 |

凡指向课程内容的编号（topic、知识点、题目、考法）都连同课程一起记，不同的课程可以用相同的课程内编号。一份作答考的是哪门课的哪个知识点、哪种考法，写在交付事实里；它算在哪张卡片上，由卡片的文件头得出，不写进学习记录。这样对应错了改文件头即可，不必改写作答。作答的信用沿出题那门课、那个版本声明的覆盖关系传递，关系取自记录里的课程结构；课程后来换版、卸载，或者另一门课对同一个知识点另有声明，都不改变过去的作答怎样计入。答案改正后的重判照旧进行；题目已经不在任何课程里时，保留最后一次判分。

诊断是记录里唯一由模型写的文字。它不参与学生模型的计算，对错仍只看判分；它显示在卡片上，并在以后讲解同一个知识点时交给 Agent，使讲解能从这个学习者实际错过的地方说起。

任务开始时记下它要讲或要考的知识点。此后对应的改动、自述和课程改动只改变知识点上的状态，不改写这项任务的结论和 XP。例如一节没有通过的课，不会因为其中的知识点后来与一张已学的卡片合并，就变成当时已经通过。这沿用了题目结构提案的做法：记下当时采用了什么，它仍是事实。以上都是持久格式的改动，落地时按[持久格式的规则](../../../../docs/AGENTS.md#持久格式与版本)记录版本判断。

学生模型的单位随之从 topic 改为知识点。现在一节课通过才建立一份状态，复习和覆盖关系也按 topic 计算；但两门课不会把课切得一样，能在知识库里重合的只有知识点。改动以后，课、复习和测验的证据都按题目所属的知识点交给学生模型：课上每通过一个知识点，就为它建立状态；复习和测验按知识点分别得出结论。一道题只属于一个知识点。topic 仍是课程里一节课的单位，决定哪几个知识点一起讲、这节课算多少分钟。`@repa/learning-model` 的更新公式不变。它的选择器现在把“有状态”当作能不能学的条件，并按一张先修图挑选新课；这两件事改由学习插件按具体的课判断，选择器只在插件给出的合法任务里排序，并预演一次通过能消除哪些到期的复习。

于是，一个知识点对一个学习者有三种状态：没学过；自述会，即学习者说过自己会，还没有作答证据；学过，即有作答证据，带有学生模型的估计。

### 先修与覆盖

先修改为写在知识点上。课程对它讲授的每个知识点，列出离不开的知识点，可以是本课程讲授的，也可以是预备知识。判断标准只有一条：不会前者，后者的例题和题目就做不下去。讲解里先讲什么、后讲什么不算在内：用操作系统的课件试排过一次，把“讲解要先讲过前者”也算作先修，教材的编排顺序几乎全部回到先修里。因教材这样编排、因路线上排在前面而有的先后，由 topic 在课程清单里的顺序表达：几节课都可以上时，菜单优先给靠前的。现有的 topic 级 `prerequisites` 和知识点上的 `keyPrerequisites` 合并为这一项。一节课能不能上，看这一次要讲的各知识点的先修：除了在本节课里先讲的，其余都要已经学过或自述会；课程检查拒绝一节课里后讲的知识点成为先讲的知识点的先修。做不下去时的补救，从没通过的那个知识点的先修找起。

先修由课程声明，对象却是知识库里的知识点。所以它可以由任何途径满足：在别的课上学过，或者学习者自述会。两门课对同一个知识点声明的先修可以不同，各自只管自己的课，因为离不开什么取决于这节课怎样讲。

覆盖关系说的是做一个知识点的题顺带练到了哪些旧知识，学生模型按它传递信用。它同样改为知识点之间的声明，可以指向预备知识。信用只沿出题那门课声明的关系传递，几门课的声明不并成一张图，因为它说的是这门课的题实际练到了什么。于是在新课程里练习，会顺带更新在旧课程里学过的知识点，复习因此减少。权重仍是待校准的假设。

### 安排与保持

学习者开始学一门课，这门课就是在学的课，直到他结束它。在学的课可以带两个日期，都可以不填。“期限”是希望在哪一天之前学完；“保持到”是哪一天以后不再需要，过了这一天，这门课视同结束。我举过的三种学习目的都能用它们表示：为一个有期限的目标而学，填期限；为长久掌握而学，都不填；只为一次考试，两个日期都填考试那天。程序不另设目的的分类，因为目的不同时，要程序做的不同之处只有这两点：何时之前要学完，何时之后可以放下。期限目前只用于完课估算：估算的完课日期晚于期限时，告诉学习者按现在的进度学不完。两个日期到了都不写事实，读取时按当前时间判断，与现有的到期和截止相同。

新课只来自在学的课。一节课里还有学习者没学过、也没自述会的知识点，并且先修满足，这节课就可以上。这一次只讲这些知识点；已经学过或自述会的跳过，跳过不产生新的证据。整节课的知识点都已学过或自述会时，这节课不出现。现有规则把没通过的复习转为重学时，重学优先于跳过：那个知识点虽然已有状态，仍在这一次里重新讲。

复习只为需要保持的知识点安排。一个知识点需要保持，是指至少有一门在学的课涉及它，讲授或作为预备知识都算。需要保持的知识点记忆降到到期线以下，就安排复习。题目取自学习者学过或在学的课，并且那门课为这个知识点声明的先修他都已满足，免得题目用到他没学过的内容。测验也只在需要保持的知识点里抽题。

不需要保持的知识点不再产生任何任务。它不安排复习，不参与测验，挑选任务时也不把顺带消除它的到期算作好处。此前为它留下的强制补救不再拦住别的任务；还没开始的测验和换题重考按当前范围重选，选不出知识点时测验暂缓，不挡新课。已经开始的任务照常做完，已有的作答、判分和 XP 都保留。它的状态还在，记忆估计随时间下降，别的作答经覆盖关系传来的信用照常更新它。日后又有在学的课涉及它，它重新需要保持，这时多半已经到期，安排的是复习；复习没有通过，再按现有规则补救或重学。

学习者自己加进来的卡片没有任何在学的课涉及，所以不产生任务。想学它，就要有一门讲授它的课，哪怕只有一两节，可以由 Agent 生成。

### 自述

学习者可以对任何知识点自述会：知识库里的卡片，开课时列出的预备知识，或路线上还没有学到的知识点。自述是一条记录，不是证据。学习插件的规矩是没有证据就既不算对也不算错，所以自述不建立学生模型的状态，没有记忆估计，也不安排复习。它只有两个作用：以它为先修的课可以开始；讲授它的课不再讲它。

之后的作答决定它的去向。测验抽题时，自述会的知识点与学过的一样在候选之中；以它为先修的课反复不能通过时，补救安排一次对它的核对。核对与复习一样出题，只是不要求它已有状态。第一次在它上面得出结论时，通过则成为学过的知识点，状态从这次证据开始；失败则自述作废，它回到没学过，在学的课里有讲授它的课就照常安排。以它为先修的课没有通过，本身不撤销自述，要等核对得出结论。学习者学过或在学的课都没有它的题目时无从核对，自述一直有效。学习者也可以随时收回自述。

开课时，程序列出知识库里没有的预备知识，学习者自述其中会的。余下的若没有任何课讲授，以它们为先修的课不提供，菜单说明在等什么；有可用模型时由 Agent 为它们补课，与题目结构提案里缺题的处理相同。入学测验可以把核对提前、集中完成，另行设计（[#108](https://github.com/Utopia-V/repa/issues/108)），本提案不以它为前提。

### 一个例子

一位学习者学完了随包的 Python 课，其中有“列表”“索引”。十一月，他为二月的面试开始学一门算法课，期限填 2 月 1 日；又为 1 月 10 日的期末考试开始学一门概率课，两个日期都填这一天。

算法课把“列表”“索引”列为预备知识。知识库里已有同名的卡片，两个知识点对应过去，不新建卡片，也没有它们的课要上。“索引”三个月没有练过，已经到期，菜单上出现它的复习，题目取自 Python 课。算法课的第一节讲“递归”，他在别处学过，自述会，这一节不再安排，以“递归”为先修的课可以开始。后来“归并排序”一课两次没有通过，程序安排一次对“递归”的核对，他没有通过，自述作废，菜单重新提供讲“递归”的那一节。

1 月 10 日以后，概率课的知识点不再出现在复习里，卡片和记录都在。半年后他开始学一门把“条件概率”列为预备知识的课，这张卡片的记忆估计已经很低，菜单安排的是一次复习，而不是从头讲一遍。

### 迁移

本提案在第一个测试版之后实施，测试版的格式不因它改动。随包的 Python 课这样迁到新格式，题目、讲解和各级编号都不动：

- 120 个知识点的名字和别名直接作为对应的依据。别名原为显示和搜索而写，其中过于宽泛的（如“转换”“括号”）要删去，以免与别的课误认。有些名字是这门课自己的说法（如“读入后核对”），不会与别的课重合，保留无害。
- 107 条 topic 级先修改写为知识点上的先修：以各知识点现有的 `keyPrerequisites` 为起点，把指向的 topic 换成其中实际用到的知识点，再按“做不下去”的标准逐条核对。课程关系核对中标为没有用到的 9 条不再是先修。
- 111 条覆盖关系按课程关系核对逐条记下的定位，改写到知识点之间，权重沿用。

测试版学习者的数据由新版本直接读取，原有记录逐字保留，只在后面追加：

- 测试版的记录里没有课程结构，而按测试版的规则重放旧任务，要用到当时 topic 含哪些知识点、题目在哪个题池、例题是哪一道。所以测试版用过的各个课程版本的结构随学习插件冻结一份，旧任务按它重放，不查当前课程；课内进度、测验与换题重考的结果、补救要求和 XP 因此都与升级之前相同。
- 重放出的结果再记到知识点上。课里通过的知识点各自建立状态，一节课没有全部通过时，已通过的知识点同样保留。复习、测验和换题重考在测试版里按 topic 得出结论，这个结论记到该 topic 的每个知识点上，时间和质量相同。
- 有任务记录而没有开课记录的课，视为在学，两个日期都没有。
- 第一次用新版本打开空间时，为旧记录提到的每个知识点建立卡片，文件头写上它在 Python 课里的编号，不只是已经学会的。这一步可以重复执行，中途退出以后重开不会建出重复的卡片。空间里因此多出一个卡片文件夹，学习者原有的文件不动。

### 对题目结构提案的改动

[题目结构提案](2026-11-02-item-structure.md)的以下各处已随本提案修改，其余不变：

- 概念卡改称卡片，存放在知识库里；课程里的 `card` 是它的初稿。
- 课程正文里的 `repa:concept/<课程内编号>` 写法保留，经对应指向卡片；卡片正文用 `[[名字]]`。反向链接同时扫描两者。
- 一道题只属于一个知识点和一种考法，由它所在的位置和考法标注给出；新格式不再有可以列出几个知识点的 `measures`。
- 考法的编号只在一门课的一个知识点之内有意义。两门课的知识点对应到同一张卡片，不等于它们的考法相同；复习轮换考法时，各门课的考法分别计算。
- 整题的对错仍只记在所属的考法上；旧知识的复习信用改为按知识点之间的覆盖关系传递。
- 测验由每个 topic 一题改为每个抽到的知识点一题。
- 该提案待定的“我已经会了”由本提案的自述取代：跳过不以挑战题为前提，挑战题可以作为入学测验的一种形式另行设计。

## 考虑过的其他做法

- **状态仍按课程记，课程之间用等价表互认。** 每两门课要有一张表，同一个知识点的状态分存几处，学习者仍然没有一份自己的知识。
- **建立全局的知识点注册表，课程引用注册表里的编号。** 需要有人维护一份覆盖所有学科的表，学习者自己加的卡片也放不进去。名字加别名已经能让多数课程对应上，对应错了改文件头即可；日后确有需要，可以把外部编号当作别名加入。
- **直接用名字作编号。** 学习记录不能改写，卡片一改名，过去的记录就失去归属。
- **用文件路径作身份，改名靠追踪文件变化。** 在 Repa 之外改名时只能看到一删一增，要靠内容相似去猜是不是同一张卡片。
- **对应记在学习记录里，卡片文件只带一个编号。** 对应看不见，纠正要靠专门的操作，登记、对应、合并、撤销各要一种事实。作答既然只记课程里的知识点，文件头写错不会丢任何记录，没有理由把对应藏起来。
- **在交付事实里直接写知识库的编号。** 对应认错时，错误已经写进每一份作答，纠正就要逐条改写。改为只记课程内的知识点，归到哪张卡片由文件头得出。
- **重放时取当前课程的覆盖关系。** 现状如此。课程换版或卸载以后，过去顺带练到的旧知识不再算数，后装的课又会追溯地改变更早的作答；这与课程可以整门更换的要求相抵。
- **学生模型仍按 topic 记状态。** topic 是一门课自己的切法，另一门课里没有相同的 topic，状态无法共用。
- **开课时为课程的全部知识点建立卡片。** 知识库会装满学习者还没见过的内容，“有卡片不等于要学”也无从谈起。
- **卡片文字留在课程里，知识库只负责显示。** 学习者改不了；课程卸载以后，卡片也随之消失。
- **按目的分类（考试、求职、兴趣），每类一套安排规则。** 这几类只是例子；它们要程序做的不同之处只有何时学完、何时放下，用两个日期即可表示。在没有作答数据的情况下为每一类另写算法，没有依据。
- **每张卡片单独设定是否保持。** 学习者要为每个知识点做决定，这正是 Repa 要替他免去的事；按课程决定已经够用。
- **课程结束时清除或归档其知识点的状态。** 状态是要长期保存的那一部分；留着它，日后别的课涉及同一个知识点时才能安排复习而不是重教。
- **自述即按上过课处理，建立初学状态。** 这等于凭一句话造出证据；一次自述几十个知识点，第二天会同时到期。
- **开课前必须先做入学测验。** 学习者说会就按会处理是已定的要求，测验只用来加快纠正。
- **把先修定为知识库里卡片之间唯一的一套关系。** 离不开什么取决于一节课怎样讲，两门课可以不同；由课程各自声明、指向知识点，已能让别处学到的知识满足它。
- **知识库放在应用配置目录，供多个空间共用。** 那里的文件学习者平时看不到，也不进空间历史。

## 验收

以下各项都能在随包课程加一门示例课程上走一遍，从学习者看到的结果和学习记录核对：

- 学完 Python 课“列表”“索引”的学习者，开始一门把这两个知识点列为预备知识的课：没有再上它们的课；其中已经到期的，菜单安排的是复习。
- 学习者在编辑器里给一张卡片改名、移进子文件夹：重开空间以后它的学习状态不变，课程仍对应到它。删除一张有作答的卡片：作答仍在学习记录里，重建卡片并写回对应以后，状态与删除之前相同。
- 课程换成题目全部更换、讲解重写的新版本，或者整门卸载：学习者在各知识点上的状态与此前相同，过去的作答仍在各自知识点的历史里。
- 一门课填了“保持到”：这一天以后，只有它涉及的知识点不再出现在复习和测验里，为它们留下的补救不拦住别的课，卡片仍在；之后另一门在学的课涉及其中一个知识点，菜单安排的是它的复习，不是它的课。
- 学习者自己新建一张卡片：菜单不变。
- 学习者自述会一个知识点：以它为先修的课出现在菜单里，讲授它的课不再讲它。之后测验抽到它而答错：它回到没学过，讲授它的课重新出现。
- 开课时，因名字相同而被认作已经学过的知识点都列了出来；学习者指出其中一个不是一回事以后，它另有一张卡片，这门课在它上面已有的作答随之移过去，讲授它的课照常安排，此前各项任务的结论和 XP 不变。
- 两张卡片的文件头并成一张以后，两边的作答都在这张卡片上；再分开，各归原处。
- 一节课先讲一个知识点、再讲以它为先修的另一个：两个都没学过的学习者可以上这节课。
- 随包 Python 课迁移以后，每条先修都能在后一个知识点的例题或题目里指出用到前者的地方。
- 测试版学习者的空间用新版本打开：各任务的结论和 XP 与升级之前相同；学过的知识点各有一张卡片和一份状态，只通过了一部分的课，已通过的知识点不必重学；原有的文件和记录没有被改动。

## 风险与代价

- **学生模型的单位改变。** 复习从一次一个 topic 变为按知识点安排，单次更短，次数更多。`REVIEW_MAX_QUESTIONS` 等复习数值、`REVIEW_XP` 和 `QUIZ_TOPICS` 原按 topic 设定，要重新取值，仍是假设。教学流程、菜单、选择器的接口和前端契约都要随之修改。测试版学习者升级以后，哪些复习到期会与升级之前有出入。
- **名字承担了对应。** 两个知识点同名会让学习者跳过该学的内容，同一个知识点两个名字会多学一遍。前者靠开课时的清单和学习者指认，后者靠改文件头合并；程序不会自己发现。写课时要取通行的名字，写全别名。
- **同一个名字，深浅或语境不同。** 一门课只要求读懂类型转换，另一门要求写出来；一门课用 Python 讲二分查找，另一门用 C++。按名字它们是同一个知识点，后一门课不会再讲，差距要等后面的课做不下去才暴露。需要单独讲的深度应当写成另一个知识点。
- **写课多了两件事。** 一是列出预备知识，二是按“做不下去”的标准写先修。Python 课 120 个知识点的先修要逐条核对。
- **程序会往学习者的文件夹里写文件。** 新建卡片，在文件头写入对应，给手工新建的卡片补上编号。写入都经空间历史，可以撤回。
- **对应存在卡片文件里。** 只搬学习记录而不带卡片时，各课程知识点上的作答都在，但哪些算在一起要重新对应；备份和导出学习数据时要把卡片的文件头算进去。
- **自述可能一直得不到核对。** 没有题目的知识点无从核对；没有课以它为先修时，这没有后果。
- **学习记录变大。** 每个用过的课程版本要把结构记一次，按随包 Python 课现有的内容估算约 20 至 30 KB；所有课的记录在同一份日志里，打开空间时重放的代价随之增长，学习记录说明里暂缓的派生缓存会更早需要。
- **测试版的规则和课程结构要一直带着。** 读取测试版的记录需要它们，这是承诺读取旧格式的代价。

## 待定

- 卡片所在文件夹的名称，以及文件头各项的写法。名字里有文件名不允许的字符时，原名写在文件头里。
- 一次复习包含哪几个知识点；几门课同时在学时，新课怎样在它们之间分配。
- 期限是否影响每天的安排，考试之前是否提高到期线。
- 课程换版以后，是否提示学习者更新卡片的正文。
