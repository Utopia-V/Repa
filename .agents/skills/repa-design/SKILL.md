## 维护者说过的话

- 不设界面用词表。界面文字由人书写，用词表只对让模型写界面文字的做法有用，而这正是规则所禁止的。用词冲突交给写文字的人解决。
- 语言是一整套：字号、控件、状态、动效和流程都在其中。一套配色加一种字体不算语言。
- 细节要精细到可以称作设计。能用不等于设计。这有行业标准可查，要自己查、自己对照。
- 狂野也是一种设计。问题在粗糙，即实用度和用户视角。不因大胆而删减，先问它从学习者的位置看有没有用，再把它做完。功能存在不等于有用。知识树做好了很有用。
- 体系中有一部分，连主体换掉（比如从第三国际塔风格换到极简主义）也照样成立。这部分从行业资料对照要求得出，写在清单里，自己照办。
- 先设计，暂不管程序怎么跑。后端缺接口不能成为界面粗糙的理由，把需要什么记下来，继续做。
- 要做的是产品语言。dsh 那样的插件化不在这次范围内，不要在可替换的框架、皮肤和相应的检查工具上花工夫。
- 大框架不是前提。先探索结构，再谈表面；左中右三栏和先选文件夹都可以打破。
- 风格偏好：简洁，或有几何走向的繁复，极简式构成主义；同时要考虑软件设计性。几何只报告状态。
- 好的设计没有一堆说明文字。任何面向人类展示的文字都不要用模型生成（#101）。
- 规则要落到文档和 Skill，下次不必再讲。
- 写给人看的话不要有攻击性；要幽默，也由人来写。
- 前端由 Aqua 负责。落到 `apps/web` 须维护者决定，并与 Aqua 商定。

## 保护学习证据

这是产品要求，不随风格改变：不泄露答案，不显示未放行的内容，隐藏的控件也不可到达。

## 踩过的坑

- 每个视图都要用真实内容走一遍，亲眼看。topic 图和链接图曾经明显是坏的，脚本全部通过，因为没有人打开看。
- 结果要落在学习者正看着的地方。题目一长，放在作答框下方的判定就在屏幕外，学习者按了提交，什么也没看到。
- 例题是做好的步骤，不是表单。显示答案的输入框看起来像要填，“你的选择”的标记也不实。
- 离开不能有代价：未提交的作答、阅读位置、写了一半的问题都要保留。保留题号不等于保留现场。
- 查阅用的内容必须自足。知识卡提到表 M，旁边就要有表 M，否则又把记忆负担还给学习者。
- 触屏上，正文里的链接预览，本身就是目的地的链接直接前往。把所有链接都变成预览，学习者会差一步到不了。
- 只读不等于放行。判分中和没判出时作答被锁定，但不能露出任何结果。
- 隐藏必须不可到达。`opacity: 0` 的菜单仍能用 Tab 进入，要用 `inert`；每条通往内容的路都要核对权限，包括改地址。
- 校验放在操作入口，任何界面都绕不过。空答案不算错答。
- 奖励按后端公式（`docs/development/learning-quiz-xp.md`）：没通过的测验也可能得 XP，不要在界面里另算。
- 作答期间参考内容关闭，把历史留在屏幕上的界面此时要隐藏。复习和测验结束前不给反馈；任务结束不等于成功，还有没通过、时间到和待定。
- 知识库可以显示大纲，内容只放已学和当前的 topic。记忆按 topic 估计。课的结果写“通过”，“掌握”留给学生模型的估计。
- 单选用圆形标记，多选用方形标记。排序题可能需要调整缩进。
- CSS 的 `scale()` 会连 `non-scaling-stroke` 一起放大。

## 交出前

运行审查脚本，每个状态都查，手机宽度也查：

```sh
python .agents/skills/interface-craft/scripts/craft_audit.py 'http://127.0.0.1:5180/repa.html?later=1' 'http://127.0.0.1:5180/repa.html?later=1&go=wrong#/learn' 'http://127.0.0.1:5180/repa.html?later=1#/k/py02.k1'
```

脚本通过只是必要条件。以学习者的身份把任务做一遍，覆盖每个视图、真实内容、手机宽度和深色，对照清单，看原尺寸截图，并说明哪些没有核实。
