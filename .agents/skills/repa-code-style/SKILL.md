# Repa 代码规范

新增和实质修改的代码遵循本规范，测试代码共用格式与类型规则，测试组织另见[测试规范](../repa-test-style/SKILL.md)。局部修正保留无关区域的格式，避免整文件格式化。前端的组件、样式和交互细则由所属目录的 `AGENTS.md` 与设计系统文档补充；下列 NodeNext 和后端模块规则只适用于后端。

## 格式与命名

- TypeScript 使用两个空格缩进、双引号和分号；插值使用模板字符串，多行对象、数组和导入保留尾逗号。
- 文件名使用小写连字符，类、接口、类型和 React 组件使用 PascalCase，函数、方法、局部变量和属性使用 camelCase；协议 schema 使用 `XxxSchema`，命名常量沿用 `UPPER_SNAKE_CASE`。
- 一行表达一个操作。多步骤分支、资源清理和嵌套请求对象展开书写；短的无副作用守卫和紧凑 schema 登记可以保持单行。不用多重三元表达式压缩状态逻辑。
- 新注释使用简体中文，说明责任、时序、不变量或非显然的原因。保留专名和标识符；第三方原始注释不为语言统一而改写。

## TypeScript 与导入

- 后端沿用 `strict`、`noUncheckedIndexedAccess`、`noUnusedLocals`、`noUnusedParameters` 与 `verbatimModuleSyntax`；配置由 `tsconfig.json` 持有。
- 后端使用 ESM，Node 标准库写 `node:` 前缀，相对 TypeScript 模块导入写生成后的 `.js` 后缀。类型使用 `import type` 或命名导入中的 `type`；不引入 CommonJS 包装。
- 导入按 Node 标准库、外部包、项目模块组织；不为排序改动整个文件。前端沿用其构建器支持的路径别名和 CSS 导入，不套用 NodeNext 后缀规则。
- 文件、网络和插件输入先视为 `unknown`，在入口解析与校验后使用。不能通过 `any`、非空断言或 `@ts-ignore` 代替边界校验；SDK 泛型无法直接表达的适配应局限在边界，并注明原因。

## 契约、数据与错误

- 公开数据在所属 TypeBox schema 中定义，静态类型从 `Static<typeof Schema>` 推导；不手写第二套相同接口。协议入口在 `protocol.ts` 及所属模块的协议定义中登记。
- 固定对象复用 `schema.ts` 的 `object()`，明确可选字段，默认拒绝未知字段。状态与输入变体使用 `kind`、`type` 或 `status` 等明确判别字段，避免用数个布尔值表示互斥状态。
- RPC 方法沿用带命名空间的动作名，例如 `content.applyPatch`；需要程序处理的错误抛 `RepaFault(code, message, details)`，错误码使用英文小写下划线，面向用户的说明使用简体中文。
- 只在明确允许缺失的位置把 `ENOENT` 解释为不存在。权限错误、损坏文件和解析失败保留为可处理错误；不将读取失败返回成空列表或默认配置。
- 公开协议保持可序列化。Pi 运行对象、文件句柄和可执行函数不进入响应、事件或持久记录；原始上游错误只公开调用方有权获得的信息。

## 模块与副作用

- `client.ts` 及其依赖保持浏览器可用，使用标准 WebSocket／Fetch；不得经公共导出间接引入 Node、Pi 或后端存储模块。
- Pi 运行与消息类型留在后端接入边界，前端和 Agent 工具共享内容的版本检查、保存与恢复语义。运行记录、配置及插件自有数据由各自模块持有写入入口；当前模块位置与调用路径见[开发指南](../../../docs/development/README.md#从哪里开始)。调整实现位置时同步调用方与说明，保留这些责任边界。
- 通用存储辅助能力只承担文件与调度操作，数据格式、恢复判断与业务含义由所属模块持有。复用前核对原子性、持久化时机和操作顺序是否满足调用方；当前辅助能力见[开发指南](../../../docs/development/README.md#从哪里开始)。
- 普通文件 I/O 优先异步，避免阻塞后端处理其他请求。SDK 同步回调等确需同步完成的路径可使用同步实现，注明必要时序，并控制单次阻塞的工作量。
- 必须完成的保存和收尾纳入调用方可等待的完成链，成功响应不得早于必要工作完成；可以使用 `await`、返回 Promise 或组合 Promise。后台任务由所属生命周期持有并处理失败。`void` 不表示错误已处理，也不能用于提前报告保存成功。
- 已有 Web／Electron 组件通过 `repa/client` 与后端连接，沿用近端的基础组件、语义 token 和交互规则；不在页面中另建协议客户端或并行的视觉系统。

## 检查入口

当前后端类型检查使用 `npm run check`，构建使用 `npm run build`。具体脚本、编译选项与依赖版本分别以所属 `package.json`、`tsconfig` 和锁文件为准。本规范不引入新的格式化器、linter 或全仓重排任务。
