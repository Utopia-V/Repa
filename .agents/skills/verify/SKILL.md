# 把应用跑起来验证

单元测试、lint 和文档检查全过，应用却是坏的，这种情形已经反复出现：重开后做课面板是空的，学完一节后学习页右上角的入口不对，等等。它们都要把应用真正跑起来、像学习者那样点一遍才看得出。`npm run verify` 做的就是这件事，约 40 秒走完，不联网，不调用付费模型，也不打开任何窗口。

## 什么时候跑

改了 `apps/web`、`packages/learning`、底座的会话、插件、备份与导出，或者桌面端提供界面的方式以后，在提交之前运行。只改文档或只改与学习者流程无关的测试时不必运行。

走查目前不进 CI，由改动的作者在本机运行。

## 怎样跑

在仓库根目录运行：

```sh
npm run verify
```

它先运行 `build:packages`，再按桌面端的方式构建 `apps/web`（约 3 秒），启动学习者版本的后端、一个无界面浏览器和本机的假模型，然后按顺序走下面的步骤。第一次运行前要有 Pyodide 离线包（`npm run course:runtime`，已有一份时加 `--from 那个目录` 只复制不下载），缺了会直接说明。浏览器用机器上已有的：Playwright 缓存里的 `chrome-headless-shell`，或 PATH 里的 Chromium、Chrome、Edge；都没有时用 `REPA_VERIFY_BROWSER` 指定。

每次运行的全部状态放在 `.scratch/verify/<时间>/` 下：临时的 HOME 与应用配置目录、学习空间、备份、导出、截图和 `report.json`。真实的 `~/.repa`、`~/.config/repa` 和 `~/.pi` 不会被读写，环境里的 API key 也不会传给后端。只保留最近 10 次的目录，每次约 8 MB。

| 步骤 | 走什么 |
| --- | --- |
| `first-run` | 全新用户的第一屏，起名建课，没有模型时学习页的提示 |
| `making` | 接上模型；做课的 Agent 写课、`course_check`、`course_confirm`（假模型独立作答）、`course_use` |
| `lesson` | 从界面上完第一节，故意答错一道填空；回到菜单时的已学数、下一项任务、右上角入口 |
| `reopen` | 关闭后端再打开页面，回到原处 |
| `regrade` | 在新会话里让 Agent 改正那道题的答案并换用，过去的作答重判为对，今日 XP 不减少 |
| `grading-failures` | 开放题判分时模型请求失败（余额不足、连不上）：按原因说一句，不记为错，可以再判 |
| `mid-lesson` | 开放题判分途中关闭再打开，接着做，没判出结果的不记为错，模型可用后补判为对 |
| `next-day` | 后端时钟拨到第二天，菜单出现复习，复习做完 |
| `backup-export` | 立即备份，导出学习数据，导出的 zip 里有作答记录 |
| `expansion-failure` | 让通用 Agent 给课加一部分轮廓，学习页随即在后台展开它；展开的请求余额不足时，“整门课”下说明原因，原文折叠，有“重试” |
| `model-failures` | 模型请求断开、超时、key 无效、余额不足、限流、服务端出错时，对话里按原因说一句中文、只说一次（Pi 照常自动重试），撤掉故障后重新发送有回答 |
| `key-check` | 在设置里填 API key：提供方拒绝的不保存；连不上时照样保存并说明没能验证；能用的直接连上 |

## 怎样读结果

每一步打印一行“通过”或“不通过”，下面逐项列出检查。`✓` 是成立的检查，`✗` 是不成立的；`○ 预期失败` 是已知而尚未修好的界面问题，不影响结果；`! 已修好` 表示那个已知问题不再出现。退出码 0 表示没有不成立的检查。

一步不通过时，后面的步骤不再运行（它们依赖前一步留下的状态），并给出这一步的截图路径、当时的页面文字、页面里报过的错和假模型最近收到的请求。先看页面文字和截图判断卡在哪里，再看假模型的记录：Agent 的工具结果（例如 `course_check` 报的问题）就在里面。

已知问题写在 `scripts/verify/steps.ts` 的 `KNOWN` 里，检查用 `checks.known` 写出修好以后应当成立的情形。修好其中一个时，走查会报“已修好”；在同一个提交里把那一项改成 `checks.expect`，并从 `KNOWN` 删掉。

## 停下来自己看

```sh
npm run verify -- --until lesson     # 走到这一步为止，之后应用保持运行
npm run verify -- --keep             # 走完以后保持运行
npm run verify -- --list             # 列出步骤
npm run verify:drive -- <操作> [参数…]
```

保持运行时，`verify:drive` 给它发一条操作并打印结果：

| 操作 | 作用 |
| --- | --- |
| `text`、`url`、`shot [名称]` | 读页面文字、地址，截图（打印文件路径） |
| `click <名称> [附近的文字]` | 按可见文字或可访问名称点一个按钮、链接或选项；同名的有几个时用附近的文字区分 |
| `fill <标签> <文字> [附近的文字]`、`press Enter` | 在输入框里输入，按键 |
| `wait <文字> [秒]`、`goto <路径>`、`eval <表达式>` | 等文字出现，打开页面路径，在页面里求值 |
| `reopen [天数]` | 关闭后端再打开页面；给了天数时后端时钟往后拨这么多天 |
| `rpc <方法> [JSON]`、`plugin <插件> <方法> [JSON]` | 直接调用后端；插件方法的调用也算一次方法调用，可能触发后台补判 |
| `model`、`errors` | 假模型收到的请求和工具结果，页面里报过的错 |
| `quit` | 关闭一切 |

页面的 CSP 不允许字符串脚本，等待一律是读页面文字再轮询；不要在页面里用 `eval`、`new Function` 一类的写法。

## 改走查

步骤在 `scripts/verify/steps.ts`，每一步像学习者那样操作界面，再用 `checks.expect` 写下必须成立的事。证据优先取自界面；界面上看不到的（某份作答的判分结论、备份目录里有什么）读空间和配置目录里的文件，不经后端调用，免得走查自己改变状态。

假模型在 `scripts/verify/model.ts`，说 OpenAI 兼容的流式接口，按请求的种类回答：通用 Agent 的一轮按学习者消息里的文字找 `model.script` 给的剧本，一步是一次回答；课程核对按题面查 `scripts/verify/course.ts` 用学习插件自己的函数算好的标准答案；开放题判分判对，`holdGrading` 时先扣住，`failGrading` 时按给定的方式失败。`failAgent` 让之后通用 Agent 的请求按给定的方式失败（断开、不回、按提供方的格式回 401、402、429、500），直到撤销，也可以只让用户消息含某段文字的那些失败（后台展开的任务）；带的不是走查自己配的 key 时是保存 key 时的验证请求，按 key 回答。没有剧本的请求会让走查立即停下并报出来，而不是等到超时。超时那一种靠 `app.reopen({ settings })` 在重开前把 Pi 的请求超时和重试间隔调短，只改走查临时配置目录里的 `agent/settings.json`。走查用的课在 `scripts/verify/course/`。

某一步跑不稳时，找出原因再改，不要加固定的等待或重试来掩盖。点按钮前已经等元素位置稳定（对话框和抽屉有打开动画），之后等页面文字变化。

后端的时钟由 `scripts/verify/clock.mjs` 拨动：走查拉起后端时经 `NODE_OPTIONS` 先加载它，`Date.now()` 加上偏移，开始时拨到当天上午 10 点，隔天再加一天。产品代码里没有对应的入口。

## 局限

- 界面在无界面浏览器里打开，按桌面端的方式构建并由桌面端主进程的 repa 协议处理函数提供；Electron 窗口、preload 与主进程的启动和退出不在其中，安装包由打包核对验证。
- 窗口大小固定为桌面端的缺省 1120×760，学习页的面板收在右上角；宽屏布局没有走。
- 假模型只证明流程接得上，不说明真实模型的表现。代码题、页面里运行 Python、选课件没有走。
- 只在 Linux 上运行过。
