# 复：Repa 的设计语言（候选）

Repa 的名字来自 repetition。这套语言的图形只有一个单元：一块方格，内含两段四分之一圆弧。每一格的样子就是一个知识点的状态。第一天，一门课是一片点阵；学得越久，同样的格子织成越繁复的图案。简洁与繁复因此不是两种风格，而是同一个学习者在时间上的两端。

实物是 [`repa.html`](README.md)，它用整门 Python 课的真实内容走通今天、上课、复习、测验、知识库和设置。规则的依据与逐条结果见 [CHECKLIST.md](CHECKLIST.md)，细节取值的核对见 [CRAFT.md](CRAFT.md)，界面文字的取舍见 [`ui-text`](../../.agents/skills/ui-text/SKILL.md)，为什么要这样做见[设计记录](../../.agents/notes/proposed/feature/2026-11-04-design-language.md)。

## 理念与做法

| Repa 的要求 | 界面上的做法 |
| --- | --- |
| 界面是学习状态的视图 | 地图上每一格对应一个知识点；指向它就说出它是什么、学得怎样，点开就是它的页面 |
| 减少学习外的心智负担 | 打开就是“今天”和下一步，写明缘由和分量；不放积压数字；离开不必善后 |
| 对学习者呈现同一个对象 | 问模型不必先选去处：输入框就贴在当前页上，回答接在页面里 |
| 作答必须独立完成 | 作答时讲解回看、辅导、搜索、知识库都关闭；复习和测验从头到尾如此 |
| 答错要有分量，由系统判定 | 一枚红色楔形指向答错处；不扣分，不用惩罚的语气；红色不作他用 |
| 学过的内容随时可查 | 全局搜索、就地预览和知识库；上课时读讲解也能查 |
| 图谱不应要求学习者先学会操作一张大网 | 树和页面是主入口，局部关系只画一跳，全图不做默认 |

## 哪些属于主体，哪些不属于

换一个主体，比如从“复”换成第三国际塔或者纯粹的极简主义，下面两栏的归属不变。左栏来自行业资料和用户视角，见清单第一、二部分；右栏才是风格。

| 不随主体变化 | 属于“复”这个主体 |
| --- | --- |
| 同一件事总在同一位置，主操作不跳动 | 方格单元与 Truchet 织纹 |
| 能点的看着能点，模糊和去色后层级仍在 | 墨与淡蓝，OKLCH 色阶 |
| 每个部件的状态都画过，手感统一 | 宋体只用于名字 |
| 响应即时，数字彼此一致 | 方角，只有浮层是圆的 |
| 每一刻回答学习者的问题（清单第二部分） | 红色楔形 |
| 每种视图只做它擅长的任务（清单第三部分） | 进入格子的放大过渡，通过后当面织上一格 |

风格最响的一层只放大字和图形，正文留在中性字面上。

## 版面

- **内容框**：宽 1440，两侧边距 48，所有路由共用，顶栏不随页面移动。窄于 960 改为单栏。
- **顶栏**：高 72。标识、今天、知识库在左；搜索、设置在右。任务中隐藏。
- **今天**：左为地图，上沿对齐右栏，下沿与右栏最下一行对齐；右栏宽 400，由上到下是课程名、今日目标、任务、输入框、格子说明。
- **任务页**：一格放大成 760 × 860 的页面。上部（返回、标题、进度、位置）不动，只有正文滚动，底栏固定。
- **知识库**：树 300，页面最多 38 字宽，右栏 260。全图和塔占页面的位置，树和右栏不动。

地图的列数按窗口算出，让格子尽量大。120 格时是 12 × 10；格子边长上限 112，所以很小的课也不会撑满全屏。

## 单元

四项事实彼此独立，分别画出：

| 事实 | 来源 | 格子 |
| --- | --- | --- |
| 作答历史 | 学习记录 | 没有作答是一个点；作答一次一段细弧；两次以上两段 |
| 通过 | 课的结果，可能因重判而失去 | 两段粗带，宽为格边的 0.3 |
| 记忆 | 学生模型的估计，按 topic | 粗带的浓淡，同一 topic 一起变化 |
| 当前 | 下一项或正在做的任务 | 外加方框 |

弧向由知识点编号算出，只要编号不变就不变，别处增删知识点不影响它。弧连接各边中点，相邻格子永远相连，并各超出边界一点，接缝不可见。

格子不是状态的唯一表达：名称、可访问标签和列表里都读得到同样的信息。“通过”用于课的结果，“掌握”留给学生模型的估计。

## 字

| Token | 规格 | 用途 |
| --- | --- | --- |
| `--fs-display` | 44 / 1.25，宋体 | 任务结论 |
| `--fs-name` | 32 / 40，宋体 | 页面标题 |
| `--fs-title` | 24 / 32，宋体 | 课程名、任务标题、知识点名、首要任务 |
| `--fs-lead` | 20 / 32 | 标识、对话框标题 |
| `--fs-body` | 17 / 30，黑体 | 正文；17 / 24 宋体用于任务名 |
| `--fs-small` | 14 / 24，黑体 | 状态、控件、标签 |
| `--fs-note` | 13 / 20，黑体 | 标记 |
| 代码 | 15 / 26，IBM Plex Mono | 代码块；行内也是 15 |

- **字体**：宋体只用于名字。正文用系统黑体，西文经 `unicode-range` 接 IBM Plex Sans，字面调到 97%，由肉眼对齐。代码用 IBM Plex Mono。
- **字重**：400 正文，500 标签，600 名字和重要结论。悬停和选中不改字重。
- **行宽**：至多 38 字（`--measure: 38em`）。任务页正文宽 664，约 39 字。
- **行高**：正文 30/17 = 1.76，是假设，要由人长时间阅读来核对。
- **中文排版**：`text-autospace: normal`，不手打中西文空格；`text-spacing-trim: normal`，依赖字体带 `halt`；`line-break: strict`；正文 `text-wrap: pretty`；名字用 `Intl.Segmenter` 找词边界，只在词间断行。
- **数字**：状态和计时用 `tabular-nums`。正文用比例数字。
- **字距**：名字和小字 +.01em。缺少中文标题字距的可靠来源，这也是假设。

## 色

用 OKLCH 写色阶。职责照 Radix 的 12 阶：

| Token | 浅色 | 深色 | 职责 |
| --- | --- | --- | --- |
| `--paper` | `oklch(98.2% .003 245)` | `oklch(19% .012 255)` | 页面（第 1 阶） |
| `--tint` | `oklch(94.6% .007 245)` | `oklch(24.5% .015 255)` | 内嵌面（第 3 阶） |
| `--hair` | `oklch(87.5% .012 245)` | `oklch(33% .018 255)` | 细线（第 6 阶） |
| `--faint` | `oklch(50% .018 250)` | `oklch(74% .018 252)` | 最弱文字 |
| `--soft` | `oklch(41% .016 255)` | `oklch(86% .014 248)` | 次要文字（第 11 阶） |
| `--ink` | `oklch(24% .012 260)` | `oklch(93% .007 245)` | 正文（第 12 阶） |
| `--accent` | `oklch(47% .085 243)` | `oklch(83% .065 238)` | 通过、答对、焦点、链接 |
| `--sting` | `oklch(52% .18 32)` | `oklch(72% .16 32)` | 只用于错 |
| `--solid` | 同 `--ink` | 同 `--ink` | 主要操作，深色下反转为浅底 |
| `--well` | 同 `--ink` | `oklch(14.5% .01 255)` | 代码块、排序行，深色下是凹陷的井 |

中性色带一点蓝，不用纯黑。对比度同时看 WCAG 2（规范）和 APCA（草案）。

## 距、形、面

- **距**：4、8、16、24、32、48、64、96。同组内的距明显小于组间。
- **形**：不动的元素方角，浮层 12 px 圆角。子元素圆角不超过父元素。
- **线**：输入框 1 px，错和对时内加 1 px；细线在高密度屏上 0.5 px。分隔优先用留白。
- **面**：实色面只用于主要操作、代码块和当前项。只有浮层有阴影：两层，同一光源，带色相，不做动画。
- **控件**：高 40，触屏 44；输入字号触屏不低于 16。列表项之间用内距，不留死区。

## 动

只回应动作，或表示等待，或标记一次少见的地点变化。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--dur-press` | 100 ms | 按下，缩到 .97 |
| `--dur-pop` | 200 ms | 浮层、淡入 |
| `--dur-space` | 420 ms | 进入和离开格子 |

曲线取 Carbon：标准 `(.2,0,.38,.9)`，进入 `(0,0,.38,.9)`。悬停不做动画；从键盘发起的跳转不做动画。只动 `transform` 和 `opacity`，唯一的例外是通过时织上一格，640 ms，只此一次。减少动态效果的偏好下全部关闭。

## 状态

| 状态 | 表达 |
| --- | --- |
| 悬停 | 仅在 `@media (hover: hover)` 下；对比度升高，不改字重 |
| 焦点 | `:focus-visible`，2 px 强调色；树里焦点与选中外观不同 |
| 按下 | 缩到 .97 |
| 不可用 | .38 不透明度；不预先禁用提交；知识库在作答时变弱并说明 |
| 等待 | 底栏写“正在判分…”，按钮 `aria-busy` |
| 没判出 | 底栏说明，可以再判一次，也可以先做下一题 |
| 未填 | 不算作答，就地提示并把焦点移过去 |
| 对、错 | 颜色加形状加文字，不只靠颜色 |
| 空 | 说明为什么空和下一步，没有任务时写明何时恢复 |
| 断线 | 底部一条状态，作答保留 |

单选用圆形标记，多选用方形标记，靠约定传达含义。

## 模式

### 今天

一个明确的下一步，放在实色块里，写明类型、缘由、XP 和动词；其余一两项可选。今日目标写成 XP，1 XP 约 1 分钟，目标可在设置里调。达到目标以后首项退回普通样式，仍可继续做。

地图是真实入口：指向任一格，同一 topic 的格子亮起，下方说明它是什么、学得怎样；点开进入知识库。指向任务时，地图上亮起它涉及的格子。

### 任务页

进度条覆盖全课，每段是一步或一题：走过的是蓝色，答错的是红色，当前的是墨色。其下写当前知识点和“讲解、例题、练习”。走过的步骤是下划线链接，可以回看；作答时都不能点，也不像链接。

主操作固定在底栏右侧，“提交”和“继续”落在同一点。全程可以不碰鼠标：焦点落在作答框或主按钮上，Enter 继续；数字键选选项。

### 反馈

题目留在原处，不被推开。结果紧贴作答处：错的输入框变红，旁边是楔形，下方是正确答案和针对这个错法的说明；然后是解析。判定写在底栏，就在刚才按下的按钮旁边，题目再长也看得到。题目长到把作答框推出视野时，页面自动把它带回来。

### 辅导

能问时，输入框就在底栏；回答接在当前页的末尾。答错时它正好在手边，不用召唤。不能问时输入框直接不出现，不画锁。整段对话从页面顶部打开，它是连续的，不按任务拆开。

### 中断与结束

左上角回到今天，任务保留，今天页首位变成继续，写明停在哪一题，测验的时钟照走。在知识库里，顶栏有一键回到任务的入口。中止放在今天页，并且要确认。

结束时一律先给结论：通过、没有通过、时间到、还有作答在判。复习和测验此时才放出每题的结果，错的默认展开。通过一节课回到地图时，这一格当面织上。

### 知识库

| 视图 | 任务 | 做法 |
| --- | --- | --- |
| 就地预览 | 这个词是什么来着 | 悬停 500 毫秒或点按，卡片有定义和“打开”；能移上去，Esc 关闭；触屏是底部弹层 |
| 搜索 | 已知要找什么 | `/` 打开，名称和别名排在正文前面；空输入时列出最近学的；未学的只给名字 |
| 树 | 学到哪了 | 打开时定位当前项；可同时展开多项；键盘照 APG；未学的收在末尾一组 |
| 页面 | 回顾一整块 | 一个 topic 一页，知识点连排，定义、条件、例子和“讲解”都在；滚动时树跟着走 |
| 局部关系 | 依赖什么，通向什么 | 一跳，和页面同屏；先修在上，后续在下，一根竖线连起来；未学的只见名字 |
| 全图 | 整门课的全貌 | 不是默认入口；先修由上而下排在格点上，平时只突出当前项的边，随学习填满 |
| 塔 | 好看 | 留作把玩，不承担任务 |

记忆强弱只用浓淡和页面上一行字表达，不放“待复习”列表，以免成为第二套复习系统。可读范围是已学内容和当前任务的 topic，其余只见名字。

## 文字

遵循 [`ui-text`](../../.agents/skills/ui-text/SKILL.md)：先问这句话能否由结构代替，能否去掉选择，能否改成可撤销。原型里的按钮和标签只是占位，定稿由人书写（#101）。

## 探索稿

`app.html`、`matrix.html`、`explore.html`、`index.html`、`themes/` 等是探索阶段的材料，保留备查：8 种框架、9 种皮肤、19 种图形。这些都算设计，问题在粗糙，因此 `repa.html` 只把其中一条路线做透，其余并未被否定。

## 未解决

- **原型是演示**：课程内容是真的，流程规则照学习文档；判分用字符串比较，代码不运行，日期、记忆和辅导的回答都是演示。
- **数据**：今天和知识库需要全课 topic 与知识点的只读状态查询，作答历史要跨任务，记忆估计要按 topic 给出。设计先行，学习契约还没有这些（#7 已提及）。
- **多门课**：今天页显示一门还是多门，还没想过。
- **效果**：没有真实学习者用过。只在 Linux 的 Chromium 里看过，Windows 和 macOS 的字体回退未核对。宋体需要随应用打包切片，切片后要核对 `halt`。
- **假设**：正文行高、字号步长、中文标题字距、控件高度比例都没有可靠来源，见 [CRAFT.md](CRAFT.md)。
- **第一次使用**：打开直接进今天、自动建空间，这一条尚未决定。
- **落地**：`apps/web` 的基础组件是 shadcn，页面结构要重做，前端由 Aqua 负责，落地方式需要协商。
