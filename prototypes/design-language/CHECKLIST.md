# 清单

判定方法是把任务实际做一遍，不看截图是否好看：好看的稿子会掩盖问题，NN/g 也提醒，审美只能原谅小问题，而且会在测试中遮住问题。因此每条都写成做得到或做不到的形式。

依据标注：**[弱]** 指论坛、厂商博客或搜索摘要，只作线索；未标注的读过原页。细节规范（字、色、动效的取值）不重复，见 [CRAFT.md](CRAFT.md) 和 [`interface-craft`](../../.agents/skills/interface-craft/references/standards.md)。

## 一、换了主体也成立

从第三国际塔到极简主义，这些要求都不变。风格可以放在字形、动效和颜色里；结构要守住位置、层级、状态提示和响应这四件事。Persona 5 与 Cyberpunk 2077 的对比说明了这一点：前者风格极端，但始终是有清楚光标的列表，路径很短；后者的失败都在结构上，如标签会移位、名称与内容不符，并不在风格上。

| 编号 | 要求 | 怎样核对 | 依据 |
| --- | --- | --- | --- |
| S1 | 能点的看着能点，不能点的看着不能点 | 逐屏核对：长得像按钮或标签页的都能点；能点的不依赖悬停才露出线索 | [NN/g 扁平设计](https://www.nngroup.com/articles/flat-design/) 2015；[brutalist-web.design](https://brutalist-web.design) |
| S2 | 模糊后层级仍在，去色后层级仍在 | 模糊和灰度截图各看一次；每屏至多 2 个突出元素、3 种对比处理 | [NN/g 视觉层级](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/) 2021 |
| S3 | 功能层与装饰层分得开 | 装饰不用信号色，不占信号的位置；红色只表示答错 | [Cyberpunk 2077 批评](https://interfaceingame.com/articles/cyberpunk-2077-ux-ui-critique/) |
| S4 | 同一件事总在同一位置 | 导航不移位；主操作在各阶段落在同一点；换步骤时上方内容不动 | 同上；[十条启发式](https://www.nngroup.com/articles/ten-usability-heuristics/) 3、4、6 |
| S5 | 名称与内容相符，随时知道身在何处、怎样退出 | 每屏回答“这是哪里”和“怎样回去” | 同上 |
| S6 | 天天做的事有捷径 | 上课全程不碰鼠标可以走完；查一个词一步到达 | 启发式 7；Cyberpunk 批评 |
| S7 | 每个部件的状态都画过 | 默认、悬停、焦点、按下、禁用、加载、空、错、溢出逐个看 | [Linear](https://linear.app/now/quality-wednesdays) 2025；设计走查清单 [弱] |
| S8 | 手感统一 | 同级按钮尺寸和反馈相同；内容增加时布局不跳 | Linear 2025 |
| S9 | 可读性不靠风格配合 | 风格最响的一层只放大字，正文留在中性字面上 | [NN/g 新粗野主义](https://www.nngroup.com/articles/neobrutalism/) 2025 |
| S10 | 响应即时 | 0.1 秒内有反应，1 秒内不断流，更久要有进度 | [NN/g 响应时间](https://www.nngroup.com/articles/response-times-3-important-limits/) |
| S11 | 数字彼此一致 | 同一屏和不同屏的估计不互相矛盾 | [Hecker 2025](https://frankhecker.com/2025/02/17/math-academy-part-10/) |
| S12 | 每个图形都有用途 | 删掉它，用户会少知道什么、少做到什么；答不上来就是装饰 | brutalist-web.design；我的推论 |

## 二、学习者在每一刻要什么

| 编号 | 时刻 | 学习者的问题 | 屏幕要答什么 | 依据 |
| --- | --- | --- | --- | --- |
| L1 | 打开 | 现在做什么 | 一个明确的下一步，也能选别的 | MA 的任务组；[HN 2025](https://news.ycombinator.com/item?id=43656481) |
| L2 | 打开 | 为什么是它 | 用事实说明选择的缘由；没有任务时明说并给出何时恢复 | [HN 2024](https://news.ycombinator.com/item?id=41534847)：返回的用户看不到复习，就怀疑系统 |
| L3 | 打开 | 今天要多久 | 用 XP 计，1 XP 约 1 分钟，目标可调；不承诺单项时长 | [MA](https://www.mathacademy.com/how-it-works)；Duolingo 撤掉计时 [弱] |
| L4 | 阅读 | 讲到哪了，前面的还能看吗 | 全课进度一眼可见；没有题等着作答时可以回看 | MA 允许回看 |
| L5 | 阅读 | 这个词是什么来着 | 就地查看 | 根目录 `AGENTS.md`；见 K1 |
| L6 | 作答 | 要答什么，还有几题 | 题、作答框、题数；此外不放别的 | Repa 学习证据 |
| L7 | 答错 | 错在哪，为什么，正确的是什么 | 三者都紧贴出错处；不扣分，不用惩罚性语气 | [NN/g 错误提示](https://www.nngroup.com/articles/error-message-guidelines/)；[HN](https://news.ycombinator.com/item?id=41534847)：扣分和提前结束让人觉得被惩罚 |
| L8 | 答对 | 下一个 | 反应快，一键继续，不放庆祝动画 | MA 的朴素受成人学习者称赞 [弱] |
| L9 | 求助 | 我能问吗 | 输入框贴在题目旁，答错后就在手边；不用另外召唤 | [Hechinger 2026](https://hechingerreport.org/proof-points-khanmigo-math-ai-tutor/)：可选的辅导多数学生不用；效果证据仍弱 |
| L10 | 中断 | 刚才的还在吗 | 离开没有代价；再打开就回到原题；测验的时钟明确还在走 | Repa 学习流程；各家均无一手资料 |
| L11 | 结束 | 有什么变了 | 看得到结果和状态的变化，下一步就在手边；不能毫无表示，也不要开宝箱 | Hecker：完课毫无表示；Duolingo：完成的人只想继续练 [弱] |
| L12 | 长期 | 我学到哪了 | 能看到位置和增长；不放待办积压数字，不放连续天数的压力 | [Anki 积压是弃用主因](https://my-senpai.com/insights/why-people-quit-anki.html) [弱]；[Mobbin](https://mobbin.com/blog/streaks-are-about-losing-a-study-of-859-streak-designs) [弱] |

## 三、知识库：每种视图只承担它擅长的任务

| 编号 | 任务 | 承担者 | 要求 | 依据 |
| --- | --- | --- | --- | --- |
| K1 | “这个词是什么来着” | 就地预览 | 悬停约 500 毫秒打开，点按立即打开；能移到卡片上；Esc 关闭；键盘可开；触屏改为点按；卡片里的内容跟链接过去都能找到 | [Wikipedia 预览 2018](https://diff.wikimedia.org/2018/04/18/how-we-designed-page-previews-for-wikipedia/)（500 至 650 毫秒）；[A/B 实验](https://www.mediawiki.org/wiki/Page_Previews/2017-18_A/B_Tests)；WCAG 1.4.13 |
| K2 | 已知要找什么 | 搜索 | 全局一键打开；名称、别名、正文都搜；未学的只给名字 | [NN/g 搜索与浏览](https://www.nngroup.com/articles/search-not-enough/) [弱] |
| K3 | 学到哪了，周围有什么 | 树 | 打开即定位当前项；多项可同时展开；有展开指示线；每行看得出状态；已学与未学分得开 | NN/g 手风琴 [弱]；VS Code 缩进 [弱] |
| K4 | 键盘走树 | 树 | 上下移动，右展开或进子项，左收起或回父项，Home、End，Enter 打开，打字跳转；焦点和选中外观不同 | [WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/) |
| K5 | 回顾一整块 | 页面 | 一个 topic 一页，知识点连续排，不必逐个点开；写明何时学的 | 我的推论：回顾是连读，不是逐张翻 |
| K6 | 这个依赖什么，又通向什么 | 局部关系 | 只画一跳，默认和页面同屏；先修在上，后续在下 | [XDA 2026](https://www.xda-developers.com/ignored-obsidian-graph-view-for-years-but-i-was-looking-at-the-wrong-graph/)；此前调研的结论：先列表，方向和分支读得更清楚时才画图 |
| K7 | 整门课的全貌 | 全图 | 不做默认入口；按状态着色，随学习填满；平时只突出焦点项的边 | [Obsidian 论坛](https://forum.obsidian.md/t/whats-the-point-of-the-graph-view-how-are-you-using-it/71316?page=2) [弱]；[Khan 撤掉知识地图](https://support.khanacademy.org/hc/en-us/community/posts/360027982751-What-happened-to-the-knowledge-map) [弱]；[Metacademy 测试](https://github.com/metacademy/metacademy-application/wiki/Weekly-usability-studies) [弱] |
| K8 | 不成为第二套复习系统 | 全部 | 记忆强弱只用浓淡和页面上一行字表达；不放“待复习”列表 | 根目录 `AGENTS.md` |

## 四、这一版要怎样才算好

走查原型时查到的粗糙之处，以及对应的做法：

| 现状 | 违反 | 做法 |
| --- | --- | --- |
| topic 图和链接图的节点放大成巨弧，连线散落 | S7 | 重画，全图只留层级图 |
| 知识库是四个并列标签，图和卡片互斥 | K5、K6 | 页面加局部关系同屏，全图和塔退到次要位置 |
| 树是 48 行等重文字，没有搜索 | K2、K3、K4 | 实现完整的树，加搜索 |
| 对话里提到的词只有一处样例能查 | K1、L5 | 统一的就地预览，全站通用 |
| 地图只能看，格子没有用途 | S12 | 悬停显示 topic 和状态，点击进入知识库页 |
| 今天页与知识库导航不一致；课程名、进度、任务分散，面板缩在角落 | S4、S2 | 同一顶栏，右侧一栏从上到下排好 |
| 任务只有名字，不知缘由和分量 | L2、L3 | 每项写缘由和 XP |
| “讲解 例题 练习”像标签页却点不了 | S1、L4 | 改成进度：走过的可以回看，作答时不能 |
| 小方块串没有含义提示 | S1、L6 | 改成“第几题，共几题”，每题的对错标在一起 |
| 主按钮随内容长短跳动 | S4 | 底栏固定 |
| 判定结果插在题目上方，把题目推下去 | S4、S8、L7 | 题目不动，结果紧贴作答框 |
| 辅导浮在角落，关闭时是一块斜纹和一把锁 | L9、S1 | 能问时输入框就在底栏，回答接在页面里；不能问时不出现 |
| “中止新课”和进度并排，离开有代价的样子 | L10、S5 | 左上角回到今天，任务保留；中止放到今天页并要确认 |
| 通过一节课只有结果页 | L11 | 回到地图，当面把这一格织上 |
| 中断和回来没有设计 | L10 | 今天页首位显示继续，写明停在第几题 |

## 五、这一版的结果

结果对应 `repa.html`。✓ 指实际走过或脚本重放过，△ 指部分做到，✗ 指没做。

| 编号 | 结果 | 说明 |
| --- | --- | --- |
| S1 | ✓ | “讲解、例题”只在能回看时是链接；不能看的知识库明确变弱 |
| S2 | △ | 灰度和模糊测试还没有系统做，只看过截图 |
| S3 | ✓ | 红色只表示答错；地图是状态，不是装饰 |
| S4 | ✓ | 顶栏和内容框跨路由不动；主操作固定在底栏；反馈不推动题目 |
| S5 | ✓ | 任务页左上角回今天；知识库里一键回任务 |
| S6 | ✓ | 一节课可以全程用键盘走完（Enter 继续、数字选项，`/` 搜索），脚本走过 |
| S7 | △ | 判分中、没判出、待定、断线、空、达标都画了；加载延迟只有演示 |
| S8 | ✓ | 同级按钮尺寸一致；触屏目标统一到 44 |
| S9 | ✓ | 宋体只放名字，正文用中性黑体 |
| S10 | △ | 原型没有真实等待，真实响应时间未测 |
| S11 | ✓ | XP 只在今日目标和任务上出现，计算同一处 |
| S12 | ✓ | 地图能回答“这一格是什么”，也能进入知识库；塔明说只是把玩 |
| L1 至 L3 | ✓ | 下一步、缘由、XP 都在；空状态写明何时恢复 |
| L4 | ✓ | 全课进度条；走过的步骤和本课已通过的知识点都能回看 |
| L5 | ✓ | 课内可查：概念链接就地预览，读讲解时可搜索 |
| L6 | ✓ | 作答时只留题、题数、“不会”和“提交” |
| L7 | ✓ | 正确答案和错因贴着作答处，题长时自动带回视野 |
| L8 | ✓ | Enter 继续，没有庆祝动画 |
| L9 | ✓ | 输入框在底栏，回答接在页面里；效果未验证 |
| L10 | ✓ | 未提交的作答、阅读位置和没发出的问题都保留 |
| L11 | ✓ | 结论页，回到地图当面织上一格；结果可以重新打开 |
| L12 | △ | 不放积压数字和连续天数；“学到哪了”没有真实学习者验证 |
| K1 | ✓ | 悬停 500 毫秒、点按、键盘、Esc、触屏弹层都走过 |
| K2 | ✓ | 全局搜索，含别名；未学只给名字 |
| K3、K4 | ✓ | 手机上改为按需打开；键盘照 APG |
| K5 | ✓ | 一页连读；例子自带它用到的表 |
| K6 | ✓ | 局部关系一跳，和页面同屏；手机上是弹层 |
| K7 | △ | 全图可用，邻接项有名字；是否真比列表有用，没有证据 |
| K8 | ✓ | 没有“待复习”列表 |

新发现的要求，补在这里：**查阅用的内容必须自足。** 知识卡里写“表 M”，旁边就要有表 M，否则又把记忆负担还给了学习者。

## 六、证据不足的部分

- 树与搜索在学习产品里的实际比例，没有查到数据。
- 全图的批评几乎都来自论坛自述，没有用量数据。
- 预览的研究只证明探索增多、后退减少，没有测理解和记忆，也没有回答是否打断阅读。
- 辅导贴在题目旁能否提高使用率，Khan 的改动尚未评估。
- MA 学生端的知识图展示只在播客里提过，没有找到截图。
- 代码与公式怎样呈现，没有查到学习产品的专门资料。
- Persona 5 的分析都来自玩家和爱好者文章，没有开发者原话。
